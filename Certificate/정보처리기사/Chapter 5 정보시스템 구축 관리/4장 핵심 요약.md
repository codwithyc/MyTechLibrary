## 153. 서비스 공격 유형

### 1. 서비스 거부 공격의 개념

서비스 거부 공격(DoS, Denial of Service)은 서버나 네트워크에 **과도한 트래픽 또는 비정상적인 요청을 발생시켜 정상 사용자가 서비스를 이용하지 못하도록 하는 공격**입니다.

```text
공격자
  ↓
대량의 요청
  ↓
Server
  ↓
CPU / Memory / Network 자원 고갈
  ↓
정상 사용자 서비스 불가
```

#### 주요 목적

* 서버 자원 고갈
* 네트워크 대역폭 소진
* 시스템 장애 발생
* 정상적인 서비스 제공 방해

DoS와 DDoS의 차이:

| 구분    | DoS      | DDoS        |
| ----- | -------- | ----------- |
| 공격 주체 | 하나 또는 소수 | 다수의 감염된 시스템 |
| 공격 규모 | 상대적으로 작음 | 매우 큼        |
| 추적    | 비교적 쉬움   | 어려움         |
| 차단    | 상대적으로 쉬움 | 어려움         |

---

### 2. 죽음의 핑(Ping of Death)

Ping of Death는 정상적인 크기를 초과하는 **비정상적으로 큰 ICMP 패킷을 전송하여 시스템 오류나 장애를 발생시키는 공격**입니다.

IPv4 패킷의 최대 크기는 일반적으로 `65,535 Byte`입니다.

공격자는 큰 패킷을 여러 조각(Fragment)으로 나누어 전송하고, 대상 시스템이 이를 재조립하는 과정에서 문제를 발생시키도록 합니다.

```text
비정상적인 ICMP Packet
       ↓
Fragmentation
       ↓
Target Server
       ↓
패킷 재조립
       ↓
Buffer 문제 / 시스템 장애
```

현대 운영체제에서는 대부분 방어되어 있는 고전적인 공격 방식입니다.

---

### 3. Smurfing(스머핑)

Smurfing은 공격자가 **출발지 IP 주소를 공격 대상의 IP 주소로 위조한 ICMP Echo Request를 브로드캐스트 주소로 전송**하여 다수의 응답이 피해자에게 집중되도록 하는 공격입니다.

```text
공격자
   ↓
출발지 IP = 피해자 IP로 위조
   ↓
Broadcast Network
  ↙ ↓ ↓ ↘
PC PC PC PC
  ↘ ↓ ↓ ↙
    피해자
```

#### 공격 과정

1. 공격자가 피해자의 IP로 Source IP를 위조합니다.
2. 네트워크 브로드캐스트 주소로 Ping을 전송합니다.
3. 네트워크의 여러 장치가 응답합니다.
4. 모든 응답이 피해자에게 집중됩니다.
5. 피해자의 네트워크 자원이 고갈됩니다.

핵심:

```text
IP Spoofing
    +
ICMP
    +
Broadcast
    =
Smurfing
```

---

### 4. SYN Flooding

SYN Flooding은 TCP 연결 과정인 **3-Way Handshake의 특성을 악용하여 서버의 연결 자원을 고갈시키는 공격**입니다.

정상적인 TCP 연결:

```text
Client                  Server

SYN ───────────────────→

    ←──────────── SYN + ACK

ACK ───────────────────→

       연결 완료
```

SYN Flooding:

```text
공격자                  Server

SYN ───────────────────→
    ←──────────── SYN + ACK

ACK 없음

SYN ───────────────────→
    ←──────────── SYN + ACK

ACK 없음

       반복
```

서버는 `SYN-RECEIVED` 상태의 **Half-Open Connection**을 계속 유지하게 되고 연결 큐가 고갈됩니다.

#### 대응 방법

* SYN Cookie
* 연결 Timeout 감소
* 방화벽 Rate Limiting
* 비정상적인 SYN 패킷 차단

---

### 5. LAND

LAND 공격은 패킷의 **출발지 IP와 목적지 IP를 모두 공격 대상 시스템의 IP로 설정하여 전송하는 공격**입니다.

```text
Source IP      = Victim
Destination IP = Victim
```

결과:

```text
Victim
  ↓
자기 자신에게 요청
  ↓
자기 자신에게 응답
```

과거 일부 시스템에서는 무한 응답, 시스템 부하 또는 장애가 발생할 수 있었습니다.

---

### 6. DDoS(Distributed Denial of Service) 공격

DDoS는 여러 대의 감염된 컴퓨터를 이용하여 **하나의 대상에 대량의 트래픽을 동시에 전송하는 분산 서비스 거부 공격**입니다.

```text
           공격자
             ↓
        C&C Server
             ↓
 ┌───────────┼───────────┐
Zombie     Zombie      Zombie
  │           │            │
  └───────────┼────────────┘
              ↓
           Target
```

공격에 사용되는 감염된 장치를 **Zombie PC 또는 Bot**이라고 합니다.

여러 Bot을 구성한 네트워크를 **Botnet**이라고 합니다.

#### 특징

* 여러 시스템에서 동시에 공격
* 공격 출발지가 분산됨
* 차단 및 추적이 어려움
* 대규모 트래픽 발생 가능

---

### 7. 피싱(Phishing)

피싱은 금융기관이나 유명 기업 등을 사칭하여 **사용자로부터 계정, 비밀번호, 금융정보 등의 개인정보를 탈취하는 사회공학 공격**입니다.

```text
가짜 Email / SMS
       ↓
가짜 Website
       ↓
사용자 로그인
       ↓
ID / Password 탈취
```

예:

```text
"계정이 정지되었습니다.
 아래 링크에서 본인 인증을 진행하세요."
```

#### 대응 방법

* 출처가 불분명한 링크 클릭 금지
* URL 확인
* MFA 적용
* 이메일 발신자 확인

---

### 8. Ping Flood

Ping Flood는 대상 시스템에 **대량의 ICMP Echo Request(Ping)를 지속적으로 전송하여 네트워크와 시스템 자원을 고갈시키는 DoS 공격**입니다.

```text
공격자

Ping
Ping
Ping
Ping
 ↓↓↓↓

Target
```

#### 특징

* ICMP 패킷 이용
* 네트워크 대역폭 소비
* 시스템의 ICMP 처리 자원 소모

> `Pin Flood`가 아니라 **Ping Flood**입니다.

---

### 9. 스위칭 재밍(Switch Jamming)

Switch Jamming은 스위치의 **MAC Address Table(CAM Table)을 대량의 가짜 MAC 주소로 채워 정상적인 스위칭 기능을 방해하는 공격**입니다.

MAC Flooding이라고도 합니다.

정상:

```text
MAC Table

AA:AA → Port 1
BB:BB → Port 2
CC:CC → Port 3
```

공격:

```text
가짜 MAC 주소 대량 전송

↓
CAM Table 가득 참
↓
스위치가 목적지를 판단하기 어려움
↓
일부 환경에서 Frame Flooding 발생
```

#### 대응 방법

* Port Security
* MAC 주소 등록 수 제한
* 비정상 MAC 학습 탐지

---

### 10. 블루프린팅(BluePrinting)

BluePrinting은 Bluetooth 장치를 탐색하여 **장치의 종류, 제조사, 서비스, 프로파일 등의 정보를 수집하는 행위**입니다.

```text
공격자
 ↓
Bluetooth Scan
 ↓
Target Device
 ↓
장치 정보 수집
```

수집 가능한 정보:

* Bluetooth 장치 주소
* 제조사
* 장치 유형
* 지원 서비스
* Bluetooth 프로파일

이러한 정보는 이후 Bluetooth 공격을 위한 사전 정보 수집에 활용될 수 있습니다.

---

### 11. 웜(Worm)

웜은 다른 프로그램에 기생하지 않고 **스스로 복제하여 네트워크를 통해 다른 시스템으로 전파되는 악성코드**입니다.

```text
PC A 감염
 ↓
자동 복제
 ↓
PC B
 ↓
자동 복제
 ↓
PC C
```

#### 특징

* 자기 복제 가능
* 사용자 개입 없이 전파 가능
* 네트워크를 통해 빠르게 확산
* 네트워크 트래픽 증가
* 시스템 자원 고갈 가능

#### 바이러스와 웜 비교

| 구분         | 바이러스     | 웜            |
| ---------- | -------- | ------------ |
| 다른 파일에 기생  | O        | X            |
| 자기 복제      | O        | O            |
| 네트워크 자체 전파 | 상대적으로 적음 | O            |
| 사용자 실행 필요  | 일반적으로 필요 | 필요하지 않을 수 있음 |

---

### 12. 키로거 공격(Key Logger Attack)

Key Logger는 사용자가 키보드로 입력하는 내용을 **몰래 기록하여 개인정보를 탈취하는 공격**입니다.

```text
사용자 입력

ID
Password
Card Number
    ↓
Key Logger
    ↓
공격자
```

탈취 대상:

* ID
* 비밀번호
* 카드 번호
* 개인정보
* 메시지

키로거는 소프트웨어나 하드웨어 형태로 존재할 수 있습니다.

---

### 13. 랜섬웨어(Ransomware)

랜섬웨어는 시스템이나 파일을 암호화한 후 **복구를 대가로 금전을 요구하는 악성코드**입니다.

```text
악성코드 감염
    ↓
파일 암호화
    ↓
사용 불가능
    ↓
금전 요구
```

#### 주요 특징

* 파일 암호화
* 시스템 접근 제한
* 금전 또는 암호화폐 요구
* 네트워크 공유 폴더까지 피해 확산 가능

#### 대응 방법

* 중요 데이터 정기 백업
* 운영체제와 소프트웨어 업데이트
* 의심스러운 파일 실행 금지
* 최소 권한 적용
* 백업 데이터 분리 보관

---

### 14. 백도어(Back Door, Trap Door)

백도어는 정상적인 인증 절차를 거치지 않고 **시스템에 접근할 수 있도록 만들어진 숨겨진 접근 경로**입니다.

```text
정상 사용자

Login
 ↓
Authentication
 ↓
System


공격자

Backdoor
 ↓
인증 우회
 ↓
System
```

백도어는 개발자가 유지보수를 위해 만들기도 하지만 공격자가 시스템을 장악한 뒤 지속적인 접근을 위해 설치하기도 합니다.

#### 위험

* 인증 우회
* 원격 명령 실행
* 데이터 탈취
* 추가 악성코드 설치

---

### 15. 파밍(Pharming)

파밍은 DNS 등의 정보를 조작하여 사용자가 정상적인 주소를 입력하더라도 **공격자가 만든 가짜 사이트로 이동하게 하는 공격**입니다.

```text
사용자

www.bank.com 입력
       ↓
DNS 정보 변조
       ↓
가짜 Bank Site
       ↓
개인정보 탈취
```

#### 피싱과 파밍 비교

| 구분     | 피싱       | 파밍                |
| ------ | -------- | ----------------- |
| 주요 방식  | 가짜 링크 유도 | DNS 등 주소 정보 조작    |
| 사용자 행동 | 공격 링크 클릭 | 정상 주소를 입력해도 피해 가능 |
| 목적     | 개인정보 탈취  | 개인정보 탈취           |

핵심:

```text
Phishing
→ 사용자를 속여 가짜 사이트로 이동

Pharming
→ 주소 체계를 조작하여 가짜 사이트로 이동
```

---

## 154. 서버 인증

### 1. 인증(Authentication)

인증은 사용자가 **누구인지 확인하는 과정**입니다.

```text
사용자
 ↓
ID + Password
 ↓
Authentication
 ↓
"누구인가?"
```

예:

* ID / Password
* OTP
* 인증서
* 생체인식

---

### 2. 인가(Authorization)

인가는 인증된 사용자가 **어떤 자원에 접근할 수 있는지 권한을 확인하는 과정**입니다.

```text
Authentication
     ↓
사용자 확인 완료
     ↓
Authorization
     ↓
접근 권한 확인
```

예:

```text
Admin
→ READ / WRITE / DELETE

User
→ READ
```

#### 인증과 인가 비교

| 구분 | 인증             | 인가            |
| -- | -------------- | ------------- |
| 영어 | Authentication | Authorization |
| 질문 | 누구인가?          | 무엇을 할 수 있는가?  |
| 예  | 로그인            | 관리자 페이지 접근 권한 |
| 순서 | 먼저 수행          | 인증 이후 수행      |

---

### 3. 지식 기반 인증(Something You Know)

사용자가 **알고 있는 정보**를 이용하여 인증하는 방식입니다.

예:

* 비밀번호
* PIN
* 보안 질문

```text
Something You Know

Password
PIN
Secret Question
```

#### 장점

* 구현이 간단함
* 별도의 장치가 필요하지 않음

#### 단점

* 유출 가능
* 추측 공격 가능
* 재사용된 비밀번호 위험

---

### 4. 소유 기반 인증(Something You Have)

사용자가 **소유하고 있는 장치나 매체**를 이용하는 인증 방식입니다.

예:

* OTP Token
* 스마트카드
* 보안카드
* 휴대전화
* 인증서가 저장된 보안장치

```text
Something You Have

Smart Card
OTP Token
Smartphone
```

---

### 5. 행위 기반 인증(Something You Do)

사용자의 **행동 또는 행동 패턴**을 이용하여 인증하는 방식입니다.

예:

* 키보드 입력 패턴
* 서명 패턴
* 마우스 움직임
* 걸음걸이

```text
사용자 행동
    ↓
패턴 분석
    ↓
Authentication
```

참고로 인증 요소는 다음과 같이 확장해서 구분할 수 있습니다.

| 인증 요소              | 의미       | 예          |
| ------------------ | -------- | ---------- |
| Something You Know | 알고 있는 것  | Password   |
| Something You Have | 가지고 있는 것 | OTP        |
| Something You Are  | 신체적 특징   | 지문, 얼굴     |
| Something You Do   | 행동 특징    | 서명, 키보드 패턴 |

둘 이상의 서로 다른 인증 요소를 사용하는 방식을 **다중 요소 인증(MFA)**이라고 합니다.

---

## 155. 보안 아키텍처 / 보안 프레임워크

정보 시스템의 보안 대책은 크게 **관리적, 물리적, 기술적 보안**으로 구분할 수 있습니다.

```text
정보보안

├─ 관리적 보안
├─ 물리적 보안
└─ 기술적 보안
```

---

### 1. 관리적 보안

관리적 보안은 조직의 **보안 정책, 절차, 인력 등을 관리하여 보안을 확보하는 방법**입니다.

대표적인 대책:

* 정보보안 정책 수립
* 보안 지침 및 절차 수립
* 보안 교육
* 인력 관리
* 권한 관리 정책
* 보안 감사
* 사고 대응 절차 수립

예:

```text
신입사원
 ↓
보안 교육
 ↓
접근 권한 부여
 ↓
정기 보안 점검
```

---

### 2. 물리적 보안

물리적 보안은 서버, 네트워크 장비, 시설 등에 **물리적으로 접근하지 못하도록 보호하는 방법**입니다.

대표적인 대책:

* 출입 통제
* CCTV
* 경비 시스템
* 생체 인증 출입
* 서버실 잠금
* 화재 감지
* UPS
* 온도 및 습도 관리

```text
외부 사용자
     ↓
출입 통제
     ↓
Server Room
```

대표적인 기술:

* Firewall
* IDS / IPS
* VPN
* 암호화
* 접근 제어
* 인증
* 백신
* DLP
* 로그 분석

```text
Internet
   ↓
Firewall
   ↓
IDS / IPS
   ↓
Server
```

#### 세 가지 보안 비교

| 구분  | 주요 대상      | 예             |
| --- | ---------- | ------------- |
| 관리적 | 사람 / 정책    | 보안 교육, 보안 지침  |
| 물리적 | 시설 / 장비    | CCTV, 출입 통제   |

## 156. 로그 분석

로그(Log)는 운영체제, 서버, 애플리케이션 등이 수행한 작업이나 발생한 이벤트를 **시간 순서대로 기록한 데이터**입니다.

로그 분석을 통해 다음을 확인할 수 있습니다.

* 시스템 장애 원인
* 사용자 접근 기록
* 침입 흔적
* 오류 발생 내역
* 시스템 상태

---

### 1. 커널 로그의 종류

UNIX/Linux 시스템에서는 운영체제와 서비스의 상태를 여러 로그 파일을 통해 확인할 수 있습니다.

대표적인 로그는 다음과 같습니다.

| 로그                  | 설명                 |
| ------------------- | ------------------ |
| `dmesg`             | 부팅 과정 및 커널 메시지     |
| `/var/log/messages` | 시스템의 일반적인 메시지      |
| `/var/log/syslog`   | 시스템 및 서비스 로그       |
| `/var/log/auth.log` | 사용자 인증 및 로그인 관련 로그 |
| `/var/log/secure`   | 인증 및 보안 관련 로그      |
| `/var/log/boot.log` | 시스템 부팅 관련 로그       |
| `/var/log/cron`     | Cron 작업 실행 로그      |

> Linux 배포판에 따라 실제 파일의 종류와 위치에는 차이가 있습니다.

#### dmesg

커널이 생성하는 메시지를 확인합니다.

```bash
dmesg
```

확인 가능한 정보:

* Kernel 초기화
* CPU
* Memory
* Disk
* Network Device
* Driver

---

#### messages

시스템에서 발생하는 일반적인 메시지를 기록합니다.

```text
/var/log/messages
```

주요 내용:

* 시스템 상태
* 서비스 동작
* 일부 커널 메시지
* 시스템 오류

---

#### secure / auth.log

사용자 인증과 보안 이벤트를 기록합니다.

```text
Red Hat 계열
→ /var/log/secure

Debian / Ubuntu 계열
→ /var/log/auth.log
```

기록 내용:

* SSH 로그인
* 로그인 실패
* `sudo` 사용
* 사용자 인증

## 157. 보안 솔루션

### 1. 침입 탐지 시스템(IDS; Intrusion Detection System)

IDS는 네트워크나 시스템을 감시하여 **비정상적인 접근이나 공격을 탐지하고 관리자에게 알리는 보안 시스템**입니다.

```text
Internet
   ↓
Network Traffic
   ↓
  IDS
   ↓
공격 탐지
   ↓
관리자 Alert
```

IDS는 기본적으로 공격을 **탐지(Detection)**하는 역할을 합니다.

#### IDS 종류

##### NIDS(Network-Based IDS)

네트워크 트래픽을 분석합니다.

```text
Network
  ↓
NIDS
  ↓
Traffic 분석
```

##### HIDS(Host-Based IDS)

특정 서버나 시스템 내부의 활동을 분석합니다.

```text
Server
 ↓
HIDS
 ↓
File / Log / Process 분석
```

#### 탐지 방식

| 방식                       | 설명                    |
| ------------------------ | --------------------- |
| 오용 탐지(Misuse Detection)  | 알려진 공격 패턴과 비교         |
| 이상 탐지(Anomaly Detection) | 정상 행동과 다른 비정상적인 활동 탐지 |

IDS와 IPS 비교:

| 구분    | IDS                 | IPS                  |
| ----- | ------------------- | -------------------- |
| 의미    | Intrusion Detection | Intrusion Prevention |
| 주요 역할 | 탐지                  | 탐지 + 차단              |
| 공격 발견 | O                   | O                    |
| 자동 차단 | 일반적으로 X             | O                    |

---

### 2. VPN(Virtual Private Network, 가상 사설망)

VPN은 인터넷과 같은 공용 네트워크를 이용하면서 **암호화된 가상의 전용 통신망을 구성하는 기술**입니다.

```text
사용자
   ↓
Encrypted Tunnel
══════════════════
   Internet
══════════════════
   ↓
Company Network
```

VPN은 **터널링(Tunneling)**과 암호화를 이용해 통신 데이터를 보호합니다.

#### 주요 기능

* 데이터 암호화
* 사용자 인증
* 데이터 무결성 보호
* 안전한 원격 접속
* 공용망을 이용한 사설망 구성

#### VPN의 형태

```text
Remote Access VPN

사용자
 ↓
Internet
 ↓
회사 Network
```

```text
Site-to-Site VPN

회사 A
  ↓
Internet
  ↓
회사 B
```

---

### 3. SSH(Secure Shell)

SSH는 원격 시스템에 **안전하게 접속하고 명령을 실행하기 위한 암호화 네트워크 프로토콜**입니다.

기본적으로 TCP `22`번 포트를 사용합니다.

```text
Client

SSH
 ↓
Encrypted Connection
 ↓

Server
TCP 22
```

#### 주요 기능

* 원격 로그인
* 원격 명령 실행
* 암호화 통신
* 서버 인증
* 사용자 인증
* 파일 전송

SSH 기반 파일 전송 방식:

* SCP
* SFTP

#### Telnet과 SSH 비교

| 구분     | Telnet | SSH |
| ------ | ------ | --- |
| 기본 포트  | 23     | 22  |
| 통신 암호화 | X      | O   |
| 보안성    | 낮음     | 높음  |
| 원격 명령  | O      | O   |

핵심:

```text
Telnet
→ 평문 통신
→ TCP 23

SSH
→ 암호화 통신
→ TCP 22
```
