## 077. 정보 보안 기법

### 1. 방화벽(Firewall)

방화벽은 **외부의 불법 침입으로부터 내부 네트워크를 보호하는 시스템**입니다.

| 특징 | 설명 |
| --- | --- |
| 위치 | 내부 네트워크와 외부 네트워크의 **경계**에 설치합니다. |
| 기능 | 허용된 통신만 통과시키고 나머지는 차단합니다. |
| 로그 | 통과·차단된 접속 기록을 남겨 **추적과 감사**에 활용합니다. |
| **한계** | **외부로부터의 침입은 막을 수 있지만, 내부에서 일어나는 위협은 막을 수 없습니다.** |

#### 왜 방화벽은 내부 위협을 막지 못할까?

방화벽은 **경계선에 서 있는 문지기**와 같습니다.

문을 통과하는 사람은 검사할 수 있지만,  
**이미 안에 있는 사람의 행동은 볼 수 없습니다.**

따라서

- 내부 직원의 정보 유출
- 내부에서 실행된 악성 코드

는 방화벽만으로 막을 수 없고, **접근 권한 관리와 내부 감시**가 별도로 필요합니다.

**프록시 서버(Proxy Server)**

- 내부 네트워크와 인터넷 사이에서 **중계 역할**을 하는 서버입니다.
- 내부 컴퓨터의 **IP 주소를 숨겨** 보안을 강화합니다.
- 자주 요청되는 데이터를 **캐시**에 저장하여 속도를 높입니다.
- 유해 사이트 접근을 차단할 수 있습니다.

---

### 2. 암호화(Encryption)

암호화는 **데이터를 제3자가 알아볼 수 없는 형태로 변환**하는 기술입니다.

| 용어 | 의미 |
| --- | --- |
| 평문(Plain Text) | 암호화하기 전의 원래 데이터 |
| 암호문(Cipher Text) | 암호화된 데이터 |
| **암호화** | 평문 → 암호문 |
| **복호화** | 암호문 → 평문 |
| 키(Key) | 암호화와 복호화에 사용하는 값 |

---

### 3. 비밀키 암호화(대칭키 암호화)

- **암호화 키와 복호화 키가 동일**합니다.
- 대표 알고리즘 : **DES**, AES, SEED

| 장점 | 단점 |
| --- | --- |
| 암호화·복호화 **속도가 빠릅니다.** | **키를 안전하게 전달하기 어렵습니다.** |
| 알고리즘이 단순합니다. | 사용자가 많아지면 **키의 개수가 급격히 늘어납니다.** |

**필요한 키의 개수** : 사용자가 n명일 때 **n(n-1)/2** 개

#### 왜 키 관리가 어려울까?

같은 키를 사용하려면, 상대에게 **키를 미리 전달**해야 합니다.

그런데 그 전달 과정에서 키가 유출되면 암호화 자체가 무의미해집니다.  
"안전하게 전달하기 위한 암호"인데, 그 열쇠를 안전하게 전달할 방법이 필요한 **순환 문제**가 생깁니다.

또한 사용자가 10명이면 45개, 100명이면 4,950개의 키가 필요하여  
**관리 자체가 불가능**해집니다.

---

### 4. 공개키 암호화(비대칭키 암호화)

- **암호화 키(공개키)와 복호화 키(개인키)가 서로 다릅니다.**
- **공개키는 모두에게 공개**하고, **개인키는 본인만 보관**합니다.
- 대표 알고리즘 : **RSA**

| 장점 | 단점 |
| --- | --- |
| **키 분배가 쉽습니다.** (공개키는 공개해도 무방) | 암호화·복호화 **속도가 느립니다.** |
| 사용자가 많아도 키 관리가 간단합니다. | 알고리즘이 복잡합니다. |
| **전자 서명**이 가능합니다. | |

**필요한 키의 개수** : 사용자가 n명일 때 **2n** 개

#### 왜 공개키를 공개해도 안전할까?

공개키로 암호화한 데이터는 **오직 짝이 되는 개인키로만 복호화**할 수 있습니다.

공개키를 아는 사람은 **암호를 만들 수는 있어도 풀 수는 없습니다.**

우편함에 비유하면

- **공개키** : 우편함 투입구 → 누구나 편지를 넣을 수 있음
- **개인키** : 우편함 열쇠 → 주인만 꺼내 볼 수 있음

이 구조 덕분에 **키를 미리 안전하게 전달할 필요가 없어집니다.**

**비밀키 vs 공개키 비교**

| 구분 | 비밀키(대칭키) | 공개키(비대칭키) |
| --- | --- | --- |
| 키 | **동일한 키** | **서로 다른 키 쌍** |
| 속도 | **빠름** | **느림** |
| 키 개수 | **n(n-1)/2** | **2n** |
| 키 분배 | **어려움** | **쉬움** |
| 전자 서명 | 불가능 | **가능** |
| 알고리즘 | DES, AES, SEED | **RSA** |

#### 실제로는 두 방식을 함께 사용합니다

공개키는 안전하지만 느리고, 비밀키는 빠르지만 키 전달이 어렵습니다.

그래서 실제 통신(예: HTTPS)에서는

1. **공개키 방식으로 비밀키를 안전하게 전달**하고
2. 이후의 실제 데이터는 **빠른 비밀키 방식으로 암호화**합니다.

두 방식의 장점만 취한 구조이며, 이를 **하이브리드 암호화**라고 합니다.

### 5. 전자 서명(Digital Signature)

- 문서의 **작성자를 확인**하고 **내용이 변경되지 않았음을 증명**하는 기술입니다.
- **자신의 개인키로 서명**하고, **상대는 공개키로 검증**합니다.
- 기밀성보다는 **인증, 무결성, 부인 방지**를 목적으로 합니다.

#### 왜 전자 서명은 암호화와 키 사용 순서가 반대일까?

목적이 다르기 때문입니다.

| 목적 | 사용하는 키 | 이유 |
| --- | --- | --- |
| **비밀 전송** | 상대의 **공개키**로 암호화 | 상대만 열어 볼 수 있어야 하므로 |
| **전자 서명** | 자신의 **개인키**로 서명 | **나만 만들 수 있어야** 하므로 |

전자 서명은 내용을 감추는 것이 목적이 아니라,  
**"이것은 분명히 내가 작성했다"는 것을 누구나 확인할 수 있게** 하는 것이 목적입니다.

개인키는 본인만 가지고 있으므로, 공개키로 검증이 성공했다는 것은  
**해당 개인키 소유자가 서명했다는 증거**가 됩니다.

### 6. 그 밖의 보안 기술

| 기술 | 설명 |
| --- | --- |
| **SSL / TLS** | 웹 통신을 암호화하는 프로토콜입니다. **HTTPS**에 사용됩니다. |
| **VPN(가상 사설망)** | 공중망에 **암호화된 터널**을 만들어 전용선처럼 안전하게 사용합니다. |
| **침입 탐지 시스템(IDS)** | 비정상적인 접근을 **탐지하여 알립니다.** |
| **침입 방지 시스템(IPS)** | 탐지에 그치지 않고 **즉시 차단**합니다. |
| **인증서 / 공인인증서** | 신뢰할 수 있는 기관이 발급하여 신원을 보증합니다. |
| **OTP(일회용 비밀번호)** | 매번 새로운 비밀번호를 생성하여 재사용을 막습니다. |
| **생체 인식** | 지문, 홍채, 얼굴 등 신체 특징으로 인증합니다. |
| **해시 함수** | 데이터를 고정 길이의 값으로 변환하여 **무결성 확인**에 사용합니다. |

#### IDS vs IPS

| 구분 | IDS | IPS |
| --- | --- | --- |
| 역할 | **탐지 후 경고** | **탐지 후 차단** |
| 위치 | 트래픽을 복사해서 감시 | 트래픽 경로 위에 위치 |
| 비유 | **CCTV** | **경비원** |

#### 왜 OTP가 안전할까?

일반 비밀번호는 유출되면 **계속 사용될 수 있습니다.**

OTP는 **30초 정도만 유효한 일회용 번호**이므로,  
누군가 가로채더라도 사용할 수 있는 시간이 거의 없습니다.

즉, OTP는 **유출을 막는 기술이 아니라, 유출되어도 쓸모없게 만드는 기술**입니다.

#### 왜 해시 함수로 무결성을 확인할 수 있을까?

해시 함수는 입력이 **조금만 달라져도 결과값이 완전히 달라집니다.**

파일을 보낼 때 해시값을 함께 전달하면,  
받는 쪽에서 다시 계산한 해시값과 비교하여 **파일이 변조되었는지 즉시 확인**할 수 있습니다.

또한 해시는 **되돌릴 수 없는(단방향) 함수**이므로,  
비밀번호를 원문 대신 해시값으로 저장하면 **유출되어도 원래 비밀번호를 알 수 없습니다.**

---

### 한 줄 정리

**방화벽은 외부 침입만 차단(내부 위협은 불가)** 하고,  
**비밀키는 빠르지만 키 분배가 어렵고(n(n-1)/2개), 공개키는 느리지만 키 분배가 쉬우며(2n개) 전자 서명이 가능**하고,  
**전자 서명은 자신의 개인키로 서명하고 상대는 공개키로 검증**합니다.
