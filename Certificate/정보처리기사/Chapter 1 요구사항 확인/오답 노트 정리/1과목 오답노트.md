3. **③ 맞음** — 변경 용이성은 시스템을 **쉽게 수정하거나 확장할 수 있는 정도**를 의미한다.
4. **④ 맞음** — 사용성은 사용자가 시스템을 **쉽게 배우고 편리하게 사용할 수 있는 정도**를 의미한다.

1. **① 연계 서버** — 서로 다른 시스템 간의 데이터 연계를 지원하는 서버이다.
2. **② 중계 서버** — 송신 시스템과 수신 시스템 사이에서 데이터를 전달하고 중계하는 서버이다.
3. **③ 송신 시스템 → 정답** — DB나 애플리케이션의 데이터를 연계 테이블 또는 파일 형태로 만들어 **전송하는 시스템**이다.
4. **④ 수신 시스템** — 전달받은 데이터를 변환·저장하거나 애플리케이션에서 사용할 수 있도록 처리하는 시스템이다.


![alt text](image-27.png)

1. **① 클라이언트-서버 구조** — 클라이언트가 서버에 서비스를 요청하고 서버가 처리 결과를 반환하는 구조이다.
2. **② 계층 구조** — 시스템을 여러 계층으로 나누고 각 계층이 정해진 역할을 수행하는 구조이다.
3. **③ MVC 구조** — Model, View, Controller로 역할을 분리하여 구성하는 구조이다.
4. **④ 파이프 필터 구조 → 정답** — 한 서브시스템의 **출력 결과가 다음 서브시스템의 입력이 되어 반복적으로 처리**되는 구조이다.

1. **① 지원함** — 상위 CASE는 모델들 사이의 **모순이나 불일치를 검사**할 수 있다.
2. **② 지원하지 않음 → 정답** — **전체 소스코드 생성**은 주로 하위 CASE가 담당한다.

4. **④ 지원함** — 상위 CASE는 분석·설계 단계에서 **자료흐름도(DFD)를 작성**할 수 있다.

1. **① 맞음** — 요구사항 변경에 따른 **비용과 효과를 분석**하는 데 필요하다.
2. **② 틀림 → 정답** — 기존 시스템과 신규 시스템의 **성능 비교는 요구사항 관리 도구의 주요 목적이 아니다.**
3. **③ 맞음** — 요구사항이 언제, 어떻게 변경되었는지 **추적**할 수 있다.
4. **④ 맞음** — 요구사항 변경이 다른 기능이나 시스템에 미치는 **영향을 평가**할 수 있다.
