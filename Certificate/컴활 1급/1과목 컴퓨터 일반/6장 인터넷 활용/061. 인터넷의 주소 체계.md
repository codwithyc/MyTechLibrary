## 061. 인터넷의 주소 체계

### 1. IP 주소(IP Address)

IP 주소는 **인터넷에 연결된 컴퓨터를 구분하기 위한 고유한 주소**입니다.

**IPv4**

- **32비트**로 구성되며, **8비트씩 4개 부분**으로 나누어 **점(.)** 으로 구분합니다.
- 각 부분은 **0~255** 사이의 10진수로 표현합니다. (예: `192.168.0.1`)
- 이론상 약 **43억 개(2³²)** 의 주소를 표현할 수 있습니다.

**IPv6**

- **128비트**로 구성되며, **16비트씩 8개 부분**으로 나누어 **콜론(:)** 으로 구분합니다.
- 각 부분은 **16진수**로 표현합니다. (예: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`)
- IPv4의 **주소 부족 문제를 해결**하기 위해 등장했습니다.
- **인증성, 기밀성, 데이터 무결성**을 지원하여 보안이 강화되었습니다.
- 주소 자동 설정 기능을 지원하며, **실시간 흐름 제어**로 품질 보장이 쉽습니다.

#### 왜 IPv6가 필요했을까?

IPv4의 43억 개는 처음에는 충분해 보였습니다.

그러나 컴퓨터뿐 아니라 **스마트폰, 태블릿, 가전제품, 자동차, 센서**까지 인터넷에 연결되면서  
주소가 부족해졌습니다.

IPv6는 128비트를 사용하므로 **2¹²⁸개**라는 사실상 무한에 가까운 주소를 제공합니다.

또한 IPv4 시절에는 보안이 나중에 덧붙여진 기능이었지만,  
IPv6는 **설계 단계부터 보안(IPsec)을 포함**했다는 점도 중요한 차이입니다.

**IPv4 vs IPv6 비교**

| 구분 | IPv4 | IPv6 |
| --- | --- | --- |
| 길이 | 32비트 | **128비트** |
| 구분 단위 | 8비트씩 4부분 | 16비트씩 8부분 |
| 구분 기호 | **점(.)** | **콜론(:)** |
| 표기 진법 | 10진수 | **16진수** |
| 주소 클래스 | A~E 클래스 | 유니캐스트 / 멀티캐스트 / **애니캐스트** |
| 보안 | 별도 기능 필요 | **자체 지원** |

> IPv6에는 **브로드캐스트가 없고, 대신 애니캐스트가 있습니다.** 자주 출제되는 포인트입니다.

### 2. IPv4의 클래스

| 클래스 | 용도 | 첫 번째 옥텟 범위 |
| --- | --- | --- |
| **A 클래스** | 대규모 네트워크 | 0 ~ 127 |
| **B 클래스** | 중규모 네트워크 | 128 ~ 191 |
| **C 클래스** | 소규모 네트워크 | 192 ~ 223 |
| **D 클래스** | **멀티캐스트용** | 224 ~ 239 |
| **E 클래스** | 연구·예약용 | 240 ~ 255 |

**전송 방식**

| 방식 | 설명 |
| --- | --- |
| **유니캐스트(Unicast)** | **1 대 1** 전송 |
| **멀티캐스트(Multicast)** | **1 대 다수(특정 그룹)** 전송 |
| **브로드캐스트(Broadcast)** | **1 대 전체** 전송 |
| **애니캐스트(Anycast)** | 그룹 중 **가장 가까운 하나**에게 전송 (IPv6) |

#### 왜 애니캐스트가 IPv6에서 새로 생겼을까?

같은 내용을 제공하는 서버가 세계 여러 곳에 있을 때,  
사용자는 **가장 가까운 서버**에 접속하는 것이 가장 빠릅니다.

애니캐스트는 여러 서버가 같은 주소를 공유하고,  
네트워크가 **자동으로 가장 가까운 서버로 안내**하는 방식입니다.

사용자는 아무것도 몰라도 최적의 서버에 연결되므로,  
**속도와 부하 분산을 동시에 해결**할 수 있습니다.

### 3. 도메인 네임(Domain Name)

숫자로 된 IP 주소를 **사람이 기억하기 쉬운 문자 형태**로 바꾼 것입니다.

**구성 (뒤에서부터 큰 단위)**

`www.example.co.kr`

| 부분 | 의미 |
| --- | --- |
| `www` | 호스트(서버) 이름 |
| `example` | 기관 이름 |
| `co` | 기관의 종류 |
| `kr` | 국가 코드 |

**기관 종류**

| 코드 | 의미 |
| --- | --- |
| `com` / `co` | 영리 기관(회사) |
| `org` / `or` | 비영리 기관 |
| `net` / `ne` | 네트워크 관련 기관 |
| `gov` / `go` | 정부 기관 |
| `edu` / `ac` | 교육 기관 |
| `mil` | 군사 기관 |
| `int` | 국제 기구 |

> 미국은 국가 코드를 생략하며, `com`, `org`, `net` 처럼 3자리를 사용합니다.  
> 그 외 국가는 `co.kr`, `or.kr` 처럼 2자리 + 국가 코드를 사용합니다.

---

### 4. DNS(Domain Name System)

**도메인 네임을 IP 주소로 변환해 주는 시스템**입니다.

- 도메인 네임을 IP 주소로 바꾸는 것을 **네임 서비스**라고 합니다.
- 이 역할을 하는 서버를 **DNS 서버(네임 서버)** 라고 합니다.

#### 왜 DNS가 필요할까?

컴퓨터는 **IP 주소로만 통신**할 수 있습니다.  
반면 사람은 숫자보다 **이름을 훨씬 잘 기억**합니다.

DNS는 이 둘 사이를 연결하는 **전화번호부** 역할을 합니다.

또한 서버를 이전하여 IP 주소가 바뀌더라도,  
**DNS에 등록된 주소만 수정하면** 사용자는 같은 도메인으로 접속할 수 있습니다.

즉, DNS는 편의성뿐 아니라 **주소 변경에 대한 유연성**도 제공합니다.

### 5. URL(Uniform Resource Locator)

인터넷상의 자원 위치를 나타내는 **표준 주소 체계**입니다.

**형식** : `프로토콜://호스트주소[:포트번호][/경로/파일명]`

예 : `https://www.example.com:443/docs/index.html`

| 구성 | 설명 |
| --- | --- |
| 프로토콜 | `http`, `https`, `ftp`, `mailto`, `telnet`, `news` 등 |
| 호스트 주소 | 도메인 네임 또는 IP 주소 |
| 포트 번호 | 생략하면 기본 포트가 사용됩니다. |
| 경로 / 파일명 | 서버 안에서의 위치와 파일 이름 |

**주요 프로토콜의 기본 포트 번호**

| 프로토콜 | 포트 |
| --- | --- |
| **HTTP** | **80** |
| **HTTPS** | **443** |
| **FTP** | **21** |
| **TELNET** | **23** |
| **SMTP** | **25** |
| **POP3** | **110** |
| **DNS** | **53** |
| NEWS | 119 |

#### 왜 포트 번호가 필요할까?

IP 주소는 **어느 컴퓨터인지**를 알려 주지만,  
그 컴퓨터 안에서 **어떤 서비스와 통신할지**는 알려 주지 않습니다.

한 대의 서버가 웹 서비스, 메일 서비스, FTP를 동시에 제공할 수 있기 때문입니다.

포트 번호는 **컴퓨터 안의 서비스를 구분하는 번호**입니다.

주소에 비유하면

- **IP 주소** : 건물 주소
- **포트 번호** : 그 건물의 호수

이라고 이해하면 됩니다.

---

### 한 줄 정리

**IPv4는 32비트·점(.)·10진수**, **IPv6는 128비트·콜론(:)·16진수**이며,  
IPv6에는 **브로드캐스트가 없고 애니캐스트가 있습니다.**  
**DNS는 도메인을 IP로 변환**하고, **HTTP는 80·HTTPS는 443·FTP는 21·TELNET은 23번 포트**를 사용합니다.
