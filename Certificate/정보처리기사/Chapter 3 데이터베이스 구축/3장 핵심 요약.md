## 079. SQL의 개념
### 1. DDL(Data Definition Language, 데이터 정의어)

DDL은 **데이터베이스의 구조를 정의하거나 변경, 삭제하기 위해 사용하는 언어**이다.

테이블, 뷰, 인덱스 등의 **스키마 구조를 정의하는 명령어**가 포함된다.

| 명령어          | 의미    | 설명                   |
| ------------ | ----- | -------------------- |
| **CREATE**   | 생성    | 데이터베이스, 테이블, 뷰 등을 생성 |
| **ALTER**    | 변경    | 기존 데이터베이스 객체의 구조를 변경 |
| **DROP**     | 삭제    | 데이터베이스 객체를 삭제        |
| **TRUNCATE** | 초기화   | 테이블의 모든 데이터를 제거      |
| **RENAME**   | 이름 변경 | 데이터베이스 객체의 이름을 변경    |

#### 예시

```sql
CREATE TABLE student (
    id INT,
    name VARCHAR(50)
);
```

```sql
ALTER TABLE student
ADD department VARCHAR(50);
```

```sql
DROP TABLE student;
```

> **DDL = 데이터베이스의 구조를 정의하는 언어**

---

### 2. DML(Data Manipulation Language, 데이터 조작어)

DML은 **데이터베이스에 저장된 데이터를 조회, 삽입, 수정, 삭제하기 위해 사용하는 언어**이다.

| 명령어        | 의미 | 설명           |
| ---------- | -- | ------------ |
| **SELECT** | 조회 | 테이블의 데이터를 검색 |
| **INSERT** | 삽입 | 새로운 데이터를 추가  |
| **UPDATE** | 수정 | 기존 데이터를 변경   |
| **DELETE** | 삭제 | 기존 데이터를 삭제   |

#### 예시

```sql
SELECT *
FROM student;
```

```sql
INSERT INTO student (id, name)
VALUES (1, '홍길동');
```

```sql
UPDATE student
SET name = '김철수'
WHERE id = 1;
```

```sql
DELETE FROM student
WHERE id = 1;
```

#### DML의 구분

| 구분           | 의미                            |
| ------------ | ----------------------------- |
| **절차적 DML**  | 사용자가 데이터에 접근하는 절차까지 직접 지정     |
| **비절차적 DML** | 원하는 데이터만 명시하고 접근 방법은 DBMS가 결정 |

SQL은 대표적인 **비절차적 언어**이다.

> **DML = 실제 데이터를 조회하고 변경하는 언어**

---

### 3. DCL(Data Control Language, 데이터 제어어)

DCL은 **데이터베이스 사용자의 권한을 부여하거나 회수하고, 데이터 접근을 제어하기 위해 사용하는 언어**이다.

| 명령어        | 의미    | 설명                     |
| ---------- | ----- | ---------------------- |
| **GRANT**  | 권한 부여 | 사용자에게 특정 데이터베이스 권한을 부여 |
| **REVOKE** | 권한 회수 | 사용자에게 부여된 권한을 회수       |

#### 예시

```sql
GRANT SELECT, INSERT
ON student
TO user1;
```

```sql
REVOKE INSERT
ON student
FROM user1;
```

### 트랜잭션 관련 명령어

교재나 시험 범위에 따라 다음 명령어도 DCL에 포함하여 분류하는 경우가 있다.

| 명령어           | 의미  | 설명                         |
| ------------- | --- | -------------------------- |
| **COMMIT**    | 확정  | 트랜잭션의 변경 내용을 데이터베이스에 영구 반영 |
| **ROLLBACK**  | 취소  | 트랜잭션의 변경 내용을 이전 상태로 되돌림    |
| **SAVEPOINT** | 저장점 | 트랜잭션 내에서 특정 복구 지점을 설정      |

```sql
COMMIT;
```

```sql
ROLLBACK;
```

> 엄밀하게는 `COMMIT`, `ROLLBACK`, `SAVEPOINT`를 **TCL(Transaction Control Language)** 로 별도 분류하기도 한다.

---

### DDL · DML · DCL 비교

| 구분      | 역할        | 주요 명령어                         |
| ------- | --------- | ------------------------------ |
| **DDL** | 데이터 구조 정의 | CREATE, ALTER, DROP, TRUNCATE  |
| **DML** | 데이터 조회·조작 | SELECT, INSERT, UPDATE, DELETE |
| **DCL** | 사용자 권한 제어 | GRANT, REVOKE                  |

```text
DDL → 구조를 만든다
DML → 데이터를 다룬다
DCL → 권한을 관리한다
```

시험 대비로는 **DDL = 구조, DML = 데이터, DCL = 권한**으로 구분해서 기억하면 됩니다.


## 080. DDL
### 1. CREATE TABLE

`CREATE TABLE`은 **새로운 테이블을 생성하는 DDL 명령어**이다.

테이블 이름과 함께 각 속성(Column)의 이름, 데이터 타입, 제약조건 등을 정의한다.

#### 기본 형식

```sql
CREATE TABLE 테이블명 (
    속성명 데이터타입 [제약조건],
    속성명 데이터타입 [제약조건],
    ...
);
```

#### 예시

```sql
CREATE TABLE STUDENT (
    STUDENT_ID INT PRIMARY KEY,
    NAME VARCHAR(50) NOT NULL,
    DEPARTMENT VARCHAR(50),
    AGE INT
);
```

| 구성 요소         | 설명            |
| ------------- | ------------- |
| `STUDENT`     | 생성할 테이블 이름    |
| `STUDENT_ID`  | 속성(Column) 이름 |
| `INT`         | 정수형 데이터 타입    |
| `VARCHAR(50)` | 최대 50자의 문자열   |
| `PRIMARY KEY` | 기본키 지정        |
| `NOT NULL`    | NULL 값 입력 금지  |

#### 주요 제약조건

| 제약조건          | 의미                    |
| ------------- | --------------------- |
| `PRIMARY KEY` | 각 행을 유일하게 식별하는 기본키    |
| `FOREIGN KEY` | 다른 테이블의 기본키를 참조하는 외래키 |
| `UNIQUE`      | 중복된 값의 입력을 방지         |
| `NOT NULL`    | NULL 값 입력을 허용하지 않음    |
| `CHECK`       | 지정한 조건을 만족하는 값만 허용    |
| `DEFAULT`     | 값이 입력되지 않았을 때 기본값을 사용 |

예를 들어 외래키까지 포함하면 다음과 같이 작성할 수 있다.

```sql
CREATE TABLE STUDENT (
    STUDENT_ID INT PRIMARY KEY,
    NAME VARCHAR(50) NOT NULL,
    DEPT_ID INT,
    FOREIGN KEY (DEPT_ID)
        REFERENCES DEPARTMENT(DEPT_ID)
);
```

> **CREATE TABLE = 테이블의 구조를 새롭게 정의하고 생성**

---

### 2. ALTER TABLE

`ALTER TABLE`은 **이미 존재하는 테이블의 구조를 변경하는 DDL 명령어**이다.

속성을 추가하거나 삭제하고, 데이터 타입이나 제약조건 등을 변경할 때 사용한다.

| 작업                 | 의미                |
| ------------------ | ----------------- |
| `ADD`              | 새로운 속성 또는 제약조건 추가 |
| `ALTER` / `MODIFY` | 기존 속성의 정의 변경      |
| `DROP`             | 속성 또는 제약조건 삭제     |
| `RENAME`           | 테이블 또는 속성 이름 변경   |

#### 속성 추가

```sql
ALTER TABLE STUDENT
ADD EMAIL VARCHAR(100);
```

```text
변경 전
STUDENT_ID | NAME | DEPARTMENT

변경 후
STUDENT_ID | NAME | DEPARTMENT | EMAIL
```

#### 속성 변경

DBMS에 따라 문법이 다를 수 있다.

MySQL:

```sql
ALTER TABLE STUDENT
MODIFY EMAIL VARCHAR(200);
```

표준 SQL 계열:

```sql
ALTER TABLE STUDENT
ALTER COLUMN EMAIL VARCHAR(200);
```

#### 속성 삭제

```sql
ALTER TABLE STUDENT
DROP COLUMN EMAIL;
```

#### 제약조건 추가

```sql
ALTER TABLE STUDUDENT
ADD CONSTRAINT PK_STUDENT
PRIMARY KEY (STUDENT_ID);
```

`STUDUDENT`는 오타가 될 수 있으므로 실제로는 다음처럼 작성한다.

```sql
ALTER TABLE STUDENT
ADD CONSTRAINT PK_STUDENT
PRIMARY KEY (STUDENT_ID);
```

#### 제약조건 삭제

```sql
ALTER TABLE STUDENT
DROP CONSTRAINT PK_STUDENT;
```

> **ALTER TABLE = 기존 테이블의 구조를 변경**

---

### 3. DROP

`DROP`은 **데이터베이스에 존재하는 객체를 완전히 삭제하는 DDL 명령어**이다.

테이블을 삭제할 때는 `DROP TABLE`을 사용한다.

#### 기본 형식

```sql
DROP TABLE 테이블명;
```

#### 예시

```sql
DROP TABLE STUDENT;
```

실행하면 `STUDENT` 테이블의 **데이터뿐만 아니라 테이블 구조 자체도 삭제**된다.

| 명령어          | 데이터 삭제 | 테이블 구조 삭제 |
| ------------ | -----: | --------: |
| `DELETE`     |      O |         X |
| `TRUNCATE`   |      O |         X |
| `DROP TABLE` |      O |         O |

#### DELETE와 DROP 차이

```text
DELETE
→ 테이블은 유지
→ 데이터만 삭제

DROP
→ 데이터 삭제
→ 테이블 구조까지 삭제
```

예:

```sql
DELETE FROM STUDENT;
```

실행 후:

```text
STUDENT 테이블 존재 O
데이터 없음
```

반면,

```sql
DROP TABLE STUDENT;
```

실행 후:

```text
STUDENT 테이블 존재 X
데이터 존재 X
```

---

### CREATE · ALTER · DROP 비교

| 명령어      | 역할          | 예시             |
| -------- | ----------- | -------------- |
| `CREATE` | 새로운 객체 생성   | `CREATE TABLE` |
| `ALTER`  | 기존 객체 구조 변경 | `ALTER TABLE`  |
| `DROP`   | 객체 자체를 삭제   | `DROP TABLE`   |

```text
CREATE → 만든다
ALTER  → 바꾼다
DROP   → 없앤다
```

세 명령어 모두 **DDL(Data Definition Language, 데이터 정의어)** 에 속한다.


## 081. DCL
### 1. GRANT / REVOKE

`GRANT`와 `REVOKE`는 **데이터베이스 사용자에게 권한을 부여하거나 회수하기 위한 DCL(Data Control Language) 명령어**이다.

| 명령어      | 의미    | 설명                        |
| -------- | ----- | ------------------------- |
| `GRANT`  | 권한 부여 | 사용자에게 특정 객체에 대한 접근 권한을 부여 |
| `REVOKE` | 권한 회수 | 사용자에게 부여된 권한을 제거          |

#### GRANT 기본 형식

```sql
GRANT 권한
ON 객체
TO 사용자;
```

예를 들어 `user1` 사용자에게 `STUDENT` 테이블의 조회 권한을 부여하려면 다음과 같이 작성한다.

```sql
GRANT SELECT
ON STUDENT
TO user1;
```

여러 권한을 동시에 부여할 수도 있다.

```sql
GRANT SELECT, INSERT, UPDATE
ON STUDENT
TO user1;
```

#### 주요 권한

| 권한       | 의미       |
| -------- | -------- |
| `SELECT` | 데이터 조회   |
| `INSERT` | 데이터 삽입   |
| `UPDATE` | 데이터 수정   |
| `DELETE` | 데이터 삭제   |
| `ALL`    | 모든 권한 부여 |

#### REVOKE 기본 형식

```sql
REVOKE 권한
ON 객체
FROM 사용자;
```

예를 들어 `user1`에게 부여한 `UPDATE` 권한을 회수하려면 다음과 같이 작성한다.

```sql
REVOKE UPDATE
ON STUDENT
FROM user1;
```

여러 권한을 동시에 회수할 수도 있다.

```sql
REVOKE INSERT, UPDATE
ON STUDENT
FROM user1;
```

### GRANT / REVOKE 비교

| 구분    | GRANT     | REVOKE    |
| ----- | --------- | --------- |
| 역할    | 권한 부여     | 권한 회수     |
| 대상    | 사용자 또는 역할 | 사용자 또는 역할 |
| 사용 목적 | 접근 허용     | 접근 제한     |
| 분류    | DCL       | DCL       |

```text
GRANT  → 권한을 준다
REVOKE → 권한을 빼앗는다
```

---

### 2. ROLLBACK

`ROLLBACK`은 **현재 트랜잭션에서 수행한 변경 내용을 취소하고 이전 상태로 되돌리는 명령어**이다.

보통 `INSERT`, `UPDATE`, `DELETE`와 같은 데이터 변경 작업을 취소할 때 사용한다.

#### 기본 형식

```sql
ROLLBACK;
```

예를 들어 다음과 같이 데이터를 수정했다고 가정한다.

```sql
UPDATE STUDENT
SET NAME = '김철수'
WHERE STUDENT_ID = 1;
```

아직 `COMMIT`을 수행하지 않은 상태에서 다음 명령어를 실행하면,

```sql
ROLLBACK;
```

변경 전 상태로 되돌아간다.

```text
변경 전
STUDENT_ID = 1
NAME = 홍길동

UPDATE 실행
↓
NAME = 김철수

ROLLBACK 실행
↓
NAME = 홍길동
```

### COMMIT과 ROLLBACK 비교

| 명령어        | 의미      | 결과               |
| ---------- | ------- | ---------------- |
| `COMMIT`   | 트랜잭션 확정 | 변경 내용을 영구 저장     |
| `ROLLBACK` | 트랜잭션 취소 | 변경 내용을 이전 상태로 복구 |

```text
트랜잭션 시작
      ↓
 INSERT / UPDATE / DELETE
      ↓
   ┌──┴──┐
   ↓     ↓
COMMIT  ROLLBACK
   ↓     ↓
확정    취소
```

### SAVEPOINT와 함께 사용하는 경우

`SAVEPOINT`를 사용하면 트랜잭션 전체가 아니라 **특정 시점까지만 되돌릴 수 있다.**

```sql
SAVEPOINT SP1;
```

이후 작업을 수행한 다음,

```sql
ROLLBACK TO SP1;
```

을 실행하면 `SP1` 이후의 작업만 취소된다.

| 명령어           | 역할             |
| ------------- | -------------- |
| `SAVEPOINT`   | 트랜잭션 중간 저장점 설정 |
| `ROLLBACK`    | 트랜잭션 전체 취소     |
| `ROLLBACK TO` | 특정 저장점까지 취소    |
| `COMMIT`      | 변경 내용 최종 확정    |

> 핵심은 **GRANT = 권한 부여, REVOKE = 권한 회수, ROLLBACK = 변경 내용 취소**로 기억하면 됩니다.


## 082. DML
### 1. 삽입문(INSERT INTO ~)

`INSERT`는 **테이블에 새로운 행(Row, Tuple)을 추가하는 DML(Data Manipulation Language) 명령어**이다.

#### 기본 형식

```sql
INSERT INTO 테이블명 (속성명1, 속성명2, ...)
VALUES (값1, 값2, ...);
```

#### 예시

```sql
INSERT INTO STUDENT (STUDENT_ID, NAME, DEPARTMENT)
VALUES (1, '홍길동', '컴퓨터공학과');
```

| STUDENT_ID | NAME | DEPARTMENT |
| ---------: | ---- | ---------- |
|          1 | 홍길동  | 컴퓨터공학과     |

모든 속성에 값을 입력하는 경우 속성명을 생략할 수도 있다.

```sql
INSERT INTO STUDENT
VALUES (2, '김철수', '전자공학과');
```

단, 이 경우에는 **테이블에 정의된 속성 순서와 값의 순서가 일치해야 한다.**

#### 다른 테이블의 데이터를 삽입하는 경우

```sql
INSERT INTO STUDENT_BACKUP
SELECT *
FROM STUDENT;
```

> **INSERT = 새로운 데이터를 추가**

---

### 2. 삭제문(DELETE FROM ~)

`DELETE`는 **테이블에서 조건을 만족하는 행(Row)을 삭제하는 DML 명령어**이다.

#### 기본 형식

```sql
DELETE FROM 테이블명
WHERE 조건;
```

#### 예시

```sql
DELETE FROM STUDENT
WHERE STUDENT_ID = 1;
```

실행 전:

| STUDENT_ID | NAME | DEPARTMENT |
| ---------: | ---- | ---------- |
|          1 | 홍길동  | 컴퓨터공학과     |
|          2 | 김철수  | 전자공학과      |

실행 후:

| STUDENT_ID | NAME | DEPARTMENT |
| ---------: | ---- | ---------- |
|          2 | 김철수  | 전자공학과      |

#### 여러 조건을 사용하는 경우

```sql
DELETE FROM STUDENT
WHERE DEPARTMENT = '컴퓨터공학과'
  AND STUDENT_ID = 1;
```

#### 모든 데이터를 삭제하는 경우

```sql
DELETE FROM STUDENT;
```

`WHERE` 조건을 작성하지 않으면 **테이블의 모든 행이 삭제**된다.

```text
DELETE FROM STUDENT
        ↓
모든 데이터 삭제
        ↓
테이블 구조는 유지
```

> **DELETE = 기존 데이터를 삭제**

---

### 3. 갱신문(UPDATE SET ~)

`UPDATE`는 **테이블에 저장되어 있는 기존 데이터를 변경하는 DML 명령어**이다.

#### 기본 형식

```sql
UPDATE 테이블명
SET 속성명 = 값
WHERE 조건;
```

#### 예시

```sql
UPDATE STUDENT
SET NAME = '이영희'
WHERE STUDENT_ID = 1;
```

실행 전:

| STUDENT_ID | NAME | DEPARTMENT |
| ---------: | ---- | ---------- |
|          1 | 홍길동  | 컴퓨터공학과     |

실행 후:

| STUDENT_ID | NAME | DEPARTMENT |
| ---------: | ---- | ---------- |
|          1 | 이영희  | 컴퓨터공학과     |

#### 여러 속성을 동시에 수정하는 경우

```sql
UPDATE STUDENT
SET NAME = '이영희',
    DEPARTMENT = '소프트웨어학과'
WHERE STUDENT_ID = 1;
```

#### 조건에 해당하는 여러 행 수정

```sql
UPDATE STUDENT
SET DEPARTMENT = '소프트웨어학과'
WHERE DEPARTMENT = '컴퓨터공학과';
```

`WHERE`를 생략하면 **테이블의 모든 행이 수정**되므로 주의해야 한다.

```sql
UPDATE STUDENT
SET DEPARTMENT = '소프트웨어학과';
```

```text
WHERE 있음 → 조건에 맞는 데이터만 수정
WHERE 없음 → 모든 데이터 수정
```

> **UPDATE = 기존 데이터를 변경**

---

### INSERT · DELETE · UPDATE 비교

| 명령어      | 역할     | 주요 절             |
| -------- | ------ | ---------------- |
| `INSERT` | 데이터 삽입 | `INTO`, `VALUES` |
| `DELETE` | 데이터 삭제 | `FROM`, `WHERE`  |
| `UPDATE` | 데이터 수정 | `SET`, `WHERE`   |

```text
INSERT → 넣는다
DELETE → 지운다
UPDATE → 바꾼다
```

세 명령어 모두 **DML(Data Manipulation Language, 데이터 조작어)** 에 해당합니다.

## 083. DML-SELECT-1
### 1. 일반형식 및 기본 검색

`SELECT`문은 **테이블에서 원하는 데이터를 검색하는 DML 명령어**이다.

#### 기본 형식

```sql
SELECT 속성명
FROM 테이블명;
```

예를 들어 `STUDENT` 테이블의 모든 데이터를 조회하려면 다음과 같이 작성한다.

```sql
SELECT *
FROM STUDENT;
```

특정 속성만 조회할 수도 있다.

```sql
SELECT NAME, DEPARTMENT
FROM STUDENT;
```

| 구문         | 의미               |
| ---------- | ---------------- |
| `SELECT`   | 조회할 속성을 지정       |
| `FROM`     | 데이터를 조회할 테이블을 지정 |
| `*`        | 모든 속성을 조회        |
| `DISTINCT` | 중복된 값을 제거하여 조회   |

#### DISTINCT

```sql
SELECT DISTINCT DEPARTMENT
FROM STUDENT;
```

`DEPARTMENT`에 같은 학과가 여러 번 존재하더라도 한 번씩만 출력한다.

> **SELECT = 무엇을 조회할지, FROM = 어디에서 조회할지**

---

### 2. 조건 연산자

조건 연산자는 `WHERE`절에서 **조회할 데이터의 조건을 지정할 때 사용하는 연산자**이다.

#### 비교 연산자

| 연산자        | 의미     |
| ---------- | ------ |
| `=`        | 같다     |
| `<>`, `!=` | 같지 않다  |
| `>`        | 크다     |
| `<`        | 작다     |
| `>=`       | 크거나 같다 |
| `<=`       | 작거나 같다 |

```sql
SELECT *
FROM STUDENT
WHERE AGE >= 20;
```

#### 논리 연산자

| 연산자   | 의미              |
| ----- | --------------- |
| `AND` | 모든 조건을 만족       |
| `OR`  | 하나 이상의 조건을 만족   |
| `NOT` | 조건을 만족하지 않는 데이터 |

```sql
SELECT *
FROM STUDENT
WHERE AGE >= 20
  AND DEPARTMENT = '컴퓨터공학과';
```

#### 주요 조건 연산자

| 연산자           | 의미            | 예시                                  |
| ------------- | ------------- | ----------------------------------- |
| `BETWEEN`     | 지정된 범위에 포함    | `AGE BETWEEN 20 AND 25`             |
| `IN`          | 목록 중 하나와 일치   | `DEPARTMENT IN ('컴퓨터공학과', '전자공학과')` |
| `LIKE`        | 문자열 패턴 검색     | `NAME LIKE '김%'`                    |
| `IS NULL`     | NULL 값 검색     | `EMAIL IS NULL`                     |
| `IS NOT NULL` | NULL이 아닌 값 검색 | `EMAIL IS NOT NULL`                 |

#### LIKE의 와일드카드

| 기호  | 의미            |
| --- | ------------- |
| `%` | 0개 이상의 모든 문자열 |
| `_` | 임의의 한 문자      |

예:

```sql
WHERE NAME LIKE '김%'
```

→ `김`으로 시작하는 모든 이름

```sql
WHERE NAME LIKE '%수'
```

→ `수`로 끝나는 모든 이름

```sql
WHERE NAME LIKE '김_수'
```

→ `김` + 한 글자 + `수` 형태의 이름

---

### 3. 조건 지정 검색

조건 지정 검색은 `WHERE`절을 이용하여 **특정 조건을 만족하는 행만 검색하는 방법**이다.

#### 기본 형식

```sql
SELECT 속성명
FROM 테이블명
WHERE 조건;
```

예를 들어 나이가 20세 이상인 학생을 검색한다.

```sql
SELECT *
FROM STUDENT
WHERE AGE >= 20;
```

#### 여러 조건 지정

```sql
SELECT *
FROM STUDENT
WHERE AGE >= 20
  AND DEPARTMENT = '컴퓨터공학과';
```

#### BETWEEN

20세 이상 25세 이하를 검색한다.

```sql
SELECT *
FROM STUDENT
WHERE AGE BETWEEN 20 AND 25;
```

다음 조건과 같은 의미이다.

```sql
WHERE AGE >= 20
  AND AGE <= 25
```

#### IN

여러 값 중 하나에 해당하는 데이터를 검색한다.

```sql
SELECT *
FROM STUDENT
WHERE DEPARTMENT IN (
    '컴퓨터공학과',
    '소프트웨어학과'
);
```

#### NULL 검색

NULL은 `=` 연산자로 비교하지 않고 `IS NULL`을 사용한다.

```sql
SELECT *
FROM STUDENT
WHERE EMAIL IS NULL;
```

```text
잘못된 표현
EMAIL = NULL

올바른 표현
EMAIL IS NULL
```

---

### 4. 정렬 검색

`ORDER BY`는 **검색 결과를 특정 속성을 기준으로 정렬할 때 사용**한다.

#### 기본 형식

```sql
SELECT 속성명
FROM 테이블명
ORDER BY 속성명 [ASC | DESC];
```

| 옵션     | 의미      |
| ------ | ------- |
| `ASC`  | 오름차순 정렬 |
| `DESC` | 내림차순 정렬 |

#### 오름차순

```sql
SELECT *
FROM STUDENT
ORDER BY AGE ASC;
```

```text
20
21
22
23
24
```

`ASC`는 기본값이므로 생략할 수 있다.

```sql
SELECT *
FROM STUDENT
ORDER BY AGE;
```

#### 내림차순

```sql
SELECT *
FROM STUDENT
ORDER BY AGE DESC;
```

```text
24
23
22
21
20
```

#### 여러 속성을 기준으로 정렬

```sql
SELECT *
FROM STUDENT
ORDER BY DEPARTMENT ASC, AGE DESC;
```

먼저 `DEPARTMENT`를 오름차순으로 정렬하고, 같은 학과에서는 `AGE`를 내림차순으로 정렬한다.

| 구문                  | 의미                      |
| ------------------- | ----------------------- |
| `ORDER BY AGE ASC`  | 나이 오름차순                 |
| `ORDER BY AGE DESC` | 나이 내림차순                 |
| `ORDER BY A, B`     | A를 먼저 정렬하고 같은 값에서 B로 정렬 |

> **ASC = 작은 값 → 큰 값, DESC = 큰 값 → 작은 값**

---

### 5. 하위 질의

하위 질의(Subquery)는 **SQL문 내부에 포함된 또 다른 SELECT문**을 의미한다.

다른 질의의 검색 결과를 조건으로 사용할 때 주로 사용한다.

#### 기본 형식

```sql
SELECT 속성명
FROM 테이블명
WHERE 속성명 연산자 (
    SELECT 속성명
    FROM 테이블명
    WHERE 조건
);
```

예를 들어 전체 학생의 평균 나이보다 나이가 많은 학생을 검색한다.

```sql
SELECT *
FROM STUDENT
WHERE AGE > (
    SELECT AVG(AGE)
    FROM STUDENT
);
```

실행 순서는 다음과 같다.

```text
1. 하위 질의 실행

SELECT AVG(AGE)
FROM STUDENT;

        ↓

2. 평균 나이 계산

        ↓

3. 상위 질의 실행

AGE > 평균 나이

        ↓

평균보다 나이가 많은 학생 조회
```

### 단일 행 하위 질의

하위 질의 결과가 **하나의 값**인 경우이다.

| 연산자  | 의미     |
| ---- | ------ |
| `=`  | 같다     |
| `>`  | 크다     |
| `<`  | 작다     |
| `>=` | 크거나 같다 |
| `<=` | 작거나 같다 |
| `<>` | 같지 않다  |

```sql
SELECT *
FROM STUDENT
WHERE AGE = (
    SELECT MAX(AGE)
    FROM STUDENT
);
```

→ 가장 나이가 많은 학생을 조회한다.

### 다중 행 하위 질의

하위 질의 결과가 **여러 개의 값**인 경우이다.

| 연산자      | 의미                  |
| -------- | ------------------- |
| `IN`     | 결과 중 하나와 일치         |
| `ANY`    | 결과 중 하나라도 조건을 만족    |
| `ALL`    | 모든 결과에 대해 조건을 만족    |
| `EXISTS` | 하위 질의의 결과가 존재하는지 확인 |

#### IN

```sql
SELECT *
FROM STUDENT
WHERE DEPT_ID IN (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE LOCATION = '서울'
);
```

→ 서울에 위치한 학과에 소속된 학생을 조회한다.

#### ANY

```sql
WHERE AGE > ANY (
    SELECT AGE
    FROM STUDENT
    WHERE DEPARTMENT = '컴퓨터공학과'
);
```

→ 하위 질의 결과 중 **하나의 값보다라도 크면 참**이다.

#### ALL

```sql
WHERE AGE > ALL (
    SELECT AGE
    FROM STUDENT
    WHERE DEPARTMENT = '컴퓨터공학과'
);
```

→ 하위 질의의 **모든 값보다 커야 참**이다.

#### EXISTS

```sql
SELECT *
FROM DEPARTMENT D
WHERE EXISTS (
    SELECT 1
    FROM STUDENT S
    WHERE S.DEPT_ID = D.DEPT_ID
);
```

→ 학생이 한 명이라도 존재하는 학과를 조회한다.

### 하위 질의 연산자 정리

| 연산자      | 의미              |
| -------- | --------------- |
| `IN`     | 여러 결과 중 하나와 일치  |
| `ANY`    | 하나 이상 조건 만족     |
| `ALL`    | 모든 값이 조건 만족     |
| `EXISTS` | 검색 결과의 존재 여부 확인 |

### SELECT문의 기본 작성 순서

```sql
SELECT 속성
FROM 테이블
WHERE 조건
ORDER BY 속성 ASC | DESC;
```

핵심적으로는 **`SELECT → 조회`, `WHERE → 조건`, `ORDER BY → 정렬`, `Subquery → SELECT 안의 SELECT`** 로 구분하면 됩니다.


## 084. DML-SELECT-2
### 1. 그룹 지정

`GROUP BY`는 **특정 속성의 값이 같은 행들을 하나의 그룹으로 묶어 처리할 때 사용하는 구문**이다.

주로 `COUNT`, `SUM`, `AVG`, `MAX`, `MIN`과 같은 **그룹 함수(집계 함수)**와 함께 사용한다.

#### 기본 형식

```sql
SELECT 그룹속성, 그룹함수(속성)
FROM 테이블명
GROUP BY 그룹속성;
```

예를 들어 학생 테이블이 다음과 같다고 가정한다.

| STUDENT_ID | NAME | DEPARTMENT | SCORE |
| ---------: | ---- | ---------- | ----: |
|          1 | 홍길동  | 컴퓨터공학과     |    90 |
|          2 | 김철수  | 컴퓨터공학과     |    80 |
|          3 | 이영희  | 전자공학과      |    85 |
|          4 | 박민수  | 전자공학과      |    95 |

학과별 학생 수를 조회하면 다음과 같다.

```sql
SELECT DEPARTMENT, COUNT(*)
FROM STUDENT
GROUP BY DEPARTMENT;
```

결과:

| DEPARTMENT | COUNT(*) |
| ---------- | -------: |
| 컴퓨터공학과     |        2 |
| 전자공학과      |        2 |

즉,

```text
전체 데이터
    ↓
GROUP BY DEPARTMENT
    ↓
┌────────────────┐
│ 컴퓨터공학과 그룹 │
│ 홍길동, 김철수    │
└────────────────┘

┌────────────────┐
│ 전자공학과 그룹   │
│ 이영희, 박민수    │
└────────────────┘
```

### HAVING

`HAVING`은 **GROUP BY로 생성된 그룹에 조건을 지정할 때 사용**한다.

#### 기본 형식

```sql
SELECT 그룹속성, 그룹함수(속성)
FROM 테이블명
GROUP BY 그룹속성
HAVING 조건;
```

예를 들어 학생이 2명 이상인 학과만 조회한다.

```sql
SELECT DEPARTMENT, COUNT(*)
FROM STUDENT
GROUP BY DEPARTMENT
HAVING COUNT(*) >= 2;
```

`WHERE`와 `HAVING`의 차이는 다음과 같다.

| 구분       | WHERE         | HAVING          |
| -------- | ------------- | --------------- |
| 조건 대상    | 개별 행(Row)     | 그룹(Group)       |
| 적용 시점    | 그룹화 이전        | 그룹화 이후          |
| 그룹 함수 조건 | 일반적으로 사용하지 않음 | 사용 가능           |
| 예시       | `AGE >= 20`   | `COUNT(*) >= 2` |

```text
WHERE  → 행을 먼저 거른다
GROUP BY → 남은 행을 그룹으로 묶는다
HAVING → 만들어진 그룹을 거른다
```

예를 들어:

```sql
SELECT DEPARTMENT, AVG(SCORE)
FROM STUDENT
WHERE SCORE >= 60
GROUP BY DEPARTMENT
HAVING AVG(SCORE) >= 80;
```

처리 개념은 다음과 같다.

```text
STUDENT
   ↓
WHERE SCORE >= 60
   ↓
GROUP BY DEPARTMENT
   ↓
학과별 그룹 생성
   ↓
AVG(SCORE) 계산
   ↓
HAVING AVG(SCORE) >= 80
```

> **GROUP BY = 같은 값을 가진 데이터를 그룹으로 묶는다.**
> **HAVING = 만들어진 그룹에 조건을 지정한다.**

---

### 2. 그룹 함수

그룹 함수(Group Function)는 **여러 행의 값을 하나의 그룹으로 묶어 계산하고 하나의 결과값을 반환하는 함수**이다.

집계 함수(Aggregate Function)라고도 한다.

| 함수        | 의미  | 설명             |
| --------- | --- | -------------- |
| `COUNT()` | 개수  | 행 또는 값의 개수를 계산 |
| `SUM()`   | 합계  | 숫자 값의 합계를 계산   |
| `AVG()`   | 평균  | 숫자 값의 평균을 계산   |
| `MAX()`   | 최댓값 | 가장 큰 값을 반환     |
| `MIN()`   | 최솟값 | 가장 작은 값을 반환    |

### COUNT

데이터의 **개수**를 구한다.

```sql
SELECT COUNT(*)
FROM STUDENT;
```

전체 학생 수를 반환한다.

특정 속성을 지정할 수도 있다.

```sql
SELECT COUNT(DEPARTMENT)
FROM STUDENT;
```

#### COUNT의 차이

| 표현                   | 의미                    |
| -------------------- | --------------------- |
| `COUNT(*)`           | 모든 행의 개수              |
| `COUNT(속성)`          | 해당 속성이 NULL이 아닌 행의 개수 |
| `COUNT(DISTINCT 속성)` | 중복과 NULL을 제외한 값의 개수   |

예:

```sql
SELECT COUNT(DISTINCT DEPARTMENT)
FROM STUDENT;
```

→ 서로 다른 학과의 개수를 구한다.

---

### SUM

숫자 속성의 **합계**를 구한다.

```sql
SELECT SUM(SCORE)
FROM STUDENT;
```

예를 들어 점수가 다음과 같다면,

```text
90 + 80 + 85 + 95
```

결과는 `350`이 된다.

학과별 점수 합계를 구하려면:

```sql
SELECT DEPARTMENT, SUM(SCORE)
FROM STUDENT
GROUP BY DEPARTMENT;
```

---

### AVG

숫자 속성의 **평균값**을 구한다.

```sql
SELECT AVG(SCORE)
FROM STUDENT;
```

학과별 평균 점수를 구하려면:

```sql
SELECT DEPARTMENT, AVG(SCORE)
FROM STUDENT
GROUP BY DEPARTMENT;
```

결과:

| DEPARTMENT | AVG(SCORE) |
| ---------- | ---------: |
| 컴퓨터공학과     |         85 |
| 전자공학과      |         90 |

---

### MAX / MIN

`MAX`는 가장 큰 값, `MIN`은 가장 작은 값을 반환한다.

```sql
SELECT MAX(SCORE)
FROM STUDENT;
```

→ 최고 점수

```sql
SELECT MIN(SCORE)
FROM STUDENT;
```

→ 최저 점수

두 함수를 동시에 사용할 수도 있다.

```sql
SELECT MAX(SCORE), MIN(SCORE)
FROM STUDENT;
```

### 그룹 함수 정리

| 함수        | 역할  | 예시    |
| --------- | --- | ----- |
| `COUNT()` | 개수  | 학생 수  |
| `SUM()`   | 합계  | 점수 총합 |
| `AVG()`   | 평균  | 평균 점수 |
| `MAX()`   | 최댓값 | 최고 점수 |
| `MIN()`   | 최솟값 | 최저 점수 |

```text
COUNT → 몇 개인가?
SUM   → 모두 더하면?
AVG   → 평균은?
MAX   → 가장 큰 값은?
MIN   → 가장 작은 값은?
```

### GROUP BY와 그룹 함수 예시

```sql
SELECT DEPARTMENT,
       COUNT(*) AS STUDENT_COUNT,
       AVG(SCORE) AS AVG_SCORE,
       MAX(SCORE) AS MAX_SCORE,
       MIN(SCORE) AS MIN_SCORE
FROM STUDENT
GROUP BY DEPARTMENT;
```

즉, 핵심 구조는 다음과 같이 기억하면 됩니다.

```sql
SELECT 그룹속성, 그룹함수()
FROM 테이블
WHERE 행에 대한 조건
GROUP BY 그룹속성
HAVING 그룹에 대한 조건
ORDER BY 정렬속성;
```

> **WHERE = 행 조건 / GROUP BY = 그룹 생성 / HAVING = 그룹 조건 / 그룹 함수 = 그룹별 계산**


## 085. DML-JOIN
### 1. INNER JOIN

`INNER JOIN`은 **두 테이블에서 조인 조건이 일치하는 데이터만 조회하는 방식**이다.

즉, 두 테이블에 **공통으로 존재하는 데이터만 결과에 포함**된다.

#### 기본 형식

```sql
SELECT 속성명
FROM 테이블1
INNER JOIN 테이블2
ON 테이블1.속성 = 테이블2.속성;
```

예를 들어 다음 두 테이블이 있다고 가정한다.

**STUDENT**

| STUDENT_ID | NAME | DEPT_ID |
| ---------: | ---- | ------: |
|          1 | 홍길동  |      10 |
|          2 | 김철수  |      20 |
|          3 | 이영희  |      30 |

**DEPARTMENT**

| DEPT_ID | DEPT_NAME |
| ------: | --------- |
|      10 | 컴퓨터공학과    |
|      20 | 전자공학과     |
|      40 | 기계공학과     |

다음과 같이 조회하면,

```sql
SELECT S.NAME, D.DEPT_NAME
FROM STUDENT S
INNER JOIN DEPARTMENT D
ON S.DEPT_ID = D.DEPT_ID;
```

결과는 다음과 같다.

| NAME | DEPT_NAME |
| ---- | --------- |
| 홍길동  | 컴퓨터공학과    |
| 김철수  | 전자공학과     |

`DEPT_ID = 30`, `DEPT_ID = 40`은 서로 대응되는 데이터가 없으므로 결과에서 제외된다.

```text
STUDENT        DEPARTMENT
   10  ────────── 10
   20  ────────── 20
   30              40

        ↓

일치하는 10, 20만 조회
```

> **INNER JOIN = 양쪽 테이블에 모두 존재하는 데이터만 조회**

---

### 2. OUTER JOIN

`OUTER JOIN`은 **조인 조건에 일치하지 않는 데이터도 포함하여 조회하는 방식**이다.

어느 테이블의 데이터를 모두 포함하느냐에 따라 `LEFT`, `RIGHT`, `FULL OUTER JOIN`으로 구분한다.

| 종류                 | 의미                  |
| ------------------ | ------------------- |
| `LEFT OUTER JOIN`  | 왼쪽 테이블의 모든 데이터를 조회  |
| `RIGHT OUTER JOIN` | 오른쪽 테이블의 모든 데이터를 조회 |
| `FULL OUTER JOIN`  | 양쪽 테이블의 모든 데이터를 조회  |

---

#### LEFT OUTER JOIN

왼쪽 테이블의 데이터를 **모두 출력**하고, 오른쪽 테이블과 일치하지 않는 부분은 `NULL`로 표시한다.

```sql
SELECT S.NAME, D.DEPT_NAME
FROM STUDENT S
LEFT OUTER JOIN DEPARTMENT D
ON S.DEPT_ID = D.DEPT_ID;
```

결과:

| NAME | DEPT_NAME |
| ---- | --------- |
| 홍길동  | 컴퓨터공학과    |
| 김철수  | 전자공학과     |
| 이영희  | NULL      |

`STUDENT`가 왼쪽에 있으므로 학생 데이터는 모두 출력된다.

```text
왼쪽 테이블 전체 유지

STUDENT        DEPARTMENT
   10  ────────── 10
   20  ────────── 20
   30  ────────── NULL
```

> **LEFT JOIN = 왼쪽은 전부**

---

#### RIGHT OUTER JOIN

오른쪽 테이블의 데이터를 **모두 출력**하고, 왼쪽 테이블과 일치하지 않는 부분은 `NULL`로 표시한다.

```sql
SELECT S.NAME, D.DEPT_NAME
FROM STUDENT S
RIGHT OUTER JOIN DEPARTMENT D
ON S.DEPT_ID = D.DEPT_ID;
```

결과:

| NAME | DEPT_NAME |
| ---- | --------- |
| 홍길동  | 컴퓨터공학과    |
| 김철수  | 전자공학과     |
| NULL | 기계공학과     |

```text
오른쪽 테이블 전체 유지

STUDENT        DEPARTMENT
   10  ────────── 10
   20  ────────── 20
 NULL ─────────── 40
```

> **RIGHT JOIN = 오른쪽은 전부**

---

#### FULL OUTER JOIN

두 테이블의 데이터를 **모두 포함하여 조회**한다.

```sql
SELECT S.NAME, D.DEPT_NAME
FROM STUDENT S
FULL OUTER JOIN DEPARTMENT D
ON S.DEPT_ID = D.DEPT_ID;
```

결과 개념:

| NAME | DEPT_NAME |
| ---- | --------- |
| 홍길동  | 컴퓨터공학과    |
| 김철수  | 전자공학과     |
| 이영희  | NULL      |
| NULL | 기계공학과     |

> `FULL OUTER JOIN` 지원 여부는 DBMS에 따라 다르다.

---

### OUTER JOIN 비교

| 조인                | 기준      | 일치하지 않는 데이터  |
| ----------------- | ------- | ------------ |
| `LEFT JOIN`       | 왼쪽 테이블  | 왼쪽 데이터 유지    |
| `RIGHT JOIN`      | 오른쪽 테이블 | 오른쪽 데이터 유지   |
| `FULL OUTER JOIN` | 양쪽 테이블  | 양쪽 데이터 모두 유지 |

```text
LEFT  → 왼쪽 전체
RIGHT → 오른쪽 전체
FULL  → 양쪽 전체
```

---

### 3. SELF JOIN

`SELF JOIN`은 **하나의 테이블을 자기 자신과 조인하는 방식**이다.

동일한 테이블 안에서 서로 관계가 있는 데이터를 조회할 때 사용하며, 테이블을 구분하기 위해 **별칭(Alias)**을 사용한다.

대표적인 예가 **직원과 관리자 관계**이다.

**EMPLOYEE**

| EMP_ID | NAME | MANAGER_ID |
| -----: | ---- | ---------: |
|      1 | 김부장  |       NULL |
|      2 | 이대리  |          1 |
|      3 | 박사원  |          2 |

`MANAGER_ID`에는 해당 직원의 관리자 `EMP_ID`가 저장되어 있다고 가정한다.

#### 기본 형식

```sql
SELECT A.속성, B.속성
FROM 테이블 A
JOIN 테이블 B
ON A.속성 = B.속성;
```

직원과 관리자의 이름을 조회하면 다음과 같다.

```sql
SELECT E.NAME AS EMPLOYEE,
       M.NAME AS MANAGER
FROM EMPLOYEE E
LEFT JOIN EMPLOYEE M
ON E.MANAGER_ID = M.EMP_ID;
```

결과:

| EMPLOYEE | MANAGER |
| -------- | ------- |
| 김부장      | NULL    |
| 이대리      | 김부장     |
| 박사원      | 이대리     |

실제로는 하나의 테이블이지만 SQL에서는 별칭을 이용하여 두 개의 테이블처럼 처리한다.

```text
EMPLOYEE E                EMPLOYEE M

이대리                       김부장
MANAGER_ID = 1  ───────→   EMP_ID = 1

박사원                       이대리
MANAGER_ID = 2  ───────→   EMP_ID = 2
```

> **SELF JOIN = 자기 자신의 테이블과 JOIN**

---

### JOIN 종류 비교

| 종류                 | 의미                    |
| ------------------ | --------------------- |
| `INNER JOIN`       | 양쪽 테이블에서 일치하는 데이터만 조회 |
| `LEFT OUTER JOIN`  | 왼쪽 테이블 전체 + 일치 데이터    |
| `RIGHT OUTER JOIN` | 오른쪽 테이블 전체 + 일치 데이터   |
| `FULL OUTER JOIN`  | 양쪽 테이블의 모든 데이터        |
| `SELF JOIN`        | 하나의 테이블을 자기 자신과 조인    |

```text
INNER JOIN → 교집합
OUTER JOIN → 일치하지 않는 데이터도 포함
SELF JOIN  → 자기 자신과 조인
```
