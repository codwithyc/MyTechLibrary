# 정보통신 이론
## 3-1 정보 및 정보의 전송 방식
### 1) 정보 이론
1. 채널 용량
    - **어떠한 전송 매체의 최대 정보 전송 능력**을 의미합니다.
    - 채널 용량 계산법

2. 신호(Signal)
    - 아날로그 신호 : 연속적으로 변하는 전자기적 신호
    - 디지털 신호 : 0과 1로 표현되는 데이터 신호

### 2) 정보의 전송 방식
1. 신호의 종류에 따른 분류
    - **아날로그 전송** : **연속적으로 변하는 아날로그 신호**를 사용한 데이터 전송 방법으로 **잡음 발생 가능성이 높습니다.**
    - **디지털 전송** : 0과 1로 표현되는 **디지털 펄스 신호**를 사용한 데이터 전송 방법으로 아날로그 전송에 비해 **잡음에 강하고 에러가 적습니다.**

2. 데이터의 저송 방향에 따른 분류
    - 단방향 통신 (Simplex Communication) : 데이터를 보내는 디바이스와 받는 디바이스가 정해져 있어, 한쪽 방향으로만  
    정보가 전달되는 통신 방법입니다.  
    예) TV, 라디오 [디바이스 -> 디바이스]
    - 반이중 토신 (Half-Duplex Communication) : 디바이스 간 양방향 통신이 가능하고, 서로 동시에 통신하는 것도 가능한 통신  
    방법으로 완전하게 이중인 통신입니다.  
    예) 무전기 [디바이스 <- 디바이스]
    - 전이중 통신 (Full-Duplex Communication) : 디바이스 간 양방향 통신이 가능하고, 서로 동시에 통신하는 것도 가능한 통신  
    방법으로 완전하게 이중인 통신입니다.  
    예) 전화 [디바이스 <-> 디바이스]

3. 데이터의 전송 단위에 따른 분류
    - 직렬 전송 : 여러 개의 데이터들이 하나의 전송 회선을 통하여 차례대로 전송되는 형태로, 동기식 전송 방식으로 전송 에러가 적고,  
    하나의 회선만을 이용하므로 통신 회선 비용이 저렴하여 장거리 전송에 적합하지만 전송 속도가 느립니다. 
    - 병렬 전송 : 여러 개의 데이터들이 여러 개의 전송 회선을 통하여 동시에 전송되는 형태로, 데이터를 빠르게 저송할 수 있으나, 각 회선  
    간의 순서로 인해 에러 발생 가능성이 높습니다. 통신 회선 비용이 직렬 전송에 비해 비쌉니다.

4. 데이터의 동기화 여부에 따른 분류
    - 비동기식 전송 (Asynchronous Transmission) : 스타트 비트(Start Bit)와 스톱비트 (Stop Bit)를 사용해서 한 문자 단위로  
    데이터를 전송하는 방식입니다. 각 문자 사이에는 유휴기간이 존재하기 때문에 전송 효율이 낮아 전송 속도가 느립니다.
    - 동기식 전송 (Synchronous Transmission) : 한 문자를 일정한 크기의 데이터 블록(프레임)으로 나누어 빠르게 전송하는 방식으로,  
    전송 효율이 높아 많은 양의 데이터를 빠르게 전송할 수 있습니다. 동기 방식과 비트 동기 방식으로 나눕니다.
    - 문자 동기 방식 동기식 전송의 예 : 문자를 통해 데이터 전송을 시작됨을 알립니다.

## 3-2 변조 - 아날로그와 디지털 신호의 변환
아래처럼 **“원 신호가 무엇이고, 전송을 위해 어떤 형태로 바꾸는가”** 기준으로 정리하면 됩니다.

#### 신호 변환 방식 전체 구조

| 구분 | 변환 방향       | 핵심 의미                    | 대표 방식                     |
| -- | ----------- | ------------------------ | ------------------------- |
| 1  | 아날로그 → 아날로그 | 아날로그 정보를 아날로그 반송파에 실어 보냄 | AM, FM, PM                |
| 2  | 아날로그 → 디지털  | 아날로그 신호를 디지털 데이터로 변환     | PCM, DPCM, DM, ADM, ADPCM |
| 3  | 디지털 → 아날로그  | 디지털 정보를 아날로그 신호로 변조      | ASK, FSK, PSK, QAM/APSK   |
| 4  | 디지털 → 디지털   | 디지털 데이터를 디지털 신호 형태로 부호화  | NRZ, RZ, 양극성, 바이폴라, 맨체스터  |

### 1) 아날로그 → 아날로그 변조

아날로그 신호를 멀리 보내기 위해 **아날로그 반송파**에 실어 보내는 방식입니다.

| 방식 | 의미                   | 변하는 요소 | 특징                    |
| -- | -------------------- | ------ | --------------------- |
| AM | Amplitude Modulation | 진폭     | 반송파의 진폭을 변화시켜 정보를 전달  |
| FM | Frequency Modulation | 주파수    | 반송파의 주파수를 변화시켜 정보를 전달 |
| PM | Phase Modulation     | 위상     | 반송파의 위상을 변화시켜 정보를 전달  |

#### 핵심 암기

```text
AM = 진폭 변화
FM = 주파수 변화
PM = 위상 변화
```

#### 예시

| 방식 | 예시          |
| -- | ----------- |
| AM | AM 라디오      |
| FM | FM 라디오      |
| PM | 일부 통신 변조 방식 |

### 2) 아날로그 → 디지털 변환

음성처럼 연속적인 아날로그 신호를 컴퓨터가 처리할 수 있는 **디지털 데이터**로 바꾸는 방식입니다.

대표적으로 음성 신호를 디지털화할 때 사용합니다.

#### 전체 흐름

```text
아날로그 신호
→ 표본화
→ 양자화
→ 부호화
→ 디지털 데이터
```

| 단계  | 의미                        |
| --- | ------------------------- |
| 표본화 | 일정한 시간 간격으로 아날로그 신호 값을 추출 |
| 양자화 | 추출한 값을 정해진 단계의 값으로 근사     |
| 부호화 | 양자화된 값을 0과 1의 디지털 코드로 변환  |

#### 주요 방식

| 방식    | 의미                        | 핵심 특징                              |
| ----- | ------------------------- | ---------------------------------- |
| PCM   | Pulse Code Modulation     | 아날로그 신호를 표본화, 양자화, 부호화하여 디지털화      |
| DPCM  | Differential PCM          | 현재 값 전체가 아니라 이전 값과의 차이를 부호화        |
| DM    | Delta Modulation          | 이전 값보다 증가했는지 감소했는지만 1비트로 표현        |
| ADM   | Adaptive Delta Modulation | 신호 변화량에 따라 DM의 계단 크기를 조절           |
| ADPCM | Adaptive DPCM             | DPCM에서 차이값의 크기를 적응적으로 조절해 압축 효율 향상 |

> 참고: 교재에 `CM`이라고 되어 있다면 문맥상 보통 `DM(Delta Modulation)`을 의미하는 경우가 많습니다.  
> 시험 범위에서는 `PCM, DPCM, DM, ADM, ADPCM` 조합으로 자주 나옵니다.

### 방식별 이해

#### PCM

아날로그 신호를 디지털화하는 가장 기본적인 방식입니다.

```text
표본화 → 양자화 → 부호화
```

```text
PCM = 아날로그 신호를 디지털 코드로 바꾸는 기본 방식
```

#### DPCM

PCM은 매번 전체 값을 저장합니다.
DPCM은 이전 값과 현재 값의 **차이값**만 저장합니다.

```text
이전 값: 10
현재 값: 12
저장 값: +2
```

```text
DPCM = 차이값을 부호화
```

#### DM

DM은 DPCM보다 더 단순합니다.
현재 값이 이전 값보다 커졌는지 작아졌는지만 표현합니다.

```text
증가 = 1
감소 = 0
```

```text
DM = 증가/감소만 1비트로 표현
```

#### ADM

DM은 변화가 큰 신호를 따라가기 어렵습니다.
ADM은 신호 변화가 크면 계단 크기를 크게 하고, 변화가 작으면 계단 크기를 작게 조절합니다.

```text
ADM = DM의 계단 크기를 적응적으로 조절
```

#### ADPCM

DPCM을 개선한 방식입니다.
차이값을 더 효율적으로 표현하기 위해 예측과 양자화 단계를 적응적으로 조절합니다.

```text
ADPCM = DPCM을 더 효율적으로 압축한 방식
```

#### 핵심 암기

```text
PCM = 표본화 + 양자화 + 부호화
DPCM = 이전 값과의 차이 저장
DM = 증가/감소만 저장
ADM = DM의 계단 크기 조절
ADPCM = DPCM을 적응적으로 개선
```

---

### 3) 디지털 정보 → 아날로그 변조

디지털 데이터를 아날로그 통신망으로 보내기 위해 **아날로그 신호 형태로 바꾸는 방식**입니다.

예를 들어 모뎀, 무선 통신, 이동통신에서 사용됩니다.

| 방식   | 의미                              | 변하는 요소  | 특징                        |
| ---- | ------------------------------- | ------- | ------------------------- |
| ASK  | Amplitude Shift Keying          | 진폭      | 디지털 값에 따라 진폭을 다르게 함       |
| FSK  | Frequency Shift Keying          | 주파수     | 디지털 값에 따라 주파수를 다르게 함      |
| PSK  | Phase Shift Keying              | 위상      | 디지털 값에 따라 위상을 다르게 함       |
| QAM  | Quadrature Amplitude Modulation | 진폭 + 위상 | 진폭과 위상을 함께 바꾸어 많은 데이터를 전송 |
| APSK | Amplitude Phase Shift Keying    | 진폭 + 위상 | 위상과 진폭을 함께 사용하는 변조 방식     |

> 참고: `OAM`이라고 적힌 부분은 시험/교재에 따라 `QAM`을 잘못 보거나 혼동한 것일 가능성이 큽니다. 일반적인 데이터 통신 변조 방식에서는 `ASK, FSK, PSK, QAM`이 핵심입니다.

---

### 방식별 이해

#### ASK

디지털 값에 따라 진폭을 다르게 합니다.

```text
1 = 큰 진폭
0 = 작은 진폭 또는 진폭 없음
```

```text
ASK = 진폭으로 0과 1 구분
```

#### FSK

디지털 값에 따라 주파수를 다르게 합니다.

```text
1 = 높은 주파수
0 = 낮은 주파수
```

```text
FSK = 주파수로 0과 1 구분
```

#### PSK

디지털 값에 따라 위상을 다르게 합니다.

```text
1 = 0도
0 = 180도
```

```text
PSK = 위상으로 0과 1 구분
```

#### QAM / APSK

진폭과 위상을 함께 변화시켜 더 많은 비트를 한 번에 표현합니다.

```text
QAM = 진폭 + 위상 조합
```

예를 들어 16-QAM은 한 번의 신호 변화로 4비트를 표현할 수 있습니다.

```text
16개 신호 상태 = 2⁴ = 4비트
```

#### 핵심 암기

```text
ASK = 진폭 변화
FSK = 주파수 변화
PSK = 위상 변화
QAM/APSK = 진폭 + 위상 변화
```

---

### 4) 디지털 정보 → 디지털 부호화

디지털 데이터를 실제 전송 매체에서 보낼 수 있도록 **전기적 신호 형태**로 바꾸는 방식입니다.

즉, 0과 1을 전압의 높낮이, 전압 변화, 극성 변화 등으로 표현합니다.

### 주요 방식

| 방식   | 의미                 | 특징                       |
| ---- | ------------------ | ------------------------ |
| NRZ  | Non Return to Zero | 비트 구간 동안 신호가 0으로 돌아가지 않음 |
| RZ   | Return to Zero     | 비트 구간 중간에 신호가 0으로 돌아감    |
| 단극성  | Unipolar           | 하나의 극성만 사용, 예: 0V와 +V    |
| 양극성  | Polar              | 양전압과 음전압을 사용             |
| 바이폴라 | Bipolar            | 0은 0V, 1은 +V와 -V를 번갈아 사용 |
| 맨체스터 | Manchester         | 비트 중간의 전압 변화로 0과 1을 표현   |

#### NRZ

비트가 전송되는 동안 신호가 0으로 돌아가지 않습니다.

| 구분 | 설명                      |
| -- | ----------------------- |
| 장점 | 구현이 단순함                 |
| 단점 | 같은 비트가 계속 반복되면 동기화가 어려움 |

```text
NRZ = 0으로 돌아가지 않음
```

#### RZ

비트 구간 안에서 신호가 다시 0으로 돌아옵니다.

| 구분 | 설명                     |
| -- | ---------------------- |
| 장점 | 동기화에 유리함               |
| 단점 | 신호 변화가 많아 대역폭을 더 많이 사용 |

```text
RZ = 중간에 0으로 돌아감
```

#### 단극성

0과 1을 하나의 극성으로 표현합니다.

```text
0 = 0V
1 = +V
```

```text
단극성 = 한쪽 전압만 사용
```

#### 양극성

양전압과 음전압을 사용합니다.

```text
0 = -V
1 = +V
```

```text
양극성 = +전압과 -전압 사용
```

#### 바이폴라

0은 0V로 표현하고, 1은 +V와 -V를 번갈아 사용합니다.

```text
0 = 0V
1 = +V, -V, +V, -V ...
```

```text
바이폴라 = 1을 +와 -로 번갈아 표현
```

대표 방식으로는 `AMI`가 있습니다.

#### 맨체스터

비트 구간의 중간에서 반드시 신호가 변화합니다.
이 변화 방향으로 0과 1을 구분합니다.

| 구분 | 설명         |
| -- | ---------- |
| 장점 | 동기화가 좋음    |
| 단점 | 대역폭을 많이 사용 |

```text
맨체스터 = 비트 중간의 변화로 표현
```

### 전체 요약 표

| 구분          | 대표 방식                         | 핵심 암기                  |
| ----------- | ----------------------------- | ---------------------- |
| 아날로그 → 아날로그 | AM, FM, PM                    | 진폭, 주파수, 위상 변화         |
| 아날로그 → 디지털  | PCM, DPCM, DM, ADM, ADPCM     | 표본화·양자화·부호화 또는 차이값 부호화 |
| 디지털 → 아날로그  | ASK, FSK, PSK, QAM/APSK       | 디지털 값을 아날로그 반송파에 실음    |
| 디지털 → 디지털   | NRZ, RZ, 단극성, 양극성, 바이폴라, 맨체스터 | 0과 1을 전기 신호 형태로 표현     |

### 시험용 최종 암기

```text
AM = 진폭
FM = 주파수
PM = 위상

PCM = 표본화 + 양자화 + 부호화
DPCM = 차이값
DM = 증가/감소
ADM = 계단 크기 조절
ADPCM = DPCM 개선

ASK = 진폭
FSK = 주파수
PSK = 위상
QAM/APSK = 진폭 + 위상

NRZ = 0으로 안 돌아감
RZ = 0으로 돌아감
바이폴라 = 1을 +, - 번갈아 표현
맨체스터 = 비트 중간 변화
```


## 3-3 통신 관련 기술
### 1) 흐름 제어(Flow Control)
파이프에 물을 흘려보내는 모습을 상상해보자, 많은 양의 물을 빠르게 흘려보낸다면 물이 넘쳐 손실이 발생할 수도 있고, 잘못하다간 파이프가  
고장날 수 도 있습니다. 반대로 파이프의 용량 대비 물을 너무 적게 흘려보낸다면 애써 준비한 파이프를 100% 활용하지 못하게 되어 예상보다 물을 흘려보내 데  
시간이 많이 소요될 것입니다.

이처럼 **통신을 주고받은 두 개의 컴퓨터 간에 데이터 처리 속도가 달라서 발생하는 문제들을 해결**하기 위한 방법이 바로 **흐름 제어**입니다.

1. 스톱 앤 웨이트 (Stop-and Wait)방법
    - 패킷을 보낸 후에는 일단 전송을 멈추고(Stop) 상대방이 받았다고 확인 메시지(ACK)를 줄 때가지 잠시 기다리는(Wait) 방식입니다.

> 이해를 돕는 설명
> 
> ACK(애크) : Acknowledgement, 패킷, 데이터 등을 받았음을 확인하는 신호
> Nak, Nack (나크) : Negative - Acknowledgement - 전송 실패, 간섭 등의 이유로 받기로 예정되어 있던 패킷, 데이터 등을 받지 못했음을 알리는 신호

2. 슬라이딩 윈도우 (Sliding Window) 방법
    - 수신 측에서 설정한 윈도우 크기 만큼은 확인 메시지(ACK)가 없이도 끊김없이 데이터를 전달할 수 있습니다.
    - 단, 수신 측에서 전송 실패, 간섭 등의 이유로 받기로 예정되어 있던 데이터를 다 받지 못한 경우 나크(NAK) 메시지를 보내면  
    송신 측에서는 보내는 메시지의 크기를 줄입니다. (데이터가 전송되는 윈두의 크기를 줄임)
    - 슬라이더 버튼으로 듣는 사람의 요구에 맞게 볼륨의 크기를 조절하듯, 동적으로 윈도우의 크기를 조절하여 송신 측과 수신 측의 데이터 처리 속도  
    차이를 조절하는 방법입니다.

### 2) 오류 제어 (Error Control)
통신 시에는 다양한 이유로 전송 오류가 발생합니다. 전송 오류의 종류와 오류의 검출 방법, 검출된 오류를 수정하는 방법을 알아봅니다.
    
- 전송 오류의 종류
    - 감쇠 (Attenuation) : 데이터가 회선을 통하여 전송되는 도중에 신호가 약해져 신호를 정확히 판단할 수 없는 경우
    - 지연 왜곡 (Delay Distortion) : 데이터 전송이 늦어지는 경우
    - 잡음 (Noise) : 모니터, 전자레인지 등 주변 전자기기의 영향으로 불필요한 신호가 추가되거나 기존 신호가 왜곡되는 경우
    - 혼선 (Crosstalk) : 전기 신호적 결함에 의해 한 회선의 데이터가 다른 회선에 영향을 주는 경우

1. 패리티 비트 검사 (Parity Bit Check)
    - 전송 데이터마다 **패리티 비트**를 추가하여 **비트 개수의 홀짝 여부로 오류를 확인**하는 검사
    - 패리티 비트 : 오류 확인용 비트
    - 총 8개의 비트 중 뒤의 7개 자리를 보고 1개의 개수가 몇 개인지 확인한 후 전체 1의 개수를 홀수 혹은 짝수로 맞추기 위해  
    첫 번째 자리에 1 혹은 0을 넣습니다.
    - 예를 들어, 홀수 패리티 방식으로 전체 8자리의 1의 개수가 홀수 개가 되도록 패리티 비트를 넣었을 경우, 받는 쪽에서 홀수임을 확인하면 에러가 없는 것입니다.  
    마찬가지로, 짝수 패리티 방식으로 패리티 비트를 넣었는데, 받는 쪽에서 홀수임을 확인하면 에러가 발생한 것입니다.
    - 한계 : 8개의 비트에서 오류가 두 번 발생하면 에러가 발생해도 판별할 수 없다. 

2. 블록 합 검사 (Block Sum Check)
    - **패리티 비트 검사의 단점을 극복**하기 위하여 **수평과 수직 2차원으로 블록(Block)을 합쳐서(Sum) 검사**하는 방법입니다.
    - 수평 행 단위 패리티에 수직 열 단위의 오류를 검사할 수 있는 패리티를 추가하여 이중으로 오류를 검출합니다. 추가된 열 패리티 문자를 블록 검사 문자(BCC : Block Check Character)라고 칭합니다.
    - 한계 : 수직과 수평으로 연속된 정사각형 모양의 4개의 에러가 발생하면 판별할 수 없습니다.

3. 순환 중복 검사 (CRC : Cyclic Redundancy Check)
    - 정확한 에러 검출을 위하여 **다항식을 사용**하는 방법입니다.
    - 오류가 발생하면 오류가 발생한 주변ㅇ르 포함하는 집단 오류를 검출하는 데 용이합니다.

### 3) 오류 제어의 종류

| 구분       | 방식        | 핵심 내용                                | 특징                                   |
| -------- | --------- | ------------------------------------ | ------------------------------------ |
| 전진 오류 수정 | FEC       | 수신 측에서 오류를 검출하고 직접 수정하는 방식           | 재전송이 필요 없지만, 오류 정정을 위한 추가 비트가 많이 필요함 |
| 후진 오류 수정 | BEC / ARQ | 수신 측에서 오류를 검출하면 송신 측에 재전송을 요청하는 방식   | 구현이 비교적 단순하지만, 재전송으로 인해 지연이 발생할 수 있음 |
| 오류 검출    | 패리티 검사    | 데이터에 패리티 비트를 추가하여 오류 여부를 확인          | 단순하지만 오류 수정은 불가능                     |
| 오류 검출    | 체크섬       | 데이터를 일정 단위로 나누어 합산한 값을 함께 전송하여 오류 확인 | TCP/IP 등에서 사용                        |
| 오류 검출    | CRC       | 다항식 연산을 이용해 오류를 검출하는 방식              | 오류 검출 능력이 우수하며 네트워크에서 많이 사용          |
| 오류 정정    | 해밍 코드     | 오류가 발생한 위치를 찾아 수정할 수 있는 방식           | 1비트 오류 정정 가능                         |

#### ARQ 방식 종류
| 구분                   | 핵심 내용                                     | 특징                            |
| -------------------- | ----------------------------------------- | ----------------------------- |
| Stop-and-Wait ARQ    | 하나의 프레임을 보내고 ACK를 받은 뒤 다음 프레임 전송          | 구조가 단순하지만 전송 효율이 낮음           |
| Go-Back-N ARQ        | 여러 프레임을 연속 전송하다가 오류가 발생하면 오류 프레임부터 모두 재전송 | 전송 효율은 높지만 불필요한 재전송이 발생할 수 있음 |
| Selective Repeat ARQ | 오류가 발생한 프레임만 선택적으로 재전송                    | 효율이 가장 좋지만 구현이 복잡함            |

#### 한 줄 정리
FEC = 수신 측에서 직접 오류 수정  
ARQ = 오류 발생 시 재전송 요청  
패리티/체크섬/CRC = 오류 검출  
해밍 코드 = 오류 정정  


Stop-and-Wait = 하나씩 보내고 확인  
Go-Back-N = 오류 난 지점부터 다시 전송  
Selective Repeat = 오류 난 것만 다시 전송
