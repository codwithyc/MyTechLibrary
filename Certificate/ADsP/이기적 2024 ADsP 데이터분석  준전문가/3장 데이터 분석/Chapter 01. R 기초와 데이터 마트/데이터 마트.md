# 데이터 마트

데이터 마트는 데이터 분석을 위해 필요한 데이터를 **분석 목적에 맞게 정리해 둔 작은 데이터 저장소**라고 이해하면 된다.

기업 전체 데이터를 모두 담는 것이 아니라, 특정 부서나 특정 분석 목적에 필요한 데이터만 모아둔다.

```markdown id="lbmg2p"
데이터 마트 = 특정 주제나 부서의 분석을 위해 필요한 데이터를 선별·가공해 저장한 데이터 집합
```

예를 들어 회사 전체 데이터가 다음처럼 있다고 하자.

```markdown id="jj4zxa"
고객 데이터
상품 데이터
주문 데이터
결제 데이터
배송 데이터
마케팅 데이터
고객 문의 데이터
```

이 중에서 마케팅 부서가 고객 캠페인 분석을 하려면 모든 데이터가 필요한 것은 아니다.

```markdown id="1snq2c"
고객 정보
구매 이력
캠페인 참여 이력
쿠폰 사용 이력
방문 로그
```

이렇게 마케팅 분석에 필요한 데이터만 모아둔 것이 **마케팅 데이터 마트**라고 볼 수 있다.

---

# 01. 데이터 마트의 개념

## 데이터 마트의 정의

**데이터 마트(Data Mart)**는 데이터 웨어하우스나 운영 시스템에서 필요한 데이터를 추출하여, 특정 사용자나 특정 분석 목적에 맞게 구성한 소규모 데이터 저장소다.

데이터 웨어하우스가 기업 전체 데이터를 통합 관리하는 저장소라면,
데이터 마트는 특정 부서나 업무 영역에 초점을 맞춘 분석용 저장소다.

```markdown id="2pbbxx"
데이터 웨어하우스 = 전사 통합 데이터 저장소
데이터 마트 = 특정 부서나 주제 중심의 분석용 데이터 저장소
```

예를 들어 다음처럼 구분할 수 있다.

| 구분        | 예시                           |
| --------- | ---------------------------- |
| 데이터 웨어하우스 | 기업 전체 고객, 주문, 상품, 회계, 물류 데이터 |
| 데이터 마트    | 마케팅 분석용 고객 구매 데이터            |
| 데이터 마트    | 영업 분석용 매출 실적 데이터             |
| 데이터 마트    | 재무 분석용 비용·수익 데이터             |

---

## 데이터 마트가 필요한 이유

분석을 할 때 운영 시스템의 원본 데이터를 그대로 사용하는 것은 비효율적일 수 있다.

운영 시스템의 데이터는 업무 처리를 위해 설계되어 있기 때문에, 분석에 바로 사용하기에는 복잡하거나 불편한 경우가 많다.

```markdown id="snv13u"
운영 시스템 데이터 = 업무 처리 중심
데이터 마트 데이터 = 분석 활용 중심
```

예를 들어 주문 시스템의 데이터는 주문 등록, 결제 처리, 배송 상태 변경에는 적합하다.
하지만 “최근 6개월간 고객 등급별 구매 패턴”을 분석하려면 여러 테이블을 조인하고, 결측값을 처리하고, 분석용 변수도 만들어야 한다.

이런 작업을 매번 반복하면 비효율적이다.
그래서 분석 목적에 맞게 미리 데이터를 정리해 둔 데이터 마트가 필요하다.

---

# 02. 데이터 마트의 특징

| 특징      | 설명                         |
| ------- | -------------------------- |
| 주제 중심   | 특정 부서, 업무, 분석 목적에 맞게 구성    |
| 분석 목적   | 의사결정과 데이터 분석을 지원하기 위해 사용   |
| 소규모 저장소 | 전사 데이터 전체가 아니라 필요한 데이터만 포함 |
| 가공 데이터  | 원천 데이터를 분석하기 좋게 정제·통합·변환   |
| 빠른 접근   | 필요한 데이터만 모아두기 때문에 분석 속도 향상 |
| 사용자 친화적 | 현업이나 분석가가 이해하기 쉬운 형태로 제공   |

데이터 마트의 핵심은 **분석하기 쉽게 정리된 데이터**라는 점이다.

운영 시스템의 데이터를 그대로 가져오는 것이 아니라, 분석 목적에 맞게 데이터를 정제하고 구조화한다.

```markdown id="px5ixf"
데이터 마트는 원천 데이터를 분석 목적에 맞게 정제·가공한 분석용 데이터 집합이다.
```

---

# 03. 데이터 웨어하우스와 데이터 마트

## 데이터 웨어하우스의 개념

**데이터 웨어하우스(Data Warehouse, DW)**는 기업이나 조직 전체의 데이터를 통합하여 저장하는 대규모 데이터 저장소다.

여러 운영 시스템에서 발생한 데이터를 통합하고, 의사결정과 분석에 활용할 수 있도록 저장한다.

```markdown id="5cxj8o"
데이터 웨어하우스 = 전사적 의사결정을 위한 통합 데이터 저장소
```

---

## 데이터 웨어하우스와 데이터 마트 비교

| 구분     | 데이터 웨어하우스          | 데이터 마트                      |
| ------ | ------------------ | --------------------------- |
| 범위     | 전사 전체              | 특정 부서, 특정 주제                |
| 규모     | 대규모                | 상대적으로 소규모                   |
| 목적     | 전사적 의사결정 지원        | 특정 업무나 분석 지원                |
| 사용자    | 전사 사용자, 경영진, 분석 조직 | 특정 부서, 현업 담당자, 분석가          |
| 데이터 수준 | 통합 데이터             | 목적별 선별·가공 데이터               |
| 예시     | 전사 고객·매출·상품 통합 저장소 | 마케팅 고객 분석 데이터, 영업 매출 분석 데이터 |

시험에서는 이렇게 이해하면 된다.

```markdown id="hy3e1l"
DW는 전사 통합 데이터 저장소이고,
데이터 마트는 특정 부서나 주제 중심의 분석용 데이터 저장소이다.
```

---

# 04. 데이터 마트의 종류

데이터 마트는 생성 방식에 따라 크게 **종속 데이터 마트**와 **독립 데이터 마트**로 나눌 수 있다.

```markdown id="n1in5e"
종속 데이터 마트
독립 데이터 마트
```

---

## 1) 종속 데이터 마트

**종속 데이터 마트(Dependent Data Mart)**는 데이터 웨어하우스에서 필요한 데이터를 추출하여 만든 데이터 마트다.

즉, 전사 데이터 웨어하우스가 먼저 있고, 그 안에서 특정 부서나 주제에 필요한 데이터를 가져와 데이터 마트를 구성한다.

```markdown id="1aizmt"
운영 시스템 → 데이터 웨어하우스 → 종속 데이터 마트
```

| 구분     | 내용                    |
| ------ | --------------------- |
| 기준 데이터 | 데이터 웨어하우스             |
| 장점     | 데이터 일관성이 높음           |
| 단점     | 데이터 웨어하우스 구축이 선행되어야 함 |
| 특징     | 전사 표준 데이터 기반으로 구성     |

종속 데이터 마트는 데이터 웨어하우스를 기반으로 하므로 데이터 품질과 일관성을 유지하기 쉽다.

시험에서는 이렇게 이해하면 된다.

```markdown id="n61w5w"
종속 데이터 마트 = 데이터 웨어하우스에서 필요한 데이터를 추출해 만든 데이터 마트
```

---

## 2) 독립 데이터 마트

**독립 데이터 마트(Independent Data Mart)**는 데이터 웨어하우스를 거치지 않고, 운영 시스템이나 외부 데이터에서 직접 데이터를 가져와 만든 데이터 마트다.

```markdown id="5j5q9z"
운영 시스템 → 독립 데이터 마트
```

| 구분     | 내용                     |
| ------ | ---------------------- |
| 기준 데이터 | 운영 시스템 또는 외부 데이터       |
| 장점     | 빠르게 구축 가능              |
| 단점     | 부서별 데이터 기준이 달라질 수 있음   |
| 특징     | 특정 부서나 목적에 맞게 독립적으로 구성 |

독립 데이터 마트는 빠르게 만들 수 있지만, 여러 부서가 각각 독립적으로 만들면 데이터 기준이 달라질 수 있다.

예를 들어 마케팅팀과 영업팀이 각각 고객 수를 계산하는 기준이 다르면, 같은 회사 안에서도 서로 다른 숫자가 나올 수 있다.

시험에서는 이렇게 이해하면 된다.

```markdown id="lnfbtq"
독립 데이터 마트 = 데이터 웨어하우스 없이 운영 시스템이나 외부 데이터에서 직접 만든 데이터 마트
```

---

## 종속 데이터 마트와 독립 데이터 마트 비교

| 구분      | 종속 데이터 마트         | 독립 데이터 마트               |
| ------- | ----------------- | ----------------------- |
| 생성 방식   | 데이터 웨어하우스에서 추출    | 운영 시스템이나 외부 데이터에서 직접 추출 |
| 데이터 일관성 | 높음                | 낮아질 수 있음                |
| 구축 속도   | 상대적으로 느림          | 빠름                      |
| 장점      | 전사 기준과 표준 유지      | 빠른 분석 환경 구축 가능          |
| 단점      | DW 구축이 선행되어야 함    | 데이터 중복과 불일치 발생 가능       |
| 적합한 경우  | 전사 데이터 표준이 중요한 경우 | 특정 부서가 빠르게 분석해야 하는 경우   |

암기 방식은 다음과 같다.

```markdown id="igpteq"
종속 데이터 마트 = DW 기반, 일관성 높음
독립 데이터 마트 = 직접 구축, 빠르지만 불일치 위험
```

---

# 05. 데이터 마트 구축 절차

데이터 마트는 일반적으로 다음 흐름으로 구축된다.

```markdown id="43jx38"
요구사항 분석 → 데이터 수집 → 데이터 정제 → 데이터 변환 → 데이터 적재 → 데이터 활용
```

| 단계      | 설명                          |
| ------- | --------------------------- |
| 요구사항 분석 | 어떤 분석을 위해 어떤 데이터가 필요한지 정의   |
| 데이터 수집  | 운영 시스템, DW, 외부 데이터에서 데이터 추출 |
| 데이터 정제  | 결측값, 이상값, 중복 데이터 처리         |
| 데이터 변환  | 분석 목적에 맞게 변수 생성, 형식 변경, 집계  |
| 데이터 적재  | 분석용 저장소에 데이터 저장             |
| 데이터 활용  | 리포트, 대시보드, 통계 분석, 모델링에 활용   |

---

## 1) 요구사항 분석

분석 목적을 먼저 정의하는 단계다.

예를 들어 마케팅 캠페인 분석이 목적이라면 다음을 정해야 한다.

```markdown id="6a0wsp"
어떤 고객을 분석할 것인가?
어떤 기간의 구매 데이터를 볼 것인가?
캠페인 반응률을 어떻게 정의할 것인가?
고객 등급 기준은 무엇인가?
```

```markdown id="uxz6k3"
요구사항 분석 = 분석 목적과 필요한 데이터를 정의하는 단계
```

---

## 2) 데이터 수집

필요한 데이터를 운영 시스템, 데이터 웨어하우스, 외부 데이터 등에서 가져오는 단계다.

```markdown id="zt9eq2"
데이터 수집 = 분석에 필요한 원천 데이터를 확보하는 단계
```

---

## 3) 데이터 정제

수집한 데이터의 오류를 수정하고 품질을 높이는 단계다.

대표적인 정제 대상은 다음과 같다.

```markdown id="8hcv0b"
결측값
이상값
중복 데이터
형식 오류
불일치 데이터
```

```markdown id="3nyzxy"
데이터 정제 = 오류, 결측, 중복 등을 처리해 데이터 품질을 높이는 단계
```

---

## 4) 데이터 변환

데이터를 분석 목적에 맞게 가공하는 단계다.

예를 들어 다음 작업이 포함된다.

```markdown id="ly2skx"
날짜 데이터를 월 단위로 변환
구매 금액을 고객별로 집계
나이를 연령대로 변환
고객 등급 변수 생성
여러 테이블을 조인해 분석용 데이터셋 생성
```

```markdown id="dldtnl"
데이터 변환 = 분석 목적에 맞게 데이터 형식과 구조를 바꾸는 단계
```

---

## 5) 데이터 적재

정제·변환된 데이터를 데이터 마트에 저장하는 단계다.

```markdown id="adlvh9"
데이터 적재 = 분석용 저장소에 데이터를 저장하는 단계
```

---

## 6) 데이터 활용

구축된 데이터 마트를 이용해 분석, 리포트, 대시보드, 모델링을 수행한다.

```markdown id="y4zarf"
데이터 활용 = 데이터 마트를 이용해 의사결정과 분석을 수행하는 단계
```

---

# 06. ETL

## ETL의 개념

데이터 마트를 만들 때 자주 등장하는 개념이 **ETL**이다.

**ETL**은 Extract, Transform, Load의 약자다.

```markdown id="gv00sz"
ETL = Extract + Transform + Load
```

| 단계        | 의미 | 설명                             |
| --------- | -- | ------------------------------ |
| Extract   | 추출 | 원천 시스템에서 필요한 데이터를 가져옴          |
| Transform | 변환 | 분석 목적에 맞게 정제, 가공, 통합           |
| Load      | 적재 | 변환된 데이터를 데이터 웨어하우스나 데이터 마트에 저장 |

ETL은 운영 시스템의 데이터를 분석용 저장소로 옮기기 위한 핵심 과정이다.

---

## ETL 단계별 설명

### 1) Extract, 추출

원천 데이터베이스, 파일, API, 외부 시스템 등에서 필요한 데이터를 가져오는 단계다.

```markdown id="3xabxh"
Extract = 원천 시스템에서 데이터를 가져오는 단계
```

---

### 2) Transform, 변환

추출한 데이터를 분석 목적에 맞게 정제하고 변환하는 단계다.

결측값 처리, 이상값 처리, 코드 변환, 단위 변환, 테이블 조인, 집계 등이 포함된다.

```markdown id="y6l9vy"
Transform = 데이터를 분석 가능한 형태로 정제·가공하는 단계
```

---

### 3) Load, 적재

변환된 데이터를 데이터 웨어하우스나 데이터 마트에 저장하는 단계다.

```markdown id="q6si11"
Load = 변환된 데이터를 분석용 저장소에 저장하는 단계
```

---

## ETL 암기

```markdown id="tqq1iu"
ETL은 Extract, Transform, Load의 약자로,
데이터를 추출하고, 분석 목적에 맞게 변환한 뒤, 분석용 저장소에 적재하는 과정이다.
```

# 07. 요약 변수와 파생 변수

데이터 마트에서는 분석을 쉽게 하기 위해 **요약 변수**와 **파생 변수**를 생성하는 경우가 많다.

이 둘은 시험에서도 자주 구분된다.

---

## 1) 요약 변수

### 요약 변수의 개념

**요약 변수**는 원래 데이터의 정보를 집계하여 만든 변수다.

예를 들어 고객의 주문 내역이 여러 건 있을 때, 이를 고객 단위로 요약할 수 있다.

```markdown id="s6p34c"
고객별 총 구매 금액
고객별 평균 구매 금액
고객별 구매 횟수
최근 3개월 구매 금액
최근 1년 방문 횟수
```

이런 변수들은 기존 데이터를 집계해서 만든 값이다.

```markdown id="hjwwxn"
요약 변수 = 여러 데이터를 집계하여 만든 변수
```

---

### 요약 변수 예시

| 원천 데이터     | 요약 변수       |
| ---------- | ----------- |
| 주문 금액 여러 건 | 총 구매 금액     |
| 방문 로그 여러 건 | 방문 횟수       |
| 상품 구매 기록   | 구매 상품 수     |
| 결제 기록      | 평균 결제 금액    |
| 최근 구매일     | 최근 구매 후 경과일 |

요약 변수는 고객 행동이나 상태를 압축해서 표현할 때 유용하다.

---

## 2) 파생 변수

### 파생 변수의 개념

**파생 변수**는 기존 변수들을 활용하여 새롭게 만들어낸 변수다.

단순 집계보다는 분석 목적에 맞는 의미를 부여해서 만든 값이라고 보면 된다.

예를 들어 다음과 같다.

```markdown id="ofws6l"
나이 → 연령대
구매 금액 + 구매 횟수 → 고객 등급
최근 구매일 → 휴면 고객 여부
키와 몸무게 → BMI
캠페인 참여 횟수 → 캠페인 반응도
```

```markdown id="e9vxow"
파생 변수 = 기존 변수를 조합하거나 변환하여 새롭게 만든 변수
```

---

### 파생 변수 예시

| 기존 변수        | 파생 변수 |
| ------------ | ----- |
| 생년월일         | 나이    |
| 나이           | 연령대   |
| 구매 금액, 구매 횟수 | 고객 등급 |
| 최근 구매일       | 휴면 여부 |
| 키, 몸무게       | BMI   |

---

## 요약 변수와 파생 변수 비교

| 구분 | 요약 변수                    | 파생 변수                  |
| -- | ------------------------ | ---------------------- |
| 의미 | 데이터를 집계해서 만든 변수          | 기존 변수를 가공·조합해 만든 변수    |
| 핵심 | 집계                       | 변환·조합                  |
| 예시 | 총 구매 금액, 평균 구매 금액, 구매 횟수 | 연령대, 고객 등급, 휴면 여부, BMI |
| 목적 | 데이터를 압축해 요약              | 분석에 유용한 새로운 의미 생성      |

시험에서는 이렇게 구분하면 된다.

```markdown id="wcwvlf"
요약 변수 = 집계해서 만든 변수
파생 변수 = 가공하거나 조합해서 만든 변수
```

# 08. reshape 패키지

ADsP R 기초 파트에서는 데이터 마트와 함께 `reshape` 패키지 개념이 나올 수 있다.

`reshape`는 데이터를 분석하기 좋은 형태로 바꾸는 데 사용하는 패키지다.

특히 `melt()`와 `cast()` 개념이 중요하다.

```markdown id="egvpoc"
reshape 패키지 = 데이터 구조를 변환하는 패키지
```

---

## 1) melt

**melt()**는 넓은 형태의 데이터를 긴 형태로 변환하는 함수다.

즉, 여러 열로 퍼져 있는 데이터를 변수명과 값의 형태로 녹여서 정리한다.

### 예시

넓은 형태 데이터:

| 이름  | 국어 | 영어 | 수학 |
| --- | -: | -: | -: |
| kim | 90 | 80 | 70 |
| lee | 85 | 75 | 95 |

melt 후 긴 형태:

| 이름  | 과목 | 점수 |
| --- | -- | -: |
| kim | 국어 | 90 |
| kim | 영어 | 80 |
| kim | 수학 | 70 |
| lee | 국어 | 85 |
| lee | 영어 | 75 |
| lee | 수학 | 95 |

```markdown id="19key0"
melt() = 넓은 형태의 데이터를 긴 형태로 변환
```

---

## 2) cast

**cast()**는 긴 형태의 데이터를 다시 넓은 형태로 변환하거나, 원하는 기준으로 집계하는 함수다.

즉, melt로 녹인 데이터를 다시 행과 열 구조로 재구성할 때 사용한다.

```markdown id="xma51i"
cast() = 긴 형태의 데이터를 넓은 형태로 재구성하거나 집계
```

---

## melt와 cast 비교

| 함수       | 핵심       | 방향           |
| -------- | -------- | ------------ |
| `melt()` | 데이터를 녹임  | 넓은 형태 → 긴 형태 |
| `cast()` | 데이터를 재구성 | 긴 형태 → 넓은 형태 |

시험에서는 이렇게 암기하면 된다.

```markdown id="y8qs6x"
melt는 녹여서 길게 만들고,
cast는 다시 틀에 맞춰 넓게 만든다.
```

# 09. sqldf 패키지

`sqldf` 패키지는 R에서 SQL 문법을 사용해 데이터프레임을 다룰 수 있게 해주는 패키지다.

```markdown id="md74t3"
sqldf = R 데이터프레임에 SQL 질의를 적용할 수 있게 해주는 패키지
```

예를 들어 데이터프레임에서 특정 조건의 행을 조회하거나, 그룹별 집계를 할 수 있다.

```r id="ixuv2f"
library(sqldf)

sqldf("select * from df where score >= 80")
```

SQL에 익숙한 사람은 R 문법보다 SQL로 데이터를 다루는 것이 편할 수 있다.

---

## sqldf 사용 예시

| SQL 기능     | 설명          |
| ---------- | ----------- |
| `select`   | 필요한 열 선택    |
| `where`    | 조건에 맞는 행 선택 |
| `group by` | 그룹별 집계      |
| `order by` | 정렬          |
| `join`     | 데이터프레임 결합   |

시험에서는 깊은 SQL 문법보다, `sqldf`가 무엇을 하는 패키지인지 정도를 기억하면 된다.

```markdown id="epg1f5"
sqldf는 R에서 SQL을 사용해 데이터프레임을 조회·가공할 수 있게 해주는 패키지이다.
```

# 10. plyr 패키지

`plyr` 패키지는 데이터를 분할하고, 함수를 적용한 뒤, 다시 결합하는 작업을 지원하는 패키지다.

핵심 구조는 **Split - Apply - Combine**이다.

```markdown id="hwphrb"
plyr = 데이터를 분할하고, 함수를 적용하고, 결과를 결합하는 패키지
```

---

## Split - Apply - Combine

| 단계      | 설명              |
| ------- | --------------- |
| Split   | 데이터를 그룹별로 나눈다   |
| Apply   | 각 그룹에 함수를 적용한다  |
| Combine | 결과를 다시 하나로 결합한다 |

예를 들어 고객 데이터를 성별로 나누고, 각 성별의 평균 구매 금액을 계산한 뒤, 결과를 다시 하나의 표로 합치는 방식이다.

```markdown id="xkeqgo"
plyr의 핵심 = Split → Apply → Combine
```

---

## plyr의 주요 함수

`plyr` 함수는 입력과 출력 형태에 따라 이름이 달라진다.

| 함수        | 입력     | 출력     | 설명                               |
| --------- | ------ | ------ | -------------------------------- |
| `ddply()` | 데이터프레임 | 데이터프레임 | 데이터프레임을 그룹별로 나누고 결과를 데이터프레임으로 반환 |
| `ldply()` | 리스트    | 데이터프레임 | 리스트를 처리하여 데이터프레임으로 반환            |
| `daply()` | 데이터프레임 | 배열     | 데이터프레임을 처리하여 배열로 반환              |

시험에서는 `ddply()`를 가장 많이 기억하면 된다.

```markdown id="3gkcid"
ddply() = 데이터프레임을 입력받아 그룹별 연산 후 데이터프레임으로 반환
```

---

# 데이터 마트 관련 패키지 정리

| 패키지     | 핵심                  | 주요 기능                                 |
| ------- | ------------------- | ------------------------------------- |
| reshape | 데이터 구조 변환           | `melt()`, `cast()`                    |
| sqldf   | SQL로 데이터프레임 처리      | `select`, `where`, `group by`, `join` |
| plyr    | Split-Apply-Combine | `ddply()` 등 그룹별 처리                    |

시험에서는 패키지 이름과 역할을 연결해서 기억하면 된다.

```markdown id="y2oxie"
reshape = 데이터 형태 변환
sqldf = SQL로 데이터프레임 처리
plyr = 데이터를 나누고 적용하고 결합
```

# 시험 직전 암기 문장

```markdown id="m7wky0"
데이터 마트는 특정 부서나 특정 분석 목적을 위해
필요한 데이터를 선별하고 가공하여 저장한 분석용 데이터 저장소이다.

데이터 웨어하우스가 전사 통합 데이터 저장소라면,
데이터 마트는 특정 주제나 부서 중심의 소규모 분석용 저장소이다.

데이터 마트는 운영 시스템이나 데이터 웨어하우스의 데이터를
분석 목적에 맞게 정제, 통합, 변환하여 구성한다.

종속 데이터 마트는 데이터 웨어하우스에서 필요한 데이터를 추출하여 만든 데이터 마트이며,
데이터 일관성이 높다는 장점이 있다.

독립 데이터 마트는 데이터 웨어하우스를 거치지 않고
운영 시스템이나 외부 데이터에서 직접 데이터를 가져와 만든 데이터 마트이며,
빠르게 구축할 수 있지만 데이터 중복과 불일치가 발생할 수 있다.

ETL은 Extract, Transform, Load의 약자로,
원천 시스템에서 데이터를 추출하고, 분석 목적에 맞게 변환한 뒤,
데이터 웨어하우스나 데이터 마트에 적재하는 과정이다.

요약 변수는 여러 데이터를 집계하여 만든 변수이며,
총 구매 금액, 평균 구매 금액, 구매 횟수 등이 해당한다.

파생 변수는 기존 변수를 가공하거나 조합하여 새롭게 만든 변수이며,
연령대, 고객 등급, 휴면 여부, BMI 등이 해당한다.

reshape 패키지는 데이터의 형태를 변환하는 패키지이며,
melt는 넓은 형태의 데이터를 긴 형태로 변환하고,
cast는 긴 형태의 데이터를 넓은 형태로 재구성하거나 집계한다.

sqldf 패키지는 R에서 SQL 문법을 사용해 데이터프레임을 조회하고 가공할 수 있게 해주는 패키지이다.

plyr 패키지는 데이터를 나누고, 함수를 적용하고, 결과를 결합하는
Split-Apply-Combine 방식의 데이터 처리를 지원하는 패키지이다.
```
