## 060. 데이터베이스 설계
### 1. 개념적 설계(정보 모델링, 개념화)
- 정보의 구조를 얻기 위하여 현실 세계의무한성과 계속성을 이해하고, 다른 사람과 통신하기 위하여 현실 세계에 대한 인식을 추상적 개념으로 표현하는 과정이다. 
- 요구 분석 단계에서 나온 결과인 요구 조건 명세를 DBMS에 독립적인 E-R 다이어그램으로 작성한다.
- DBMS에 독립적인 개념 스키마를 설계한다.

### 2. 논리적 설계(데이터 모델링)
- 특정 DBMS가 지원하는 논리적 자료 구조로 변환(Mapping)시키는 과정이다.
- 개념 스키마를 평가 및 정제하고 DBMS에 따라 서로 다른 논리적 스키마를 설계하는 단계이다.
- 트랜잭션의 인터페이스를 설계한다.

### 3. 물리적 설계(데이터 구조화)
- 논리적 설계 단계에서 논리적 구조로 표현된 데이터를 디스크 등의 물리적 저장장치에 저장할 수 있는 물리적 구조의 데이터로 변환하는 과정이다.
- 다양한 데이터베이스 응용에 대해 처리 성능을 얻기 위해 데이터베이스 응용에 대해 처리 성능을 얻기 위해 데이터베이스 파일의 저장 구조 및 액세스 경로를 결정한다.
- 저장 레코드의 형식, 순서, 접근 경로, 조회가 집중되는 레코드와 같은 정보를 사용하여 데이터가 컴퓨터에 저장되는 방법을 묘사한다.
- 물리적 설계 시 고려할 사항
    - 트랜잭션 처리량
    - 응답 시간
    - 디스크 용량
    - 저장 공간의 효율화 등

## 061. 데이터 모델의 개념
### 1. 관계의 형태
- 일 대 일(1 : 1) : 개체 집합 A의 각 원소가 개체 집합 B의 원소 한 개와 대응하는 관계
- 일 대 다(1 : N) : 개체 집합 A의 각 원소는 개체 집합 B의 원소 여러 개와 대응하고 있지만, 개체 집합 B의 각 원소는 개체 집합 A의 원소 한 개와 대응하는 관계
- 다 대 다(N : M) : 개체 집합 A의 각 원소는 개체 집합 B의 원소 여러 개와 대응하고, 개체 집합 B의 객체 집합 B의 원소 여러 개와 대응하고, 개체 집합 B의 각 원소도 개체 집합 A의 여러 개와 대응하는 관계

### 2. 데이터 모델에 표시할 요소
- 구조(Structure) : 논리적으로 표현된 개체 타입들 간의 관계로서 데이터 구조 및 정적 성질을 표현함
- 연산(Operation) : 데이터베이스에 저장된 실제 데이터를 처리하는 작업에 대한 명세로서 데이터베이스를 조작하는 기본 도구임
- 제약 조건(Constraint) : 데이터베이스에 저장될 수 있는 실제 데이터의 논리적인 제약 조건입니다.

## 062. E-R(개체-관계) 모델
### 1. E-R 다이어그램(Entity-Relationship Diagram)
| 기호           | 명칭                              | 의미                       |
| ------------ | ------------------------------- | ------------------------ |
| ▭ **사각형**    | 개체(Entity)                      | 현실 세계에서 독립적으로 존재하는 객체    |
| ◇ **마름모**    | 관계(Relationship)                | 개체와 개체 사이의 연관 관계         |
| ◯ **타원**     | 속성(Attribute)                   | 개체가 가지고 있는 특성            |
| ◎ **이중 타원**  | 다중값 속성(Multivalued Attribute)   | 하나의 속성이 여러 개의 값을 가질 수 있음 |
| ⋯◯ **점선 타원** | 유도 속성(Derived Attribute)        | 다른 속성으로부터 계산되어 얻어지는 속성   |
| **밑줄 친 속성**  | 기본키 속성(Key Attribute)           | 개체를 유일하게 식별하는 속성         |
| ▣ **이중 사각형** | 약한 개체(Weak Entity)              | 자체 속성만으로 식별할 수 없는 개체     |
| ◈ **이중 마름모** | 식별 관계(Identifying Relationship) | 약한 개체와 강한 개체 사이의 식별 관계   |
| ─ **실선**     | 연결선(Link)                       | 개체·속성·관계 사이의 연결을 표현      |
| ═ **이중선**    | 전체 참여(Total Participation)      | 모든 개체가 해당 관계에 반드시 참여함    |

## 063. 관계형 데이터베이스의 구조
### 1. 릴레이션(Relation)
데이터들은 표(Table)의 형태로 표현한 것으로 구조를 나타내는 릴레이션 스키마와 실제 값들인 릴레이션 인스턴스로 구성된다.

### 2. 튜플(Tuple)
- 릴레이션을 구성하는 각각의 행이다.
- 튜플의 수 = 카디널리티(Cardinality) = 기수 = 대응수

### 3. 속성(Attribute)
- 데이터베이스를 구성하는 가장 작은 논리적 단위이다.
- 속성의 수 = 디그리(Degree) = 차수

### 4. 도메인(Domain)
하나의 애트리뷰트가 취할 수 있는 같은 타입의 원자(Atomic) 값들의 집합이다.

### 5. 릴레이션의 특징
- 한 릴레이션에 포함된 튜플들은 모두 상이하다.
- 한 릴레이션에 포함된 튜플 사이에는 순서가 없다.
- 튜플들의 삽입, 삭제 등의 작업으로 인해 릴레이션은 시간에 따라 변한다.
- 릴레이션 스키마를 구성하는 속성들 간의 순서는 중요하지 않다.
- 속성의 요일한 식별을 위해 속성의 명칭은 유일해야 하지만, 속성을 구성하는 값은 동일한 값이 있을 수 있다.
- 속성은 더 이상 쪼갤 수 없는 원자값만을 저장한다.

## 064. 관계형 데이터베이스의 제약 조건 - 키(Key)
### 1. 후보키(Candidate Key)
- 릴레이션을 구성하는 속성들 중에서 튜플을 유일하게 식별하기 위해 사용하는 속성들의 부분집합이다.
- 릴레이션에 있는 모든 튜플에 대해서 유일성과 최소소엉을 만족시켜야 한다.

### 2. 기본키(Primary Key)
- 후보키 중에서 특별히 선정된 주키(Main Key)로 중복된 값을 가질 수 없다.
- 한 릴레이션에서 특정 튜플을 유일하게 구별할 수 있는 속성이다.

### 3. 대체키(Alternate Key)
후보키가 둘 이상일 때 기본키를 제외한 나머지 후보키를 의미하며, 보조키라고도 합니다.

### 4. 슈퍼키(Super Key)
- 한 릴레이션 내에 있는 속성들의 집합으로 구성된 키이다.
- 릴레이션을 구성하는 모든 튜플에 대해 유일성은 만족시키짐만, 최소성은 만족시키지 못한다.

### 5. 외래키(Foreign Key)
- 다른 릴레이션의 기본키를 참조하는 속성 또는 속성들의 집합을 의미한다.
- 한 릴레이션에 속한 속성 A와 참조 릴레이션의 기본키인 B가 도메인 상에서 정의되었을 때의 속성 A를 외래키라고 한다.

## 065. 관계형 데이터베이스의 제약 조건 - 무결성
### 1. 개체 무결성(Entity Integrity, 실체 무결성)
기본 테이블의 기본키를 구성하는 어떤 속성도 Null 값이나 중복값을 가질 수 없다는 규정이다.

### 2. 도메인 무결성(Domain Integrity, 영역 무결성)
주어진 속성 값이 정의된 도메인에 속한 값이어야 한다는 규정이다.

### 3. 참조 무결성(Referential Integrity)
외래키 값은 Null이거나 참조 릴레이션의 기본키 값과 동일해야 한다. 즉 릴레이션은 참조할 수 없는 외래키 값을 가질 수 없다는 규정이다.

### 4. 사용자 정의 무결성(User-Defined Integrity)
속성 값들이 사용자가 정의한 제약 조건에 만족해야 한다는 규정이다.

## 066. 관계대수 및 관계해석
### 1. 관계대수의 개요
- 관계형 데이터베이스에서 원하는 정보와 그 정보를 어떻게 유도하는가를 기술하는 절차적인 언어이다.
- 릴레이션을 처리하기 위해 연산자와 연산규칙을 제공하는 언어로 피연선자가 릴레이션이고, 결과도 릴레이션이다.
- 질의에 대한 해를 구하기 위해 수행해야 하는 연산의 순서를 명시한다.

### 2. 순수 관계 연산자

### 2. 순수 관계 연산자

순수 관계 연산자는 **관계형 데이터베이스에서 릴레이션을 처리하기 위해 사용하는 관계 대수 연산자**이다.

| 연산자          | 기호          | 의미                            | 예시                      |
| ------------ | ----------- | ----------------------------- | ----------------------- |
| **SELECT**   | ( \sigma )  | 릴레이션에서 **조건을 만족하는 튜플(행)**을 선택 | (\sigma_{학과='컴퓨터'}(학생)) |
| **PROJECT**  | ( \pi )     | 릴레이션에서 필요한 **속성(열)**만 선택      | (\pi_{이름, 학과}(학생))      |
| **JOIN**     | ( \bowtie ) | 두 릴레이션의 관련 있는 튜플을 **하나로 결합**  | (학생 \bowtie 수강)         |
| **DIVISION** | ( \div )    | 특정 조건을 **모두 만족하는 튜플**을 검색     | (수강 \div 필수과목)          |

### 핵심 정리

| 연산           | 기준                 |
| ------------ | ------------------ |
| **SELECT**   | 행(Row) 선택          |
| **PROJECT**  | 열(Column) 선택       |
| **JOIN**     | 릴레이션 결합            |
| **DIVISION** | 조건을 모두 만족하는 데이터 검색 |

```text
SELECT   → 행을 고른다
PROJECT  → 열을 고른다
JOIN     → 테이블을 합친다
DIVISION → 모두 만족하는 데이터를 찾는다
```

### 3. 일반 집합 연산자
### 3. 일반 집합 연산자

일반 집합 연산자는 **수학의 집합 연산을 관계형 데이터베이스의 릴레이션에 적용한 연산자**이다.

| 연산자                             | 기호         | 의미                                        | 특징                       |
| ------------------------------- | ---------- | ----------------------------------------- | ------------------------ |
| **합집합(UNION)**                  | ( \cup )   | 두 릴레이션에 존재하는 **모든 튜플**을 반환                | 중복 튜플은 제거                |
| **교집합(INTERSECTION)**           | ( \cap )   | 두 릴레이션에 **공통으로 존재하는 튜플**을 반환              | 공통 데이터만 조회               |
| **차집합(DIFFERENCE)**             | ( - )      | 첫 번째 릴레이션에는 있지만 두 번째 릴레이션에는 **없는 튜플**을 반환 | 순서에 따라 결과가 달라짐           |
| **카티션 프로덕트(CARTESIAN PRODUCT)** | ( \times ) | 두 릴레이션의 **모든 튜플 조합**을 반환                  | 결과 튜플 수 = 두 릴레이션 튜플 수의 곱 |

### 핵심 정리

| 연산           | 의미               |
| ------------ | ---------------- |
| (R \cup S)   | R 또는 S에 존재하는 튜플  |
| (R \cap S)   | R과 S에 모두 존재하는 튜플 |
| (R - S)      | R에는 있고 S에는 없는 튜플 |
| (R \times S) | R과 S의 모든 가능한 조합  |

### 연산 가능 조건

**합집합, 교집합, 차집합**을 수행하려면 두 릴레이션이 **합병 가능(Union Compatible)**해야 한다.

* 속성(Attribute)의 개수가 같아야 한다.
* 대응되는 속성의 도메인(Domain)이 같아야 한다.

예를 들어,  

R = {A, B, C}

S = {B, C, D}

이라면,

R ∪ S = {A, B, C, D}

R ∩ S = {B, C}

R − S = {A}

으로 이해하면 됩니다.

### 4. 관계 해석(Relational Calculus)
- 코드(E, F, Codd)가 수학의 Predicate Calculus(술어 해석)에 기반을 두고 관계 데이터베이스를 위해 제안했다.
- 관계해석은 웧나는 정보가 무엇이라는 것만 정의하는 비차별적 특성을 지닌다.
- 기본적으로 관계해석과 관계대수는 관계 데이터베이스를 처리하는 기능과 능력면에서 동등하다.
- 주요 논리 기호  
    | 논리 기호 | 명칭                             | 의미                   | 표현        |
    | ----- | ------------------------------ | -------------------- | --------- |
    | ∧     | AND(논리곱)                       | 두 조건을 모두 만족          | A이고 B     |
    | ∨     | OR(논리합)                        | 두 조건 중 하나 이상 만족      | A 또는 B    |
    | ¬     | NOT(부정)                        | 조건의 결과를 반대로 표현       | A가 아니다    |
    | ∀     | 전칭 정량자(Universal Quantifier)   | 모든 값에 대하여 조건이 성립     | 모든 x에 대하여 |
    | ∃     | 존재 정량자(Existential Quantifier) | 조건을 만족하는 값이 하나 이상 존재 | 어떤 x가 존재  |


## 067. 정규화(Normalization)
### 1. 정규화의 개요
- 함수의 종속성 등의 종속성 이론을 이용하여 잘못 설계된 관계형 스키마를 더 작은 속성의 세트로 쪼개어 바람직한 스키마로 만들어가는 과정이다.
- 하나의 종속성이 하나의 릴레이션에 표현될 수 있도록 분해해가는 과정이라고 할 수 있다.
- 정규화는 데이터베이스의 논리적 설계 단계에서 수행 한다.

### 2. 정규화의 목적

정규화(Normalization)는 **관계형 데이터베이스에서 데이터의 중복을 최소화하고 이상 현상을 방지하기 위해 릴레이션을 분해하는 과정**이다.

| 목적              | 설명                           |
| --------------- | ---------------------------- |
| **데이터 중복 최소화**  | 동일한 데이터가 여러 곳에 반복 저장되는 것을 줄임 |
| **이상 현상 방지**    | 삽입, 삭제, 갱신 과정에서 발생하는 문제를 방지  |
| **데이터 무결성 유지**  | 데이터의 일관성과 정확성을 유지            |
| **효율적인 데이터 구조** | 속성과 릴레이션을 논리적으로 구성           |
| **유지보수 용이성 향상** | 데이터 변경 및 관리가 쉬워짐             |

> **핵심:** 정규화 = 데이터 중복 제거 + 이상 현상 방지 + 데이터 무결성 향상

---

### 3. 이상(Anomaly)의 개념 및 종류

이상(Anomaly)은 **정규화가 제대로 이루어지지 않은 릴레이션에서 데이터의 삽입·삭제·갱신 시 발생하는 비정상적인 현상**이다.

| 종류                           | 의미                                         | 예시                           |
| ---------------------------- | ------------------------------------------ | ---------------------------- |
| **삽입 이상(Insertion Anomaly)** | 불필요한 데이터를 함께 입력하지 않으면 원하는 데이터를 삽입할 수 없는 현상 | 수강생이 없는 과목 정보를 등록할 수 없음      |
| **삭제 이상(Deletion Anomaly)**  | 특정 데이터를 삭제할 때 필요한 다른 데이터까지 함께 삭제되는 현상      | 마지막 수강생을 삭제했더니 과목 정보까지 삭제됨   |
| **갱신 이상(Update Anomaly)**    | 중복된 데이터 중 일부만 수정되어 데이터가 불일치하게 되는 현상        | 동일한 교수 이름이 여러 행에 있는데 일부만 수정됨 |

#### 핵심 정리

```text
삽입 이상 → 필요 없는 데이터까지 입력해야 함
삭제 이상 → 필요한 데이터까지 같이 삭제됨
갱신 이상 → 중복 데이터의 값이 서로 달라짐
```

### 4. 정규화의 과정

정규화는 **함수적 종속성과 데이터의 중복 구조를 분석하여 단계적으로 릴레이션을 분해하는 과정**이다.

```text
비정규 릴레이션
      ↓
제1정규형(1NF)
      ↓
제2정규형(2NF)
      ↓
제3정규형(3NF)
      ↓
BCNF
      ↓
제4정규형(4NF)
      ↓
제5정규형(5NF)
```

| 정규형            | 제거 대상           | 설명                                       |
| -------------- | --------------- | ---------------------------------------- |
| **제1정규형(1NF)** | 반복 속성, 다중값      | 모든 속성의 값이 **원자값(Atomic Value)**을 가지도록 구성 |
| **제2정규형(2NF)** | 부분 함수적 종속       | 기본키의 일부에만 종속되는 속성을 제거                    |
| **제3정규형(3NF)** | 이행 함수적 종속       | 기본키가 아닌 속성 간의 종속 관계를 제거                  |
| **BCNF**       | 결정자가 후보키가 아닌 종속 | 모든 결정자가 후보키가 되도록 구성                      |
| **제4정규형(4NF)** | 다치 종속           | 하나의 속성이 여러 독립적인 값을 결정하는 다치 종속을 제거        |
| **제5정규형(5NF)** | 조인 종속           | 불필요한 조인 종속을 제거                           |

#### 정규화 과정 암기

```text
1NF → 도메인이 원자값
2NF → 부분 함수적 종속 제거
3NF → 이행 함수적 종속 제거
BCNF → 결정자가 후보키
4NF → 다치 종속 제거
5NF → 조인 종속 제거
```

### 5. 함수적 종속(Functional Dependency)

함수적 종속은 **어떤 속성의 값이 결정되면 다른 속성의 값도 유일하게 결정되는 관계**를 의미한다.

다음과 같이 표현한다.

```text
X → Y
```

이는 **X의 값이 결정되면 Y의 값도 결정된다**는 의미이다.

* **X** : 결정자(Determinant)
* **Y** : 종속자(Dependent)

예를 들어,

```text
학번 → 이름
학번 → 학과
```

학번이 결정되면 해당 학생의 이름과 학과가 결정되므로 함수적 종속 관계가 성립한다.

| 종류            | 의미                         | 예시                     |
| ------------- | -------------------------- | ---------------------- |
| **완전 함수적 종속** | 속성이 기본키 전체에 종속             | {학번, 과목번호} → 성적        |
| **부분 함수적 종속** | 복합 기본키의 일부에만 종속            | {학번, 과목번호}에서 학번 → 학생이름 |
| **이행 함수적 종속** | X → Y이고 Y → Z일 때 X → Z가 성립 | 학번 → 학과코드 → 학과명        |

### 완전 함수적 종속

복합키 전체가 있어야 특정 속성을 결정할 수 있는 경우이다.

```text
{학번, 과목번호} → 성적
```

학번만으로는 성적을 알 수 없고, 과목번호만으로도 알 수 없다. **학번과 과목번호가 모두 있어야 성적을 결정**할 수 있다.

### 부분 함수적 종속

복합키 전체가 아닌 **일부 속성만으로도 다른 속성을 결정할 수 있는 경우**이다.

```text
{학번, 과목번호} → 학생이름

실제로는

학번 → 학생이름
```

따라서 `학생이름`은 복합키 전체가 아닌 `학번`에 부분적으로 종속되어 있다.

### 이행 함수적 종속

어떤 속성이 다른 속성을 거쳐 간접적으로 종속되는 관계이다.

```text
학번 → 학과코드
학과코드 → 학과명

따라서

학번 → 학과명
```

### 함수적 종속과 정규화의 관계

| 종속 관계       | 제거되는 정규화 단계 |
| ----------- | ----------- |
| 반복값 / 비원자값  | **1NF**     |
| 부분 함수적 종속   | **2NF**     |
| 이행 함수적 종속   | **3NF**     |
| 후보키가 아닌 결정자 | **BCNF**    |
| 다치 종속       | **4NF**     |
| 조인 종속       | **5NF**     |

## 069. 시스템 카탈로그
### 1. 시스템 카탈로그(System Catalog)
- 시스템 그 자체에 관련이 있는 다양한 객체에 관한 정보를 포함하는 시스템 데이터베이스이다.
- 좁은 의미로는 데이터 사전(Data Dictionary)라고도 한다.
- 시스템 카탈로그에 저장된 정보를 메타 데이터(Meta-Data)라고 한다.
- 카탈로그 자체도 시스템 테이블로 구성되어 있어 일반 이용자도 SQL을 이용하여 내용을 검색해 볼 수 있다.
- INSERT, DELETE, UPDATE문으로 카탈로그를 갱신하는 것은 허용되지 않는다.
