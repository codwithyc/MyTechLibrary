## 001. 한글 Windows 10의 특징

### 1. 그래픽 사용자 인터페이스(GUI)

키보드로 명령어를 직접 입력하지 않고, 아이콘이나 메뉴를 마우스로 선택하여 작업을 수행하는 방식입니다.

- 대표적인 조작 방법은 **마우스 클릭, 드래그 앤 드롭(Drag & Drop)** 입니다.

#### 왜 GUI 방식이 필요했을까?

과거 MS-DOS처럼 명령어를 직접 입력하는 방식(CUI)은 사용자가 명령어를 전부 외우고 있어야 했습니다.  
그래서 컴퓨터를 처음 접하는 사람은 무엇을 어떻게 해야 하는지조차 알기 어려웠습니다.

반면 GUI는 **할 수 있는 일이 화면에 그림으로 보이기 때문에**, 사용자가 외우지 않아도 직관적으로 조작할 수 있습니다.

즉, GUI는  
**컴퓨터 사용의 진입 장벽을 낮추기 위해 등장한 인터페이스 방식**입니다.

---

### 2. 선점형 멀티태스킹(Preemptive Multitasking)

운영체제가 각 작업의 CPU 이용 시간을 직접 제어하여, 여러 개의 프로그램을 동시에 실행하는 방식입니다.

- 응용 프로그램 실행 중 문제가 발생하면 **해당 프로그램만 강제 종료**하고, 나머지 프로그램은 계속 실행됩니다.
- 시스템 전체가 다운되는 현상을 방지할 수 있습니다.

#### 왜 "선점형"이라는 말이 붙을까?

선점형(Preemptive)이란 **운영체제가 CPU 사용권을 빼앗을 수 있다**는 뜻입니다.

비선점형(Non-preemptive) 방식에서는 프로그램이 스스로 CPU를 반납할 때까지 운영체제가 기다려야 합니다.  
그래서 어떤 프로그램 하나가 멈춰버리면 CPU를 계속 붙잡고 있어, 시스템 전체가 멈추게 됩니다.

선점형 방식은 운영체제가 강제로 CPU를 회수할 수 있으므로,  
**문제가 생긴 프로그램 하나 때문에 전체가 멈추는 상황을 막을 수 있습니다.**

즉, 선점형 멀티태스킹의 핵심은 "동시 실행"이 아니라 **"주도권이 운영체제에 있다"** 는 점입니다.

---

### 3. PnP(Plug and Play, 자동 감지 기능)

컴퓨터에 새로운 하드웨어를 설치할 때, 운영체제가 이를 자동으로 감지하여 드라이버를 설치하고 환경을 설정해 주는 기능입니다.

- **운영체제와 하드웨어 모두 PnP를 지원해야** 정상적으로 동작합니다.
- PnP를 지원하지 않는 장치는 사용자가 직접 드라이버를 설치해야 합니다.

#### 왜 PnP가 필요할까?

PnP가 없던 시절에는 하드웨어를 하나 추가할 때마다 사용자가 IRQ나 DMA 채널 같은 자원을 직접 지정해 주어야 했습니다.  
설정이 겹치면 장치가 동작하지 않았고, 원인을 찾기도 어려웠습니다.

PnP는 이 과정을 운영체제가 대신 처리해 주는 기능입니다.

즉, PnP는  
**하드웨어 설치를 "꽂으면 바로 쓰는" 수준으로 단순화하기 위한 기능**입니다.

---

### 4. OLE(Object Linking and Embedding, 개체 연결 및 삽입)

다른 응용 프로그램에서 작성된 그림, 표, 차트 등의 개체(Object)를 현재 편집 중인 문서에 연결하거나 삽입하여 사용하는 기능입니다.

- **연결(Linking)** : 원본 개체가 수정되면 문서에 삽입된 개체에도 자동으로 반영됩니다.
- **삽입(Embedding)** : 개체를 문서 안에 복사해 넣는 방식으로, 원본이 변경되어도 반영되지 않습니다.
- 삽입된 개체를 더블클릭하면 해당 개체를 만든 프로그램이 실행되어 바로 편집할 수 있습니다.

#### 왜 연결과 삽입을 구분할까?

두 방식은 "원본과의 관계"가 다릅니다.

- 항상 최신 상태를 유지해야 하는 자료라면 → **연결**
- 문서 하나만 전달해도 온전히 보여야 하는 자료라면 → **삽입**

즉, OLE는  
**개체를 원본과 계속 이어둘 것인지, 문서 안에 통째로 담아둘 것인지를 선택하는 기능**입니다.

---

### 5. 64비트 데이터 처리

한글 Windows 10은 완전한 64비트 운영체제로, 32비트 운영체제보다 많은 양의 데이터를 한 번에 처리할 수 있습니다.

- 32비트 시스템은 이론적으로 최대 4GB의 메모리만 사용할 수 있지만, 64비트 시스템은 그 이상의 메모리를 사용할 수 있습니다.
- 64비트 운영체제에서는 32비트 응용 프로그램도 실행할 수 있습니다.

#### 왜 64비트가 필요했을까?

32비트로는 주소를 2³²개, 즉 약 4GB까지밖에 표현할 수 없습니다.  
프로그램이 점점 커지고 메모리 요구량이 늘어나면서 이 한계가 문제가 되었습니다.

64비트는 훨씬 넓은 주소 공간을 표현할 수 있으므로,  
**대용량 메모리를 사용하는 작업(영상 편집, 대규모 연산 등)을 처리하기 위해 필요**합니다.

### 6. 그 밖의 주요 기능

| 기능 | 특징 |
| --- | --- |
| 에어로 스냅(Aero Snap) | 창을 화면의 가장자리로 드래그하면 창 크기가 자동으로 조절되는 기능입니다. |
| 에어로 피크(Aero Peek) | 작업 표시줄 오른쪽 끝의 '바탕 화면 보기' 단추에 마우스를 가져가면 열린 창이 투명해져 바탕 화면을 미리 볼 수 있는 기능입니다. |
| 에어로 셰이크(Aero Shake) | 창의 제목 표시줄을 잡고 흔들면 해당 창을 제외한 나머지 창이 모두 최소화되는 기능입니다. |
| 가상 데스크톱 | 하나의 컴퓨터에서 여러 개의 바탕 화면을 만들어 작업 공간을 분리해 사용하는 기능입니다. |
| 원드라이브(OneDrive) | 클라우드 저장소로, 파일을 저장해 두면 여러 기기에서 동일하게 사용할 수 있습니다. |
| 사용자 계정 컨트롤(UAC) | 시스템에 영향을 주는 변경이 일어날 때 사용자에게 확인을 요구하여 무단 변경을 방지하는 기능입니다. |
| 자동 업데이트 | Windows Update를 통해 보안 패치와 기능 업데이트가 자동으로 설치됩니다. |
| 라이브러리(Library) | 서로 다른 위치에 흩어져 있는 폴더를 하나의 폴더처럼 모아서 보여 주는 가상의 폴더입니다. |

#### 왜 라이브러리가 필요할까?

같은 성격의 파일이라도 저장 위치는 제각각일 수 있습니다.  
예를 들어 사진은 C 드라이브, D 드라이브, 외장 하드에 흩어져 있을 수 있습니다.

라이브러리는 이 파일들을 **실제로 옮기지 않고도** 한곳에서 모아 볼 수 있게 해 줍니다.

즉, 라이브러리는  
**물리적 위치는 그대로 두고, 논리적으로만 묶어 주는 가상 폴더**입니다.

#### 왜 사용자 계정 컨트롤(UAC)이 필요할까?

악성 프로그램은 사용자가 모르는 사이에 시스템 설정을 바꾸거나 프로그램을 설치하려고 합니다.

UAC는 시스템에 영향을 주는 변경이 시도될 때 **반드시 사용자 확인을 거치도록** 만들어,  
사용자가 인지하지 못한 변경을 차단합니다.

---

### 한 줄 정리

한글 Windows 10은 **GUI 기반의 64비트 운영체제**로,  
**선점형 멀티태스킹**으로 안정성을 확보하고 **PnP, OLE, UAC** 등을 통해 편의성과 보안을 함께 제공합니다.
