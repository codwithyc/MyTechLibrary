## 062. 프로토콜

### 1. 프로토콜(Protocol)의 개요

프로토콜은 **네트워크에서 서로 다른 컴퓨터가 통신하기 위해 정한 규칙과 약속**입니다.

**프로토콜의 3요소**

| 요소 | 설명 |
| --- | --- |
| **구문(Syntax)** | 데이터의 **형식, 부호화, 신호 레벨**을 규정합니다. |
| **의미(Semantics)** | 전송 제어와 **오류 처리**를 위한 제어 정보를 규정합니다. |
| **시간(Timing)** | 통신 **속도와 순서**를 규정합니다. |

#### 왜 프로토콜이 필요할까?

서로 다른 제조사, 다른 운영체제의 컴퓨터가 통신하려면  
**"어떤 형식으로, 어떤 순서로, 무슨 의미로"** 데이터를 주고받을지 미리 합의해야 합니다.

이 합의가 없으면 데이터를 받아도 **해석할 수 없습니다.**

사람으로 치면 **같은 언어와 대화 규칙을 정하는 것**과 같습니다.

### 2. TCP/IP

인터넷에서 사용하는 **표준 프로토콜**입니다.

| 프로토콜 | 계층 | 역할 |
| --- | --- | --- |
| **TCP(Transmission Control Protocol)** | 전송 계층 | 데이터를 **패킷으로 나누고, 순서를 관리하며, 오류를 검사**하고 재전송을 요청합니다. **신뢰성 있는 연결형** 서비스입니다. |
| **IP(Internet Protocol)** | 네트워크 계층 | 패킷의 **주소를 지정하고 경로를 결정**합니다. **비연결형** 서비스로 신뢰성을 보장하지 않습니다. |

#### 왜 TCP와 IP로 역할을 나누었을까?

두 프로토콜은 서로 다른 문제를 담당합니다.

- **IP** : "이 데이터를 어디로 보낼 것인가" → **주소와 경로**
- **TCP** : "제대로 도착했는가, 순서는 맞는가" → **신뢰성**

역할을 나누면 한쪽을 개선해도 다른 쪽에 영향을 주지 않습니다.

예를 들어 속도가 더 중요한 상황에서는 TCP 대신 **UDP**를 쓰면서도  
IP는 그대로 사용할 수 있습니다.

**TCP vs UDP**

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | **연결형** | **비연결형** |
| 신뢰성 | 높음 (재전송, 순서 보장) | 낮음 |
| 속도 | 상대적으로 느림 | **빠름** |
| 용도 | 웹, 메일, 파일 전송 | 실시간 스트리밍, 인터넷 전화, DNS |

#### 왜 실시간 방송에는 UDP를 쓸까?

TCP는 데이터가 빠지면 **재전송을 요청하고 기다립니다.**

그런데 실시간 영상에서는 **1초 전의 화면을 다시 받아 봐야 의미가 없습니다.**  
기다리는 동안 오히려 영상이 끊깁니다.

UDP는 빠진 데이터를 그냥 버리고 **계속 진행**합니다.  
화질이 잠깐 나빠지더라도 **끊기지 않는 것이 더 중요**하기 때문입니다.

### 3. OSI 7계층

국제표준화기구(ISO)가 정의한 **네트워크 통신 구조의 표준 모델**입니다.

| 계층 | 이름 | 역할 | 관련 장비 |
| --- | --- | --- | --- |
| **7** | **응용 계층** | 사용자에게 서비스를 제공합니다. (HTTP, FTP, SMTP) | 게이트웨이 |
| **6** | **표현 계층** | 데이터의 **암호화, 압축, 형식 변환**을 담당합니다. | |
| **5** | **세션 계층** | 통신의 **연결을 설정하고 관리·종료**합니다. | |
| **4** | **전송 계층** | 신뢰성 있는 데이터 전송을 담당합니다. (TCP, UDP) | |
| **3** | **네트워크 계층** | **경로 선택(라우팅)과 주소 지정**을 담당합니다. (IP) | **라우터** |
| **2** | **데이터 링크 계층** | 인접한 장치 간의 **오류 없는 전송**을 담당합니다. (MAC 주소) | **브리지, 스위치** |
| **1** | **물리 계층** | 전기적·기계적 신호를 전달합니다. | **리피터, 허브** |

#### 왜 계층을 나누었을까?

네트워크 통신은 매우 복잡합니다.  
전기 신호 처리부터 암호화, 화면 표시까지 모든 것을 한 덩어리로 만들면  
**한 부분만 바꿔도 전체를 다시 만들어야** 합니다.

계층으로 나누면

- 각 계층은 **바로 위·아래 계층과의 약속만 지키면** 됩니다.
- 유선을 무선으로 바꿔도 **1~2계층만 바꾸면 되고**, 상위 계층은 그대로 사용할 수 있습니다.

즉, 계층화는 **변경의 영향 범위를 줄이고 역할을 분리하기 위한 설계**입니다.

### 4. 주요 응용 계층 프로토콜

| 프로토콜 | 기능 |
| --- | --- |
| **HTTP** | 웹 문서를 주고받습니다. (포트 80) |
| **HTTPS** | HTTP에 **암호화(SSL/TLS)** 를 적용한 것입니다. (포트 443) |
| **FTP** | 파일을 전송합니다. (포트 21) |
| **TELNET** | 원격 컴퓨터에 접속하여 명령을 실행합니다. (포트 23) |
| **SMTP** | 전자 우편을 **보냅니다.** (포트 25) |
| **POP3** | 전자 우편을 **서버에서 내려받습니다.** (포트 110) |
| **IMAP** | 전자 우편을 **서버에 두고 관리**합니다. |
| **MIME** | 전자 우편에서 **멀티미디어 파일을 첨부**할 수 있게 합니다. |
| **DHCP** | IP 주소를 **자동으로 할당**합니다. |
| **DNS** | 도메인 이름을 IP 주소로 변환합니다. (포트 53) |
| **SNMP** | 네트워크 장비를 관리하고 감시합니다. |
| **ARP** | **IP 주소를 MAC 주소로** 변환합니다. |
| **RARP** | **MAC 주소를 IP 주소로** 변환합니다. |
| **ICMP** | 오류 메시지와 상태 정보를 전달합니다. (`ping` 명령에 사용) |

#### 왜 SMTP와 POP3가 나뉘어 있을까?

메일은 **보내는 과정**과 **받는 과정**의 성격이 다릅니다.

- **보내기(SMTP)** : 내 컴퓨터 → 메일 서버 → 상대 메일 서버 (**밀어내는 방식**)
- **받기(POP3)** : 내 컴퓨터가 서버에 접속해서 가져옴 (**가져오는 방식**)

상대방이 컴퓨터를 꺼 두었을 수도 있으므로,  
메일은 일단 **서버에 보관**되었다가 사용자가 접속할 때 전달됩니다.

**POP3 vs IMAP**

| 구분 | POP3 | IMAP |
| --- | --- | --- |
| 저장 위치 | 내려받은 후 **내 컴퓨터**에 저장 | **서버에 그대로 보관** |
| 여러 기기 사용 | 불편함 | **편리함** (동기화됨) |

#### 왜 ARP가 필요할까?

실제 데이터 전달은 **같은 네트워크 안에서 MAC 주소를 보고** 이루어집니다.

그런데 우리가 아는 것은 보통 IP 주소뿐입니다.

ARP는 "이 IP 주소를 가진 기기의 MAC 주소를 알려 달라"고 물어보는 프로토콜입니다.

즉, ARP는 **논리 주소(IP)와 물리 주소(MAC)를 이어 주는 다리**입니다.

---

### 한 줄 정리

프로토콜의 3요소는 **구문·의미·시간**이며,  
**TCP는 신뢰성(연결형), IP는 주소와 경로(비연결형), UDP는 속도 우선**을 담당하고,  
OSI 7계층은 아래부터 **물-데-네-전-세-표-응** 순입니다.
