# 분석 기획 방향성 도출

분석 기획 방향성 도출은 **어떤 분석 과제를 수행할지 찾고, 그 과제가 실제로 수행할 가치가 있는지 판단하는 과정**이다.

앞에서 정리한 “분석 기획”이 분석을 시작하기 위한 전체 계획이라면,  
이번 단원은 그중에서도 **분석 과제를 어떻게 발굴하고 선정할 것인가**에 초점이 있다.

```markdown id="0c56ty"
분석 과제 도출 = 분석할 문제를 찾고, 분석 가능한 과제로 바꾸고, 수행할 가치가 있는지 판단하는 과정
```

ADsP 시험에서는 주로 다음을 묻는다.

* 데이터 분석 과제 도출의 개념
* 하향식 접근 방식의 단계
* 상향식 접근 방식의 특징
* 디자인 싱킹, 프로토타이핑, 비지도 학습의 의미
* 분석 프로젝트의 특징

네가 올렸던 정리 스타일처럼, 이번에도 개념 설명을 먼저 두고 표로 정리하는 방식이 시험 직전 복습에 적합하다. 

---

# 01. 데이터 분석 과제 도출

## 1) 데이터 분석 과제 도출 개요

### 데이터 분석 과제 도출의 정의

**데이터 분석 과제 도출**이란 조직이나 업무에서 해결해야 할 문제를 찾고, 이를 데이터 분석으로 해결 가능한 과제로 구체화하는 과정이다.

즉, 단순히 “데이터를 분석하자”가 아니라,  
**분석할 만한 가치가 있는 문제를 찾아 분석 과제로 바꾸는 단계**다.

예를 들어 다음과 같은 상황이 있다고 하자.

```markdown id="ph8mhv"
고객 이탈률이 증가하고 있다.
매출이 특정 기간에 감소하고 있다.
마케팅 비용 대비 성과가 낮다.
상품 추천 정확도가 낮다.
```

이런 문제를 분석 과제로 바꾸면 다음과 같다.

```markdown id="91ddzg"
고객 이탈 가능성을 예측하는 분석 과제
매출 감소 원인을 파악하는 분석 과제
마케팅 캠페인 성과를 최적화하는 분석 과제
상품 추천 알고리즘을 개선하는 분석 과제
```

즉, 분석 과제 도출은 **비즈니스 문제를 데이터 기반으로 해결할 수 있는 형태로 전환하는 작업**이다.

---

### 분석 과제 도출의 핵심

| 구분        | 설명                           |
| --------- | ---------------------------- |
| 문제 발견     | 조직이나 업무에서 해결해야 할 문제를 찾는다     |
| 분석 가능성 검토 | 해당 문제가 데이터로 분석 가능한지 확인한다     |
| 과제 정의     | 분석 목적, 범위, 기대 효과를 구체화한다      |
| 우선순위 판단   | 여러 과제 중 가치와 가능성이 높은 과제를 선정한다 |

시험에서는 이렇게 이해하면 된다.

```markdown id="61d7tj"
분석 과제 도출은 문제를 찾고, 데이터 분석이 가능한 과제로 정의한 뒤, 수행할 과제를 선정하는 과정이다.
```

---

## 2) 분석 과제 도출 방법

분석 과제를 도출하는 방법은 크게 2가지다.

```markdown id="9gsem9"
하향식 접근 방식
상향식 접근 방식
```

| 구분                     | 하향식 접근 방식                      | 상향식 접근 방식 |
| ---------------------- | ------------------------------ | --------- |
| 출발점                    | 비즈니스 문제                        |           |
| 데이터                    |                                |           |
| 방향                     | 문제 → 데이터 → 분석                  |           |
| 데이터 → 패턴 → 문제 발견       |                                |           |
| 특징                     | 문제가 명확할 때 적합                   |           |
| 문제가 명확하지 않을 때 적합       |                                |           |
| 핵심                     | 문제를 분석 과제로 전환                  |           |
| 데이터를 탐색하여 새로운 인사이트 발견  |                                |           |
| 대표 개념                  | 문제 탐색, 문제 정의, 해결 방안 탐색, 타당성 검토 |           |
| 디자인 싱킹, 프로토타이핑, 비지도 학습 |                                |           |

위 표를 더 정확히 정리하면 다음과 같다.

| 구분     | 하향식 접근 방식                   | 상향식 접근 방식                  |
| ------ | --------------------------- | -------------------------- |
| 출발점    | 비즈니스 문제                     | 보유 데이터                     |
| 진행 방향  | 문제에서 출발해 분석 과제 도출           | 데이터에서 출발해 의미 있는 패턴 발견      |
| 적합한 상황 | 해결해야 할 문제가 명확한 경우           | 문제가 명확하지 않거나 새로운 기회를 찾는 경우 |
| 핵심 질문  | 어떤 문제를 해결할 것인가?             | 데이터 속에 어떤 의미가 있는가?         |
| 장점     | 목적이 명확하고 실행 방향이 뚜렷함         | 예상하지 못한 통찰과 기회 발견 가능       |
| 단점     | 기존 문제 중심이라 새로운 발견이 제한될 수 있음 | 명확한 목적 없이 탐색하면 비효율적일 수 있음  |

시험에서는 이렇게 외우면 된다.

```markdown id="pm8kam"
하향식 = 문제에서 출발
상향식 = 데이터에서 출발
```

# 02. 하향식 접근 방식, Top-Down Approach

## 하향식 접근 방식의 개념

**하향식 접근 방식**은 먼저 비즈니스 문제를 정의한 뒤, 그 문제를 해결하기 위한 분석 과제를 도출하는 방식이다.

즉, 출발점은 데이터가 아니라 **문제**다.

예를 들어, 회사에서 다음과 같은 문제가 있다고 하자.

```markdown id="ufkwwx"
최근 3개월 동안 고객 이탈률이 증가했다.
```

하향식 접근 방식에서는 이 문제를 먼저 정의하고,  
그다음 데이터 분석으로 해결할 수 있는 형태로 바꾼다.

```markdown id="tcer5w"
고객 이탈률 증가 원인은 무엇인가?
이탈 가능성이 높은 고객은 누구인가?
이탈을 줄이기 위해 어떤 조치를 취해야 하는가?
```

즉, 하향식 접근 방식은 **명확한 비즈니스 문제를 분석 문제로 전환하는 방식**이다.

---

## 하향식 접근 방식의 단계

하향식 접근 방식은 일반적으로 다음 4단계로 진행된다.

```markdown id="dkow4y"
문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토
```

| 단계       | 핵심                 | 설명                         |
| -------- | ------------------ | -------------------------- |
| 문제 탐색    | Problem Discovery  | 해결해야 할 비즈니스 문제를 찾는다        |
| 문제 정의    | Problem Definition | 비즈니스 문제를 데이터 분석 문제로 변환한다   |
| 해결 방안 탐색 | Solution Search    | 분석 기법, 데이터, 수행 옵션을 검토한다    |
| 타당성 검토   | Feasibility Study  | 분석 과제의 수행 가능성과 기대 효과를 평가한다 |

시험에서는 단계 순서가 중요하다.

```markdown id="birw6q"
문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토
```

---

## 1) 문제 탐색 단계, Problem Discovery

### 문제 탐색의 개념

**문제 탐색**은 조직이나 업무에서 해결해야 할 문제를 찾는 단계다.

이 단계에서는 아직 분석 과제가 구체적으로 정의된 상태가 아니다.  
먼저 비즈니스 관점에서 어떤 문제가 있는지, 어떤 기회가 있는지 탐색한다.  

예를 들어 다음과 같은 질문을 던질 수 있다.

```markdown id="mn27sp"
현재 조직에서 가장 큰 비효율은 무엇인가?
매출, 비용, 고객 만족도에서 문제가 발생하는 부분은 어디인가?
데이터를 활용하면 개선할 수 있는 업무는 무엇인가?
경쟁사 대비 약점은 무엇인가?
```

---

### 문제 탐색의 핵심

| 구분    | 설명                          |
| ----- | --------------------------- |
| 목적    | 해결할 가치가 있는 비즈니스 문제를 찾는 것    |
| 출발점   | 조직의 전략, 업무 이슈, 현업 요구, 외부 환경 |
| 주요 활동 | 문제 후보 발굴, 기회 탐색, 이슈 정리      |
| 결과    | 분석 후보 과제 목록                 |

문제 탐색 단계에서는 **문제를 많이 찾는 것**이 중요하다.  
처음부터 하나의 정답을 고르는 것이 아니라, 가능한 분석 후보를 넓게 탐색한다.

시험에서는 이렇게 이해하면 된다.

```markdown id="xb2m19"
문제 탐색 = 분석할 만한 비즈니스 문제 후보를 찾는 단계
```

---

## 2) 문제 정의 단계, Problem Definition

### 문제 정의의 개념

**문제 정의**는 문제 탐색 단계에서 찾은 비즈니스 문제를 데이터 분석 문제로 바꾸는 단계다.

즉, 현업의 언어로 표현된 문제를  
분석이 가능한 질문으로 구체화한다.

예를 들어 다음과 같은 비즈니스 문제가 있다.

```markdown id="4xm2na"
요즘 고객이 많이 빠져나가는 것 같다.
```

이 문장은 아직 분석 과제로는 애매하다.
이를 분석 문제로 바꾸면 다음과 같다.

```markdown id="hn9gf3"
최근 6개월간 고객 이탈률은 어떻게 변화했는가?
이탈 고객의 공통 특성은 무엇인가?
이탈 가능성이 높은 고객을 사전에 예측할 수 있는가?
```

이처럼 문제 정의 단계에서는 **문제를 데이터로 측정 가능한 형태로 바꾸는 것**이 핵심이다.

---

### 문제 정의의 핵심

| 구분    | 설명                           |
| ----- | ---------------------------- |
| 목적    | 비즈니스 문제를 분석 가능한 문제로 전환       |
| 핵심    | 문제를 데이터, 변수, 지표, 분석 목표로 구체화  |
| 주요 활동 | 분석 목표 정의, 분석 범위 설정, 성공 기준 수립 |
| 결과    | 분석 과제 정의서                    |

시험에서는 이렇게 이해하면 된다.

```markdown id="j9exzk"
문제 정의 = 비즈니스 문제를 데이터 분석 문제로 변환하는 단계
```

---

## 3) 해결 방안 탐색 단계, Solution Search

### 해결 방안 탐색의 개념

**해결 방안 탐색**은 정의된 분석 문제를 해결하기 위해 어떤 방법을 사용할지 검토하는 단계다.

여기서는 분석 기법, 사용할 데이터, 시스템 환경, 수행 방식 등을 탐색한다.

예를 들어 고객 이탈 예측 과제가 있다면 다음을 검토할 수 있다.

```markdown id="d0q3gz"
어떤 데이터를 사용할 것인가?
분류 모델을 사용할 것인가?
로지스틱 회귀, 의사결정나무, 랜덤포레스트 중 무엇이 적합한가?
외부 데이터가 필요한가?
분석 결과를 대시보드로 제공할 것인가?
```

즉, 해결 방안 탐색은 **분석 과제를 실제로 수행하기 위한 옵션을 도출하는 단계**다.

---

### 해결 방안 탐색의 핵심

| 구분    | 설명                           |
| ----- | ---------------------------- |
| 목적    | 분석 문제를 해결할 수 있는 수행 방법을 찾는 것  |
| 핵심    | 분석 기법, 데이터, 도구, 시스템, 인력 검토   |
| 주요 활동 | 분석 방법 후보 도출, 수행 옵션 비교, 대안 검토 |
| 결과    | 분석 수행 옵션 목록                  |

시험에서는 이렇게 이해하면 된다.

```markdown id="upmqzs"
해결 방안 탐색 = 분석 문제를 해결하기 위한 수행 옵션을 찾는 단계
```

---

## 4) 타당성 검토 단계, Feasibility Study

### 타당성 검토의 개념

**타당성 검토**는 해결 방안 탐색 단계에서 도출한 분석 과제가 실제로 수행할 만한 가치와 가능성이 있는지 평가하는 단계다.

분석 아이디어가 좋아 보여도 다음과 같은 문제가 있으면 실제 과제로 선정하기 어렵다.

```markdown id="cxz5xf"
필요한 데이터가 없다.
데이터 품질이 너무 낮다.
분석 결과를 활용할 부서가 없다.
비용 대비 효과가 낮다.
보안이나 개인정보 이슈가 크다.
```

따라서 타당성 검토 단계에서는 분석 과제를 선정하기 전에  
**가치와 실행 가능성**을 함께 평가한다.

---

### 타당성 검토의 핵심

| 구분    | 설명                              |
| ----- | ------------------------------- |
| 목적    | 분석 과제의 수행 가능성과 기대 효과 평가         |
| 핵심    | 가치와 실행 가능성 검토                   |
| 주요 활동 | 데이터 타당성, 기술 타당성, 경제성, 활용 가능성 평가 |
| 결과    | 최종 분석 과제 선정                     |

타당성 검토에서는 보통 다음 기준을 본다.

| 평가 기준   | 설명                             |
| ------- | ------------------------------ |
| 데이터 타당성 | 필요한 데이터가 존재하고 품질이 적절한가?        |
| 기술 타당성  | 분석을 수행할 기술과 인프라가 있는가?          |
| 경제성     | 비용 대비 기대 효과가 충분한가?             |
| 활용 가능성  | 분석 결과를 실제 업무에 적용할 수 있는가?       |
| 조직 수용성  | 현업 부서가 분석 결과를 받아들이고 활용할 수 있는가? |

시험에서는 이렇게 이해하면 된다.

```markdown id="5jjfjm"
타당성 검토 = 분석 과제의 가치와 수행 가능성을 평가하여 최종 과제를 선정하는 단계
```

---

## 하향식 접근 방식 전체 정리

| 단계       | 핵심 질문                        | 결과          |
| -------- | ---------------------------- | ----------- |
| 문제 탐색    | 어떤 문제가 있는가?                  | 분석 후보 과제    |
| 문제 정의    | 이 문제를 데이터 분석 문제로 어떻게 바꿀 것인가? | 분석 과제 정의    |
| 해결 방안 탐색 | 어떤 데이터와 분석 방법으로 해결할 것인가?     | 수행 옵션       |
| 타당성 검토   | 실제로 수행할 가치와 가능성이 있는가?        | 최종 분석 과제 선정 |

암기 방식은 다음과 같다.

```markdown id="tpj7er"
하향식 접근 = 문제를 찾고 → 분석 문제로 정의하고 → 해결 방안을 찾고 → 타당성을 검토한다
```

---

# 03. 상향식 접근 방식, Bottom-Up Approach

## 1) 상향식 접근 방식의 등장

### 상향식 접근 방식의 개념

**상향식 접근 방식**은 명확한 비즈니스 문제에서 출발하는 것이 아니라,  
보유한 데이터를 탐색하면서 새로운 문제나 인사이트를 발견하는 방식이다.

즉, 출발점은 문제가 아니라 **데이터**다.

하향식 접근 방식은 문제가 명확할 때 효과적이다.  
하지만 실제 빅데이터 환경에서는 처음부터 문제가 명확하지 않은 경우가 많다.

예를 들어 다음과 같은 상황이다.

```markdown id="le0z3i"
로그 데이터는 많이 쌓여 있는데 어떤 문제가 있는지는 아직 모른다.
고객 행동 데이터에서 새로운 패턴을 찾고 싶다.
SNS 데이터에서 예상하지 못한 소비자 반응을 발견하고 싶다.
```

이런 경우에는 먼저 데이터를 탐색하면서 의미 있는 패턴이나 이상 현상을 찾는다.  
이것이 상향식 접근 방식이다.

---

### 상향식 접근 방식이 등장한 이유

| 이유         | 설명                                             |
| ---------- | ---------------------------------------------- |
| 데이터 규모 증가  | 대량의 데이터가 축적되면서 데이터 자체에서 새로운 가치 발견 가능           |
| 비정형 데이터 증가 | 텍스트, 이미지, 로그, 센서 데이터 등 기존 방식으로 정의하기 어려운 데이터 증가 |
| 문제 불명확성    | 처음부터 해결할 문제가 명확하지 않은 경우가 많음                    |
| 새로운 기회 발견  | 기존 문제 해결이 아니라 새로운 패턴과 인사이트 발굴 가능               |

시험에서는 이렇게 이해하면 된다.

```markdown id="yfcbpn"
상향식 접근 방식은 명확한 문제 없이 데이터 탐색을 통해 새로운 인사이트와 분석 과제를 발견하는 방식이다.
```

---

## 2) 상향식 접근 방식의 수행

상향식 접근 방식은 데이터를 먼저 살펴보고, 그 안에서 의미 있는 패턴을 찾는다.

일반적인 흐름은 다음과 같다.

```markdown id="5qjc1y"
데이터 수집 → 데이터 탐색 → 패턴 발견 → 인사이트 도출 → 분석 과제 정의
```

예를 들어, 서비스 로그 데이터를 분석하다가  
특정 시간대에 오류율이 증가하는 패턴을 발견했다고 하자.

처음부터 “오류율 증가 원인을 분석하자”는 문제가 있었던 것은 아니다.  
데이터를 탐색하다가 문제를 발견한 것이다.

이 경우 분석 과제는 다음처럼 정의될 수 있다.

```markdown id="g8d1oy"
특정 시간대 오류율 증가 원인 분석
서버 부하와 사용자 행동 패턴 간 관계 분석
장애 발생 예측 모델 개발
```

---

### 상향식 접근 방식의 핵심

| 구분    | 설명                             |
| ----- | ------------------------------ |
| 출발점   | 데이터                            |
| 목적    | 데이터 속에서 패턴, 관계, 이상 현상, 인사이트 발견 |
| 주요 활동 | 데이터 탐색, 시각화, 군집화, 연관분석, 이상치 탐지 |
| 결과    | 새로운 분석 과제 또는 비즈니스 기회 도출        |

시험에서는 이렇게 이해하면 된다.

```markdown id="2a46k8"
상향식 접근 = 데이터를 먼저 탐색하여 문제나 기회를 발견하는 방식
```

---

## 3) 디자인 싱킹, Design Thinking

### 디자인 싱킹의 개념

**디자인 싱킹**은 사용자의 문제를 공감하고, 아이디어를 빠르게 실험하면서 해결책을 찾아가는 문제 해결 방식이다.

데이터 분석에서 디자인 싱킹은 단순히 데이터만 보는 것이 아니라,  
**사용자와 현업의 실제 문제를 이해하고 분석 과제를 도출하는 데 활용**된다.

디자인 싱킹은 보통 다음 흐름으로 이해하면 된다.

```markdown id="na7glm"
공감 → 문제 정의 → 아이디어 도출 → 프로토타입 → 테스트
```

---

### 디자인 싱킹의 핵심

| 단계      | 설명                      |
| ------- | ----------------------- |
| 공감      | 사용자의 상황과 문제를 이해한다       |
| 문제 정의   | 해결해야 할 핵심 문제를 정의한다      |
| 아이디어 도출 | 다양한 해결 방안을 생각한다         |
| 프로토타입   | 빠르게 시제품이나 분석 결과 형태를 만든다 |
| 테스트     | 사용자 피드백을 통해 개선한다        |

디자인 싱킹은 특히 상향식 접근 방식과 잘 연결된다.

왜냐하면 처음부터 명확한 정답을 정해놓기보다,
데이터와 사용자의 반응을 보면서 문제를 구체화하기 때문이다.

시험에서는 이렇게 이해하면 된다.

```markdown id="9n9wd6"
디자인 싱킹 = 사용자 중심으로 문제를 이해하고 빠르게 실험하며 해결책을 찾는 방식
```

---

## 4) 프로토타이핑 모델

### 프로토타이핑 모델의 개념

**프로토타이핑 모델**은 완성된 결과물을 바로 만들기 전에,  
간단한 시제품이나 분석 결과물을 먼저 만들어 검증하는 방식이다.

데이터 분석에서는 다음과 같은 형태가 프로토타입이 될 수 있다.

```markdown id="uj9skd"
간단한 분석 모델
초기 대시보드
샘플 데이터 기반 분석 결과
간단한 예측 결과 화면
```

프로토타입을 먼저 만들면 사용자의 요구사항을 더 명확히 알 수 있고,  
분석 방향이 맞는지 빠르게 확인할 수 있다.

---

### 프로토타이핑 모델의 핵심

| 구분     | 설명                               |
| ------ | -------------------------------- |
| 목적     | 빠른 검증과 피드백                       |
| 특징     | 완성 전 시제품을 만들어 사용자 반응 확인          |
| 장점     | 요구사항을 구체화하고 실패 비용을 줄일 수 있음       |
| 단점     | 반복 과정에서 일정과 비용이 증가할 수 있음         |
| 적합한 경우 | 요구사항이 불명확하거나 분석 결과 활용 방식이 애매한 경우 |

시험에서는 이렇게 이해하면 된다.

```markdown id="la1n82"
프로토타이핑 = 완성 전에 시제품을 만들어 요구사항과 분석 방향을 검증하는 방식
```

---

## 5) 비지도 학습

### 비지도 학습의 개념

**비지도 학습**은 정답 데이터가 없는 상태에서 데이터의 구조나 패턴을 찾는 학습 방식이다.

지도 학습은 정답이 있는 데이터를 학습한다.

예를 들어 다음과 같다.

```markdown id="2gotz8"
입력: 고객 나이, 구매 횟수, 방문 빈도
정답: 이탈 여부
```

반면 비지도 학습은 정답이 없다.

```markdown id="3k0xqg"
입력: 고객 나이, 구매 횟수, 방문 빈도
정답: 없음
```

이 경우 모델은 데이터의 유사성이나 패턴을 기준으로 고객을 그룹화하거나, 이상한 데이터를 찾아낸다.

---

### 비지도 학습의 핵심

| 구분     | 설명                        |
| ------ | ------------------------- |
| 정답 데이터 | 없음                        |
| 목적     | 데이터 속 구조, 패턴, 군집, 이상치 발견  |
| 대표 기법  | 군집분석, 연관분석, 차원축소, 이상치 탐지  |
| 활용 예시  | 고객 세분화, 장바구니 분석, 이상 거래 탐지 |

비지도 학습은 상향식 접근 방식과 잘 맞는다.

왜냐하면 상향식 접근 방식은 명확한 문제나 정답이 없는 상태에서  
데이터를 탐색하며 의미 있는 패턴을 찾기 때문이다.

시험에서는 이렇게 이해하면 된다.

```markdown id="sgyd2l"
비지도 학습 = 정답 없이 데이터의 숨겨진 구조와 패턴을 찾는 학습
```

---

## 상향식 접근 방식 전체 정리

| 개념        | 핵심                    | 시험 포인트                      |
| --------- | --------------------- | --------------------------- |
| 상향식 접근 방식 | 데이터에서 출발해 문제나 인사이트 발견 | 문제가 명확하지 않을 때 적합            |
| 디자인 싱킹    | 사용자 중심 문제 해결 방식       | 공감, 문제 정의, 아이디어, 프로토타입, 테스트 |
| 프로토타이핑    | 시제품을 통한 빠른 검증         | 요구사항이 불명확할 때 유리             |
| 비지도 학습    | 정답 없이 패턴 발견           | 군집, 연관, 이상치 탐지              |

암기 방식은 다음과 같다.

```markdown id="gy9awj"
상향식 = 데이터 탐색
디자인 싱킹 = 사용자 중심
프로토타이핑 = 빠른 시제품 검증
비지도 학습 = 정답 없이 패턴 발견
```

---

# 하향식 접근 방식과 상향식 접근 방식 비교

| 구분     | 하향식 접근 방식              | 상향식 접근 방식              |
| ------ | ---------------------- | ---------------------- |
| 출발점    | 비즈니스 문제                | 데이터                    |
| 문제 명확성 | 문제 명확                  | 문제 불명확                 |
| 진행 방향  | 문제 → 분석 과제             | 데이터 → 인사이트 → 분석 과제     |
| 핵심 활동  | 문제 정의, 타당성 검토          | 데이터 탐색, 패턴 발견          |
| 적합한 경우 | 해결해야 할 문제가 정해진 경우      | 새로운 기회나 통찰을 찾는 경우      |
| 대표 기법  | 문제 탐색, 문제 정의, 해결 방안 탐색 | 디자인 싱킹, 프로토타이핑, 비지도 학습 |
| 장점     | 목적과 범위가 명확함            | 새로운 문제와 기회 발견 가능       |
| 단점     | 기존 문제 중심으로 제한될 수 있음    | 목적 없이 탐색하면 비효율적일 수 있음  |

시험에서는 이 표를 기준으로 판단하면 된다.

```markdown id="jcisqx"
하향식은 문제를 먼저 정하고 분석한다.
상향식은 데이터를 먼저 탐색하고 문제를 발견한다.
```

# 04. 분석 프로젝트 특징

## 분석 프로젝트의 개념

**분석 프로젝트**는 데이터 분석을 통해 문제를 해결하거나 의사결정을 지원하기 위한 프로젝트다.

일반적인 시스템 개발 프로젝트와 비슷하게 일정, 인력, 비용, 산출물 관리가 필요하지만,  
분석 프로젝트는 데이터와 모델을 다루기 때문에 불확실성이 더 크다.

예를 들어 시스템 개발 프로젝트는 요구사항이 비교적 명확한 경우가 많다.

```markdown id="m5v5y6"
회원가입 기능을 만든다.
결제 기능을 만든다.
게시글 조회 API를 만든다.
```

하지만 분석 프로젝트는 다음처럼 결과가 처음부터 확정되어 있지 않다.

```markdown id="tj57z6"
고객 이탈을 예측할 수 있을까?
매출 감소 원인을 데이터로 설명할 수 있을까?
로그 데이터에서 이상 패턴을 찾을 수 있을까?
```

즉, 분석 프로젝트는 **결과의 불확실성**이 크다.

---

## 분석 프로젝트의 주요 특징

| 특징       | 설명                                 |
| -------- | ---------------------------------- |
| 불확실성     | 분석 결과가 처음부터 명확하지 않다                |
| 반복성      | 데이터 탐색, 모델링, 평가를 반복한다              |
| 데이터 의존성  | 데이터 품질과 확보 가능성이 프로젝트 성패에 큰 영향을 준다  |
| 업무 이해 필요 | 비즈니스 문제를 이해해야 의미 있는 분석이 가능하다       |
| 성과 측정 필요 | 모델 성능뿐 아니라 실제 업무 성과를 함께 평가해야 한다    |
| 협업 필요    | 현업, 분석가, IT 담당자, 의사결정자가 함께 참여해야 한다 |

---

## ① 불확실성

분석 프로젝트는 시작할 때 결과를 확정하기 어렵다.

데이터가 충분할지,  
분석 모델이 좋은 성능을 낼지,  
분석 결과가 실제 업무에 도움이 될지 처음부터 알기 어렵다.

시험에서는 이렇게 이해하면 된다.

```markdown id="i23hp7"
분석 프로젝트는 결과와 수행 과정의 불확실성이 크다.
```

---

## ② 반복성

분석 프로젝트는 한 번에 끝나지 않는다.

데이터를 탐색하다가 문제가 발견되면 다시 정제해야 하고,  
모델 성능이 낮으면 변수를 바꾸거나 다른 기법을 적용해야 한다.

```markdown id="7qvlzj"
데이터 탐색 → 전처리 → 모델링 → 평가 → 개선
```

이 과정을 반복하면서 분석 품질을 높인다.

시험에서는 이렇게 이해하면 된다.

```markdown id="pi8xuk"
분석 프로젝트는 탐색, 모델링, 평가, 개선이 반복된다.
```

---

## ③ 데이터 의존성

분석 프로젝트는 데이터 품질에 크게 의존한다.

아무리 좋은 분석 기법을 사용해도 데이터가 부족하거나 품질이 낮으면 좋은 결과를 얻기 어렵다.

대표적인 데이터 문제는 다음과 같다.

```markdown id="hclram"
결측치가 많다.
이상치가 많다.
데이터 수집 기준이 일관되지 않다.
필요한 데이터가 존재하지 않는다.
데이터 접근 권한이 없다.
```

시험에서는 이렇게 이해하면 된다.

```markdown id="5svfoq"
분석 프로젝트의 성패는 데이터 품질과 확보 가능성에 크게 좌우된다.
```

---

## ④ 업무 이해 필요

분석 프로젝트는 데이터만 잘 다룬다고 성공하지 않는다.

분석 결과가 실제 업무 문제와 연결되어야 하므로,  
해당 업무의 흐름과 의사결정 구조를 이해해야 한다.

예를 들어 고객 이탈 분석을 한다면
단순히 이탈 고객을 예측하는 것만으로는 부족하다.

```markdown id="dm7pd3"
이탈 고객에게 어떤 조치를 할 것인가?
어느 부서가 결과를 활용할 것인가?
예측 결과를 언제 제공해야 효과적인가?
```

이런 업무 맥락을 이해해야 분석 결과가 실제 가치로 이어진다.

시험에서는 이렇게 이해하면 된다.

```markdown id="83bjyv"
분석 프로젝트는 비즈니스 이해와 데이터 분석 역량이 함께 필요하다.
```

---

## ⑤ 성과 측정 필요

분석 프로젝트는 모델 성능뿐 아니라 실제 업무 성과도 평가해야 한다.

예를 들어 이탈 예측 모델의 정확도가 높더라도,  
실제로 고객 이탈률이 줄어들지 않았다면 프로젝트 성과는 부족할 수 있다.

따라서 분석 프로젝트에서는 다음 두 가지를 함께 본다.

| 평가 관점   | 설명                                 |
| ------- | ---------------------------------- |
| 분석 성능   | 정확도, 재현율, F1-score, 예측력 등          |
| 비즈니스 성과 | 매출 증가, 비용 절감, 고객 이탈 감소, 업무 효율 향상 등 |

시험에서는 이렇게 이해하면 된다.

```markdown id="jktoyi"
분석 프로젝트는 모델 성능과 비즈니스 성과를 함께 평가해야 한다.
```

---

## ⑥ 협업 필요

분석 프로젝트는 분석가 혼자 수행하기 어렵다.

보통 다음 역할이 함께 참여한다.

| 역할      | 설명                    |
| ------- | --------------------- |
| 현업 담당자  | 문제 정의와 결과 활용 관점 제공    |
| 데이터 분석가 | 분석 설계, 모델링, 결과 해석 수행  |
| IT 담당자  | 데이터 수집, 저장, 시스템 구현 지원 |
| 의사결정자   | 분석 과제 선정과 결과 활용 의사결정  |

분석 결과가 실제 업무에 적용되려면
현업과 분석가, IT 담당자 간의 협업이 필수다.

시험에서는 이렇게 이해하면 된다.

```markdown id="tqkv09"
분석 프로젝트는 현업, 분석가, IT 담당자의 협업이 필요하다.
```

# 최종 암기 정리

## 데이터 분석 과제 도출 핵심

| 구분 | 핵심 내용                                 |
| -- | ------------------------------------- |
| 정의 | 비즈니스 문제를 데이터 분석으로 해결 가능한 과제로 구체화하는 과정 |
| 목적 | 분석 가치가 있고 수행 가능한 과제 선정                |
| 방법 | 하향식 접근 방식, 상향식 접근 방식                  |
| 핵심 | 문제를 분석 가능한 형태로 바꾸고 타당성을 검토하는 것        |

---

## 하향식 접근 방식 핵심

| 단계       | 핵심                       |
| -------- | ------------------------ |
| 문제 탐색    | 해결할 비즈니스 문제 후보를 찾는다      |
| 문제 정의    | 비즈니스 문제를 데이터 분석 문제로 변환한다 |
| 해결 방안 탐색 | 분석 기법, 데이터, 수행 옵션을 검토한다  |
| 타당성 검토   | 가치와 수행 가능성을 평가해 과제를 선정한다 |

```markdown id="31u72x"
하향식 접근 방식 = 문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토
```

---

## 상향식 접근 방식 핵심

| 개념        | 핵심                       |
| --------- | ------------------------ |
| 상향식 접근 방식 | 데이터 탐색을 통해 문제와 인사이트 발견   |
| 디자인 싱킹    | 사용자 중심으로 문제를 이해하고 해결책 탐색 |
| 프로토타이핑    | 시제품을 통해 빠르게 검증하고 개선      |
| 비지도 학습    | 정답 없이 데이터의 패턴과 구조 발견     |

```markdown id="u5u60t"
상향식 접근 방식 = 데이터에서 출발해 새로운 문제와 기회를 발견하는 방식
```

---

## 하향식 vs 상향식 핵심 비교

| 구분     | 하향식 접근 방식        | 상향식 접근 방식         |
| ------ | ---------------- | ----------------- |
| 출발점    | 비즈니스 문제          | 데이터               |
| 문제 상태  | 문제가 명확함          | 문제가 명확하지 않음       |
| 핵심 활동  | 문제 정의와 타당성 검토    | 데이터 탐색과 패턴 발견     |
| 적합한 상황 | 해결할 문제가 정해져 있을 때 | 새로운 인사이트를 찾고 싶을 때 |
| 암기     | 문제 → 분석          | 데이터 → 인사이트        |

## 분석 프로젝트 특징 핵심

| 특징       | 핵심                        |
| -------- | ------------------------- |
| 불확실성     | 결과가 처음부터 명확하지 않다          |
| 반복성      | 탐색, 모델링, 평가, 개선을 반복한다     |
| 데이터 의존성  | 데이터 품질과 확보 가능성이 중요하다      |
| 업무 이해 필요 | 비즈니스 맥락을 이해해야 한다          |
| 성과 측정 필요 | 모델 성능과 비즈니스 성과를 함께 본다     |
| 협업 필요    | 현업, 분석가, IT 담당자의 협업이 필요하다 |

# 시험 직전 암기 문장

```markdown id="jj5ysf"
데이터 분석 과제 도출은 비즈니스 문제를 데이터 분석으로 해결 가능한 과제로 구체화하고,
수행 가치와 가능성을 검토하여 최종 분석 과제를 선정하는 과정이다.

분석 과제 도출 방법은 하향식 접근 방식과 상향식 접근 방식으로 구분된다.

하향식 접근 방식은 비즈니스 문제에서 출발하여 분석 과제를 도출하는 방식이며,
문제 탐색, 문제 정의, 해결 방안 탐색, 타당성 검토의 순서로 진행된다.

문제 탐색은 해결할 비즈니스 문제 후보를 찾는 단계이고,
문제 정의는 비즈니스 문제를 데이터 분석 문제로 변환하는 단계이다.

해결 방안 탐색은 분석 기법, 데이터, 도구 등 수행 옵션을 검토하는 단계이며,
타당성 검토는 분석 과제의 가치와 수행 가능성을 평가하여 최종 과제를 선정하는 단계이다.

상향식 접근 방식은 명확한 문제 없이 데이터에서 출발하여
패턴, 관계, 이상 현상 등을 탐색하고 새로운 분석 과제나 인사이트를 발견하는 방식이다.

디자인 싱킹은 사용자 중심으로 문제를 이해하고 빠르게 실험하며 해결책을 찾는 방식이고,
프로토타이핑은 완성 전에 시제품을 만들어 요구사항과 분석 방향을 검증하는 방식이다.

비지도 학습은 정답 데이터 없이 데이터의 숨겨진 구조와 패턴을 찾는 학습 방식이며,
상향식 접근 방식과 관련이 깊다.

분석 프로젝트는 결과의 불확실성이 크고,
데이터 탐색, 모델링, 평가, 개선이 반복되며,
데이터 품질과 확보 가능성에 크게 의존한다.

또한 분석 프로젝트는 비즈니스 이해가 필요하고,
모델 성능뿐 아니라 실제 업무 성과를 함께 평가해야 하며,
현업, 분석가, IT 담당자의 협업이 중요하다.
```
