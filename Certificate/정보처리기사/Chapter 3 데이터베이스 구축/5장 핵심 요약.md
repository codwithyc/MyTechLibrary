## 090. 데이터 전환

### 1. 데이터 전환

데이터 전환(Data Conversion)은 **기존 시스템의 데이터를 새로운 시스템에서 사용할 수 있도록 추출·변환·적재하는 과정**이다.

기존 데이터의 구조, 형식, 코드 체계 등을 새로운 시스템의 데이터 구조에 맞게 변경하여 이전한다.

| 단계                 | 설명                            |
| ------------------ | ----------------------------- |
| **추출(Extract)**    | 기존 시스템에서 필요한 데이터를 추출          |
| **변환(Transform)**  | 새로운 시스템의 구조와 형식에 맞게 데이터를 변경   |
| **적재(Load)**       | 변환된 데이터를 새로운 시스템에 저장          |
| **검증(Validation)** | 전환된 데이터가 정확하고 누락 없이 이전되었는지 확인 |

```text
기존 시스템
    ↓
데이터 추출
    ↓
데이터 변환
    ↓
데이터 정제
    ↓
신규 시스템 적재
    ↓
데이터 검증
```

데이터 전환 시에는 다음 사항을 고려해야 한다.

| 고려사항    | 내용                              |
| ------- | ------------------------------- |
| **완전성** | 필요한 데이터가 빠짐없이 전환되어야 함           |
| **정확성** | 원본과 전환 데이터의 값이 정확해야 함           |
| **일관성** | 데이터 간 관계와 규칙이 유지되어야 함           |
| **무결성** | PK, FK 등의 데이터 관계가 정상적으로 유지되어야 함 |
| **가용성** | 전환 이후 새로운 시스템에서 정상적으로 사용 가능해야 함 |

> **데이터 전환 = 기존 데이터 → 변환 → 신규 시스템으로 이전**

## 091. 데이터 전환 방안

### 1. 데이터 전환 방안 항목

데이터 전환 방안은 **데이터를 어떤 방법과 절차로 새로운 시스템에 이전할 것인지 구체적으로 정의한 계획**이다.

| 항목             | 설명                                |
| -------------- | --------------------------------- |
| **데이터 전환 대상**  | 전환해야 하는 테이블, 파일, 데이터 범위를 정의       |
| **데이터 전환 범위**  | 전체 데이터 또는 일부 데이터 등 전환 범위를 결정      |
| **데이터 전환 방법**  | 일괄 전환, 단계적 전환 등의 방법 결정            |
| **데이터 전환 절차**  | 추출 → 변환 → 적재 → 검증 등의 작업 순서를 정의    |
| **데이터 매핑**     | 기존 시스템과 신규 시스템의 컬럼 및 코드 관계를 정의    |
| **데이터 정제**     | 중복, 누락, 오류 데이터를 수정하거나 제거          |
| **전환 일정**      | 테스트 및 본 전환 등의 작업 일정을 수립           |
| **전환 조직 및 역할** | 전환 작업 담당자와 책임을 정의                 |
| **검증 방법**      | 데이터 건수, 값, 무결성 등을 검증하는 방법 정의      |
| **오류 처리 방안**   | 전환 과정에서 발생하는 오류의 처리 방법 정의         |
| **백업 및 복구 방안** | 전환 실패에 대비하여 기존 데이터를 백업하고 복구 절차 마련 |

### 데이터 전환 방식

| 방식         | 설명                           |
| ---------- | ---------------------------- |
| **일괄 전환**  | 특정 시점에 모든 데이터를 한 번에 전환       |
| **단계적 전환** | 시스템 또는 데이터 영역별로 나누어 순차적으로 전환 |
| **병행 전환**  | 기존 시스템과 신규 시스템을 일정 기간 함께 운영  |

```text
전환 대상 선정
      ↓
데이터 분석
      ↓
데이터 매핑
      ↓
전환 프로그램 작성
      ↓
테스트 전환
      ↓
검증 및 오류 수정
      ↓
본 전환
```

> 핵심은 **무엇을, 어떻게, 언제, 누가 전환하고 어떻게 검증할 것인지 정의하는 것**이다.

## 092. 데이터 검증

### 1. 데이터 검증

데이터 검증(Data Validation)은 **전환된 데이터가 기존 데이터와 비교하여 정확하고 완전하게 이전되었는지 확인하는 과정**이다.

| 검증 항목        | 설명                              |
| ------------ | ------------------------------- |
| **건수 검증**    | 원천 데이터와 전환 데이터의 건수가 일치하는지 확인    |
| **항목 검증**    | 각 컬럼의 값이 정확하게 전환되었는지 확인         |
| **범위 검증**    | 데이터 값이 허용된 범위에 포함되는지 확인         |
| **형식 검증**    | 날짜, 전화번호 등의 데이터 형식이 올바른지 확인     |
| **중복 검증**    | 동일한 데이터가 불필요하게 중복되어 있는지 확인      |
| **NULL 검증**  | 필수 데이터가 NULL로 전환되지 않았는지 확인      |
| **무결성 검증**   | PK, FK 등의 참조 관계가 정상적으로 유지되는지 확인 |
| **업무 규칙 검증** | 시스템의 비즈니스 규칙을 만족하는지 확인          |

### 검증 방법

| 방법         | 설명                       |
| ---------- | ------------------------ |
| **전수 검증**  | 모든 데이터를 대상으로 검증          |
| **샘플링 검증** | 일부 데이터를 선정하여 검증          |
| **자동 검증**  | SQL이나 검증 프로그램을 이용해 자동 비교 |
| **수동 검증**  | 담당자가 직접 데이터를 확인          |

예를 들어 전환 전·후 데이터 건수를 확인할 수 있다.

```sql
SELECT COUNT(*)
FROM OLD_STUDENT;
```

```sql
SELECT COUNT(*)
FROM NEW_STUDENT;
```

```text
기존 데이터 : 10,000건
신규 데이터 : 10,000건
              ↓
       건수 검증 통과
```

하지만 **건수가 같다고 해서 값까지 정확하다는 의미는 아니므로** 내용 검증과 무결성 검증도 함께 수행해야 한다.

### 데이터 검증 과정

```text
전환 데이터 생성
      ↓
건수 검증
      ↓
데이터 값 검증
      ↓
무결성 검증
      ↓
업무 규칙 검증
      ↓
오류 발견
      ↓
수정 및 재검증
```

> **데이터 검증 = 전환된 데이터의 완전성·정확성·일관성 확인**

## 093. 오류 데이터 측정 및 정제

※ 제목의 `정체`는 일반적으로 **오류 데이터 측정 및 정제**를 의미한다.

### 1. 오류 데이터 측정 및 정제

오류 데이터 측정은 **데이터 전환 및 검증 과정에서 발견된 오류의 유형과 발생 건수를 파악하는 과정**이며, 데이터 정제(Data Cleansing)는 **발견된 오류 데이터를 수정하거나 제거하여 데이터 품질을 향상시키는 과정**이다.

### 오류 데이터 유형

| 오류 유형         | 설명                     | 예시              |
| ------------- | ---------------------- | --------------- |
| **누락 데이터**    | 필요한 값이 존재하지 않음         | 이름, 주소 등이 NULL  |
| **중복 데이터**    | 동일하거나 유사한 데이터가 여러 번 존재 | 같은 회원이 두 번 등록   |
| **잘못된 값**     | 허용되지 않는 값이 저장됨         | 나이 = -10        |
| **형식 오류**     | 정해진 데이터 형식을 위반         | `2026/99/40`    |
| **범위 오류**     | 허용 범위를 벗어난 값           | 점수 = 120        |
| **불일치 데이터**   | 관련 데이터 사이에 모순 발생       | 우편번호와 주소 불일치    |
| **참조 무결성 오류** | 참조 대상 데이터가 존재하지 않음     | 존재하지 않는 학과번호 참조 |

### 오류 데이터 측정

오류의 발생 정도를 파악하기 위해 **오류 건수와 오류율** 등을 측정한다.

```text
전체 데이터 : 10,000건
오류 데이터 : 200건

오류율 = 200 / 10,000 × 100
       = 2%
```

| 측정 항목         | 설명                       |
| ------------- | ------------------------ |
| **전체 데이터 건수** | 검증 대상 전체 데이터             |
| **오류 데이터 건수** | 오류가 발견된 데이터 수            |
| **오류 유형별 건수** | 누락, 중복, 형식 오류 등을 유형별 측정  |
| **오류율**       | 전체 데이터 중 오류 데이터가 차지하는 비율 |

### 데이터 정제 방법

| 방법        | 설명                       |
| --------- | ------------------------ |
| **삭제**    | 불필요하거나 잘못된 데이터를 제거       |
| **수정**    | 잘못된 값을 정상적인 값으로 변경       |
| **보완**    | 누락된 데이터를 추가              |
| **중복 제거** | 동일한 데이터를 하나로 통합          |
| **형식 변환** | 데이터 형식을 표준 형식으로 통일       |
| **코드 변환** | 기존 코드값을 신규 시스템의 코드값으로 변환 |

예:

```text
01012345678
010-1234-5678
010 1234 5678
```

형식을 정제하면:

```text
010-1234-5678
```

### 오류 데이터 처리 과정

```text
데이터 검증
    ↓
오류 데이터 발견
    ↓
오류 유형 분류
    ↓
오류 건수 및 오류율 측정
    ↓
원인 분석
    ↓
데이터 정제
    ↓
재검증
```

### 전체 흐름 정리

```text
데이터 전환
    ↓
전환 방안 수립
    ↓
데이터 추출 · 변환 · 적재
    ↓
데이터 검증
    ↓
오류 데이터 발견
    ↓
오류 측정
    ↓
데이터 정제
    ↓
재검증
    ↓
전환 완료
```

| 구분            | 핵심 내용                 |
| ------------- | --------------------- |
| **데이터 전환**    | 기존 데이터를 신규 시스템으로 이전   |
| **데이터 전환 방안** | 전환 대상·방법·절차·일정 등을 계획  |
| **데이터 검증**    | 전환 데이터의 정확성과 완전성을 확인  |
| **오류 데이터 측정** | 오류 유형·건수·비율을 파악       |
| **데이터 정제**    | 오류·중복·누락 데이터를 수정 및 제거 |
