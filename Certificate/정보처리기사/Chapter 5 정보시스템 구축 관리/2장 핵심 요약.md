## 135. 네트워크 관련 신기술

### 1. SDN(Software Defined Networking)

SDN은 네트워크 장비의 **제어 기능(Control Plane)**과 실제 데이터 전달 기능(Data Plane)을 분리하여, 네트워크를 소프트웨어를 통해 중앙에서 제어하고 관리하는 기술입니다.

기존 네트워크에서는 각각의 라우터와 스위치가 독립적으로 제어 기능을 수행하지만, SDN에서는 중앙의 **SDN Controller**가 네트워크를 제어합니다.

```text
기존 네트워크

Router ─ 자체 제어
Switch ─ 자체 제어


SDN

        SDN Controller
              ↓
       ┌──────┼──────┐
     Switch Switch Router
```

#### 특징

* 네트워크 제어와 데이터 전달 기능 분리
* 중앙 집중식 네트워크 관리
* 소프트웨어를 통한 네트워크 구성 변경
* 네트워크 자동화 가능
* 네트워크 관리의 유연성 향상

---

### 2. SDS(Software-Defined Storage)

SDS는 물리적인 저장장치를 소프트웨어적으로 추상화하여 **스토리지 자원을 통합하고 소프트웨어로 관리하는 기술**입니다.

```text
SSD
HDD
NAS
SAN
 ↓
SDS
 ↓
통합 Storage Pool
```

#### 특징

* 물리적 저장장치와 관리 기능 분리
* 여러 스토리지를 하나의 자원처럼 관리
* 저장 공간을 필요에 따라 동적으로 할당
* 하드웨어 의존성 감소
* 스토리지 관리 자동화

---

### 3. SDDC(Software Defined Data Center)

SDDC는 데이터센터를 구성하는 **서버, 네트워크, 스토리지 등의 모든 인프라 자원을 가상화하고 소프트웨어로 관리하는 데이터센터**입니다.

```text
          SDDC
           │
 ┌─────────┼─────────┐
Compute   Network   Storage
  ↓         ↓         ↓
가상화     가상화      가상화
```

주요 구성:

* 서버 가상화
* SDN
* SDS
* 자동화 및 오케스트레이션

> `SDDS`가 아니라 **SDDC(Software Defined Data Center)**입니다.

---

### 4. 유비쿼터스 컴퓨팅(Ubiquitous Computing)

유비쿼터스 컴퓨팅은 사용자가 시간과 장소에 구애받지 않고 **언제 어디서나 컴퓨팅 서비스를 이용할 수 있는 환경**을 의미합니다.

```text
사람
 ↓
스마트폰 ─ 자동차 ─ 가전 ─ 센서 ─ 컴퓨터
            ↓
        Network
```

#### 특징

* 언제 어디서나 컴퓨팅 가능
* 다양한 사물에 컴퓨팅 기능 내장
* 네트워크를 통한 상호 연결
* 사용자 상황을 인식하여 서비스 제공

---

### 5. 올조인(AllJoyn)

AllJoyn은 서로 다른 제조사의 IoT 장치들이 **동일한 네트워크에서 서로 발견하고 통신할 수 있도록 지원하는 오픈소스 기반 프레임워크**입니다.

주요 목적:

* IoT 장치 간 상호 운용성 제공
* 장치 자동 검색
* 장치 간 메시지 통신
* 제조사와 운영체제에 대한 의존성 감소

```text
Smart TV
    ↘
Smartphone → AllJoyn → IoT Device
    ↗
Speaker
```

---

### 6. 메시 네트워크(Mesh Network)

Mesh Network는 여러 노드가 서로 연결되어 **그물망 형태의 네트워크를 구성하는 방식**입니다. 대규모 장치 네트워크나 홈 네트워크 등에 활용할 수 있습니다.

```text
A ───── B
│ \     │
│  \    │
C ───── D
 \     /
    E
```

#### 특징

* 하나의 노드에 장애가 발생해도 다른 경로 이용 가능
* 네트워크 신뢰성이 높음
* 네트워크 확장이 용이
* 여러 경로를 통한 데이터 전달 가능

---

### 7. 피코넷(PICONET)

피코넷은 Bluetooth를 사용하는 장치들이 **소규모 무선 네트워크를 구성하는 방식**입니다.

전통적인 Bluetooth 피코넷에서는 하나의 Master를 중심으로 여러 Slave 장치가 연결됩니다.

```text
         Slave
           │
Slave ── Master ── Slave
           │
         Slave
```

여러 피코넷을 서로 연결한 네트워크를 **스캐터넷(Scatternet)**이라고 합니다.

---

### 8. 클라우드 기반 HSM

HSM(Hardware Security Module)은 암호화 키를 안전하게 생성·저장·관리하기 위한 **전용 보안 장비**입니다.

클라우드 기반 HSM은 이러한 기능을 클라우드 환경에서 서비스 형태로 제공합니다.

주요 기능:

* 암호화 키 생성
* 암호화 키 안전한 저장
* 암호화 및 복호화
* 전자서명
* 키 접근 통제

```text
Application
    ↓
Cloud HSM
    ↓
Encryption Key
```

민감한 암호화 키가 일반 애플리케이션이나 데이터베이스에 직접 노출되는 것을 방지합니다.

---

### 9. PaaS-TA

PaaS-TA는 국내에서 개발된 **개방형 클라우드 플랫폼**으로, 애플리케이션을 개발하고 배포할 수 있는 PaaS 환경을 제공합니다.

```text
Application
     ↓
   PaaS-TA
     ↓
Cloud Infrastructure
```

주요 특징:

* 개방형 클라우드 플랫폼
* 애플리케이션 개발 및 배포 지원
* 클라우드 서비스 간 종속성 감소
* 개발 및 운영 환경 제공

---

### 10. 징(Zing)

Zing은 기기를 서로 가까이 접촉시키거나 근접시키면 **대용량 데이터를 빠르게 전송할 수 있는 초고속 근접 무선통신 기술**입니다. 정보처리기사 학습 자료에서는 약 10cm 이내의 근거리에서 고속 데이터 전송이 가능한 기술로 소개됩니다.

예:

```text
스마트폰
   ↕ 근접
Kiosk
   ↓
대용량 데이터 전송
```

---

### 11. WDM(Wavelength Division Multiplexing)

WDM은 하나의 광섬유에 **서로 다른 파장의 광신호를 동시에 전송하는 다중화 기술**입니다.

```text
λ1 ─┐
λ2 ─┼→ 하나의 광섬유 → 분리
λ3 ─┘
```

#### 특징

* 하나의 광섬유를 여러 채널이 공유
* 광통신 전송 용량 증가
* 파장이 다른 광신호를 사용

---

### 12. 웹 크롤링(Web Crawling)

웹 크롤링은 자동화 프로그램이 웹사이트를 순회하면서 **웹 페이지의 정보를 수집하는 기술**입니다.

```text
Crawler
  ↓
Web Page A
  ↓ Link
Web Page B
  ↓ Link
Web Page C
```

웹 크롤링 프로그램을 **Crawler, Spider, Bot** 등으로 부릅니다.

---

### 13. SSO(Single Sign On)

SSO는 사용자가 한 번 인증하면 **여러 시스템이나 서비스를 추가 로그인 없이 이용할 수 있도록 하는 인증 방식**입니다.

```text
          Login
            ↓
           SSO
       ┌────┼────┐
     App A App B App C
```

#### 장점

* 사용자 편의성 향상
* 로그인 횟수 감소
* 계정 관리 단순화

> `SSD(Single Sign On)`가 아니라 **SSO(Single Sign On)**입니다.

---

### 14. 스마트 그리드(Smart Grid)

스마트 그리드는 기존 전력망에 정보통신 기술을 결합하여 **전력 공급자와 소비자가 전력 사용 정보를 실시간으로 교환하고 효율적으로 에너지를 관리하는 지능형 전력망**입니다.

```text
발전소
  ↕
Smart Grid
  ↕
가정 / 기업 / 전기자동차
```

주요 특징:

* 양방향 전력 정보 교환
* 전력 사용량 실시간 관리
* 에너지 효율 향상
* 신재생 에너지 연계

---

### 15. 메타버스(Metaverse)

메타버스는 현실 세계와 가상 세계가 결합된 **지속적인 3차원 가상 공간 또는 디지털 환경**을 의미합니다.

대표적인 요소:

* 가상현실(VR)
* 증강현실(AR)
* 디지털 아바타
* 가상 경제
* 사용자 간 상호작용

---

## 136. 네트워크 구축

### 1. 버스형(Bus)

버스형 네트워크는 하나의 주 통신 회선에 **여러 장치를 연결하는 네트워크 구조**입니다.

```text
PC ─── PC ─── PC ─── PC
        Bus
```

#### 장점

* 구조가 간단함
* 설치 비용이 저렴함
* 장치 추가가 비교적 쉬움

#### 단점

* 주 회선 장애 시 전체 네트워크에 영향
* 장치가 많아질수록 성능 저하
* 충돌 발생 가능

---

### 2. VLAN(Virtual Local Area Network)

VLAN은 물리적인 위치와 관계없이 네트워크 장치를 **논리적인 LAN으로 분할하는 기술**입니다.

```text
하나의 Switch

Port 1 ─ VLAN 10
Port 2 ─ VLAN 10

Port 3 ─ VLAN 20
Port 4 ─ VLAN 20
```

#### 장점

* 브로드캐스트 영역 분리
* 네트워크 보안 향상
* 네트워크 관리 용이
* 물리적 위치와 관계없이 그룹 구성 가능

---

### 3. WPA(Wi-Fi Protected Access)

WPA는 무선 LAN의 보안을 강화하기 위해 만들어진 **무선 네트워크 인증 및 암호화 기술**입니다.

발전 과정:

```text
WEP
 ↓
WPA
 ↓
WPA2
 ↓
WPA3
```

WEP의 보안 취약점을 개선하기 위해 WPA가 등장했습니다.

---

### 4. LAN의 표준 규격 - 802.11e

IEEE 802.11e는 무선 LAN에서 **QoS(Quality of Service)를 지원하기 위해 기존 802.11의 MAC 계층을 개선한 표준**입니다.

음성이나 영상처럼 지연에 민감한 데이터의 우선 처리를 지원하기 위한 규격입니다.

> `802.lle`가 아니라 **IEEE 802.11e**입니다.

---

### 5. CSMA/CD

CSMA/CD(Carrier Sense Multiple Access with Collision Detection)는 전통적인 Ethernet에서 **데이터 충돌을 감지하여 재전송하는 방식**입니다.

동작:

```text
회선 상태 확인
     ↓
회선이 비었는가?
     ↓ Yes
데이터 전송
     ↓
충돌 발생?
     ↓ Yes
전송 중단
     ↓
일정 시간 대기
     ↓
재전송
```

주로 유선 Ethernet의 반이중 환경에서 사용합니다.

---

### 6. CSMA/CA

CSMA/CA(Carrier Sense Multiple Access with Collision Avoidance)는 충돌을 감지하는 것이 아니라 **충돌이 발생하기 전에 회피하는 방식**입니다.

주로 무선 LAN에서 사용합니다.

```text
채널 확인
   ↓
비어 있음
   ↓
임의 시간 대기
   ↓
데이터 전송
```

#### 비교

| 구분    | CSMA/CD     | CSMA/CA |
| ----- | ----------- | ------- |
| 의미    | 충돌 검출       | 충돌 회피   |
| 대표 환경 | 유선 Ethernet | 무선 LAN  |
| 처리    | 충돌 후 대응     | 충돌 전 예방 |

---

## 137. 경로 제어 / 트래픽 제어

### 1. RIP(Routing Information Protocol)

RIP는 라우터 간에 경로 정보를 교환하는 **거리 벡터(Distance Vector) 기반 라우팅 프로토콜**입니다.

최적 경로를 결정할 때 **Hop Count**를 사용합니다.

```text
Router A
   ↓ 1 Hop
Router B
   ↓ 1 Hop
Router C

총 2 Hop
```

#### 특징

* 거리 벡터 알고리즘 사용
* Hop Count 기준으로 최적 경로 결정
* 최대 Hop Count는 15
* 16 Hop은 도달 불가능으로 판단
* 구조가 간단함
* 소규모 네트워크에 적합

---

### 2. OSPF(Open Shortest Path First Protocol)

OSPF는 **링크 상태(Link State)**를 기반으로 최단 경로를 계산하는 라우팅 프로토콜입니다.

최단 경로 계산에 **Dijkstra 알고리즘**을 사용합니다.

```text
Router
 ↓
Link State 정보 수집
 ↓
Topology 구성
 ↓
Dijkstra
 ↓
최단 경로 결정
```

#### 특징

* 링크 상태 라우팅 프로토콜
* 최단 경로 알고리즘 사용
* 대규모 네트워크에 적합
* 네트워크를 Area로 분할 가능
* RIP보다 빠른 경로 수렴

#### RIP와 OSPF

| 구분    | RIP             | OSPF       |
| ----- | --------------- | ---------- |
| 방식    | Distance Vector | Link State |
| 기준    | Hop Count       | Cost       |
| 알고리즘  | Bellman-Ford 계열 | Dijkstra   |
| 규모    | 소규모             | 중·대규모      |
| 수렴 속도 | 느림              | 빠름         |

---

### 3. 흐름 제어 - 정지 대기(Stop and Wait)

Stop-and-Wait는 송신자가 하나의 프레임을 전송한 후 **수신자의 ACK를 받을 때까지 다음 프레임을 전송하지 않는 방식**입니다.

```text
송신자                 수신자

Frame 1 ─────────────→
        ←──────── ACK

Frame 2 ─────────────→
        ←──────── ACK
```

#### 특징

* 구조가 간단함
* 한 번에 하나의 프레임만 전송
* 신뢰성 확보가 쉬움
* 전송 효율은 상대적으로 낮음

---

## 138. SW 관련 신기술

### 1. 매시업(Mashup)

Mashup은 여러 웹서비스나 데이터 소스에서 제공하는 기능과 정보를 결합하여 **새로운 서비스나 애플리케이션을 만드는 기술**입니다.

```text
지도 API
   +
날씨 API
   +
교통 API
   ↓
새로운 서비스
```

---

### 2. 베이퍼웨어(Vaporware)

Vaporware는 제품이나 소프트웨어가 개발 중이라고 발표되었지만 **실제로 출시되지 않거나 출시 일정이 계속 지연되는 제품**을 의미합니다.

```text
제품 발표
   ↓
출시 예정
   ↓
계속 연기
   ↓
실제 제품 없음
```

> `증빌폼(Vapoware)`은 **Vaporware(베이퍼웨어)**를 의미합니다.

---

### 3. 서비스 지향 아키텍처(SOA) 기반 애플리케이션 구성 계층

SOA(Service-Oriented Architecture)는 소프트웨어 기능을 독립적인 **서비스 단위로 구성하여 재사용하고 조합하는 아키텍처**입니다.

시험에서 정리하는 대표적인 구성 계층은 다음과 같습니다.

```text
표현 계층
   ↓
프로세스 계층
   ↓
서비스 계층
   ↓
비즈니스 계층
   ↓
영속 계층
```

| 계층               | 역할             |
| ---------------- | -------------- |
| 표현(Presentation) | 사용자 인터페이스      |
| 프로세스(Process)    | 업무 흐름 및 서비스 조합 |

Hadoop은 대규모 데이터를 여러 서버에 분산 저장하고 병렬 처리하기 위한 **오픈소스 분산 컴퓨팅 플랫폼**입니다.

```text
Hadoop
```

분산된 데이터를 병렬로 처리합니다.

### 2. 맵리듀스(MapReduce)

MapReduce는 대용량 데이터를 여러 컴퓨터에서 **분산·병렬 처리하기 위한 프로그래밍 모델**입니다.

```text
Raw Data
   ↓

   ↓
```

#### Reduce

예:

```text
입력

apple
banana
apple

↓

Map

(apple, 1)
(banana, 1)
(apple, 1)

↓

Reduce

(apple, 2)
(banana, 1)
```

## 143. 회복 / 병행제어

### 1. 회복(Recovery)

회복은 트랜잭션 처리 도중 장애가 발생했을 때 **데이터베이스를 장애가 발생하기 이전의 일관된 상태로 복구하는 작업**입니다.

장애 유형:

* 트랜잭션 장애
* 시스템 장애
* 미디어 장애

대표적인 회복 기법:

* 로그 기반 회복
* 검사점(Checkpoint)
* 즉각 갱신
* 지연 갱신
* 그림자 페이지(Shadow Paging)

#### 주요 회복 연산

| 연산   | 의미               |
| ---- | ---------------- |
| REDO | 트랜잭션을 다시 실행      |
| UNDO | 트랜잭션 수행 이전으로 되돌림 |

---

### 2. 즉각 갱신 기법(Immediate Update)

즉각 갱신은 트랜잭션이 완료되기 전이라도 **변경 내용을 데이터베이스에 즉시 반영할 수 있는 회복 기법**입니다.

```text
Transaction 실행
      ↓
Log 기록
      ↓
DB 즉시 변경
      ↓
Commit
```

Commit 이전에 장애가 발생할 수도 있기 때문에 **UNDO와 REDO가 모두 필요**합니다.

#### 장애 발생 시

Commit 이전:

```text
UNDO
```

Commit 이후:

```text
REDO
```

핵심:

```text
Immediate Update
→ UNDO + REDO
```

---

### 3. 병행제어의 목적

병행제어(Concurrency Control)는 여러 트랜잭션이 동시에 데이터베이스를 사용할 때 **데이터의 일관성과 정확성을 유지하도록 실행을 제어하는 기술**입니다.

주요 목적:

* 데이터베이스 일관성 유지
* 트랜잭션 간 간섭 방지
* 시스템 활용도 향상
* 데이터베이스 공유도 향상
* 직렬 가능성(Serializability) 보장

병행제어가 제대로 수행되지 않으면 다음과 같은 문제가 발생할 수 있습니다.

* 갱신 분실(Lost Update)
* 비완료 의존성(Uncommitted Dependency)
* 모순성(Inconsistency)
* 연쇄 복귀(Cascading Rollback)

---

### 4. 로킹(Locking)

로킹은 트랜잭션이 데이터를 사용하는 동안 다른 트랜잭션이 해당 데이터에 접근하지 못하도록 **Lock을 설정하는 병행제어 방법**입니다.

대표적인 Lock:

#### 공유 잠금(Shared Lock)

데이터를 읽을 때 사용합니다.

```text
Read 가능
Write 불가능
```

여러 트랜잭션이 동시에 Shared Lock을 사용할 수 있습니다.

#### 배타 잠금(Exclusive Lock)

데이터를 변경할 때 사용합니다.

```text
Read 제한
Write 제한
```

다른 트랜잭션의 접근을 차단합니다.

---

### 5. 타임스탬프 순서(Time Stamp Ordering)

타임스탬프 순서 기법은 각 트랜잭션에 고유한 시간값을 부여하고 **타임스탬프 순서에 따라 트랜잭션의 실행 순서를 결정하는 병행제어 기법**입니다.

```text
T1 → Timestamp 10
T2 → Timestamp 20
T3 → Timestamp 30
```

일반적으로 오래된 트랜잭션부터 실행 순서를 결정합니다.

#### 특징

* Lock을 사용하지 않음
* 교착상태가 발생하지 않음
* 트랜잭션 순서를 미리 결정
* 순서에 위배되면 트랜잭션을 Rollback할 수 있음

---

### 6. 로킹 단위(Locking Granularity)

로킹 단위는 Lock을 설정하는 **데이터의 크기**를 의미합니다.

예:

```text
Database
   ↓
Table
   ↓
Page
   ↓
Row
   ↓
Field
```

#### 로킹 단위가 큰 경우

```text
Database / Table 단위
```

* Lock 수 감소
* 관리 오버헤드 감소
* 병행성 감소
* 동시에 실행할 수 있는 트랜잭션 감소

#### 로킹 단위가 작은 경우

```text
Row / Field 단위
```

* Lock 수 증가
* 관리 오버헤드 증가
* 병행성 증가
* 동시에 실행할 수 있는 트랜잭션 증가

정리:

| 구분      | 큰 로킹 단위 | 작은 로킹 단위 |
| ------- | ------- | -------- |
| Lock 수  | 적음      | 많음       |
| 관리 오버헤드 | 낮음      | 높음       |
| 병행성     | 낮음      | 높음       |
| 관리      | 단순      | 복잡       |

> `Loogin Granularity`가 아니라 **Locking Granularity**입니다.

## 144. 교착상태

교착상태(Deadlock)는 둘 이상의 프로세스나 트랜잭션이 서로 상대방이 가진 자원을 기다리면서 **무한히 대기하는 상태**입니다.

예:

```text
Transaction A
 │
 │ Resource 1 보유
 │ Resource 2 대기
 ↓
Transaction B
 │
 │ Resource 2 보유
 │ Resource 1 대기
 ↓

서로 무한 대기
→ Deadlock
```

---

### 1. 교착상태 발생의 필요 충분 조건 4가지

교착상태가 발생하기 위해서는 다음 **4가지 조건이 모두 성립**해야 합니다.

#### ① 상호 배제(Mutual Exclusion)

하나의 자원을 한 번에 하나의 프로세스만 사용할 수 있습니다.

```text
Resource
   ↓
Process A만 사용
```

---

#### ② 점유와 대기(Hold and Wait)

프로세스가 하나 이상의 자원을 가지고 있으면서 **다른 자원을 추가로 기다리는 상태**입니다.

```text
Process A

Resource 1 보유
+
Resource 2 대기
```

---

#### ③ 비선점(No Preemption)

다른 프로세스가 사용 중인 자원을 **강제로 빼앗을 수 없는 상태**입니다.

자원을 보유한 프로세스가 스스로 반환해야 합니다.

---

#### ④ 환형 대기(Circular Wait)

여러 프로세스가 원형으로 서로의 자원을 기다립니다.

```text
P1 → P2의 자원 대기
 ↑                ↓
P4 ← P3 ←─────────
```

#### 핵심 암기

```text
상호 배제
점유와 대기
비선점
환형 대기
```

교착상태는 이 네 조건이 **동시에 만족될 때** 발생할 수 있습니다.

---

### 2. 회피 기법(Avoidance)

교착상태 회피는 자원을 할당하기 전에 해당 자원 할당으로 인해 **교착상태가 발생할 가능성이 있는지를 검사하고 안전한 경우에만 자원을 할당하는 방법**입니다.

대표적인 알고리즘:

```text
은행원 알고리즘
Banker's Algorithm
```

은행원 알고리즘은 시스템의 상태를 다음 두 가지로 구분합니다.

#### 안전 상태(Safe State)

모든 프로세스가 정상적으로 종료될 수 있는 순서가 존재하는 상태입니다.

```text
P1 → P3 → P2 → P4
```

와 같이 모든 프로세스가 완료될 수 있는 순서인 **Safe Sequence**가 존재합니다.

#### 불안전 상태(Unsafe State)

모든 프로세스가 정상 종료할 수 있다고 보장할 수 없는 상태입니다.

```text
Safe State
   ↓
자원 할당 가능

Unsafe State
   ↓
자원 할당하지 않음
```

은행원 알고리즘은 자원 요청이 들어오면 해당 자원을 가상으로 할당한 후 시스템이 **안전 상태를 유지할 수 있는지 검사**합니다.

#### 교착상태 처리 방식 비교

| 방식             | 설명                  |
| -------------- | ------------------- |
| 예방(Prevention) | 교착상태 발생 조건 중 하나를 제거 |
| 회피(Avoidance)  | 안전 상태를 유지하도록 자원 할당  |
| 탐지(Detection)  | 교착상태 발생 후 탐지        |
| 회복(Recovery)   | 발생한 교착상태를 해결        |

핵심:

```text
교착상태 회피
      ↓
안전 상태 유지
      ↓
Banker's Algorithm
```
