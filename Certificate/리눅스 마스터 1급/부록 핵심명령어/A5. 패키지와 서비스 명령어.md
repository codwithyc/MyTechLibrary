> 이론은 [020. RPM과 YUM/DNF], [021. DEB와 APT], [019. 프로세스 관리]를 참고하세요.

### 1. RPM/DNF ↔ DEB/APT 대조표 (핵심)

| 작업 | **Red Hat 계열** | **Debian 계열** |
| --- | --- | --- |
| 목록 갱신 | (자동) | **`apt update`** ⭐ |
| **설치** | `dnf install pkg` | `apt install pkg` |
| 로컬 파일 설치 | `dnf install ./f.rpm` | `apt install ./f.deb` |
| **저수준 설치** | **`rpm -ivh f.rpm`** | **`dpkg -i f.deb`** |
| 삭제 | `dnf remove pkg` | `apt remove pkg` |
| **완전 삭제** | `dnf remove` | **`apt purge`** ⭐ |
| 업그레이드 | `dnf update` | **`apt upgrade`** |
| 검색 | `dnf search` | `apt search` |
| 정보 | `dnf info` / `rpm -qi` | `apt show` / `dpkg -s` |
| **설치 목록** | **`rpm -qa`** | **`dpkg -l`** |
| **파일 목록** | **`rpm -ql`** | **`dpkg -L`** |
| **파일→패키지** | **`rpm -qf`** ⭐ | **`dpkg -S`** ⭐ |
| 파일 제공 검색 | **`dnf provides`** | `apt-file search` |
| 불필요 정리 | `dnf autoremove` | `apt autoremove` |
| 캐시 정리 | `dnf clean all` | `apt clean` |
| **저장소 설정** | **`/etc/yum.repos.d/`** | **`/etc/apt/sources.list`** |
| 버전 고정 | `dnf versionlock` | **`apt-mark hold`** |
| 의존성 복구 | — | **`apt -f install`** |
| 패키지 DB | `/var/lib/rpm` | `/var/lib/dpkg` |

### 2. `rpm` — 저수준 (Red Hat 계열)

#### 설치·삭제

```bash
$ sudo rpm -ivh package.rpm          # ⭐ 설치 (install, verbose, hash)
$ sudo rpm -Uvh package.rpm          # ⭐ 업그레이드 (없으면 설치)
$ sudo rpm -Fvh package.rpm          # 이미 설치된 것만 업그레이드
$ sudo rpm -e package-name           # ⭐ 삭제

$ sudo rpm -ivh --test package.rpm   # ⭐ 테스트만 (실제 설치 안 함)
$ sudo rpm -ivh --nodeps package.rpm # ❗의존성 무시 (위험)
$ sudo rpm -ivh --force package.rpm  # 강제
```

| 옵션 | 의미 |
| --- | --- |
| **`-i`** | 설치 (이미 있으면 **에러**) |
| **`-U`** | **없으면 설치, 있으면 업그레이드** ⭐ |
| **`-F`** | **설치된 것만** 업그레이드 |
| **`-e`** | 삭제 |
| `-v` / `-h` | 상세 / 진행 표시 |
| `--test` | 테스트만 |
| `--nodeps` | 의존성 검사 생략 |

> **`-i` vs `-U` vs `-F` (시험 단골)** ⭐  
> `-i` : 새로 설치만 / **`-U` : 가장 안전하고 일반적** / `-F` : 있는 것만 갱신

#### 조회 (`-q`)

```bash
$ rpm -q httpd                       # ⭐ 설치 여부
httpd-2.4.37-51.module+el8.x86_64

$ rpm -qa                            # ⭐ 전체 목록
$ rpm -qa | grep httpd
$ rpm -qa | wc -l                    # 설치된 패키지 수
$ rpm -qa --last | head              # ⭐ 최근 설치 순

$ rpm -qi httpd                      # ⭐ 상세 정보
$ rpm -ql httpd                      # ⭐ 포함된 파일 목록
$ rpm -qc httpd                      # 설정 파일만
$ rpm -qd httpd                      # 문서만
$ rpm -qR httpd                      # 의존성
$ rpm -q --whatrequires httpd        # 이 패키지를 필요로 하는 것
$ rpm -q --changelog httpd | head    # 변경 이력

# ⭐⭐ 파일이 어느 패키지 소속인지 (매우 자주 사용)
$ rpm -qf /usr/sbin/httpd
httpd-2.4.37-51.module+el8.x86_64
$ rpm -qf $(which ls)
coreutils-8.30-15.el8.x86_64

# 설치하지 않은 rpm 파일 조회 (-p)
$ rpm -qip package.rpm               # 정보
$ rpm -qlp package.rpm               # 파일 목록
```

| 조회 옵션 | 의미 |
| --- | --- |
| **`-qa`** | 설치된 **전체** |
| **`-qi`** | **정보** |
| **`-ql`** | **파일 목록** |
| **`-qf`** | **파일 → 패키지** ⭐ |
| `-qc` / `-qd` | 설정 / 문서 |
| `-qR` | 의존성 |
| **`-p`** | 설치 안 된 **파일** 대상 |

#### 검증 (`-V`)

```bash
$ rpm -V httpd
S.5....T.  c /etc/httpd/conf/httpd.conf

$ sudo rpm -Va | head -20            # ⭐ 전체 검증 (침해 조사)
$ sudo rpm -Va | grep "^..5"         # ⭐ 내용이 변조된 파일만
```

| 문자 | 변경 항목 |
| --- | --- |
| **`S`** | 크기 (Size) |
| **`M`** | 권한 (Mode) |
| **`5`** | **MD5 체크섬 (내용 변조)** ⭐ |
| **`U`/`G`** | 소유자 / 그룹 |
| **`T`** | 수정 시각 |
| `c` | 설정 파일 표시 |

> **침해 사고 조사에서 `rpm -Va`** 로 **`/usr/bin/ls` 같은 기본 명령이 변조**되었는지 확인합니다. ⭐  
> 변조되었다면 **루트킷 감염**을 의심해야 합니다.

```bash
$ sudo rpm --rebuilddb               # DB 손상 시 복구
```

### 3. `dnf` / `yum` — 고수준 (Red Hat 계열)

```bash
# ────────── 설치·삭제 ──────────
$ sudo dnf install httpd
$ sudo dnf install -y httpd nginx
$ sudo dnf install ./local.rpm       # ⭐ 로컬 파일도 의존성 해결
$ sudo dnf remove httpd
$ sudo dnf autoremove                # ⭐ 불필요한 의존 패키지 정리

# ────────── 업데이트 ──────────
$ sudo dnf check-update               # ⭐ 목록만 확인
$ sudo dnf update                     # 전체
$ sudo dnf update httpd               # 특정 패키지
$ sudo dnf update --security          # ⭐⭐ 보안 업데이트만
$ sudo dnf downgrade httpd            # 다운그레이드

# ────────── 검색·정보 ──────────
$ dnf search httpd
$ dnf info httpd
$ dnf list installed
$ dnf list available
$ dnf list --upgrades                 # 업그레이드 가능
$ dnf provides /usr/sbin/httpd        # ⭐⭐ 파일 제공 패키지 찾기
$ dnf provides "*/ifconfig"
$ dnf deplist httpd
$ dnf repoquery --requires httpd

# ────────── 그룹 ──────────
$ dnf group list
$ dnf group info "Development Tools"
$ sudo dnf group install "Development Tools"    # ⭐ 컴파일 도구 일괄
$ sudo dnf group install "Server with GUI"

# ────────── 히스토리 ⭐ ──────────
$ sudo dnf history
$ sudo dnf history info 5
$ sudo dnf history undo 5             # ⭐⭐ 업데이트 되돌리기
$ sudo dnf history redo 5
$ sudo dnf history rollback 4

# ────────── 캐시 ──────────
$ sudo dnf clean all                  # ⭐ 저장소 오류 시 첫 조치
$ sudo dnf makecache

# ────────── 버전 고정 ──────────
$ sudo dnf install python3-dnf-plugin-versionlock
$ sudo dnf versionlock add httpd
$ sudo dnf versionlock list
$ sudo dnf versionlock delete httpd
```

> **실무에서 매우 유용한 두 명령** ⭐  
> **`dnf provides`** : `command not found` 일 때 어떤 패키지를 설치할지 알려 줍니다.
> ```bash
> $ dnf provides ifconfig
> net-tools-2.0-0.52.el8.x86_64 : Basic networking tools
> ```
> **`dnf history undo`** : 업데이트 후 문제가 생기면 **이전 상태로 롤백**합니다.  
> `rpm`만으로는 불가능한 기능입니다.

#### 저장소 관리

```bash
$ dnf repolist                        # ⭐ 활성 저장소
$ dnf repolist all                    # 비활성 포함
$ ls /etc/yum.repos.d/                # ⭐ 설정 파일

# EPEL 추가 (가장 많이 쓰는 추가 저장소) ⭐
$ sudo dnf install epel-release

# 저장소 추가·활성화
$ sudo dnf config-manager --add-repo https://example.com/repo.repo
$ sudo dnf config-manager --set-enabled epel
$ sudo dnf config-manager --set-disabled epel

# 특정 저장소만 사용
$ sudo dnf --enablerepo=epel install htop
$ sudo dnf --disablerepo=epel update
```

**저장소 설정 파일 구조**

```ini
[baseos]
name=Rocky Linux $releasever - BaseOS
baseurl=http://dl.rockylinux.org/...      # 또는 mirrorlist
gpgcheck=1                                 # ⭐ 서명 검증 (보안상 필수)
enabled=1                                  # ⭐ 1=사용, 0=사용 안 함
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-rockyofficial
```

> **`gpgcheck=0`으로 두면 안 됩니다.** ⭐  
> 중간자 공격이나 저장소 침해로 **악성 코드가 삽입된 패키지**를 받아도 알 수 없습니다.

#### 로컬 저장소 만들기 (폐쇄망)

```bash
$ sudo dnf install createrepo
$ sudo mkdir -p /repo && sudo cp *.rpm /repo/
$ sudo createrepo /repo

$ sudo vi /etc/yum.repos.d/local.repo
[local]
name=Local Repository
baseurl=file:///repo
enabled=1
gpgcheck=0

$ sudo dnf clean all && sudo dnf repolist
```

### 4. `dpkg` — 저수준 (Debian 계열)

```bash
$ sudo dpkg -i package.deb           # ⭐ 설치
$ sudo dpkg -r package-name          # 삭제 (설정 유지)
$ sudo dpkg -P package-name          # ⭐ 완전 삭제 (purge)
$ sudo dpkg --configure -a           # ⭐ 설정 중단된 패키지 마무리

# 조회
$ dpkg -l                            # ⭐ 설치 목록
$ dpkg -l | grep nginx
$ dpkg -L nginx                      # ⭐ 파일 목록
$ dpkg -S /usr/sbin/nginx            # ⭐⭐ 파일 → 패키지
$ dpkg -s nginx                      # 상태 정보
$ dpkg -I package.deb                # 파일 정보
$ dpkg -c package.deb                # 파일 목록

# 의존성 문제 해결
$ sudo apt -f install                # ⭐ fix-broken
```

**`dpkg -l` 상태 코드**

| 표시 | 의미 |
| --- | --- |
| **`ii`** | **정상 설치됨** |
| **`rc`** | 삭제됐지만 **설정 파일 남음** |
| `iU` | 설정 미완료 |
| `iF` | 설치 실패 |

```bash
# 설정만 남은 패키지 정리 ⭐
$ dpkg -l | grep '^rc' | awk '{print $2}' | xargs sudo dpkg -P
```

### 5. `apt` — 고수준 (Debian 계열)

```bash
# ⭐⭐ 설치 전 반드시 목록 갱신
$ sudo apt update

$ sudo apt install nginx
$ sudo apt install -y nginx curl
$ sudo apt install ./local.deb

$ sudo apt remove nginx              # 설정 유지
$ sudo apt purge nginx               # ⭐ 설정까지 삭제
$ sudo apt autoremove                # ⭐ 불필요 의존 패키지

$ sudo apt upgrade                   # ⭐ 업그레이드
$ sudo apt full-upgrade              # 패키지 삭제도 허용
$ sudo apt dist-upgrade              # 동일 (구 명령)

$ apt search nginx
$ apt show nginx
$ apt list --installed
$ apt list --upgradable              # ⭐ 업그레이드 가능 목록

$ sudo apt clean                     # 캐시 삭제
$ sudo apt autoclean

$ sudo apt-mark hold nginx           # ⭐ 버전 고정
$ apt-mark showhold
$ sudo apt-mark unhold nginx
```

> **`update`와 `upgrade`를 반드시 구분하세요.** ⭐  
> **`apt update`** : 저장소의 **목록(메타데이터)만 갱신** — 아무것도 설치하지 않음  
> **`apt upgrade`** : **실제 패키지 업그레이드**  
>
> `update`를 먼저 하지 않으면 **"Unable to locate package"** 오류가 납니다.  
> 그래서 항상 **`sudo apt update && sudo apt install ...`** 로 붙여 씁니다.

| 명령 | 삭제 대상 |
| --- | --- |
| **`remove`** | 프로그램 (**설정 유지**) |
| **`purge`** | 프로그램 + **설정 파일** |
| **`autoremove`** | 아무도 필요로 하지 않는 **의존 패키지** |

#### 저장소 관리

```bash
$ cat /etc/apt/sources.list
deb http://archive.ubuntu.com/ubuntu jammy main restricted universe multiverse
 │              │                      │        │
 형식          URL                  코드명    컴포넌트

$ ls /etc/apt/sources.list.d/

# PPA 추가 (Ubuntu)
$ sudo add-apt-repository ppa:nginx/stable
$ sudo apt update
$ sudo add-apt-repository --remove ppa:nginx/stable

# 서드파티 저장소 (신규 방식) ⭐
$ curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
$ echo "deb [signed-by=/etc/apt/keyrings/docker.gpg] \
    https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
    sudo tee /etc/apt/sources.list.d/docker.list
```

| 컴포넌트 | 의미 |
| --- | --- |
| **`main`** | 공식 지원 + 자유 소프트웨어 |
| `restricted` | 공식 지원 + 독점 드라이버 |
| **`universe`** | 커뮤니티 관리 |
| `multiverse` | 라이선스 제한 |

> **`apt-key`는 폐지되었습니다.** ⭐  
> 전역 키 등록은 **모든 저장소가 그 키를 신뢰**하게 되어 위험했습니다.  
> 이제는 **`/etc/apt/keyrings/`에 키를 두고 `signed-by=`로 저장소별 연결**합니다.

### 6. 서비스 관리 — `systemctl`

```bash
# ────────── 기본 제어 ──────────
$ sudo systemctl start httpd
$ sudo systemctl stop httpd
$ sudo systemctl restart httpd          # 중단 발생
$ sudo systemctl reload httpd           # ⭐ 무중단 (설정만 재읽기)
$ sudo systemctl reload-or-restart httpd

# ────────── 자동 시작 ──────────
$ sudo systemctl enable httpd
$ sudo systemctl disable httpd
$ sudo systemctl enable --now httpd     # ⭐ 등록 + 즉시 시작
$ sudo systemctl disable --now httpd
$ sudo systemctl mask httpd             # ⭐ 완전 차단
$ sudo systemctl unmask httpd

# ────────── 상태 확인 ──────────
$ systemctl status httpd                # ⭐
$ systemctl is-active httpd
$ systemctl is-enabled httpd
$ systemctl is-failed httpd

# ────────── 목록 ──────────
$ systemctl list-units --type=service
$ systemctl list-units --type=service --state=running    # ⭐
$ systemctl list-unit-files --type=service --state=enabled
$ systemctl --failed                    # ⭐⭐ 실패한 서비스
$ systemctl list-dependencies httpd

# ────────── 유닛 파일 ──────────
$ systemctl cat httpd                   # ⭐ 내용 확인
$ sudo systemctl edit httpd             # ⭐ 오버라이드 (원본 보존)
$ sudo systemctl edit --full httpd      # 전체 복사 후 편집
$ sudo systemctl daemon-reload          # ⭐⭐ 수정 후 필수
$ sudo systemctl revert httpd           # 오버라이드 제거
```

> **`disable` vs `mask`** ⭐  
> **`disable`** : 자동 시작만 해제 → **수동 `start`는 가능**  
> **`mask`** : `/dev/null`로 링크 → **`start` 자체가 불가능**

> **`restart` vs `reload`** ⭐  
> **`restart`** : 프로세스를 죽였다 다시 시작 → **연결이 끊깁니다**  
> **`reload`** : 프로세스 유지, 설정만 재읽기 → **무중단**  
> 운영 중 설정만 바꿨다면 **반드시 `reload`**

> **유닛 파일 수정 후 `daemon-reload`를 빠뜨리면** ⭐  
> systemd가 변경을 인식하지 못해 **예전 설정으로 동작**하거나 "Unit not found"가 납니다.

#### 유닛 파일 위치와 우선순위

| 경로 | 용도 | 우선순위 |
| --- | --- | --- |
| **`/etc/systemd/system/`** | **관리자가 만든/수정한 것** | **가장 높음** ⭐ |
| `/run/systemd/system/` | 런타임 생성 | 중간 |
| **`/usr/lib/systemd/system/`** | **패키지가 설치한 기본 유닛** | 낮음 |

#### 사용자 정의 서비스 만들기

```bash
$ sudo vi /etc/systemd/system/myapp.service
```
```ini
[Unit]
Description=My Application
After=network.target
Wants=network-online.target

[Service]
Type=simple
User=appuser
Group=appuser
WorkingDirectory=/opt/myapp
ExecStart=/opt/myapp/bin/start.sh
ExecReload=/bin/kill -HUP $MAINPID
Restart=always                  # ⭐ 실패 시 자동 재시작
RestartSec=10
LimitNOFILE=65536               # ⭐ 자원 제한
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```
```bash
$ sudo systemctl daemon-reload          # ⭐ 필수
$ sudo systemctl enable --now myapp
$ systemctl status myapp
$ journalctl -u myapp -f
```

| 섹션 | 역할 |
| --- | --- |
| **`[Unit]`** | 설명, **의존 관계** (`After`, `Requires`, `Wants`) |
| **`[Service]`** | 실행 방법 (`ExecStart`, `Restart`, `User`) |
| **`[Install]`** | `enable` 시 연결될 타깃 |

| `Type=` | 의미 |
| --- | --- |
| **`simple`** | ExecStart가 메인 프로세스 (기본) |
| `forking` | fork 후 부모 종료 (전통 데몬) |
| `oneshot` | 한 번 실행 후 종료 |
| `notify` | 준비 완료를 systemd에 알림 |

#### 타깃 (런레벨)

```bash
$ systemctl get-default                          # ⭐
$ sudo systemctl set-default multi-user.target   # ⭐ 텍스트 모드
$ sudo systemctl set-default graphical.target    # GUI
$ sudo systemctl isolate rescue.target           # 즉시 전환
```

| 런레벨 | 타깃 |
| --- | --- |
| 0 | `poweroff.target` |
| 1 | `rescue.target` |
| **3** | **`multi-user.target`** ⭐ |
| **5** | **`graphical.target`** ⭐ |
| 6 | `reboot.target` |

#### systemd 타이머 (cron 대체)

```bash
$ systemctl list-timers                          # ⭐ 타이머 목록

$ sudo vi /etc/systemd/system/backup.timer
[Unit]
Description=Daily Backup

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true                # ⭐ 놓친 작업을 부팅 후 실행
RandomizedDelaySec=300

[Install]
WantedBy=timers.target

$ sudo systemctl daemon-reload
$ sudo systemctl enable --now backup.timer
```

#### 부팅 분석

```bash
$ systemd-analyze                    # 총 부팅 시간
$ systemd-analyze blame | head       # ⭐ 서비스별 소요 시간
$ systemd-analyze critical-chain
$ systemd-cgtop                      # cgroup 자원 사용
```

### 8. 소스 설치

```bash
# 컴파일 도구 준비
$ sudo dnf group install "Development Tools"     # ⭐ RHEL
$ sudo apt install build-essential               # ⭐ Debian

# ⭐ 3단계
$ tar xvzf nginx-1.24.0.tar.gz && cd nginx-1.24.0
$ ./configure --prefix=/usr/local/nginx \
              --with-http_ssl_module
$ make -j$(nproc)                    # ⭐ 병렬 컴파일
$ sudo make install

# 정리
$ make clean                         # 빌드 결과물 삭제
$ make distclean                     # ⭐ .config까지 삭제
$ sudo make uninstall                # 지원하는 경우만

# 패키지로 만들어 설치 (관리 용이) ⭐
$ sudo checkinstall
```

| 단계 | 역할 |
| --- | --- |
| **`./configure`** | **환경 검사 + Makefile 생성** |
| **`make`** | 컴파일 |
| **`make install`** | 지정 위치에 복사 |
| **`--prefix`** | **설치 경로 (삭제·버전 관리에 중요)** ⭐ |

```bash
# 라이브러리 의존성 확인
$ ldd /usr/local/nginx/sbin/nginx     # ⭐
        libssl.so.1.1 => not found    ← 누락 ❗

# 라이브러리 경로 등록
$ echo "/usr/local/lib" | sudo tee /etc/ld.so.conf.d/local.conf
$ sudo ldconfig
```

> **`/usr/local`에 설치하는 이유** ⭐  
> `/usr/bin`은 **패키지 관리자의 영역**입니다.  
> 여기에 소스 설치 파일을 넣으면 **패키지 업데이트 시 충돌**합니다.

### 9. 문제 해결

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| **패키지를 못 찾음** | 저장소 문제 | **`dnf clean all && makecache`** / **`apt update`** ⭐ |
| **의존성 오류** | 의존 패키지 누락 | `dnf install` 사용 / **`apt -f install`** ⭐ |
| GPG 키 오류 | 키 미등록 | `rpm --import` / 키 등록 |
| **서비스 시작 실패** | 설정 오류 | **`systemctl status`**, **`journalctl -xeu`** ⭐ |
| 유닛 변경 미반영 | daemon-reload 누락 | **`systemctl daemon-reload`** ⭐ |
| `dpkg` lock 오류 | 다른 apt 실행 중 | 대기 후 `dpkg --configure -a` |
| 업데이트 후 문제 | — | **`dnf history undo`** ⭐ |

```bash
# ⭐ 서비스 시작 실패 진단 순서
$ systemctl status httpd                 # ① 상태·에러 메시지
$ journalctl -xeu httpd                  # ② 상세 로그 ⭐
$ sudo httpd -t                          # ③ 설정 문법 검사
$ sudo ss -tulnp | grep :80              # ④ 포트 충돌
$ sudo ausearch -m avc -ts recent        # ⑤ SELinux
$ ls -lZ /var/www/html                   # ⑥ 권한·컨텍스트
```

### 10. 실무 관용구

```bash
# ⭐ 명령어가 없을 때 어느 패키지인지 찾기
$ dnf provides ifconfig
$ apt-file search ifconfig

# ⭐ 최근 설치된 패키지 확인 (변경 추적)
$ rpm -qa --last | head -20
$ grep " install " /var/log/dpkg.log | tail -20

# ⭐ 특정 파일이 어느 패키지 소속인지
$ rpm -qf /etc/httpd/conf/httpd.conf
$ dpkg -S /etc/nginx/nginx.conf

# ⭐ 변조된 파일 점검 (침해 조사)
$ sudo rpm -Va | grep "^..5" | head

# ⭐ 보안 업데이트만 적용
$ sudo dnf update --security
$ sudo apt install unattended-upgrades

# ⭐ 실패한 서비스 전체 확인
$ systemctl --failed

# ⭐ 자동 시작 서비스 목록 (불필요한 것 정리)
$ systemctl list-unit-files --type=service --state=enabled

# ⭐ 부팅 시간이 오래 걸리는 서비스
$ systemd-analyze blame | head -10

# ⭐ 특정 서비스의 최근 에러만
$ journalctl -u nginx -p err --since "1 hour ago"

# ⭐ 설치된 패키지 목록 백업 (재구축용)
$ rpm -qa > /backup/packages-$(date +%F).txt
$ dpkg --get-selections > /backup/packages-$(date +%F).txt

# 복원
$ sudo dnf install $(cat /backup/packages.txt)
$ sudo dpkg --set-selections < /backup/packages.txt && sudo apt-get dselect-upgrade
```

### 11. 명령어 요약

| 목적 | **Red Hat** | **Debian** |
| --- | --- | --- |
| **설치** | `dnf install` | `apt update && apt install` |
| **삭제** | `dnf remove` | `apt purge` |
| **업데이트** | `dnf update` | `apt upgrade` |
| **보안 업데이트** | **`dnf update --security`** | `unattended-upgrades` |
| **설치 목록** | **`rpm -qa`** | **`dpkg -l`** |
| **파일 목록** | **`rpm -ql`** | **`dpkg -L`** |
| **파일→패키지** | **`rpm -qf`** | **`dpkg -S`** |
| **파일 제공 검색** | **`dnf provides`** | `apt-file search` |
| **검증** | **`rpm -V`** | `debsums` |
| **되돌리기** | **`dnf history undo`** | — |
| **저장소** | `/etc/yum.repos.d/` | `/etc/apt/sources.list` |

| 서비스 관리 | 명령 |
| --- | --- |
| 시작·자동시작 | **`systemctl enable --now`** |
| 무중단 반영 | **`systemctl reload`** |
| 완전 차단 | **`systemctl mask`** |
| 유닛 수정 후 | **`systemctl daemon-reload`** ⭐ |
| 실패 서비스 | **`systemctl --failed`** |
| 로그 확인 | **`journalctl -xeu 서비스`** |
| 기본 타깃 | **`systemctl set-default`** |
| 부팅 분석 | **`systemd-analyze blame`** |

### 한 줄 정리

패키지는 **저수준(`rpm`/`dpkg` — 파일 하나)** 과 **고수준(`dnf`/`apt` — 의존성 자동)** 으로 나뉘며,  
조회는 **`rpm -qa`/`-ql`/`-qf`**, 문제 해결은 **`dnf provides`(패키지 찾기)** 와 **`dnf history undo`(롤백)** 가 핵심이고,  
서비스는 **`systemctl enable --now`로 등록·시작**, **설정 변경은 무중단인 `reload`**,  
**유닛 파일 수정 후에는 반드시 `daemon-reload`** 를 실행해야 합니다.
