## 111. 운영체제의 개념

운영체제(OS, Operating System)는 컴퓨터의 **하드웨어와 소프트웨어 자원을 관리**하고, 사용자와 컴퓨터 사이의 인터페이스를 제공하는 시스템 소프트웨어입니다.

대표적인 운영체제에는 Windows, Linux, UNIX, macOS 등이 있습니다.

---

### 1. 운영체제의 목적

운영체제의 주요 목적은 다음과 같습니다.

| 목적                        | 설명                             |
| ------------------------- | ------------------------------ |
| 처리 능력(Throughput) 향상      | 일정 시간 동안 처리하는 작업의 양을 증가        |
| 반환 시간(Turnaround Time) 단축 | 작업을 요청한 시점부터 결과를 받을 때까지의 시간 단축 |
| 사용 가능도(Availability) 향상   | 시스템을 사용할 수 있는 시간 증가            |
| 신뢰도(Reliability) 향상       | 시스템이 정확하고 안정적으로 동작하도록 관리       |

#### 핵심

```text
처리 능력 ↑
사용 가능도 ↑
신뢰도 ↑
반환 시간 ↓
```

---

### 2. 운영체제의 구성

운영체제는 크게 **제어 프로그램(Control Program)**과 **처리 프로그램(Processing Program)**으로 구분할 수 있습니다.

#### 제어 프로그램

컴퓨터 시스템 전체의 동작과 자원을 관리합니다.

| 종류          | 역할                |
| ----------- | ----------------- |
| 감시 프로그램     | 시스템 전체의 동작 상태 감시  |
| 작업 관리 프로그램  | 작업의 실행 순서 및 작업 관리 |
| 데이터 관리 프로그램 | 파일과 데이터의 입출력 관리   |

#### 처리 프로그램

사용자의 작업을 처리하기 위해 사용하는 프로그램입니다.

| 종류         | 설명                  |
| ---------- | ------------------- |
| 언어 번역 프로그램 | 컴파일러, 어셈블러 등        |
| 서비스 프로그램   | 정렬, 편집, 연결 등의 기능 제공 |
| 문제 처리 프로그램 | 특정 업무를 처리하는 응용 프로그램 |

---

### 3. 운영체제의 기능

운영체제의 주요 기능은 다음과 같습니다.

* 프로세스 및 CPU 관리
* 기억장치 관리
* 입·출력 장치 관리
* 파일 시스템 관리
* 사용자 인터페이스 제공
* 자원 할당 및 회수
* 시스템 오류 감지 및 처리
* 사용자 간 자원 공유
* 보안 및 접근 권한 관리

```text
운영체제

├─ 프로세스 관리
├─ 메모리 관리
├─ 파일 관리
├─ 입출력 관리
├─ 자원 관리
└─ 보안 관리
```

---

## 112. Windows

Windows는 Microsoft에서 개발한 GUI 기반 운영체제로, 개인용 PC에서 널리 사용됩니다.

---

### 1. 선점형 멀티태스킹

선점형 멀티태스킹(Preemptive Multitasking)은 운영체제가 실행 중인 프로세스로부터 **CPU 사용 권한을 강제로 회수하여 다른 프로세스에 할당할 수 있는 방식**입니다.

```text
프로세스 A 실행
      ↓
운영체제가 CPU 회수
      ↓
프로세스 B 실행
```

#### 특징

* 여러 프로그램을 동시에 실행할 수 있습니다.
* 특정 프로그램이 CPU를 독점하는 것을 방지합니다.
* 운영체제가 CPU 사용 시간을 관리합니다.
* 시스템 응답성을 높일 수 있습니다.

---

### 2. PnP(Plug and Play)

PnP는 새로운 하드웨어를 컴퓨터에 연결하면 운영체제가 이를 **자동으로 인식하고 필요한 설정을 수행하는 기능**입니다.

예:

```text
USB 연결
   ↓
장치 자동 인식
   ↓
드라이버 검색 및 설치
   ↓
사용 가능
```

대표적인 PnP 장치:

* USB 메모리
* 키보드
* 마우스
* 프린터
* 외장 저장장치

---

## 113. UNIX / LINUX / macOS

UNIX는 다중 사용자와 다중 작업을 지원하는 운영체제로, Linux와 macOS 역시 UNIX 계열의 영향을 크게 받은 운영체제입니다.

---

### 1. UNIX 특징

UNIX의 주요 특징은 다음과 같습니다.

* 다중 사용자(Multi User) 지원
* 다중 작업(Multi Tasking) 지원
* 대부분 C언어로 작성
* 높은 이식성
* 계층적 파일 시스템 제공
* 다양한 네트워크 기능 제공
* 쉘을 통한 명령어 사용
* 시스템 소스와 기능을 쉽게 확장 가능

구조:

```text
사용자
  ↓
Shell
  ↓
Kernel
  ↓
Hardware
```

---

### 2. 커널(Kernel)

커널은 운영체제의 핵심 부분으로 **하드웨어와 시스템 자원을 직접 관리**합니다.

주요 기능:

* CPU 관리
* 프로세스 관리
* 메모리 관리
* 파일 시스템 관리
* 입·출력 장치 관리
* 인터럽트 처리

```text
Application
     ↓
   Shell
     ↓
  Kernel
     ↓
 Hardware
```

---

### 3. 쉘(Shell)

쉘은 사용자와 커널 사이에서 명령어를 전달하는 **명령어 해석기(Command Interpreter)**입니다.

사용자가 입력한 명령을 해석하여 커널에 전달합니다.

대표적인 쉘:

| 쉘    | 설명                 |
| ---- | ------------------ |
| sh   | Bourne Shell       |
| bash | Bourne Again Shell |
| csh  | C Shell            |
| ksh  | Korn Shell         |
| zsh  | Z Shell            |

예:

```bash
ls
cd /home
mkdir test
```

---

### 4. 파일 디스크립터(File Descriptor)

파일 디스크립터는 UNIX/Linux에서 열려 있는 파일이나 입·출력 자원을 식별하기 위해 사용하는 **정수 형태의 번호**입니다.

기본 파일 디스크립터:

| 번호  | 이름     | 의미    |
| --- | ------ | ----- |
| `0` | stdin  | 표준 입력 |
| `1` | stdout | 표준 출력 |
| `2` | stderr | 표준 오류 |

예:

```bash
command > output.txt
```

표준 출력을 파일로 전달합니다.

```bash
command 2> error.txt
```

표준 오류를 파일로 전달합니다.

---

## 114. 기억장치 관리의 개요

운영체제는 한정된 주기억장치를 여러 프로그램이 효율적으로 사용할 수 있도록 관리합니다.

---

### 1. 기억장치 관리 전략

기억장치 관리 전략은 크게 **반입, 배치, 교체 전략**으로 구분됩니다.

| 전략              | 설명                          |
| --------------- | --------------------------- |
| 반입(Fetch)       | 언제 프로그램이나 데이터를 메모리로 가져올지 결정 |
| 배치(Placement)   | 메모리의 어느 위치에 저장할지 결정         |
| 교체(Replacement) | 메모리가 부족할 때 어떤 데이터를 제거할지 결정  |

#### 반입 전략

* 요구 반입(Demand Fetch)
* 예상 반입(Anticipatory Fetch)

#### 배치 전략

| 방식               | 설명                |
| ---------------- | ----------------- |
| 최초 적합(First Fit) | 처음 발견한 충분한 공간에 배치 |
| 최적 적합(Best Fit)  | 가장 작은 적절한 공간에 배치  |
| 최악 적합(Worst Fit) | 가장 큰 공간에 배치       |

---

## 115. 기억장치 구현 기법 / 페이지 교체 알고리즘

### 1. 페이징(Paging) 기법

페이징은 가상 기억장치를 **동일한 크기의 블록**으로 나누어 관리하는 기법입니다.

프로그램을 나눈 단위를 **Page**, 주기억장치를 나눈 단위를 **Frame**이라고 합니다.

```text
프로세스

Page 0
Page 1
Page 2
Page 3

       ↓ 배치

메모리

Frame 0 → Page 2
Frame 1 → Page 0
Frame 2 → Page 3
Frame 3 → Page 1
```

#### 특징

* 페이지와 프레임의 크기는 같습니다.
* 연속된 메모리 공간에 저장할 필요가 없습니다.
* 외부 단편화가 발생하지 않습니다.
* 내부 단편화가 발생할 수 있습니다.
* 페이지 테이블을 이용하여 주소를 변환합니다.

---

### 2. 세그먼테이션(Segmentation) 기법

세그먼테이션은 프로그램을 **논리적인 기능 단위로 서로 다른 크기로 나누어 관리하는 방식**입니다.

예:

```text
프로그램

Segment 0 → Code
Segment 1 → Data
Segment 2 → Stack
Segment 3 → Heap
```

#### 특징

* 세그먼트의 크기가 서로 다를 수 있습니다.
* 논리적인 프로그램 구조를 반영합니다.
* 외부 단편화가 발생할 수 있습니다.
* 내부 단편화는 거의 발생하지 않습니다.

#### Paging과 Segmentation 비교

| 구분     | Paging | Segmentation |
| ------ | ------ | ------------ |
| 분할 기준  | 물리적    | 논리적          |
| 크기     | 고정     | 가변           |
| 단위     | Page   | Segment      |
| 내부 단편화 | 발생 가능  | 거의 없음        |
| 외부 단편화 | 없음     | 발생 가능        |

---

### 3. 페이지 교체 알고리즘

페이지 부재(Page Fault)가 발생하고 빈 프레임이 없을 경우, 메모리에 존재하는 페이지 중 하나를 제거해야 합니다.

이때 제거할 페이지를 선택하는 방법이 **페이지 교체 알고리즘**입니다.

대표적인 알고리즘:

| 알고리즘 | 기준                      |
| ---- | ----------------------- |
| OPT  | 앞으로 가장 오랫동안 사용되지 않을 페이지 |
| FIFO | 가장 먼저 들어온 페이지           |
| LRU  | 가장 오랫동안 사용되지 않은 페이지     |
| LFU  | 사용 횟수가 가장 적은 페이지        |
| NUR  | 최근 사용되지 않은 페이지          |
| SCR  | FIFO를 개선한 Second Chance |

---

### 4. 페이지 교체 알고리즘 - FIFO

FIFO(First In First Out)는 **가장 먼저 메모리에 들어온 페이지를 먼저 교체**합니다.

예:

```text
참조 페이지 : 1 2 3 4

Frame
1
↓
1 2
↓
1 2 3
↓
4 2 3
```

`1`이 가장 먼저 들어왔으므로 `4`가 들어올 때 `1`을 제거합니다.

#### 특징

* 구현이 간단합니다.
* 페이지 사용 빈도를 고려하지 않습니다.
* 프레임 수가 증가했는데 페이지 부재가 증가하는 **Belady의 모순**이 발생할 수 있습니다.

---

### 5. 페이지 교체 알고리즘 - LRU

LRU(Least Recently Used)는 **가장 오랫동안 사용되지 않은 페이지를 교체**하는 방식입니다.

예:

```text
1 → 2 → 3 → 1 → 4
```

`4`가 들어오는 시점에서 `2`가 가장 오랫동안 사용되지 않았다면 `2`를 교체합니다.

#### 특징

* 최근 사용 기록을 기준으로 판단합니다.
* FIFO보다 페이지 사용 패턴을 잘 반영합니다.
* 사용 시점을 기록해야 하므로 추가적인 관리가 필요합니다.

---

## 116. 기억장치 기타 관리 사항

### 1. 페이지 크기가 작을 경우

페이지 크기가 작으면 다음과 같은 특징이 있습니다.

#### 장점

* 내부 단편화가 감소합니다.
* 필요한 데이터만 메모리에 적재할 수 있습니다.
* 메모리를 효율적으로 사용할 수 있습니다.

#### 단점

* 페이지 수가 증가합니다.
* 페이지 테이블 크기가 증가합니다.
* 주소 변환에 필요한 관리 비용이 증가합니다.
* 디스크 I/O 횟수가 증가할 수 있습니다.

반대로 페이지가 크면 페이지 테이블은 작아지지만 내부 단편화가 증가할 수 있습니다.

---

### 2. Locality

Locality(지역성)는 프로세스가 실행되는 동안 **특정 부분의 메모리를 집중적으로 참조하는 성질**입니다.

#### 시간 지역성(Temporal Locality)

최근에 사용한 데이터가 다시 사용될 가능성이 높은 성질입니다.

예:

```text
반복문
변수
스택
```

#### 공간 지역성(Spatial Locality)

현재 사용한 메모리 주소와 가까운 데이터가 사용될 가능성이 높은 성질입니다.

예:

```text
배열의 연속된 요소
순차적으로 실행되는 명령어
```

---

### 3. 워킹 셋(Working Set)

워킹 셋은 프로세스가 일정 시간 동안 **집중적으로 참조하는 페이지의 집합**입니다.

```text
프로세스가 최근 사용한 페이지

{2, 3, 5, 7}
        ↓
   Working Set
```

워킹 셋을 메모리에 유지하면 페이지 부재를 감소시키고 스래싱을 방지할 수 있습니다.

---

### 4. 스래싱(Thrashing)

스래싱은 프로세스 실행보다 **페이지 교체에 지나치게 많은 시간이 소비되는 현상**입니다.

```text
메모리 부족
   ↓
Page Fault 증가
   ↓
페이지 교체 증가
   ↓
디스크 I/O 증가
   ↓
CPU 이용률 감소
   ↓
Thrashing
```

#### 해결 방법

* 다중 프로그래밍 정도 감소
* 프로세스에 할당하는 프레임 증가
* Working Set 사용
* Page Fault Frequency 방식 사용

---

## 117. 프로세스의 개요

### 1. 프로세스의 정의

프로세스(Process)는 **실행 중인 프로그램**을 의미합니다.

프로그램이 디스크에 저장된 정적인 코드라면, 프로세스는 메모리에 적재되어 CPU에 의해 실행되고 있는 동적인 상태입니다.

```text
Program
  ↓ 실행
Process
```

프로세스는 운영체제로부터 다음과 같은 자원을 할당받습니다.

* CPU
* 메모리
* 파일
* 입·출력 장치

프로세스에 대한 정보는 **PCB(Process Control Block)**에 저장됩니다.

PCB 주요 정보:

* 프로세스 ID
* 프로세스 상태
* 프로그램 카운터
* CPU 레지스터
* 스케줄링 정보
* 메모리 관리 정보

---

### 2. 프로세스 상태 전이

프로세스의 대표적인 상태는 다음과 같습니다.

```text
        Dispatch
Ready ───────────→ Running
  ↑                   │
  │                   │ Wait
  │                   ↓
  └────────────── Waiting
        Wake Up
```

주요 상태:

| 상태                | 설명                |
| ----------------- | ----------------- |
| New               | 프로세스 생성           |
| Ready             | CPU 할당을 기다리는 상태   |
| Running           | CPU를 사용하여 실행 중    |
| Waiting / Blocked | I/O 등의 작업 완료를 기다림 |
| Terminated        | 프로세스 종료           |

---

### 3. Dispatch

Dispatch는 준비 상태(Ready)의 프로세스 중 하나에게 CPU를 할당하여 **실행 상태(Running)로 전환하는 과정**입니다.

```text
Ready
  ↓ Dispatch
Running
```

이를 수행하는 운영체제 구성 요소를 **Dispatcher**라고 합니다.

Dispatcher의 주요 작업:

* 프로세스 문맥 교환
* 사용자 모드 전환
* 실행할 명령어 위치로 이동

---

### 4. 스레드의 특징

스레드(Thread)는 하나의 프로세스 내부에서 실행되는 **작업의 최소 단위**입니다.

```text
Process
├─ Thread 1
├─ Thread 2
└─ Thread 3
```

같은 프로세스의 스레드는 다음 자원을 공유합니다.

* Code
* Data
* Heap
* 열린 파일

각 스레드는 독립적으로 다음을 가집니다.

* Stack
* Program Counter
* Register

#### 특징

* 프로세스 생성보다 오버헤드가 작습니다.
* 문맥 교환 비용이 상대적으로 작습니다.
* 프로세스 내부의 자원을 공유합니다.
* 여러 작업을 동시에 처리할 수 있습니다.

---

## 118. 스케줄링

스케줄링은 CPU를 사용할 프로세스를 결정하는 운영체제의 기능입니다.

---

### 1. 비선점(Non-Preemptive) 스케줄링

비선점 방식은 한 프로세스가 CPU를 할당받으면 **프로세스가 종료되거나 스스로 CPU를 반환할 때까지 다른 프로세스가 CPU를 강제로 빼앗을 수 없는 방식**입니다.

대표 알고리즘:

* FCFS
* SJF
* HRN
* 우선순위 방식 일부

#### 장점

* 구현이 간단합니다.
* 문맥 교환 횟수가 적습니다.

#### 단점

* 긴 작업이 CPU를 차지하면 다른 프로세스의 대기 시간이 길어집니다.
* 응답성이 낮을 수 있습니다.

---

### 2. 선점(Preemptive) 스케줄링

선점 방식은 운영체제가 실행 중인 프로세스의 CPU를 **강제로 회수하여 다른 프로세스에 할당할 수 있는 방식**입니다.

대표 알고리즘:

* Round Robin
* SRT
* Multi-Level Queue
* Multi-Level Feedback Queue

#### 장점

* 빠른 응답이 가능합니다.
* 긴 프로세스의 CPU 독점을 방지합니다.

#### 단점

* 문맥 교환이 자주 발생합니다.
* 스케줄링 오버헤드가 증가할 수 있습니다.

---

## 119. 주요 스케줄링 알고리즘

### 1. SJF(Shortest Job First)

SJF는 실행 시간이 가장 짧은 프로세스를 **먼저 실행하는 방식**입니다.

예:

| 프로세스 | 실행 시간 |
| ---- | ----: |
| P1   |     8 |
| P2   |     3 |
| P3   |     5 |

실행 순서:

```text
P2 → P3 → P1
```

#### 특징

* 평균 대기 시간을 최소화할 수 있습니다.
* 실행 시간이 긴 프로세스는 계속 뒤로 밀릴 수 있습니다.
* **기아 상태(Starvation)**가 발생할 수 있습니다.
* 기본 SJF는 비선점 방식입니다.

선점형 SJF를 **SRT(Shortest Remaining Time)**라고 합니다.

---

### 2. HRN(Highest Response-ratio Next)

HRN은 SJF의 기아 상태 문제를 개선하기 위해 **대기 시간과 서비스 시간을 함께 고려하는 비선점 스케줄링 방식**입니다.

우선순위 계산식:

[
우선순위 = \frac{대기시간 + 서비스시간}{서비스시간}
]

또는

[
우선순위 = 1 + \frac{대기시간}{서비스시간}
]

우선순위 값이 **가장 큰 프로세스를 먼저 실행**합니다.

예:

| 프로세스 | 대기 시간 | 실행 시간 | 우선순위 |
| ---- | ----: | ----: | ---: |
| P1   |    10 |     5 |    3 |
| P2   |     5 |     5 |    2 |

따라서:

```text
P1 → P2
```

#### 특징

* 대기 시간이 길수록 우선순위가 높아집니다.
* 긴 작업의 기아 상태를 완화합니다.
* 비선점 방식입니다.

---

## 122. 인터넷

### 1. IP 주소

IP 주소는 네트워크에 연결된 장치를 식별하기 위해 사용하는 **논리적 주소**입니다.

IPv4는 총 **32비트**로 구성됩니다.

예:

```text
192.168.0.1
```

IPv4 주소는 8비트씩 4개로 나누어 표현합니다.

```text
11000000.10101000.00000000.00000001

192     .168     .0       .1
```

---

### 2. 서브네팅의 예

서브네팅(Subnetting)은 하나의 네트워크를 여러 개의 작은 네트워크로 분할하는 기술입니다.

예:

```text
192.168.1.0/24
```

`/24`는 앞의 24비트가 네트워크 주소임을 의미합니다.

서브넷 마스크:

```text
255.255.255.0
```

사용 가능한 주소 범위:

```text
Network Address
192.168.1.0

Host
192.168.1.1
~
192.168.1.254

Broadcast
192.168.1.255
```

#### /24를 /26으로 분할하는 경우

```text
192.168.1.0/26
192.168.1.64/26
192.168.1.128/26
192.168.1.192/26
```

하나의 `/26` 네트워크는 64개의 주소를 가지며, 네트워크 주소와 브로드캐스트 주소를 제외하면 일반적으로 **62개의 호스트 주소**를 사용할 수 있습니다.

---

### 3. IPv6

IPv6는 IPv4의 주소 부족 문제를 해결하기 위해 개발된 인터넷 프로토콜입니다.

IPv6의 주소 길이는 **128비트**입니다.

예:

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

#### 특징

* 128비트 주소 사용
* 매우 많은 주소 제공
* 주소 자동 설정 지원
* 보안 기능 강화
* 헤더 구조 단순화
* 멀티캐스트 지원
* 브로드캐스트를 사용하지 않음

---

### 4. IPv6 주소 체계

IPv6의 주요 주소 유형은 다음과 같습니다.

| 주소        | 설명                     |
| --------- | ---------------------- |
| Unicast   | 한 송신자 → 한 수신자          |
| Multicast | 한 송신자 → 여러 수신자         |
| Anycast   | 한 송신자 → 가장 가까운 하나의 수신자 |

#### Unicast

```text
1 : 1
```

#### Multicast

```text
1 : N
```

#### Anycast

```text
1 : 가장 가까운 1
```

> IPv6에는 IPv4의 Broadcast 방식이 없습니다.

## 123. OSI 참조 모델

OSI 7계층은 네트워크 통신 기능을 **7개의 계층으로 나눈 표준 참조 모델**입니다.

```text
7. Application
6. Presentation
5. Session
4. Transport
3. Network
2. Data Link
1. Physical
```

암기:

```text
물 → 데 → 네 → 전 → 세 → 표 → 응
```

---

### 1. 물리 계층

Physical Layer는 데이터를 **전기적·기계적 신호로 전송**합니다.

주요 역할:

* 비트 전송
* 전기 신호 변환
* 케이블 및 연결 장치 규격 정의

전송 단위:

```text
Bit
```

대표 장비:

* 허브(Hub)
* 리피터(Repeater)

---

### 2. 데이터 링크 계층

Data Link Layer는 인접한 장치 간의 **신뢰성 있는 데이터 전송**을 담당합니다.

주요 역할:

* MAC 주소 사용
* 프레임 전송
* 오류 검출
* 흐름 제어
* 매체 접근 제어

전송 단위:

```text
Frame
```

대표 장비:

* 브리지
* 스위치

---

### 3. 네트워크 계층

Network Layer는 서로 다른 네트워크 사이에서 **데이터의 전달 경로를 결정**합니다.

주요 역할:

* IP 주소 사용
* 라우팅
* 경로 설정
* 패킷 전달

전송 단위:

```text
Packet
```

대표 프로토콜:

* IP
* ICMP

대표 장비:

* Router

---

### 4. 전송 계층

Transport Layer는 송신자와 수신자 사이의 **종단 간 통신**을 담당합니다.

주요 역할:

* 신뢰성 있는 데이터 전송
* 오류 제어
* 흐름 제어
* 포트 번호 사용

전송 단위:

```text
Segment → TCP
Datagram → UDP
```

대표 프로토콜:

* TCP
* UDP

---

### 5. 세션 계층

Session Layer는 응용 프로그램 사이의 **연결 및 세션을 설정·유지·종료**합니다.

주요 기능:

* 세션 설정
* 세션 유지
* 세션 종료
* 동기화

---

### 6. 표현 계층

Presentation Layer는 데이터의 표현 방식을 변환합니다.

주요 기능:

* 데이터 형식 변환
* 문자 코드 변환
* 암호화 / 복호화
* 압축 / 해제

예:

```text
ASCII
Unicode
JPEG
MPEG
```

---

### 7. 응용 계층

Application Layer는 사용자가 네트워크 서비스를 직접 사용할 수 있도록 인터페이스를 제공합니다.

대표 프로토콜:

* HTTP
* HTTPS
* FTP
* SMTP
* DNS
* Telnet
* SSH

---

## 124. 네트워크 관련 장비

### 1. 브리지

Bridge는 두 개의 LAN을 연결하는 장비입니다.

OSI 계층:

```text
2계층 - Data Link
```

#### 특징

* MAC 주소를 이용합니다.
* 불필요한 트래픽을 필터링합니다.
* 네트워크를 여러 세그먼트로 분할할 수 있습니다.

---

### 2. 스위치

Switch는 여러 장치를 연결하고 MAC 주소를 기반으로 목적지 장치에만 데이터를 전달합니다.

OSI 계층:

```text
2계층 - Data Link
```

#### 특징

* MAC Address Table을 사용합니다.
* 각 포트가 독립적인 충돌 도메인을 가집니다.
* 허브보다 효율적인 데이터 전송이 가능합니다.

```text
PC A ─┐
PC B ─┼─ Switch
PC C ─┘
```

---

### 3. 라우터

Router는 서로 다른 네트워크를 연결하고 **IP 주소를 이용하여 최적의 경로를 결정하는 장비**입니다.

OSI 계층:

```text
3계층 - Network
```

주요 기능:

* Routing
* Packet Forwarding
* 경로 결정
* 서로 다른 네트워크 연결

---

### 4. 브라우터

Brouter는 **Bridge + Router**의 기능을 결합한 장비입니다.

```text
Brouter
=
Bridge
+
Router
```

라우팅이 가능한 프로토콜은 Router처럼 처리하고, 라우팅할 수 없는 프로토콜은 Bridge처럼 처리합니다.

---

### 5. 전처리기

전처리기(FEP, Front-End Processor)는 중앙 컴퓨터가 처리해야 하는 통신 관련 작업을 대신 수행하는 장치입니다.

주요 기능:

* 데이터 통신 제어
* 메시지 처리
* 프로토콜 처리
* 오류 검출
* 데이터 형식 변환

이를 통해 중앙 컴퓨터의 통신 처리 부담을 줄일 수 있습니다.

---

## 125. TCP/IP

TCP/IP는 인터넷에서 데이터를 주고받기 위해 사용하는 대표적인 네트워크 프로토콜 집합입니다.

---

### 1. TCP

TCP(Transmission Control Protocol)는 **연결 지향형 프로토콜**입니다.

#### 특징

* 연결 지향
* 신뢰성 있는 데이터 전송
* 순서 보장
* 오류 검출
* 재전송
* 흐름 제어
* 혼잡 제어

통신 전 **3-Way Handshake**를 수행합니다.

```text
Client              Server

  SYN  ─────────────→

       ←──────── SYN + ACK

  ACK  ─────────────→

      연결 완료
```

TCP를 사용하는 대표 프로토콜:

* HTTP/HTTPS
* FTP
* SMTP
* SSH

---

### 2. IP

IP(Internet Protocol)는 네트워크에서 **패킷을 목적지까지 전달하기 위한 프로토콜**입니다.

주요 기능:

* IP 주소 지정
* 패킷 전달
* 라우팅

#### 특징

* 비연결형
* 비신뢰성
* 패킷 전달 자체를 담당
* 데이터 도착 여부나 순서를 보장하지 않음

```text
TCP
 ↓
IP
 ↓
Network
```

---

### 3. MQTT

MQTT(Message Queuing Telemetry Transport)는 IoT 환경에서 많이 사용되는 **경량 메시징 프로토콜**입니다.

Publish / Subscribe 방식을 사용합니다.

```text
Publisher
    ↓
  Broker
  ↙   ↘
Sub A  Sub B
```

구성 요소:

| 구성         | 설명           |
| ---------- | ------------ |
| Publisher  | 메시지를 발행      |
| Subscriber | 메시지를 구독      |
| Broker     | 메시지를 중계      |
| Topic      | 메시지를 구분하는 채널 |

#### 특징

* 가벼운 프로토콜
* 적은 네트워크 대역폭 사용
* IoT 장치에 적합
* TCP 기반
* 발행/구독 구조 사용

---

### 4. UDP

UDP(User Datagram Protocol)는 **비연결형 전송 프로토콜**입니다.

#### 특징

* 연결 설정 과정이 없음
* 전송 속도가 빠름
* 데이터 도착을 보장하지 않음
* 순서를 보장하지 않음
* 재전송 기능이 없음
* 오버헤드가 작음

대표적인 사용:

* 실시간 스트리밍
* VoIP
* 온라인 게임
* DNS

#### TCP와 UDP 비교

| 구분    | TCP      | UDP  |
| ----- | -------- | ---- |
| 연결    | 연결형      | 비연결형 |
| 신뢰성   | 높음       | 낮음   |
| 순서 보장 | O        | X    |
| 재전송   | O        | X    |
| 속도    | 상대적으로 느림 | 빠름   |
| 헤더    | 상대적으로 큼  | 작음   |

---

### 5. ICMP

ICMP(Internet Control Message Protocol)는 IP 통신 중 발생하는 **오류나 네트워크 상태 정보를 전달하는 프로토콜**입니다.

대표적인 활용:

```bash
ping
```

`ping` 명령은 ICMP Echo Request와 Echo Reply를 이용합니다.

주요 기능:

* 네트워크 연결 상태 확인
* 오류 메시지 전달
* 목적지 도달 가능 여부 확인

---

### 6. ARP

ARP(Address Resolution Protocol)는 **IP 주소를 MAC 주소로 변환**하는 프로토콜입니다.

예:

```text
IP Address
192.168.0.10
      ↓ ARP
MAC Address
AA:BB:CC:DD:EE:FF
```

동작 과정:

```text
1. 목적지 IP 확인

2. ARP Request
   "192.168.0.10 누구야?"

3. 해당 장치가 ARP Reply

4. MAC 주소 확인

5. 데이터 전송
```

핵심:

```text
ARP
IP → MAC
```

---

### 7. CSMA/CD

CSMA/CD(Carrier Sense Multiple Access with Collision Detection)는 공유 Ethernet 환경에서 여러 장치가 동시에 데이터를 전송할 때 **충돌을 감지하고 처리하는 방식**입니다.

#### 동작 과정

```text
1. Carrier Sense
   ↓
회선이 사용 중인지 확인

2. 비어 있으면 전송
   ↓
3. Collision 발생 여부 확인
   ↓
4. 충돌 발생 시 전송 중단
   ↓
5. 일정 시간 대기
   ↓
6. 다시 전송
```

각 용어의 의미:

| 용어                  | 의미                  |
| ------------------- | ------------------- |
| Carrier Sense       | 전송 전에 회선 사용 여부 확인   |
| Multiple Access     | 여러 장치가 하나의 전송 매체 공유 |
| Collision Detection | 데이터 충돌을 감지          |

> CSMA/CD는 전통적인 **반이중(Half-Duplex) Ethernet 환경**에서 사용되며, 오늘날의 스위치 기반 전이중 Ethernet에서는 일반적으로 충돌이 발생하지 않아 사용되지 않습니다.
