## 050. PC 관리

### 1. PC 관리의 기본 원칙

컴퓨터는 정밀한 전자 부품으로 이루어져 있으므로,  
**온도·습도·전원·먼지·충격** 관리가 수명과 안정성에 큰 영향을 줍니다.

---

### 2. 하드웨어 관리

| 항목 | 관리 방법 |
| --- | --- |
| 온도 | 직사광선과 난방기를 피하고, **통풍이 잘되는 곳**에 둡니다. |
| 습도 | 너무 습하면 부식, 너무 건조하면 **정전기**가 발생하므로 적정 습도를 유지합니다. |
| 먼지 | 주기적으로 케이스 내부와 팬의 먼지를 제거합니다. |
| 전원 | **접지가 된 콘센트**를 사용하고, 정전에 대비해 **UPS(무정전 전원 공급 장치)** 를 사용합니다. |
| 충격 | 하드디스크는 진동에 약하므로 **동작 중 이동을 피합니다.** |
| 자석 | 자기 저장 매체 근처에 자석이나 강한 전자기기를 두지 않습니다. |
| 종료 | 전원을 갑자기 차단하지 말고 **정상적인 종료 절차**를 거칩니다. |

#### 왜 정전기가 위험할까?

사람이 느끼지 못하는 수준의 정전기도 **수천 볼트**에 이릅니다.

반도체 부품은 매우 미세한 회로로 이루어져 있어,  
이 정도의 전압만으로도 **회로가 손상**될 수 있습니다.

그래서 컴퓨터 내부를 만지기 전에는

- 금속 물체를 만져 정전기를 방전시키거나
- 정전기 방지 장갑·손목 밴드를 착용해야 합니다.

#### 왜 UPS가 필요할까?

컴퓨터가 작업 중일 때 갑자기 전원이 끊기면

- 저장하지 않은 데이터가 사라지고
- 기록 도중이던 파일이 손상되며
- 심하면 **디스크의 파일 시스템 자체가 깨질 수 있습니다.**

UPS는 정전이 발생해도 **일정 시간 전원을 계속 공급**하여,  
그동안 **파일을 저장하고 안전하게 종료**할 시간을 확보해 줍니다.

#### 왜 접지가 필요할까?

접지는 **누설된 전류를 땅으로 흘려보내는 통로**입니다.

접지가 없으면

- 감전 위험이 있고
- 불안정한 전기 신호로 인해 **오작동이나 부품 손상**이 발생할 수 있습니다.

---

### 3. 소프트웨어 관리

| 항목 | 관리 방법 |
| --- | --- |
| 백신 | 백신 프로그램을 설치하고 **최신 버전으로 업데이트**하며 정기적으로 검사합니다. |
| 운영체제 | Windows 업데이트를 통해 **보안 패치**를 적용합니다. |
| 불필요한 프로그램 | 사용하지 않는 프로그램은 **반드시 [앱 및 기능]에서 제거**합니다. |
| 디스크 관리 | **디스크 정리**로 공간을 확보하고, **조각 모음**으로 속도를 유지합니다. |
| 백업 | 중요한 데이터는 **다른 저장 장치에 정기적으로 백업**합니다. |
| 시작 프로그램 | 불필요한 시작 프로그램을 정리하여 부팅 속도를 유지합니다. |

#### 왜 백업은 다른 저장 장치에 해야 할까?

백업의 목적은 **원본을 잃었을 때 대비하는 것**입니다.

원본과 백업이 같은 디스크에 있다면,  
그 디스크가 고장 났을 때 **둘 다 함께 사라집니다.**

그래서 백업은 반드시

- 다른 물리적 저장 장치
- 가능하면 다른 장소(클라우드, 외장 하드 등)

에 보관해야 의미가 있습니다.

---

### 4. 저장 매체별 관리

| 매체 | 관리 방법 |
| --- | --- |
| 하드디스크 | 동작 중 충격을 피하고, 정기적으로 오류 검사와 조각 모음을 수행합니다. |
| SSD | **조각 모음을 하지 않습니다.** (수명 단축) 여유 공간을 일정 부분 남겨 둡니다. |
| USB 메모리 | 반드시 **[하드웨어 안전하게 제거]** 후 분리합니다. |
| CD/DVD | 표면에 흠집이 나지 않도록 하고, 직사광선을 피합니다. |
| 메모리 카드 | 접점 부위를 손으로 만지지 않습니다. |

---

### 5. 자료 관리

- 중요한 자료는 **정기적으로 백업**합니다.
- 백업은 **전체 백업 / 증분 백업 / 차등 백업** 방식으로 나눌 수 있습니다.

| 백업 방식 | 설명 |
| --- | --- |
| 전체 백업 | 모든 데이터를 백업합니다. 복구는 간단하지만 시간과 용량이 많이 듭니다. |
| 증분 백업 | **마지막 백업 이후 변경된 것만** 백업합니다. 빠르지만 복구 시 여러 백업본이 필요합니다. |
| 차등 백업 | **마지막 전체 백업 이후 변경된 모든 것**을 백업합니다. |

#### 왜 증분 백업이 빠른데도 잘 쓰이지 않을까?

증분 백업은 백업할 때는 빠르지만, **복구할 때가 문제**입니다.

전체 백업 → 증분1 → 증분2 → 증분3 ... 순서대로 **모두 순서대로 적용**해야 원래 상태가 됩니다.

중간의 백업본 하나만 손상되어도 그 이후를 복구할 수 없습니다.

그래서 안정성이 중요한 환경에서는 **전체 백업 + 차등 백업** 조합을 더 많이 사용합니다.

---

### 한 줄 정리

PC 관리는 **온도·습도·전원(UPS·접지)·먼지·정전기 관리가 핵심**이며,  
소프트웨어 측면에서는 **백신 최신화, 보안 업데이트, 디스크 정리, 정기 백업**이 중요하고,  
**백업은 반드시 원본과 다른 저장 장치**에 보관해야 합니다.
