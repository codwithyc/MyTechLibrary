## 046. 마이크로프로세서

### 1. 마이크로프로세서의 개요

마이크로프로세서(Microprocessor)는 **제어장치, 연산장치, 레지스터를 하나의 칩에 집적한 장치**로,  
개인용 컴퓨터(PC)에서 **CPU 역할**을 수행합니다.

- 클럭 주파수와 내부 버스의 폭에 따라 성능이 결정됩니다.
- 마이크로프로세서의 성능이 **컴퓨터 전체의 성능을 좌우**합니다.

#### 왜 하나의 칩에 모았을까?

과거에는 제어장치와 연산장치가 각각 별도의 부품으로 만들어졌습니다.  
부품 사이의 거리가 멀면 **신호가 오가는 데 시간이 걸리고, 크기와 전력 소모도 커집니다.**

이를 하나의 칩에 집적하면

- 신호 이동 거리가 짧아져 **속도가 빨라지고**
- 크기와 전력 소모가 줄어들며
- 대량 생산으로 **가격이 낮아집니다.**

이 집적 기술 덕분에 개인용 컴퓨터가 보급될 수 있었습니다.

---

### 2. 클럭 주파수(Clock Frequency)

CPU는 일정한 간격의 전기 신호(클럭)에 맞춰 동작합니다.

- 단위는 **Hz(헤르츠)** 이며, 현재는 주로 **GHz**를 사용합니다.
- **1Hz = 1초에 1번의 클럭**을 의미합니다.
- 클럭 주파수가 **높을수록 처리 속도가 빠릅니다.**

#### 왜 클럭이 필요할까?

CPU 안에는 수많은 부품이 있고, 이들이 **정확히 같은 박자로 움직여야** 합니다.

한 부품이 계산을 끝내기도 전에 다음 부품이 값을 가져가면 잘못된 결과가 나옵니다.

클럭은 **모든 부품이 맞추어 움직이는 지휘자의 박자**와 같습니다.

박자가 빨라지면(클럭 주파수가 높아지면) 더 많은 일을 처리할 수 있지만,  
**발열과 전력 소모도 함께 증가**합니다.

---

### 3. 마이크로프로세서의 종류

| 구분 | CISC | RISC |
| --- | --- | --- |
| 명령어 수 | **많음** | **적음** |
| 명령어 길이 | 가변적 | 고정적 |
| 명령어 구조 | 복잡함 | 단순함 |
| 레지스터 수 | 적음 | 많음 |
| 처리 속도 | 상대적으로 느림 | 빠름 |
| 전력 소모 | 많음 | 적음 |
| 프로그래밍 | 쉬움 (명령어가 다양) | 복잡함 (명령어를 조합해야 함) |
| 사용 예 | 개인용 컴퓨터(x86) | 워크스테이션, 스마트폰(ARM) |

#### 왜 CISC와 RISC로 나뉘었을까?

초기 컴퓨터는 메모리가 매우 비쌌습니다.  
그래서 **명령어 하나가 많은 일을 처리하도록** 만들어 프로그램의 크기를 줄였습니다. → **CISC**

그런데 실제로 사용해 보니, **복잡한 명령어는 거의 쓰이지 않고 단순한 명령어만 반복 사용**된다는 사실이 밝혀졌습니다.

그래서 자주 쓰는 단순 명령어만 남기고, 이를 **빠르게 처리하는 데 집중**한 방식이 등장했습니다. → **RISC**

정리하면

- **CISC** : 명령어를 풍부하게 → 프로그램은 짧지만 회로가 복잡
- **RISC** : 명령어를 단순하게 → 프로그램은 길지만 처리가 빠름

전력 소모가 적다는 특성 때문에 RISC는 **스마트폰과 태블릿**에서 널리 사용됩니다.

---

### 4. 코어(Core)

코어는 **실제로 연산을 수행하는 CPU의 핵심 부분**입니다.

| 종류 | 코어 수 |
| --- | --- |
| 싱글 코어 | 1개 |
| 듀얼 코어 | 2개 |
| 쿼드 코어 | 4개 |
| 헥사 코어 | 6개 |
| 옥타 코어 | 8개 |

#### 왜 클럭을 계속 높이는 대신 코어를 늘렸을까?

클럭 주파수를 높이면 성능은 좋아지지만,  
**발열과 전력 소모가 급격히 증가**하여 일정 수준 이상 올리기 어렵습니다.

그래서 **하나를 더 빠르게 만드는 대신, 여러 개를 함께 일하게 하는 방향**으로 바뀌었습니다.

다만 코어가 많다고 항상 빨라지는 것은 아닙니다.  
프로그램이 **여러 코어에 나누어 처리될 수 있도록 작성되어야만** 효과가 있습니다.

---

### 5. 마이크로프로세서 관련 용어

| 용어 | 설명 |
| --- | --- |
| **워드(Word)** | CPU가 **한 번에 처리할 수 있는 데이터의 크기**입니다. (32비트, 64비트) |
| **버스(Bus)** | CPU와 각 장치 사이에 데이터를 주고받는 통로입니다. |
| 데이터 버스 | 데이터를 전송하는 통로로, **폭이 넓을수록 한 번에 많은 데이터를 전송**합니다. |
| 주소 버스 | 주소 정보를 전송하는 통로로, **폭이 넓을수록 더 넓은 메모리 공간을 사용**할 수 있습니다. |
| 제어 버스 | 제어 신호를 전송하는 통로입니다. |
| **MIPS** | 1초당 실행할 수 있는 명령어 수(백만 단위)로, 처리 속도를 나타냅니다. |
| **FLOPS** | 1초당 처리할 수 있는 부동 소수점 연산 횟수입니다. |
| 하이퍼스레딩 | 하나의 코어를 논리적으로 두 개처럼 동작시키는 기술입니다. |
| 캐시 메모리 | CPU와 주기억장치 사이의 속도 차이를 줄이는 고속 기억장치입니다. |

#### 왜 주소 버스의 폭이 메모리 용량을 결정할까?

주소 버스의 폭이 n비트라면, 표현할 수 있는 주소는 **2ⁿ개**입니다.

- 32비트 → 2³² = 약 4GB
- 64비트 → 훨씬 넓은 공간

즉, 주소를 표현할 수 없으면 그 메모리는 **존재해도 사용할 수 없습니다.**

이것이 32비트 시스템이 4GB 이상의 메모리를 인식하지 못하는 이유입니다.

---

### 한 줄 정리

마이크로프로세서는 **제어장치·연산장치·레지스터를 하나의 칩에 집적한 CPU**이며,  
**CISC는 명령어가 많고 복잡, RISC는 명령어가 적고 단순하며 빠르고 전력 소모가 적습니다.**  
데이터 버스 폭은 **한 번에 전송할 데이터 양**, 주소 버스 폭은 **사용 가능한 메모리 용량**을 결정합니다.
