# TCP/IP 계층의 기본 프로토콜

## 3-1. 네트워크 접근 계층의 주요 개념

### 1) MAC 주소

MAC 주소는 네트워크 장비에 부여되는 **물리적 주소**입니다.
같은 네트워크 안에서 장치를 구분하기 위해 사용되며, 주로 LAN 환경에서 데이터가 실제 장비까지 전달될 때 사용됩니다.

1. MAC 주소의 특징

   * Media Access Control Address의 약자입니다.
   * 네트워크 인터페이스 카드, 즉 NIC에 부여되는 주소입니다.
   * 일반적으로 48비트로 구성됩니다.
   * 16진수로 표현합니다.
   * 같은 LAN 안에서 장치를 식별하는 데 사용됩니다.
   * 데이터 링크 계층에서 사용됩니다.

| 구분    | 내용                           |
| ----- | ---------------------------- |
| 전체 이름 | Media Access Control Address |
| 계층    | 네트워크 접근 계층, 데이터 링크 계층        |
| 크기    | 48비트                         |
| 표현 방식 | 16진수                         |
| 사용 목적 | 같은 네트워크 안에서 장치 식별            |
| 예시    | `00:1A:2B:3C:4D:5E`          |

#### MAC 주소 구조

| 구분     | 내용                |
| ------ | ----------------- |
| 앞 24비트 | 제조사 식별 번호, OUI    |
| 뒤 24비트 | 제조사가 부여한 장치 고유 번호 |

```text
MAC 주소 = 제조사 번호 + 장치 고유 번호
```

#### 한 줄 정리

```text
MAC 주소 = 같은 LAN 안에서 장치를 구분하는 물리적 주소
```

## 3-2. 인터넷 계층의 프로토콜

인터넷 계층은 TCP/IP 계층에서 **목적지까지 데이터를 전달하는 역할**을 담당합니다.
IP 주소를 기반으로 목적지를 식별하고, 라우팅을 통해 패킷을 전달합니다.

| 프로토콜 | 전체 이름                               | 핵심 역할             |
| ---- | ----------------------------------- | ----------------- |
| IP   | Internet Protocol                   | IP 주소를 기반으로 패킷 전달 |
| ICMP | Internet Control Message Protocol   | 오류 보고와 네트워크 상태 확인 |
| IGMP | Internet Group Management Protocol  | 멀티캐스트 그룹 관리       |
| ARP  | Address Resolution Protocol         | IP 주소를 MAC 주소로 변환 |
| RARP | Reverse Address Resolution Protocol | MAC 주소를 IP 주소로 변환 |

### 1) 데이터그램

데이터그램은 인터넷 계층에서 사용하는 **독립적인 데이터 전송 단위**입니다.
각 데이터그램은 목적지 주소를 포함하고 있으며, 네트워크를 통해 독립적으로 전달됩니다.

1. 데이터그램의 특징

   * 인터넷 계층의 전송 단위입니다.
   * 각 데이터그램은 독립적으로 전달됩니다.
   * 서로 다른 경로로 전송될 수 있습니다.
   * 도착 순서가 보장되지 않을 수 있습니다.
   * IP는 기본적으로 비연결형 방식이기 때문에 데이터그램 단위로 전달합니다.

| 구분      | 내용                    |
| ------- | --------------------- |
| 계층      | 인터넷 계층                |
| 의미      | 독립적으로 전달되는 패킷 단위      |
| 특징      | 비연결형, 독립 전송, 순서 보장 없음 |
| 관련 프로토콜 | IP                    |

#### 한 줄 정리

```text
데이터그램 = 인터넷 계층에서 독립적으로 전달되는 패킷 단위
```

### 2) IP

#### IP 프로토콜의 개요와 개념

IP는 Internet Protocol의 약자로, 인터넷 계층에서 가장 핵심이 되는 프로토콜입니다.
데이터를 목적지까지 전달하기 위해 **IP 주소를 사용**합니다.

1. IP의 특징

   * 비연결형 프로토콜입니다.
   * 패킷을 목적지까지 전달합니다.
   * IP 주소를 사용하여 송신자와 수신자를 구분합니다.
   * 최선형 전달 방식, Best Effort 방식을 사용합니다.
   * 신뢰성을 보장하지 않습니다.
   * 패킷 손실, 중복, 순서 변경이 발생할 수 있습니다.
   * 신뢰성 보장은 TCP 같은 전송 계층에서 담당합니다.

| 구분    | 내용                     |
| ----- | ---------------------- |
| 전체 이름 | Internet Protocol      |
| 계층    | 인터넷 계층                 |
| 전송 단위 | 패킷, 데이터그램              |
| 주소 체계 | IP 주소                  |
| 방식    | 비연결형                   |
| 특징    | Best Effort, 신뢰성 보장 없음 |

#### 한 줄 정리

```text
IP = IP 주소를 기반으로 패킷을 목적지까지 보내는 프로토콜
```

#### IPv4와 IPv6

IPv4와 IPv6는 IP 주소 체계의 대표적인 버전입니다.
IPv4는 현재까지 널리 사용되는 32비트 주소 체계이고, IPv6는 IPv4 주소 부족 문제를 해결하기 위해 만들어진 128비트 주소 체계입니다.

| 구분     | IPv4            | IPv6                                      |
| ------ | --------------- | ----------------------------------------- |
| 주소 길이  | 32비트            | 128비트                                     |
| 표현 방식  | 10진수 4개를 점으로 구분 | 16진수 8개 그룹을 콜론으로 구분                       |
| 예시     | `192.168.0.1`   | `2001:0db8:0000:0000:0000:ff00:0042:8329` |
| 주소 개수  | 약 43억 개         | 매우 많음                                     |
| 헤더 구조  | 가변 길이           | 고정 길이                                     |
| 보안     | 별도 구성 필요        | IPsec 지원 구조 포함                            |
| 브로드캐스트 | 지원              | 지원하지 않음                                   |
| 주소 설정  | 수동 설정, DHCP     | 자동 설정 지원                                  |

#### IPv6 생략 표기

IPv6는 주소가 길기 때문에 생략 표기를 사용할 수 있습니다.

1. 앞의 0 생략

   * 각 그룹에서 앞쪽의 0은 생략할 수 있습니다.

```text
원래 주소: 2001:0db8:0000:0000:0000:ff00:0042:8329
생략 주소: 2001:db8:0:0:0:ff00:42:8329
```

2. 연속된 0 그룹 생략

   * 연속된 0 그룹은 `::`로 한 번만 생략할 수 있습니다.

```text
원래 주소: 2001:db8:0:0:0:ff00:42:8329
생략 주소: 2001:db8::ff00:42:8329
```

3. 주의할 점

   * `::`는 한 주소에서 한 번만 사용할 수 있습니다.
   * 두 번 이상 사용하면 어느 부분에 0이 몇 개 들어가는지 알 수 없습니다.

#### 한 줄 정리

```text
IPv4 = 32비트 주소
IPv6 = 128비트 주소
IPv6의 연속된 0은 ::로 한 번만 생략 가능
```

#### IP 헤더

##### 1. IP 헤더의 정의

IP 헤더는 IP 패킷을 목적지까지 전달하기 위해 필요한 제어 정보를 담고 있는 부분입니다.
출발지 IP 주소, 목적지 IP 주소, 패킷 길이, TTL, 프로토콜 정보 등이 포함됩니다.

```text
IP 패킷 = IP 헤더 + 데이터
```

##### 2. IPv4의 헤더

IPv4 헤더는 기본적으로 20바이트이며, 옵션이 추가되면 최대 60바이트까지 커질 수 있습니다.

| 필드                  | 설명                            |
| ------------------- | ----------------------------- |
| Version             | IP 버전 정보, IPv4는 4             |
| IHL                 | IP Header Length, 헤더 길이       |
| Type of Service     | 서비스 품질, 우선순위 관련 필드            |
| Total Length        | IP 패킷 전체 길이                   |
| Identification      | 단편화된 패킷을 식별하기 위한 값            |
| Flags               | 단편화 제어 정보                     |
| Fragment Offset     | 단편화된 조각의 위치                   |
| TTL                 | Time To Live, 패킷 생존 시간        |
| Protocol            | 상위 계층 프로토콜 표시, TCP/UDP/ICMP 등 |
| Header Checksum     | 헤더 오류 검출                      |
| Source Address      | 출발지 IP 주소                     |
| Destination Address | 목적지 IP 주소                     |
| Options             | 선택적 기능                        |
| Padding             | 헤더 길이를 맞추기 위한 채움 값            |

##### IPv4 헤더 핵심 필드

| 핵심 필드               | 중요 포인트                         |
| ------------------- | ------------------------------ |
| TTL                 | 라우터를 지날 때마다 감소하며, 0이 되면 패킷 폐기  |
| Protocol            | 상위 프로토콜이 TCP인지 UDP인지 ICMP인지 구분 |
| Source Address      | 출발지 IP                         |
| Destination Address | 목적지 IP                         |
| Fragment 관련 필드      | 패킷 단편화와 재조립에 사용                |

##### 3. IPv6의 헤더

IPv6 헤더는 40바이트 고정 길이입니다.
IPv4보다 구조가 단순해졌고, 필요한 추가 기능은 확장 헤더를 통해 처리합니다.

| 필드                  | 설명                    |
| ------------------- | --------------------- |
| Version             | IP 버전 정보, IPv6는 6     |
| Traffic Class       | 패킷 우선순위, 서비스 품질 관련 필드 |
| Flow Label          | 특정 흐름의 패킷을 식별하기 위한 필드 |
| Payload Length      | IPv6 헤더를 제외한 데이터 길이   |
| Next Header         | 다음 헤더 또는 상위 프로토콜 표시   |
| Hop Limit           | IPv4의 TTL과 유사한 역할     |
| Source Address      | 출발지 IPv6 주소           |
| Destination Address | 목적지 IPv6 주소           |

##### IPv6 헤더 핵심 필드

| 핵심 필드                      | 중요 포인트              |
| -------------------------- | ------------------- |
| Traffic Class              | 트래픽 우선순위 표시         |
| Flow Label                 | 동일 흐름의 패킷 식별        |
| Next Header                | 다음 헤더 또는 상위 프로토콜 지정 |
| Hop Limit                  | IPv4의 TTL과 유사       |
| Source/Destination Address | 128비트 주소 사용         |

##### 4. IPv4와 IPv6 헤더 비교

| 구분         | IPv4 헤더         | IPv6 헤더        |
| ---------- | --------------- | -------------- |
| 헤더 길이      | 가변 길이, 기본 20바이트 | 고정 길이, 40바이트   |
| 주소 길이      | 32비트            | 128비트          |
| 체크섬        | 있음              | 없음             |
| 단편화        | 라우터와 송신자가 수행 가능 | 송신자만 수행        |
| 옵션         | 기본 헤더에 포함       | 확장 헤더 사용       |
| TTL        | TTL 필드 사용       | Hop Limit 사용   |
| 상위 프로토콜 표시 | Protocol 필드     | Next Header 필드 |
| 구조         | 상대적으로 복잡        | 단순화됨           |

#### 한 줄 정리

```text
IPv4 헤더 = 가변 길이, 체크섬 있음, 32비트 주소
IPv6 헤더 = 고정 길이, 체크섬 없음, 128비트 주소
```

#### IP 주소 클래스

IPv4 주소는 과거에 네트워크 규모에 따라 A, B, C, D, E 클래스로 구분되었습니다.
현재는 CIDR 방식이 주로 사용되지만, 시험에서는 클래스 개념이 자주 등장합니다.

| 클래스   | 시작 비트 | 주소 범위                       | 기본 서브넷 마스크    | 용도       |
| ----- | ----- | --------------------------- | ------------- | -------- |
| A 클래스 | 0     | 1.0.0.0 ~ 126.255.255.255   | 255.0.0.0     | 대규모 네트워크 |
| B 클래스 | 10    | 128.0.0.0 ~ 191.255.255.255 | 255.255.0.0   | 중규모 네트워크 |
| C 클래스 | 110   | 192.0.0.0 ~ 223.255.255.255 | 255.255.255.0 | 소규모 네트워크 |
| D 클래스 | 1110  | 224.0.0.0 ~ 239.255.255.255 | 없음            | 멀티캐스트    |
| E 클래스 | 1111  | 240.0.0.0 ~ 255.255.255.255 | 없음            | 연구 및 실험용 |

#### 특수 IP 주소

| 주소                | 의미                |
| ----------------- | ----------------- |
| `0.0.0.0`         | 현재 네트워크 또는 미지정 주소 |
| `127.0.0.1`       | 루프백 주소, 자기 자신     |
| `255.255.255.255` | 제한 브로드캐스트 주소      |
| `169.254.x.x`     | APIPA, 자동 사설 IP   |
| `10.0.0.0/8`      | 사설 IP 대역          |
| `172.16.0.0/12`   | 사설 IP 대역          |
| `192.168.0.0/16`  | 사설 IP 대역          |

#### 한 줄 정리

```text
A = 대규모
B = 중규모
C = 소규모
D = 멀티캐스트
E = 실험용
```

#### IP 주소 체계

IP 주소는 네트워크에서 장치를 식별하기 위한 논리적 주소입니다.
IPv4 주소는 네트워크 부분과 호스트 부분으로 구성됩니다.

```text
IP 주소 = 네트워크 ID + 호스트 ID
```

| 구분      | 설명                          |
| ------- | --------------------------- |
| 네트워크 ID | 장치가 속한 네트워크를 식별             |
| 호스트 ID  | 네트워크 안의 개별 장치를 식별           |
| 서브넷 마스크 | IP 주소에서 네트워크 부분과 호스트 부분을 구분 |
| 게이트웨이   | 다른 네트워크로 나가기 위한 출입구         |
| DNS 서버  | 도메인 이름을 IP 주소로 변환           |

#### 공인 IP와 사설 IP

| 구분     | 공인 IP              | 사설 IP              |
| ------ | ------------------ | ------------------ |
| 의미     | 인터넷에서 직접 사용 가능한 IP | 내부 네트워크에서만 사용하는 IP |
| 중복 가능성 | 전 세계에서 유일해야 함      | 다른 내부망과 중복 가능      |
| 사용 위치  | 인터넷 구간             | 가정, 회사 내부망         |
| 예시     | ISP가 할당한 IP        | `192.168.0.10`     |

#### 사설 IP 대역

| 클래스   | 사설 IP 대역                        |
| ----- | ------------------------------- |
| A 클래스 | `10.0.0.0 ~ 10.255.255.255`     |
| B 클래스 | `172.16.0.0 ~ 172.31.255.255`   |
| C 클래스 | `192.168.0.0 ~ 192.168.255.255` |

#### 서브넷 마스크와 서브넷팅 계산 법

서브넷 마스크는 IP 주소에서 **네트워크 부분과 호스트 부분을 구분하는 값**입니다.
서브넷팅은 하나의 네트워크를 여러 개의 작은 네트워크로 나누는 작업입니다.

##### 서브넷 마스크 예시

| CIDR | 서브넷 마스크         | 사용 가능한 호스트 수 |
| ---- | --------------- | ------------ |
| /8   | 255.0.0.0       | 16,777,214개  |
| /16  | 255.255.0.0     | 65,534개      |
| /24  | 255.255.255.0   | 254개         |
| /25  | 255.255.255.128 | 126개         |
| /26  | 255.255.255.192 | 62개          |
| /27  | 255.255.255.224 | 30개          |
| /28  | 255.255.255.240 | 14개          |
| /29  | 255.255.255.248 | 6개           |
| /30  | 255.255.255.252 | 2개           |

##### 서브넷팅 계산 공식

| 구분           | 공식                          |
| ------------ | --------------------------- |
| 서브넷 개수       | `2^빌린 비트 수`                 |
| 호스트 개수       | `2^호스트 비트 수 - 2`            |
| 블록 크기        | `256 - 서브넷 마스크 값`           |
| 네트워크 주소      | 해당 서브넷의 첫 번째 주소             |
| 브로드캐스트 주소    | 해당 서브넷의 마지막 주소              |
| 사용 가능 호스트 범위 | 네트워크 주소 + 1 ~ 브로드캐스트 주소 - 1 |

##### 예시: `192.168.1.0/26`

```text
/26 = 네트워크 비트 26개
호스트 비트 = 32 - 26 = 6개
호스트 수 = 2^6 - 2 = 62개
서브넷 마스크 = 255.255.255.192
블록 크기 = 256 - 192 = 64
```

| 서브넷 | 네트워크 주소       | 사용 가능 호스트                     | 브로드캐스트 주소     |
| --- | ------------- | ----------------------------- | ------------- |
| 1번  | 192.168.1.0   | 192.168.1.1 ~ 192.168.1.62    | 192.168.1.63  |
| 2번  | 192.168.1.64  | 192.168.1.65 ~ 192.168.1.126  | 192.168.1.127 |
| 3번  | 192.168.1.128 | 192.168.1.129 ~ 192.168.1.190 | 192.168.1.191 |
| 4번  | 192.168.1.192 | 192.168.1.193 ~ 192.168.1.254 | 192.168.1.255 |

#### 한 줄 정리

```text
서브넷 마스크 = 네트워크 부분과 호스트 부분을 구분
서브넷팅 = 하나의 네트워크를 여러 개로 나누는 것
호스트 수 = 2^호스트 비트 수 - 2
블록 크기 = 256 - 서브넷 마스크 값
```

### 3) 라우팅 프로토콜

#### 라우팅의 개요

라우팅은 패킷을 목적지 네트워크까지 전달하기 위해 **최적의 경로를 선택하는 과정**입니다.
라우터는 라우팅 테이블을 참고하여 패킷을 어느 방향으로 보낼지 결정합니다.

| 구분      | 내용                           |
| ------- | ---------------------------- |
| 라우팅     | 목적지까지의 경로를 선택하는 과정           |
| 라우터     | 서로 다른 네트워크를 연결하고 패킷을 전달하는 장비 |
| 라우팅 테이블 | 목적지 네트워크와 다음 경로 정보가 저장된 표    |
| 홉       | 패킷이 거치는 라우터의 수               |
| 메트릭     | 경로 선택 기준이 되는 비용 값            |

#### 한 줄 정리

```text
라우팅 = 목적지까지 패킷이 갈 경로를 정하는 과정
```

#### 라우팅 경로의 실시간 변동 가능성에 따른 라우팅 프로토콜의 분류

| 구분     | 의미                       | 특징                              |
| ------ | ------------------------ | ------------------------------- |
| 정적 라우팅 | 관리자가 직접 경로를 설정           | 단순하고 안정적이지만 변화에 자동 대응하지 못함      |
| 동적 라우팅 | 라우터끼리 정보를 교환하여 경로를 자동 설정 | 네트워크 변화에 자동 대응 가능하지만 자원 사용량이 증가 |

#### 라우팅 범위에 따른 라우팅 프로토콜 분류

| 구분  | 전체 이름                     | 의미                              | 예시        |
| --- | ------------------------- | ------------------------------- | --------- |
| IGP | Interior Gateway Protocol | 하나의 자율 시스템 내부에서 사용하는 라우팅 프로토콜   | RIP, OSPF |
| EGP | Exterior Gateway Protocol | 서로 다른 자율 시스템 사이에서 사용하는 라우팅 프로토콜 | BGP       |

#### 라우팅 프로토콜의 개념과 방식

| 방식    | 의미                         | 대표 프로토콜 | 특징                    |
| ----- | -------------------------- | ------- | --------------------- |
| 거리 벡터 | 목적지까지의 거리와 방향을 기준으로 경로 선택  | RIP     | 구조가 단순하지만 큰 네트워크에 부적합 |
| 링크 상태 | 네트워크 전체의 연결 상태를 파악하여 경로 선택 | OSPF    | 빠르고 정확하지만 구조가 복잡      |
| 경로 벡터 | 경로 정보와 정책을 기준으로 경로 선택      | BGP     | 인터넷 규모의 라우팅에 사용       |

#### RIP

RIP는 Routing Information Protocol의 약자입니다.
거리 벡터 방식의 대표적인 라우팅 프로토콜입니다.

1. RIP의 특징

   * 거리 벡터 라우팅 프로토콜입니다.
   * 홉 수를 기준으로 최적 경로를 선택합니다.
   * 최대 홉 수는 15입니다.
   * 16홉은 도달 불가능을 의미합니다.
   * 구조가 단순하지만 대규모 네트워크에는 적합하지 않습니다.

| 구분     | 내용                           |
| ------ | ---------------------------- |
| 전체 이름  | Routing Information Protocol |
| 분류     | IGP                          |
| 방식     | 거리 벡터                        |
| 메트릭    | 홉 수                          |
| 최대 홉 수 | 15                           |
| 특징     | 단순하지만 대규모 네트워크에 부적합          |

#### OSPF

OSPF는 Open Shortest Path First의 약자입니다.
링크 상태 방식의 대표적인 라우팅 프로토콜입니다.

1. OSPF의 특징

   * 링크 상태 라우팅 프로토콜입니다.
   * 네트워크 상태 정보를 기반으로 최단 경로를 계산합니다.
   * SPF 알고리즘을 사용합니다.
   * RIP보다 빠르고 대규모 네트워크에 적합합니다.
   * 영역, Area 개념을 사용합니다.

| 구분    | 내용                       |
| ----- | ------------------------ |
| 전체 이름 | Open Shortest Path First |
| 분류    | IGP                      |
| 방식    | 링크 상태                    |
| 알고리즘  | SPF, Dijkstra 알고리즘       |
| 메트릭   | 비용, Cost                 |
| 특징    | 빠르고 대규모 네트워크에 적합         |

#### NAT

NAT는 Network Address Translation의 약자입니다.
사설 IP 주소와 공인 IP 주소를 변환하는 기술입니다.

1. NAT의 특징

   * 내부 사설 IP를 외부 공인 IP로 변환합니다.
   * IPv4 주소 부족 문제를 완화합니다.
   * 내부 네트워크 구조를 외부에서 직접 알기 어렵게 합니다.
   * 공유기에서 많이 사용됩니다.

| 구분    | 내용                          |
| ----- | --------------------------- |
| 전체 이름 | Network Address Translation |
| 의미    | 사설 IP와 공인 IP를 변환하는 기술       |
| 목적    | IPv4 주소 절약, 내부망 보호          |
| 사용 예시 | 가정용 공유기, 회사 내부망             |

#### NAT 종류

| 구분     | 의미                                     |
| ------ | -------------------------------------- |
| 정적 NAT | 하나의 사설 IP를 하나의 공인 IP로 고정 변환            |
| 동적 NAT | 여러 공인 IP 풀 중 하나를 동적으로 할당               |
| PAT    | 포트 번호를 함께 변환하여 여러 내부 장비가 하나의 공인 IP를 공유 |

#### 한 줄 정리

```text
RIP = 홉 수 기준
OSPF = 링크 상태와 비용 기준
NAT = 사설 IP와 공인 IP 변환
```

### 4) ICMP

#### 개요

ICMP는 Internet Control Message Protocol의 약자입니다.
IP 통신 중 발생하는 오류를 알리거나 네트워크 상태를 확인하기 위해 사용됩니다.

1. ICMP의 특징

   * 인터넷 계층 프로토콜입니다.
   * 오류 보고와 진단 기능을 제공합니다.
   * ping, traceroute 명령에서 사용됩니다.
   * 데이터를 전송하기 위한 프로토콜이라기보다 제어 메시지를 전달하기 위한 프로토콜입니다.

| 구분    | 내용                                |
| ----- | --------------------------------- |
| 전체 이름 | Internet Control Message Protocol |
| 계층    | 인터넷 계층                            |
| 주요 역할 | 오류 보고, 네트워크 상태 확인                 |
| 사용 예시 | ping, traceroute                  |

#### ICMP의 헤더

| 필드       | 설명                 |
| -------- | ------------------ |
| Type     | ICMP 메시지 종류        |
| Code     | Type에 대한 세부 원인     |
| Checksum | 오류 검출              |
| 기타 필드    | 메시지 종류에 따라 달라지는 정보 |

#### ICMP 메시지 종류

| Type | 메시지                     | 설명         |
| ---- | ----------------------- | ---------- |
| 0    | Echo Reply              | ping 응답    |
| 3    | Destination Unreachable | 목적지 도달 불가  |
| 5    | Redirect                | 더 나은 경로 안내 |
| 8    | Echo Request            | ping 요청    |
| 11   | Time Exceeded           | TTL 초과     |
| 12   | Parameter Problem       | 헤더 필드 문제   |

#### TTL

TTL은 Time To Live의 약자입니다.
패킷이 네트워크에서 무한히 순환하는 것을 방지하기 위한 값입니다.

1. TTL의 특징

   * 라우터를 하나 지날 때마다 1씩 감소합니다.
   * TTL 값이 0이 되면 패킷은 폐기됩니다.
   * TTL 초과 시 ICMP Time Exceeded 메시지가 발생할 수 있습니다.
   * traceroute는 TTL 값을 이용하여 경로를 추적합니다.

#### 한 줄 정리

```text
ICMP = 오류 보고와 네트워크 상태 확인
TTL = 패킷의 생존 시간
```

### 5) IGMP

#### 개요

IGMP는 Internet Group Management Protocol의 약자입니다.
멀티캐스트 통신에서 호스트가 특정 멀티캐스트 그룹에 가입하거나 탈퇴하는 것을 관리합니다.

1. IGMP의 특징

   * 인터넷 계층 프로토콜입니다.
   * 멀티캐스트 그룹 관리를 담당합니다.
   * 라우터가 어떤 호스트가 어떤 멀티캐스트 그룹에 속해 있는지 파악할 수 있게 합니다.
   * IPTV, 실시간 방송, 화상 회의 등에 활용됩니다.

| 구분    | 내용                                 |
| ----- | ---------------------------------- |
| 전체 이름 | Internet Group Management Protocol |
| 계층    | 인터넷 계층                             |
| 주요 역할 | 멀티캐스트 그룹 관리                        |
| 사용 예시 | IPTV, 실시간 스트리밍, 화상 회의              |

#### 데이터 전송 방식과 멀티캐스트

| 전송 방식  | 의미                       | 전송 대상     |
| ------ | ------------------------ | --------- |
| 유니캐스트  | 하나의 송신자가 하나의 수신자에게 전송    | 1 : 1     |
| 브로드캐스트 | 하나의 송신자가 같은 네트워크 전체에게 전송 | 1 : 전체    |
| 멀티캐스트  | 하나의 송신자가 특정 그룹에게 전송      | 1 : 특정 그룹 |

#### IGMP 헤더 v2

| 필드                | 설명              |
| ----------------- | --------------- |
| Type              | IGMP 메시지 종류     |
| Max Response Time | 응답까지 허용되는 최대 시간 |
| Checksum          | 오류 검출           |
| Group Address     | 멀티캐스트 그룹 주소     |

#### 한 줄 정리

```text
IGMP = 멀티캐스트 그룹 가입과 탈퇴를 관리하는 프로토콜
```

### 6) ARP

ARP는 Address Resolution Protocol의 약자입니다.
IP 주소를 MAC 주소로 변환하는 프로토콜입니다.

1. ARP의 특징

   * 같은 네트워크 안에서 사용됩니다.
   * IP 주소만 알고 있을 때 해당 장비의 MAC 주소를 찾습니다.
   * ARP 요청은 브로드캐스트로 전송됩니다.
   * ARP 응답은 유니캐스트로 전송됩니다.
   * 찾아낸 정보는 ARP 캐시에 일정 시간 저장됩니다.

| 구분    | 내용                          |
| ----- | --------------------------- |
| 전체 이름 | Address Resolution Protocol |
| 역할    | IP 주소를 MAC 주소로 변환           |
| 요청 방식 | 브로드캐스트                      |
| 응답 방식 | 유니캐스트                       |
| 저장 위치 | ARP 캐시                      |

#### ARP 동작 과정

```text
1. 송신자는 목적지 IP에 해당하는 MAC 주소를 모른다.
2. 네트워크 전체에 ARP Request를 보낸다.
3. 해당 IP를 가진 장비가 ARP Reply를 보낸다.
4. 송신자는 MAC 주소를 ARP 캐시에 저장하고 통신한다.
```

#### 한 줄 정리

```text
ARP = IP 주소를 MAC 주소로 변환
```

### 7) RARP

RARP는 Reverse Address Resolution Protocol의 약자입니다.
ARP와 반대로 MAC 주소를 이용해 IP 주소를 알아내는 프로토콜입니다.

1. RARP의 특징

   * MAC 주소를 IP 주소로 변환합니다.
   * 디스크가 없는 장비가 자신의 IP 주소를 알아낼 때 사용되었습니다.
   * 현재는 DHCP가 널리 사용되면서 거의 사용되지 않습니다.

| 구분    | 내용                                  |
| ----- | ----------------------------------- |
| 전체 이름 | Reverse Address Resolution Protocol |
| 역할    | MAC 주소를 IP 주소로 변환                   |
| 특징    | 현재는 거의 사용되지 않음                      |
| 대체 기술 | DHCP                                |

#### 한 줄 정리

```text
RARP = MAC 주소를 IP 주소로 변환
```

## 3-3. 전송 계층의 프로토콜

### 1) 전송 계층

전송 계층은 송신 측과 수신 측의 프로그램 사이에서 데이터를 전달하는 계층입니다.
포트 번호를 사용하여 하나의 컴퓨터 안에서 어떤 프로그램에게 데이터를 전달할지 구분합니다.

1. 전송 계층의 주요 역할

   * 종단 간 통신을 담당합니다.
   * 포트 번호를 사용하여 응용 프로그램을 식별합니다.
   * TCP와 UDP를 사용합니다.
   * TCP는 신뢰성 있는 전송을 제공합니다.
   * UDP는 빠른 전송을 제공합니다.
   * 흐름 제어, 오류 제어, 혼잡 제어와 관련됩니다.

| 구분      | 내용                    |
| ------- | --------------------- |
| 계층      | 전송 계층                 |
| 데이터 단위  | TCP는 세그먼트, UDP는 데이터그램 |
| 주소 체계   | 포트 번호                 |
| 대표 프로토콜 | TCP, UDP              |
| 주요 역할   | 프로그램 간 데이터 전달         |

#### TCP와 UDP의 대표적 차이 비교

| 구분    | TCP                           | UDP                    |
| ----- | ----------------------------- | ---------------------- |
| 전체 이름 | Transmission Control Protocol | User Datagram Protocol |
| 연결 방식 | 연결형                           | 비연결형                   |
| 신뢰성   | 높음                            | 낮음                     |
| 속도    | 상대적으로 느림                      | 상대적으로 빠름               |
| 순서 보장 | 보장함                           | 보장하지 않음                |
| 재전송   | 수행함                           | 수행하지 않음                |
| 흐름 제어 | 수행함                           | 수행하지 않음                |
| 혼잡 제어 | 수행함                           | 수행하지 않음                |
| 헤더 크기 | 20바이트 이상                      | 8바이트                   |
| 사용 예시 | 웹, 이메일, 파일 전송                 | DNS, DHCP, 스트리밍        |

#### 한 줄 정리

```text
TCP = 신뢰성 중심
UDP = 속도 중심
```

### 2) TCP

#### 개요와 특징

TCP는 Transmission Control Protocol의 약자입니다.
신뢰성 있는 데이터 전송을 제공하는 연결형 전송 계층 프로토콜입니다.

1. TCP의 특징

   * 연결형 프로토콜입니다.
   * 데이터를 보내기 전에 연결을 설정합니다.
   * 순서 보장을 제공합니다.
   * 오류 발생 시 재전송합니다.
   * 흐름 제어를 수행합니다.
   * 혼잡 제어를 수행합니다.
   * UDP보다 느리지만 안정적입니다.

| 구분     | 내용                            |
| ------ | ----------------------------- |
| 전체 이름  | Transmission Control Protocol |
| 방식     | 연결형                           |
| 신뢰성    | 높음                            |
| 데이터 단위 | 세그먼트                          |
| 주요 기능  | 순서 보장, 재전송, 흐름 제어, 혼잡 제어      |

#### 상태 전이

TCP는 연결 설정, 데이터 전송, 연결 종료 과정에서 여러 상태를 가집니다.

| 상태           | 의미                          |
| ------------ | --------------------------- |
| LISTEN       | 서버가 연결 요청을 기다리는 상태          |
| SYN-SENT     | 클라이언트가 SYN을 보내고 응답을 기다리는 상태 |
| SYN-RECEIVED | 서버가 SYN을 받고 SYN+ACK를 보낸 상태  |
| ESTABLISHED  | 연결이 설정되어 데이터 전송이 가능한 상태     |
| FIN-WAIT-1   | 연결 종료 요청을 보낸 상태             |
| FIN-WAIT-2   | 상대방의 종료 요청을 기다리는 상태         |
| CLOSE-WAIT   | 상대방의 종료 요청을 받은 상태           |
| LAST-ACK     | 종료 확인 응답을 기다리는 상태           |
| TIME-WAIT    | 마지막 ACK 후 일정 시간 기다리는 상태     |
| CLOSED       | 연결이 완전히 종료된 상태              |

#### TCP 3-Way Handshake

```text
1. 클라이언트 → 서버 : SYN
2. 서버 → 클라이언트 : SYN + ACK
3. 클라이언트 → 서버 : ACK
```

#### TCP 연결 종료

```text
1. 한쪽에서 FIN 전송
2. 상대방이 ACK 응답
3. 상대방도 FIN 전송
4. 처음 종료 요청자가 ACK 응답
```

#### 흐름 제어

흐름 제어는 송신자가 수신자의 처리 능력보다 너무 빠르게 데이터를 보내지 않도록 조절하는 기능입니다.

1. 흐름 제어의 목적

   * 수신 버퍼 오버플로우 방지
   * 송신 속도와 수신 처리 속도 조절
   * 안정적인 데이터 전송

| 방식             | 설명                           |
| -------------- | ---------------------------- |
| Stop-and-Wait  | 하나를 보내고 ACK를 받은 뒤 다음 데이터를 전송 |
| Sliding Window | 윈도우 크기만큼 ACK 없이 연속 전송 가능     |

#### 혼잡 제어

혼잡 제어는 네트워크가 과부하되지 않도록 송신량을 조절하는 기능입니다.

1. 혼잡 제어의 목적

   * 네트워크 혼잡 방지
   * 패킷 손실 감소
   * 전체 네트워크 성능 유지

| 방식                   | 설명                          |
| -------------------- | --------------------------- |
| Slow Start           | 처음에는 천천히 보내다가 점점 전송량 증가     |
| Congestion Avoidance | 혼잡이 예상되면 증가 속도를 완만하게 조절     |
| Fast Retransmit      | 중복 ACK를 받으면 손실된 패킷을 빠르게 재전송 |
| Fast Recovery        | 혼잡 발생 후 전송량을 급격히 줄이지 않고 회복  |

#### 헤더의 구조와 특징

TCP 헤더는 기본 20바이트이며, 옵션이 추가되면 더 길어질 수 있습니다.

| TCP 헤더 필드             | 설명                        |
| --------------------- | ------------------------- |
| Source Port           | 송신 측 포트 번호                |
| Destination Port      | 수신 측 포트 번호                |
| Sequence Number       | 데이터 순서를 보장하기 위한 번호        |
| Acknowledgment Number | 다음에 받을 데이터 번호를 알려주는 확인 번호 |
| Data Offset           | TCP 헤더 길이                 |
| Reserved              | 예약 필드                     |
| Flags                 | 연결 제어에 사용하는 제어 비트         |
| Window Size           | 수신 가능한 데이터 크기             |
| Checksum              | 오류 검출                     |
| Urgent Pointer        | 긴급 데이터 위치                 |
| Options               | 선택적 기능                    |
| Padding               | 헤더 길이를 맞추기 위한 채움 값        |

#### TCP 플래그

| 플래그 | 전체 이름          | 역할                 |
| --- | -------------- | ------------------ |
| SYN | Synchronize    | 연결 설정 요청           |
| ACK | Acknowledgment | 수신 확인              |
| FIN | Finish         | 연결 종료 요청           |
| RST | Reset          | 연결 강제 종료           |
| PSH | Push           | 데이터를 즉시 응용 계층으로 전달 |
| URG | Urgent         | 긴급 데이터 표시          |

#### 주로 사용하는 포트의 개념과 특징

포트 번호는 하나의 컴퓨터 안에서 어떤 프로그램에게 데이터를 전달할지 구분하는 번호입니다.

| 포트 범위         | 이름              | 설명                 |
| ------------- | --------------- | ------------------ |
| 0 ~ 1023      | Well-Known Port | 주요 서비스에 예약된 포트     |
| 1024 ~ 49151  | Registered Port | 특정 응용 프로그램에 등록된 포트 |
| 49152 ~ 65535 | Dynamic Port    | 임시 통신에 사용되는 포트     |

#### TCP 주요 포트

| 서비스     | 프로토콜 | 포트 번호 |
| ------- | ---- | ----- |
| FTP 데이터 | TCP  | 20    |
| FTP 제어  | TCP  | 21    |
| SSH     | TCP  | 22    |
| Telnet  | TCP  | 23    |
| SMTP    | TCP  | 25    |
| HTTP    | TCP  | 80    |
| POP3    | TCP  | 110   |
| IMAP    | TCP  | 143   |
| HTTPS   | TCP  | 443   |

#### 한 줄 정리

```text
TCP = 연결형, 신뢰성, 순서 보장, 재전송, 흐름 제어, 혼잡 제어
```

### 3) UDP

#### 개요와 특징

UDP는 User Datagram Protocol의 약자입니다.
연결 설정 없이 데이터를 빠르게 전송하는 비연결형 전송 계층 프로토콜입니다.

1. UDP의 특징

   * 비연결형 프로토콜입니다.
   * 연결 설정 과정이 없습니다.
   * TCP보다 빠릅니다.
   * 신뢰성은 낮습니다.
   * 순서 보장을 하지 않습니다.
   * 재전송을 수행하지 않습니다.
   * 헤더가 단순합니다.
   * 실시간 서비스에 적합합니다.

| 구분     | 내용                     |
| ------ | ---------------------- |
| 전체 이름  | User Datagram Protocol |
| 방식     | 비연결형                   |
| 신뢰성    | 낮음                     |
| 속도     | 빠름                     |
| 데이터 단위 | 데이터그램                  |
| 주요 기능  | 빠른 전송                  |

#### 헤더의 구조와 특징

UDP 헤더는 8바이트로 매우 단순합니다.

| UDP 헤더 필드        | 설명                 |
| ---------------- | ------------------ |
| Source Port      | 송신 측 포트 번호         |
| Destination Port | 수신 측 포트 번호         |
| Length           | UDP 헤더와 데이터의 전체 길이 |
| Checksum         | 오류 검출              |

#### 주로 사용하는 포트의 개념과 특징

UDP는 빠른 전송이 필요한 서비스에서 많이 사용됩니다.
대표적으로 DNS, DHCP, 스트리밍, 음성 통화, 게임 등이 있습니다.

| 서비스        | 프로토콜    | 포트 번호 |
| ---------- | ------- | ----- |
| DNS        | UDP/TCP | 53    |
| DHCP 서버    | UDP     | 67    |
| DHCP 클라이언트 | UDP     | 68    |
| TFTP       | UDP     | 69    |
| SNMP       | UDP     | 161   |
| NTP        | UDP     | 123   |

#### TCP와 UDP 포트 사용 차이

| 구분       | TCP                 | UDP           |
| -------- | ------------------- | ------------- |
| 웹        | HTTP, HTTPS         | 일반적으로 사용하지 않음 |
| 파일 전송    | FTP, SFTP           | TFTP          |
| 이메일      | SMTP, POP3, IMAP    | 일반적으로 사용하지 않음 |
| 이름 해석    | DNS Zone Transfer 등 | DNS 일반 질의     |
| IP 자동 할당 | 일반적으로 사용하지 않음       | DHCP          |
| 실시간 서비스  | 일부 사용               | 스트리밍, 음성, 게임  |

#### 한 줄 정리

```text
UDP = 비연결형, 빠른 전송, 신뢰성 낮음, 실시간 서비스에 적합
```

## 전체 핵심 요약 표

| 계층         | 프로토콜/개념 | 전체 이름                               | 핵심 역할             |
| ---------- | ------- | ----------------------------------- | ----------------- |
| 네트워크 접근 계층 | MAC     | Media Access Control                | 같은 LAN 안에서 장치 식별  |
| 인터넷 계층     | IP      | Internet Protocol                   | IP 주소 기반 패킷 전달    |
| 인터넷 계층     | ICMP    | Internet Control Message Protocol   | 오류 보고, 상태 확인      |
| 인터넷 계층     | IGMP    | Internet Group Management Protocol  | 멀티캐스트 그룹 관리       |
| 인터넷 계층     | ARP     | Address Resolution Protocol         | IP 주소를 MAC 주소로 변환 |
| 인터넷 계층     | RARP    | Reverse Address Resolution Protocol | MAC 주소를 IP 주소로 변환 |
| 전송 계층      | TCP     | Transmission Control Protocol       | 신뢰성 있는 연결형 전송     |
| 전송 계층      | UDP     | User Datagram Protocol              | 빠른 비연결형 전송        |

## 시험용 최종 암기

```text
MAC = LAN 안에서 장치 식별
IP = 목적지까지 패킷 전달
ARP = IP → MAC
RARP = MAC → IP
ICMP = 오류 보고와 상태 확인
IGMP = 멀티캐스트 그룹 관리

TCP = 연결형, 신뢰성, 순서 보장
UDP = 비연결형, 빠른 전송
RIP = 홉 수 기준 라우팅
OSPF = 링크 상태 기반 라우팅
NAT = 사설 IP와 공인 IP 변환
```
