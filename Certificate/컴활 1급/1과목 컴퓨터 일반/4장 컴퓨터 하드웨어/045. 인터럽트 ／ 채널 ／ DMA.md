## 045. 인터럽트 / 채널 / DMA

### 1. 인터럽트(Interrupt)의 개요

인터럽트는 **프로그램 실행 도중 예기치 않은 상황이 발생했을 때, 현재 작업을 잠시 중단하고 그 상황을 먼저 처리한 뒤 원래 작업으로 되돌아오는 기능**입니다.

**처리 순서**

1. 인터럽트 발생
2. 현재 실행 중인 프로그램의 상태를 **저장**
3. **인터럽트 서비스 루틴(ISR)** 실행
4. 저장해 둔 상태를 **복구**
5. 중단된 지점부터 **원래 작업 계속 수행**

#### 왜 인터럽트가 필요할까?

인터럽트가 없다면 CPU는 **모든 장치의 상태를 계속 물어봐야** 합니다.

- "키보드에 입력이 있나?"
- "프린터가 준비됐나?"
- "디스크 작업이 끝났나?"

이런 방식을 **폴링(Polling)** 이라고 하는데, 아무 일도 일어나지 않는 대부분의 시간을 **확인하는 데만 낭비**하게 됩니다.

인터럽트는 반대로 **필요한 쪽이 CPU를 부르는 방식**입니다.

즉, 인터럽트는  
**"물어보지 말고, 필요할 때 부르게 하자"는 발상의 전환**입니다.

#### 왜 상태를 저장했다가 복구할까?

CPU는 인터럽트를 처리하는 동안 **레지스터의 값을 다른 용도로 사용**하게 됩니다.

만약 원래 작업의 상태를 저장하지 않으면,  
돌아왔을 때 어디까지 실행했는지·어떤 값을 계산 중이었는지 알 수 없습니다.

그래서 인터럽트 처리 직전에 **프로그램 카운터와 레지스터 값을 저장**해 두고,  
처리가 끝나면 그대로 복구하여 **아무 일도 없었던 것처럼** 이어서 실행합니다.

---

### 2. 인터럽트의 종류

| 구분 | 종류 | 설명 |
| --- | --- | --- |
| **외부 인터럽트** | 전원 이상, 기계 착오, 입출력 장치 요청, 타이머 | **하드웨어의 이상이나 요청**으로 발생합니다. |
| **내부 인터럽트(트랩)** | 0으로 나누기, 오버플로/언더플로, 잘못된 명령어 사용 | **프로그램 실행 중의 잘못된 명령이나 데이터** 때문에 발생합니다. |
| **소프트웨어 인터럽트** | SVC(Supervisor Call) | **프로그램이 스스로 운영체제의 기능을 요청**할 때 발생합니다. |

#### 왜 인터럽트에 우선순위가 있을까?

여러 인터럽트가 동시에 발생할 수 있습니다.

이때 **전원 이상**처럼 즉시 처리하지 않으면 시스템 전체가 위험해지는 것과,  
**키보드 입력**처럼 조금 늦어도 되는 것을 같게 취급할 수는 없습니다.

그래서 인터럽트에는 우선순위가 정해져 있으며,  
일반적으로 **전원 이상 → 기계 착오 → 외부 신호 → 입출력 → 명령어 오류 → 프로그램 검사 → SVC** 순으로 처리됩니다.

### 3. 채널(Channel)

채널은 **CPU를 대신하여 입출력 작업을 전담하는 장치**입니다.

- 입출력이 진행되는 동안 CPU는 **다른 작업을 수행**할 수 있습니다.
- 입출력 작업이 끝나면 **인터럽트를 발생시켜 CPU에 알립니다.**
- 자체적인 명령어(채널 명령어)를 가지고 독립적으로 동작합니다.

**채널의 종류**

| 종류 | 특징 |
| --- | --- |
| **셀렉터 채널(Selector Channel)** | **고속 장치 한 대**를 전담합니다. (디스크, 자기 테이프) |
| **멀티플렉서 채널(Multiplexer Channel)** | **저속 장치 여러 대**를 동시에 담당합니다. (프린터, 카드 리더) |
| **블록 멀티플렉서 채널** | 셀렉터와 멀티플렉서의 장점을 결합하여, 고속 장치 여러 대를 블록 단위로 처리합니다. |

#### 왜 채널이 필요할까?

CPU가 입출력을 직접 처리하면, **느린 장치의 속도에 CPU가 묶이게 됩니다.**

채널은 이 일을 넘겨받아 처리하고, **끝났을 때만 CPU에 알립니다.**

즉, 채널은  
**입출력이라는 느린 일을 CPU에서 떼어 내어 병렬로 처리하게 하는 장치**입니다.

### 4. DMA(Direct Memory Access)

DMA는 **CPU를 거치지 않고 주변 장치가 주기억장치와 직접 데이터를 주고받는 방식**입니다.

- CPU의 개입 없이 데이터가 전송되므로 **CPU의 부담이 크게 줄어듭니다.**
- 전송이 완료되면 **인터럽트를 발생시켜 CPU에 알립니다.**
- 대량의 데이터를 전송할 때 특히 효율적입니다.

#### 왜 DMA가 더 효율적일까?

DMA가 없을 때 데이터는 다음 경로를 거칩니다.

**주변 장치 → CPU → 주기억장치**

즉, CPU가 데이터를 **일일이 받아서 다시 옮기는 중개인 역할**을 합니다.  
데이터가 많을수록 CPU는 이 단순 작업에만 매달리게 됩니다.

DMA는 경로를 다음처럼 단축합니다.

**주변 장치 → 주기억장치** (CPU는 관여하지 않음)

CPU는 "옮겨라"라고 지시만 하고, 그동안 **다른 연산을 계속 수행**할 수 있습니다.

#### 사이클 스틸링(Cycle Stealing)

DMA가 데이터를 전송할 때는 **메모리 버스를 잠깐씩 빌려 씁니다.**

이때 CPU는 그 순간 메모리에 접근하지 못하고 잠시 멈추는데,  
이처럼 **CPU의 메모리 사이클을 빼앗아 사용하는 것**을 사이클 스틸링이라고 합니다.

CPU가 완전히 멈추는 것이 아니라 **아주 짧은 순간만 양보**하는 것이므로,  
전체적으로는 훨씬 효율적입니다.

---

### 5. 세 가지 개념의 비교

| 구분 | 역할 | 핵심 |
| --- | --- | --- |
| **인터럽트** | 예외 상황을 CPU에 알림 | "지금 처리해 주세요" |
| **채널** | 입출력 작업을 전담 처리 | "입출력은 제가 맡겠습니다" |
| **DMA** | CPU를 거치지 않고 메모리와 직접 전송 | "CPU를 거치지 않고 바로 옮기겠습니다" |

세 가지 모두 **CPU가 느린 입출력에 묶이지 않게 하려는 목적**에서 나온 기술입니다.

---

### 한 줄 정리

인터럽트는 **작업을 잠시 멈추고 급한 일을 처리한 뒤 되돌아오는 기능**,  
채널은 **입출력을 전담하는 별도 장치**,  
DMA는 **CPU를 거치지 않고 주변 장치와 주기억장치가 직접 데이터를 주고받는 방식**입니다.
