## 056. 프로그래밍 언어

### 1. 프로그래밍 언어의 분류

| 구분 | 특징 |
| --- | --- |
| **저급 언어(Low Level Language)** | 컴퓨터가 이해하기 쉬운 언어입니다. **기계어, 어셈블리어** |
| **고급 언어(High Level Language)** | 사람이 이해하기 쉬운 언어입니다. **C, Java, Python, FORTRAN, COBOL** 등 |

| 언어 | 특징 |
| --- | --- |
| **기계어(Machine Language)** | **0과 1로만 구성**된 언어로, 컴퓨터가 직접 이해할 수 있는 유일한 언어입니다. 번역이 필요 없지만 사람이 이해하기 매우 어렵습니다. |
| **어셈블리어(Assembly Language)** | 기계어를 사람이 이해하기 쉬운 **기호(Mnemonic)** 로 바꾼 언어입니다. **어셈블러**가 번역합니다. |
| **고급 언어** | 사람의 언어에 가까운 형태로 작성하며, **컴파일러나 인터프리터**가 번역합니다. 기종에 관계없이 사용할 수 있어 **호환성이 높습니다.** |

#### 왜 "저급 / 고급"이라고 부를까?

여기서 급(級)은 **품질의 좋고 나쁨이 아니라 "하드웨어와 얼마나 가까운가"** 를 뜻합니다.

- **저급 언어** : 하드웨어에 가까움 → 실행이 빠르고 세밀한 제어가 가능하지만, 작성이 어렵고 기종에 종속적
- **고급 언어** : 사람에 가까움 → 작성과 유지보수가 쉽고 호환성이 좋지만, 하드웨어를 직접 제어하기는 어려움

즉, 두 언어는 우열 관계가 아니라 **용도에 따른 선택**입니다.

### 2. 주요 고급 언어

| 언어 | 특징 |
| --- | --- |
| **FORTRAN** | 최초의 고급 언어로, **과학 기술 계산**에 적합합니다. |
| **COBOL** | **사무 처리**에 적합하며, 영어 문장과 유사한 형태로 작성합니다. |
| **BASIC** | 초보자를 위한 **대화형 언어**로, 인터프리터 방식을 사용합니다. |
| **PASCAL** | **교육용**으로 개발된 **구조적 프로그래밍** 언어입니다. |
| **C** | 시스템 프로그래밍에 적합하며, **이식성이 높고 하드웨어 제어가 가능**합니다. UNIX 개발에 사용되었습니다. |
| **C++** | C에 **객체 지향** 개념을 추가한 언어입니다. |
| **JAVA** | **객체 지향 언어**로, **JVM(가상 머신)** 위에서 동작하여 **운영체제에 독립적**입니다. |
| **Python** | 문법이 간결한 인터프리터 언어로, 데이터 분석·인공지능 분야에서 널리 사용됩니다. |
| **LISP** | **인공지능** 분야에 사용되는 언어입니다. |
| **ALGOL** | 알고리즘 기술을 위한 언어입니다. |

#### 왜 Java는 운영체제에 독립적일까?

일반적인 언어는 컴파일하면 **특정 운영체제와 CPU에 맞는 기계어**가 만들어집니다.  
그래서 Windows용 프로그램은 Linux에서 실행되지 않습니다.

Java는 컴파일하면 기계어가 아니라 **바이트코드(Bytecode)** 라는 중간 형태가 만들어지고,  
각 운영체제에 설치된 **JVM이 이를 해당 환경의 기계어로 변환하여 실행**합니다.

즉, "한 번 작성하면 어디서든 실행된다(Write Once, Run Anywhere)"는 원리입니다.

### 3. 객체 지향 프로그래밍(OOP)

프로그램을 **객체(Object)** 라는 단위로 나누어 작성하는 방식입니다.

- 객체 = **데이터(속성)** + **처리 방법(메소드)**
- 대표 언어 : **Java, C++, C#, Python**

**객체 지향의 주요 특징**

| 특징 | 설명 |
| --- | --- |
| **캡슐화(Encapsulation)** | 데이터와 처리 방법을 하나로 묶고, **내부 구현을 외부에서 볼 수 없게** 숨깁니다. |
| **상속(Inheritance)** | 기존 클래스의 속성과 기능을 **물려받아 새로운 클래스를 만듭니다.** |
| **다형성(Polymorphism)** | 같은 이름의 명령이 **상황에 따라 다르게 동작**합니다. |
| **추상화(Abstraction)** | 공통된 특징만 뽑아내어 **핵심적인 개념으로 단순화**합니다. |

#### 왜 캡슐화가 필요할까?

프로그램이 커지면, 한 부분을 수정했을 때 **다른 부분이 함께 망가지는 문제**가 생깁니다.

캡슐화는 객체의 내부 데이터를 외부에서 직접 건드리지 못하게 하고,  
**정해진 통로(메소드)를 통해서만 접근**하도록 제한합니다.

그러면 내부 구현을 바꾸더라도 **통로만 그대로 유지하면 외부에는 영향이 없습니다.**

즉, 캡슐화는 **변경의 영향 범위를 줄이기 위한 장치**입니다.

#### 왜 상속이 필요할까?

비슷한 기능을 가진 프로그램을 만들 때마다 같은 코드를 반복해서 작성하면,  
수정 사항이 생겼을 때 **모든 곳을 일일이 고쳐야** 합니다.

상속은 공통된 부분을 **한 곳에 정의해 두고 물려받는 방식**이므로,

- 코드 중복이 줄고
- 공통 부분을 한 번만 수정하면 됩니다.

### 4. 구조적 프로그래밍

프로그램을 **순차, 선택, 반복**의 세 가지 기본 구조만으로 작성하는 방식입니다.

- `GOTO` 문 사용을 지양합니다.
- 프로그램의 흐름을 이해하기 쉬워 **유지보수가 용이**합니다.
- 대표 언어 : PASCAL, C

#### 왜 `GOTO` 문을 쓰지 말라고 할까?

`GOTO`는 프로그램의 흐름을 **아무 곳으로나 건너뛰게** 합니다.

몇 개만 있어도 실행 흐름이 뒤엉켜, 나중에 코드를 읽는 사람이  
**"지금 어디에서 여기로 왔는지"** 를 추적할 수 없게 됩니다.

이런 코드를 흔히 **스파게티 코드**라고 부릅니다.

순차·선택·반복만 사용하면 흐름이 **위에서 아래로 예측 가능하게** 흐르므로,  
읽기 쉽고 오류를 찾기도 쉬워집니다.

### 5. 프로그램 개발 과정

**문제 분석 → 알고리즘 설계(순서도) → 코딩 → 번역(컴파일) → 디버깅(오류 수정) → 실행 및 테스트 → 문서화 → 유지보수**

| 용어 | 설명 |
| --- | --- |
| 알고리즘 | 문제를 해결하기 위한 **처리 절차와 방법**입니다. |
| 순서도(Flowchart) | 알고리즘을 **기호와 도형으로 표현**한 그림입니다. |
| **디버깅(Debugging)** | 프로그램의 **오류(버그)를 찾아 수정**하는 과정입니다. |
| 문서화 | 프로그램의 개발 과정과 사용법을 기록합니다. |
| 유지보수 | 완성된 프로그램의 오류를 수정하고 기능을 개선합니다. |

#### 왜 문서화가 중요할까?

프로그램은 만든 사람이 계속 관리한다는 보장이 없습니다.  
심지어 본인도 몇 달이 지나면 **자신이 왜 그렇게 작성했는지 기억하지 못합니다.**

문서는 프로그램의 의도와 구조를 남겨,  
**나중에 수정하거나 다른 사람이 이어받을 때의 비용을 크게 줄여 줍니다.**

---

### 한 줄 정리

프로그래밍 언어는 **저급 언어(기계어·어셈블리어)와 고급 언어**로 나뉘며,  
**객체 지향의 핵심은 캡슐화·상속·다형성·추상화**이고,  
**Java는 JVM 덕분에 운영체제에 독립적**입니다.
