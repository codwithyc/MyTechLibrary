# 제7장 Lock과 트랜잭션 동시성 제어

## 제1절 Lock

* **공유 Lock은 서로 호환**되므로 같은 자원에 여러 사용자가 동시에 공유 Lock을 설정할 수 있다.
* **배타적 Lock은 다른 Lock과 호환되지 않으므로 한 사용자만 설정**할 수 있다.
* Oracle은 데이터를 읽을 때 공유 Lock을 사용하지 않으므로 **읽기가 쓰기를 막거나 기다리지 않는다.**
* Oracle은 **Undo 데이터를 이용한 다중버전 동시성 제어**를 통해 공유 Lock 없이도 읽기 일관성을 유지한다.
* **Blocking과 Deadlock은 서로 다른 개념**이다.
* Blocking은 Lock 충돌로 인해 특정 세션이 작업을 진행하지 못하고 기다리는 상태이다.
* Deadlock은 두 세션이 서로 상대방이 가진 자원을 기다리는 상태이며, 해결하려면 둘 중 하나가 뒤로 물러나야 한다.

## 제2절 트랜잭션

* 트랜잭션은 **업무 처리를 위한 논리적인 작업 단위**이다.
* 트랜잭션의 주요 특징은 **원자성, 일관성, 격리성, 영속성**이다.
* 낮은 격리성 수준에서는 **Dirty Read, Non-Repeatable Read, Phantom Read**가 발생할 수 있다.
* ANSI/ISO SQL 표준의 격리성 수준은 **Read Uncommitted, Read Committed, Repeatable Read, Serializable Read** 네 가지이다.

## 제3절 동시성 제어

* 여러 트랜잭션이 동시에 수행될 때 서로 간섭하지 않도록 DBMS가 데이터를 보호하는 것을 **동시성 제어**라고 한다.
* 여러 사용자가 같은 데이터를 동시에 접근할 때 **Lock을 이용해 직렬화**할 수 있다.
* 동시성 제어가 어려운 이유는 **동시성과 일관성이 서로 트레이드오프 관계**이기 때문이다.
* 가능한 많은 트랜잭션을 동시에 실행하면서도 데이터의 **무결성을 유지**해야 한다.
* 동시성 제어 방식에는 **비관적 동시성 제어와 낙관적 동시성 제어**가 있다.
* Oracle을 비롯한 많은 DBMS는 **MVCC(Multi-Version Concurrency Control)** 방식을 사용한다.
* MVCC에서는 읽기와 쓰기가 서로 방해하지 않으면서 높은 동시성과 **읽기 일관성**을 유지할 수 있다.
* **문장 수준 읽기 일관성**은 하나의 SQL이 실행되는 동안 일관된 값을 읽는 것이며, 기준 시점은 **쿼리 시작 시점**이다.
* **트랜잭션 수준 읽기 일관성**은 트랜잭션 전체에서 일관된 값을 읽는 것이며, 기준 시점은 **트랜잭션 시작 시점**이다.
