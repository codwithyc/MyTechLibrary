# 제1절 정규화

* 정규화는 **데이터 중복을 줄이고 이상 현상이 생기지 않도록 테이블을 나누는 작업**이다.
* 쉽게 말하면 **“한 테이블에 이것저것 다 넣지 말고, 각자 맡은 정보끼리 나눠서 관리하자”**라고 이해하면 된다.
* 정규화를 하는 핵심 목적은 **중복 제거 + 이상 현상 제거**다.
* 정규화가 제대로 되어 있지 않으면 **삽입 이상, 수정 이상, 삭제 이상**이 발생할 수 있다.
* 삽입 이상은 **원하는 데이터 하나를 넣기 위해 필요 없는 다른 데이터까지 같이 넣어야 하는 문제**다.
* 수정 이상은 **하나의 값을 바꾸기 위해 여러 행을 동시에 수정해야 하는 문제**다.
* 삭제 이상은 **원하는 데이터 하나를 삭제했는데 다른 필요한 정보까지 같이 사라지는 문제**다.
* 쉽게 외우면 `INSERT 문제 = 삽입 이상`, `UPDATE 문제 = 수정 이상`, `DELETE 문제 = 삭제 이상`이다.

## 함수적 종속성

* 함수적 종속성은 **A 값을 알면 B 값을 하나로 결정할 수 있는 관계**다.
* `A → B`는 **A가 B를 결정한다**는 뜻이다.
* 정규화 문제에서는 **“누가 누구를 결정하는가?”**를 먼저 찾는 것이 중요하다.

## 정규형

* 제1정규형(1NF)은 **하나의 칸에 하나의 값만 들어가도록 만드는 것**이다.
* 한 칸에 여러 값이 들어가 있으면 **1NF 위반**이다.
* 쉽게 외우면 **1NF = 한 칸에 하나**다.
* 제2정규형(2NF)은 **복합키의 일부에만 의존하는 일반 속성을 제거하는 것**이다.
* `복합키 일부 → 일반 속성` 형태를 **부분 함수 종속**이라고 한다.
* 쉽게 외우면 **2NF = 키 일부에 기대지 마**다.
* 제3정규형(3NF)은 **일반 속성이 다른 일반 속성을 결정하는 관계를 제거하는 것**이다.
* `PK → 일반 속성 → 다른 일반 속성` 형태를 **이행 함수 종속**이라고 한다.
* 쉽게 외우면 **3NF = 일반 속성끼리 기대지 마**다.
* 시험에서는 `1NF = 다중값`, `2NF = 부분 종속`, `3NF = 이행 종속`으로 연결하면 된다.

# 제2절 관계와 조인의 이해

* 관계는 **데이터 모델에서 엔터티와 엔터티가 서로 어떻게 연결되는지를 나타내는 것**이다.
* JOIN은 **그 관계를 이용해 실제 테이블의 데이터를 붙여 조회하는 것**이다.
* 쉽게 말하면 **설계할 때는 관계, SQL로 조회할 때는 JOIN**이다.
* 두 테이블을 연결할 때는 일반적으로 **PK와 FK**를 사용한다.
* PK는 **자기 테이블에서 행을 구별하는 대표 식별자**다.
* FK는 **다른 테이블의 식별자를 가져와 관계를 연결하는 값**이다.

## 관계의 종류

* `1:1`은 **한쪽의 한 건이 반대쪽 한 건과 연결되는 관계**다.
* `1:M`은 **한쪽 한 건이 반대쪽 여러 건과 연결되는 관계**다.
* `1:M` 관계에서는 보통 **M쪽에 FK가 위치**한다.
* `M:N`은 **양쪽 모두 여러 건과 연결되는 관계**다.
* `M:N` 관계는 실제 DB에서는 보통 **중간 엔터티를 만들어 두 개의 1:M 관계로 풀어낸다.**
* 예를 들어 `학생 M:N 과목`은 `학생 1:M 수강 M:1 과목`으로 만들 수 있다.

## JOIN

* JOIN은 **서로 관련 있는 두 테이블을 조건에 따라 연결해서 조회하는 것**이다.
* `EQUI JOIN`은 **`=` 조건으로 테이블을 연결하는 JOIN**이다.
* `NON-EQUI JOIN`은 **`>`, `<`, `>=`, `<=`, `BETWEEN` 같은 `=` 이외의 조건으로 연결하는 JOIN**이다.
* JOIN 조건을 제대로 작성하지 않으면 **두 테이블의 모든 행이 서로 조합되는 Cartesian Product**가 발생할 수 있다.
* A 테이블이 N건, B 테이블이 M건이면 Cartesian Product는 `N × M`건이 될 수 있다.
* 쉽게 외우면 **관계 = 설계상의 연결 / JOIN = SQL에서 실제로 붙이기**다.
* `=`이면 **EQUI**, 범위나 부등호면 **NON-EQUI**, 조건이 없으면 **Cartesian Product**를 생각하면 된다.

# 제3절 모델이 표현하는 트랜잭션의 이해

* 트랜잭션(Transaction)은 **하나로 묶어서 처리해야 하는 논리적인 업무 단위**다.
* 쉽게 말하면 **“같이 성공하거나, 문제가 생기면 같이 취소되어야 하는 일의 묶음”**이다.
* 하나의 트랜잭션 안에는 여러 개의 `INSERT`, `UPDATE`, `DELETE` 등의 작업이 함께 포함될 수 있다.
* 대표적인 예는 **계좌이체**다.
* A 계좌에서 돈을 빼고 B 계좌에 돈을 넣는 작업은 둘 다 성공해야 한다.
* 한쪽만 성공하면 데이터가 잘못되므로 **전체가 성공하거나 전체가 취소되어야 한다.**
* `COMMIT`은 **트랜잭션의 작업 결과를 확정**한다.
* `ROLLBACK`은 **아직 확정하지 않은 작업을 취소하고 이전 상태로 되돌린다.**
* 데이터 모델의 관계를 보면 **어떤 데이터들이 하나의 업무에서 함께 처리되는지** 파악할 수 있다.
* 예를 들어 주문이 생성될 때 주문상세도 함께 생성될 수 있으므로 두 엔터티의 관계를 통해 업무 처리 흐름을 이해할 수 있다.
* 관계가 반드시 존재해야 한다면 **필수 관계**, 없어도 존재할 수 있다면 **선택 관계**라고 이해하면 된다.
* 쉽게 외우면 **Transaction = 같이 처리 / COMMIT = 확정 / ROLLBACK = 취소**다.

# 제4절 NULL 속성의 이해

* NULL은 **값을 모르거나, 아직 정해지지 않았거나, 해당 값이 존재하지 않는 상태**를 의미한다.
* NULL은 숫자 `0`과 다르다.
* NULL은 일반적인 공백 문자와도 다르다.
* `0`은 **0이라는 값을 알고 있는 상태**지만, NULL은 **값 자체를 알 수 없는 상태**다.
* NULL을 비교할 때는 `= NULL`을 사용하지 않는다.
* NULL 여부는 `IS NULL`, `IS NOT NULL`을 사용해 확인한다.
* NULL과 일반 값을 산술 연산하면 결과는 보통 NULL이 된다.
* `SUM`, `AVG`, `MAX`, `MIN`, `COUNT(칼럼)` 같은 집계 함수는 일반적으로 NULL을 제외한다.
* `COUNT(*)`는 특정 칼럼의 NULL 여부와 관계없이 **행 자체의 개수**를 센다.
* Oracle에서는 빈 문자열 `''`을 NULL처럼 취급한다는 점도 주의해야 한다.
* 쉽게 외우면 **NULL = 모름 / 0 = 0임을 알고 있음**이다.

# 제5절 본질식별자 vs 인조식별자

* 본질식별자는 **업무에서 원래 의미를 가지고 존재하는 식별자**다.
* 쉽게 말하면 **시스템을 만들기 전부터 업무상 사용하던 식별값**이다.
* 사원번호, 학번, 주문번호 등이 업무에서 본래 식별값으로 사용된다면 본질식별자가 될 수 있다.
* 인조식별자는 **시스템에서 데이터를 관리하기 편하도록 새로 만든 식별자**다.
* 인조식별자는 업무 자체의 의미보다는 **데이터를 유일하게 구별하기 위한 목적**이 크다.
* `AUTO_INCREMENT`, `SEQUENCE`, UUID 등을 이용해 생성한 ID는 대표적인 인조식별자다.
* 쉽게 외우면 **본질 = 업무에서 원래 있음 / 인조 = 시스템이 새로 만듦**이다.

# 장 요약

* 정규화 → **중복과 이상 현상을 줄이기 위해 테이블 분리**
* 삽입 이상 → **넣기 문제**
* 수정 이상 → **여러 곳을 같이 수정해야 하는 문제**
* 삭제 이상 → **지우면 다른 정보도 같이 사라지는 문제**
* 함수적 종속 → **A가 B를 결정**
* 1NF → **한 칸에 하나**
* 2NF → **복합키 일부 종속 제거**
* 3NF → **일반 속성 간 이행 종속 제거**
* 관계 → **엔터티끼리 연결**
* JOIN → **테이블끼리 실제로 붙여 조회**
* PK → **내 대표 번호**
* FK → **다른 테이블과 연결하는 번호**
* `1:M` → **M쪽에 FK**
* `M:N` → **중간 엔터티**
* EQUI JOIN → **`=`**
* NON-EQUI JOIN → **범위·부등호**
* Cartesian Product → **전부 × 전부**
* 트랜잭션 → **하나의 업무 단위**
* COMMIT → **확정**
* ROLLBACK → **취소**
* NULL → **모름 / 미정**
* NULL 비교 → **`IS NULL`**
* `COUNT(*)` → **전체 행 수**
* 본질식별자 → **업무에서 원래 사용**
* 인조식별자 → **시스템이 새로 생성**
