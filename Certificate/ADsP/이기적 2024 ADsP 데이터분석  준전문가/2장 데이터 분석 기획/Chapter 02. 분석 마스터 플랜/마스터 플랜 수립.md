# 마스터 플랜 수립

마스터 플랜 수립은 조직이 데이터 분석을 일회성으로 수행하는 것이 아니라, **중장기적으로 어떤 분석 과제를 어떤 순서로 추진할지 계획하는 과정**이다.

분석 과제가 여러 개 도출되었다고 해서 모든 과제를 동시에 수행할 수는 없다.
따라서 과제의 중요도, 실행 가능성, 기대 효과를 평가하고 우선순위를 정해야 한다.

```markdown
마스터 플랜 수립 = 분석 과제를 중장기 관점에서 정렬하고 실행 순서와 계획을 수립하는 과정
```

기존에 정리한 빅데이터/분석 기획 파트처럼, 개념을 먼저 이해하고 표로 압축하는 방식이 시험 직전 복습에 좋다. 

---

# 01. 분석 마스터 플랜

## 분석 마스터 플랜의 개념

**분석 마스터 플랜**이란 조직의 데이터 분석 목표를 달성하기 위해 분석 과제의 우선순위, 추진 일정, 필요 자원, 실행 방안을 종합적으로 정리한 중장기 계획이다.

쉽게 말하면, 분석 마스터 플랜은 다음 질문에 답하는 계획이다.

```markdown
어떤 분석 과제를 먼저 수행할 것인가?
각 분석 과제를 언제 수행할 것인가?
분석 과제를 수행하기 위해 어떤 데이터와 인력이 필요한가?
분석 결과를 조직에서 어떻게 활용할 것인가?
```

즉, 분석 마스터 플랜은 단순한 과제 목록이 아니다.
**분석 과제를 전략적으로 배치하고 실행 가능한 로드맵으로 만드는 과정**이다.

---

## 분석 마스터 플랜이 필요한 이유

분석 과제는 보통 여러 부서에서 동시에 제안된다.

예를 들어 다음과 같은 분석 과제가 있을 수 있다.

```markdown
고객 이탈 예측 분석
상품 추천 모델 개발
매출 감소 원인 분석
마케팅 캠페인 성과 분석
재고 최적화 분석
이상 거래 탐지 분석
```

이 모든 과제를 한 번에 수행하기는 어렵다.
인력, 예산, 데이터, 기술, 시간이 제한되어 있기 때문이다.

따라서 다음을 기준으로 과제를 정렬해야 한다.

| 기준      | 설명                           |
| ------- | ---------------------------- |
| 전략적 중요도 | 조직의 핵심 목표와 얼마나 연결되는가         |
| 비즈니스 효과 | 매출 증가, 비용 절감, 리스크 감소 효과가 큰가  |
| 실행 가능성  | 필요한 데이터, 기술, 인력, 예산이 확보 가능한가 |
| 시급성     | 빠르게 해결해야 하는 문제인가             |
| 확장성     | 향후 다른 과제나 조직 전체로 확산 가능한가     |

시험에서는 이렇게 이해하면 된다.

```markdown
분석 마스터 플랜은 여러 분석 과제 중 우선순위를 정하고,
중장기적으로 실행할 수 있도록 로드맵과 이행계획을 수립하는 것이다.
```

---

## 분석 마스터 플랜의 핵심 구성 요소

| 구성 요소 | 설명                         |
| ----- | -------------------------- |
| 분석 목표 | 조직이 데이터 분석을 통해 달성하고자 하는 목표 |
| 분석 과제 | 수행해야 할 분석 과제 목록            |
| 우선순위  | 과제별 중요도와 실행 가능성을 고려한 순서    |
| 로드맵   | 과제를 시간 순서에 따라 배치한 계획       |
| 이행계획  | 세부 일정, 담당 조직, 필요 자원, 산출물   |
| 성과 관리 | 분석 과제가 실제 성과를 냈는지 평가하는 기준  |

분석 마스터 플랜의 핵심은 **전략성과 실행 가능성의 균형**이다.

좋아 보이는 분석 과제라도 데이터가 없거나, 현업에서 활용할 수 없거나, 비용 대비 효과가 낮으면 우선순위가 낮아질 수 있다.

```markdown
분석 마스터 플랜의 핵심 = 전략적으로 중요한 과제를 실행 가능한 순서로 배열하는 것
```

# 02. 분석 마스터플랜 수립 프레임워크

분석 마스터플랜 수립 프레임워크는 분석 과제를 도출하고, 우선순위를 평가하고, 실행 로드맵과 세부 이행계획을 만드는 절차다.

일반적으로 다음 흐름으로 정리할 수 있다.

```markdown
분석 과제 도출 → 우선순위 평가 → 로드맵 수립 → 세부 이행계획 수립
```

| 단계         | 핵심                          |
| ---------- | --------------------------- |
| 분석 과제 도출   | 수행 가능한 분석 과제 후보를 발굴         |
| 우선순위 평가    | 전략적 중요도와 실행 가능성 기준으로 평가     |
| 로드맵 수립     | 과제를 단기·중기·장기로 배치            |
| 세부 이행계획 수립 | 일정, 담당자, 자원, 산출물, 관리 방안 구체화 |

시험에서는 단계 순서가 중요하다.

```markdown
마스터플랜 수립 = 과제 도출 → 우선순위 평가 → 로드맵 → 이행계획
```

---

## 1) 분석 마스터플랜 수립

### 분석 마스터플랜 수립의 개념

**분석 마스터플랜 수립**은 조직의 분석 목표를 달성하기 위해 분석 과제들을 체계적으로 정리하고, 실행 가능한 계획으로 구체화하는 과정이다.

이 과정에서는 단순히 “무엇을 분석할지”만 정하지 않는다.
각 과제가 조직 전략과 연결되는지, 실제 수행 가능한지, 어떤 순서로 추진해야 하는지를 함께 검토한다.

---

### 분석 마스터플랜 수립 시 고려사항

| 고려사항       | 설명                       |
| ---------- | ------------------------ |
| 조직 전략과의 연계 | 분석 과제가 조직의 목표와 연결되는가     |
| 데이터 확보 가능성 | 필요한 데이터를 확보할 수 있는가       |
| 기술적 실현 가능성 | 분석 수행에 필요한 기술과 인프라가 있는가  |
| 업무 활용 가능성  | 분석 결과가 실제 업무에 적용될 수 있는가  |
| 투자 대비 효과   | 비용 대비 기대 효과가 충분한가        |
| 추진 일정      | 단기, 중기, 장기로 어떻게 나눌 것인가   |
| 조직 역량      | 분석을 수행하고 운영할 인력과 역량이 있는가 |

분석 마스터플랜은 **하고 싶은 분석 목록**이 아니다.
조직의 목표, 데이터 현실, 인력과 예산을 함께 고려한 **실행 계획**이다.

```markdown
분석 마스터플랜 수립 = 조직 전략과 분석 과제를 연결하고 실행 가능한 중장기 계획으로 구체화하는 과정
```

---

## 2) 분석 과제 도출 및 우선순위 평가 방법과 절차

분석 마스터플랜을 수립하려면 먼저 분석 과제 후보를 도출해야 한다.

분석 과제는 보통 다음 경로에서 나온다.

```markdown
현업 요구사항
조직 전략 목표
고객 문제
업무 비효율
데이터 탐색 결과
외부 환경 변화
```

---

## 분석 과제 도출

### 분석 과제 도출의 개념

**분석 과제 도출**은 조직의 문제나 기회를 데이터 분석으로 해결 가능한 과제 형태로 구체화하는 과정이다.

예를 들어 다음과 같은 비즈니스 이슈가 있다.

```markdown
고객이 자주 이탈한다.
광고비를 많이 쓰는데 성과가 낮다.
재고가 자주 부족하거나 과잉된다.
```

이를 분석 과제로 바꾸면 다음과 같다.

```markdown
고객 이탈 예측 모델 개발
광고 캠페인 성과 분석
수요 예측 기반 재고 최적화
```

즉, 분석 과제 도출은 **비즈니스 이슈를 분석 가능한 과제로 바꾸는 작업**이다.

---

### 분석 과제 도출 방법

| 방법     | 설명                       |
| ------ | ------------------------ |
| 하향식 접근 | 비즈니스 문제에서 출발해 분석 과제 도출   |
| 상향식 접근 | 데이터를 탐색하면서 새로운 분석 과제 발견  |
| 현업 인터뷰 | 현업 부서의 문제와 요구사항 수집       |
| 벤치마킹   | 유사 산업이나 경쟁사의 분석 사례 참고    |
| 데이터 탐색 | 보유 데이터에서 패턴, 이상치, 기회 발견  |
| 전략 분석  | 조직의 전략 목표와 연결되는 분석 과제 발굴 |

시험에서는 이렇게 이해하면 된다.

```markdown
분석 과제는 하향식 접근, 상향식 접근, 현업 요구, 데이터 탐색 등을 통해 도출한다.
```

---

## 분석 과제 우선순위 평가

분석 과제가 도출되면 모든 과제를 동일하게 수행하지 않고 우선순위를 정한다.

우선순위 평가는 보통 **전략적 중요도와 실행 가능성**을 기준으로 한다.

| 평가 관점   | 설명                           |
| ------- | ---------------------------- |
| 전략적 중요도 | 조직의 핵심 목표와 얼마나 관련 있는가        |
| 비즈니스 효과 | 매출 증가, 비용 절감, 리스크 감소 효과가 있는가 |
| 실행 가능성  | 데이터, 기술, 인력, 예산 측면에서 수행 가능한가 |
| 시급성     | 빠르게 해결해야 할 문제인가              |
| 활용 가능성  | 분석 결과가 실제 업무에 적용될 수 있는가      |
| 확장성     | 향후 다른 업무나 부서로 확산 가능한가        |

---

### 우선순위 평가 매트릭스

분석 과제 우선순위는 보통 **가치와 실행 가능성** 기준으로 판단한다.

| 구분    | 실행 가능성 높음 | 실행 가능성 낮음   |
| ----- | --------- | ----------- |
| 가치 높음 | 우선 추진 과제  | 중장기 검토 과제   |
| 가치 낮음 | 선택적 추진 과제 | 제외 또는 보류 과제 |

이 표는 시험에서 개념 판단용으로 중요하다.

* **가치 높음 + 실행 가능성 높음**
  → 가장 먼저 수행할 과제

* **가치 높음 + 실행 가능성 낮음**
  → 중요하지만 준비가 필요하므로 중장기 과제

* **가치 낮음 + 실행 가능성 높음**
  → 빠르게 할 수는 있지만 우선순위는 낮음

* **가치 낮음 + 실행 가능성 낮음**
  → 보류하거나 제외

```markdown
우선순위 평가 = 분석 과제의 가치와 실행 가능성을 기준으로 추진 순서를 정하는 것
```

---

### 분석 과제 도출 및 우선순위 평가 절차

| 절차          | 설명                                  |
| ----------- | ----------------------------------- |
| 1. 후보 과제 수집 | 현업 요구, 전략 목표, 데이터 탐색 등을 통해 후보 과제 도출 |
| 2. 과제 정의    | 분석 목적, 범위, 기대 효과, 필요 데이터를 정리        |
| 3. 평가 기준 설정 | 전략성, 효과성, 실행 가능성, 시급성 등 기준 설정       |
| 4. 과제 평가    | 각 과제를 기준에 따라 점수화하거나 등급화             |
| 5. 우선순위 결정  | 우선 추진, 중장기 추진, 보류 과제로 분류            |
| 6. 추진 과제 확정 | 로드맵에 반영할 최종 과제 선정                   |

시험에서는 이 흐름을 이렇게 줄여 외우면 된다.

```markdown
후보 수집 → 과제 정의 → 기준 설정 → 평가 → 우선순위 결정 → 추진 과제 확정
```

---

## 3) 로드맵 수립

### 로드맵 수립의 개념

**로드맵 수립**은 우선순위가 정해진 분석 과제를 시간 순서에 따라 배치하는 과정이다.

즉, 어떤 과제를 단기에 수행하고, 어떤 과제를 중장기적으로 추진할지 정하는 것이다.

분석 로드맵은 보통 다음처럼 구성된다.

```markdown
단기 과제
중기 과제
장기 과제
```

---

### 로드맵이 필요한 이유

로드맵이 없으면 분석 과제들이 개별적으로 수행되어 조직 전체 방향성과 맞지 않을 수 있다.

또한 선행 과제가 필요한 경우도 있다.

예를 들어 고객 이탈 예측 모델을 만들려면 먼저 고객 데이터 통합이 필요할 수 있다.

```markdown
고객 데이터 통합 → 고객 행동 분석 → 고객 이탈 예측 → 개인화 마케팅
```

이처럼 분석 과제는 서로 연결될 수 있으므로 실행 순서를 잘 정해야 한다.

---

### 로드맵 수립 기준

| 기준       | 설명                                 |
| -------- | ---------------------------------- |
| 우선순위     | 가치와 실행 가능성이 높은 과제를 먼저 배치           |
| 선후행 관계   | 데이터 구축이나 시스템 준비가 먼저 필요한지 확인        |
| 추진 기간    | 단기, 중기, 장기 과제로 구분                  |
| 자원 배분    | 인력, 예산, 기술 역량을 고려                  |
| 조직 수용성   | 현업이 받아들이고 활용할 수 있는 시점 고려           |
| 성과 창출 시점 | 빠르게 성과를 낼 수 있는 과제와 장기 과제를 균형 있게 배치 |

---

### 단기·중기·장기 로드맵

| 구분 | 핵심                        | 예시                        |
| -- | ------------------------- | ------------------------- |
| 단기 | 빠르게 실행 가능하고 성과 확인이 쉬운 과제  | 매출 현황 대시보드, 캠페인 성과 분석     |
| 중기 | 데이터 통합이나 모델링이 필요한 과제      | 고객 이탈 예측, 수요 예측           |
| 장기 | 조직 전체 분석 역량이나 플랫폼이 필요한 과제 | 전사 데이터 플랫폼, AI 기반 의사결정 체계 |

로드맵에서는 단기 과제만 많아도 문제고, 장기 과제만 많아도 문제다.

단기 과제는 빠른 성과를 만들고,
중장기 과제는 조직의 분석 역량을 키운다.

```markdown
로드맵 수립 = 분석 과제를 단기·중기·장기로 배치하여 실행 순서를 정하는 것
```

## 4) 세부 이행계획 수립

### 세부 이행계획의 개념

**세부 이행계획**은 로드맵에 포함된 분석 과제를 실제로 수행하기 위해 필요한 일정, 담당자, 자원, 산출물, 관리 방안을 구체화하는 과정이다.

로드맵이 “언제 무엇을 할 것인가”라면,
세부 이행계획은 “누가, 어떻게, 어떤 자원으로, 어떤 산출물을 만들 것인가”를 정하는 것이다.

---

### 세부 이행계획의 구성 요소

| 구성 요소    | 설명                             |
| -------- | ------------------------------ |
| 수행 일정    | 과제별 시작일, 종료일, 단계별 일정           |
| 담당 조직/인력 | 과제 수행 책임자, 분석가, 현업 담당자, IT 담당자 |
| 필요 데이터   | 분석에 필요한 데이터 목록과 확보 방법          |
| 필요 기술/도구 | 분석 도구, 플랫폼, 알고리즘, 인프라          |
| 산출물      | 분석 보고서, 모델, 대시보드, 시스템, 운영 문서   |
| 예산       | 인력, 도구, 인프라, 외부 자문 비용          |
| 위험 관리    | 데이터 부족, 일정 지연, 성능 미달 등 대응 방안   |
| 성과 지표    | 분석 과제의 성공 여부를 판단할 기준           |

세부 이행계획은 분석 과제를 실제 실행 가능한 수준으로 쪼개는 단계다.

```markdown
세부 이행계획 = 로드맵의 분석 과제를 실행 가능한 일정, 자원, 산출물, 성과 지표로 구체화하는 것
```

---

### 세부 이행계획 수립 절차

| 절차               | 설명                       |
| ---------------- | ------------------------ |
| 1. 과제별 수행 범위 정의  | 분석 대상, 목적, 제외 범위 명확화     |
| 2. 단계별 일정 수립     | 데이터 준비, 분석, 검증, 적용 일정 수립 |
| 3. 담당자 및 역할 지정   | 현업, 분석가, IT 담당자 역할 정의    |
| 4. 필요 자원 산정      | 데이터, 도구, 인프라, 예산 확인      |
| 5. 위험 및 대응 방안 수립 | 예상 문제와 대응 전략 마련          |
| 6. 성과 지표 정의      | 성공 여부를 평가할 KPI 설정        |

시험에서는 이렇게 줄여 외우면 된다.

```markdown
범위 정의 → 일정 수립 → 역할 지정 → 자원 산정 → 위험 대응 → 성과 지표 정의
```

```markdown
도출 = 무엇을 할지 찾기

```

# 시험 직전 암기 문장

```markdown
분석 마스터 플랜은 조직의 데이터 분석 목표를 달성하기 위해
분석 과제의 우선순위, 추진 일정, 필요 자원, 실행 방안을 정리한 중장기 계획이다.

분석 마스터플랜 수립은 분석 과제 도출, 우선순위 평가,
로드맵 수립, 세부 이행계획 수립의 순서로 진행된다.

분석 과제 도출은 조직의 비즈니스 문제, 현업 요구,
데이터 탐색 결과 등을 바탕으로 분석 후보 과제를 발굴하는 과정이다.

분석 과제의 우선순위는 전략적 중요도, 비즈니스 효과,
데이터 확보 가능성, 기술적 실현 가능성, 활용 가능성, 시급성 등을 기준으로 평가한다.

우선순위 평가에서는 가치가 높고 실행 가능성이 높은 과제를 우선 추진하고,
가치는 높지만 실행 가능성이 낮은 과제는 중장기 과제로 검토한다.

로드맵 수립은 우선순위가 정해진 분석 과제를
단기, 중기, 장기 일정에 맞게 배치하는 과정이다.

단기 과제는 빠르게 실행 가능하고 성과 확인이 쉬운 과제이며,
중기 과제는 데이터 통합이나 모델링이 필요한 과제이고,
장기 과제는 전사 분석 플랫폼이나 분석 역량 구축처럼 조직 차원의 기반을 만드는 과제이다.

세부 이행계획 수립은 로드맵에 포함된 과제를 실제로 수행하기 위해
일정, 담당자, 필요 데이터, 기술과 도구, 산출물, 위험 관리 방안, 성과 지표를 구체화하는 과정이다.

분석 마스터 플랜의 핵심은 여러 분석 과제를 전략적 중요도와 실행 가능성에 따라 평가하고,
실행 가능한 순서와 일정으로 정리하는 것이다.
```
