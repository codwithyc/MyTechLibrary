## 문제 1번 : 정답 1번

```
"다음 설명으로 알맞은 것은?"

"2015년 이후로 라즈베리파이 재단에 의해 라즈베리파이 단일 보드 컴퓨터 계열을 위한 주 운영체지이다. 마이크 톰슨(Mike Tompson)과 피터 그린(Peter Green)이 독립 프로젝트로 개발하였고 최초 빌드는 2012년 6월에 완성되었다. 라즈베리파이 계열의 저성능 ARM CPU에 상당히 최적화되어 있다.

1. 라즈비안(Raspbian)
2. 타이젠(Tizen)
3. 모블린(Moblin)
4. 안드로이드(Android)
```

**라즈베리파이 재단에 의해 라즈베리파이 단일 보드 컴퓨터 계열을 위한 주 운영체제**  
라즈베리파이 -> 라즈비안으로 연결해야 함

조금 더 정확하게 말하자면, 라즈비안은 **Debian을 기반으로 라즈베리파이의 ARM 환경에 맞게 최적화한 리눅스 배포판**입니다.  
이후 공식 명칙은 **Raspberry Pi OS**로 바뀌었지만 **Respbian** 이라는 이름으로 자주 등장합니다.

나머지 문제의 정리는 다음과 같습니다.

### 타이젠(Tizen)

타이젠은 라즈베리파이용 운영체제가 핵심이 아닙니다.  
삼성전자와 인텔 등이 참여해 개발한 **리눅스 기반 모바일·임베디드 운영체제**입니다.

-> 키워드 (삼성, 스마트TV, 스마트워치, 모바일, 임베디드)

### 모블린(Moblin)

모블린은 Mobile Linux에서 나온 이름이라고 생각하면 쉽습니다.  
인텔이 주도했던 리눅스 기반 프로젝트로, 주 대상은 넷북, 모바일 인터넷 기기, Intel Atom 같은 장치였습니다.


### 안드로이드(Android)

안드로이드는 Google 주도하는 Linux Kernel 기반 모바일 운영체제입니다.

### 추가 개념
커널(Kernel)은 **운영체제의 핵심 부분**입니다. 쉽게 정리하자면 프로그램과 컴퓨터 하드웨어 사이에서 일을 대신 처리해주는 관리자입니다.

예를 들어 우리가 프로그램에서 파일을 저장한다고 해도 프로그램이 SSD에 직접 쓰는 게 아닙니다.

```
프로그램
  ↓
운영체제
  ↓
커널
  ↓
CPU / 메모리 / 디스크 / 네트워크
```

커널을 주로 이런 일을 합니다.
- CPU를 어떤 프로그램에게 얼마나 줄지 관리
- 메모리를 어느 프로그램에게 줄지 관리
- 디스크의 파일을 읽고 쓰기
- 키보드, 마우스, 네트워크 카드 같은 장치 관리
- 여러 프로그램이 동시에 실행될 때 충돌하지 않게 관리

예를 들어 Chrome, Vs Code, 게임을 동시에 실행했다고 해보면, 세 프로그램 모두 CPU와 메모리를 쓰려고 합니다.
이 떄 커널이 "Chrome 너는 CPU 조금 쓰고, VS Code도 쓰고, 게임은 메모리 이만큼 사용해" 처럼 자원을 나눠주는 겁니다.

그래서 방금 전 나온 Android가 Linux Kernel 기반이라는 말도 이렇게 이해하면 됩니다.

```
Android
 ├─ 앱
 ├─ Android Framework
 ├─ Android Runtime
 └─ Linux Kernel
       ↓
   CPU / RAM / 카메라 / Wi-Fi 등
```

즉 Android 자체가 일반적인 Linux 배포판이라는 뜻은 아니고, **가장 및에서 하드웨어를 관리하는 핵심 부분으로 Linux 커널을 사용한다**는 뜻입니다.

> Kernel = 운영체제의 핵심 + 하드웨어 자원 관리자

## 문제 3번 : 정답 4번
```
"다음 중 운영체제의 목적으로 틀린 것은?"

1. 처리 능력(Throughput)
2. 반환 시간(Turnaround Time)
3. 신뢰도(Reliability)
4. 대화형 처리(Interactive Processing)
```

이번 문제의 핵심은 "운영체제가 잘 만들어졌는지를 평가하는 목표/성능 기준"과 "컴퓨터가 작업을 처리 하는 방식"을 구분하는 것입니다.  
운영체제의 대표적인 목적은 보통 다음처럼 정리 합니다.

| 항목                         | 의미                       | 좋은 OS라면   |
| -------------------------- | ------------------------ | --------- |
| **Throughput(처리 능력)**      | 일정 시간 동안 처리할 수 있는 작업량    | 높을수록 좋음 ↑ |
| **Turnaround Time(반환 시간)** | 작업 요청부터 완료까지 걸리는 시간      | 짧을수록 좋음 ↓ |
| **Availability(사용 가능도)**   | 필요할 때 시스템을 사용할 수 있는 정도   | 높을수록 좋음 ↑ |
| **Reliability(신뢰도)**       | 시스템이 오류 없이 안정적으로 동작하는 정도 | 높을수록 좋음 ↑ |

### Interactive Processing(대화형 처리)

**대화형 처리**는 운영체제를 평가하는 목표가 아니라 **작업을 처리 하는 방식**입니다.  
예를 들어 터미널에서 `$ ls`를 입력하면 컴퓨터가 바로 결과를 보여주고, `$ cd project`를 입력하면 또 바로 반응합니다.

즉
```
사용자 입력
   ↓
컴퓨터 응답
   ↓
사용자 입력
   ↓
컴퓨터 응답
```
이렇게 사람과 컴퓨터가 **서로 대화하듯 작업하는 것**이 Interactive Processin입니다.
그래서 "Interactive Processing을 높인다." 라는 표현 자체가 이상합니다.

> 추가로 대화형 처리 말고도 다양한 처리 방식이 존재합니다.  
> | 처리 방식                              | 쉽게 말하면                        | 핵심 키워드  |
> | ---------------------------------- | ----------------------------- | ------- |
> | **일괄 처리(Batch Processing)**        | 작업을 모아두었다가 한꺼번에 처리            | 모아서 처리  |
> | **다중 프로그래밍(Multiprogramming)**     | 여러 프로그램을 메모리에 올려 CPU를 쉬지 않게 함 | CPU 효율  |
> | **시분할 처리(Time Sharing)**           | CPU 시간을 잘게 나눠 여러 사용자가 번갈아 사용  | 여러 사용자  |
> | **대화형 처리(Interactive Processing)** | 사용자가 명령하면 시스템이 바로 반응          | 입력 ↔ 응답 |
> | **실시간 처리(Real-Time Processing)**   | 반드시 정해진 시간 안에 결과를 처리          | 시간 제한   |

## 문제 4번 : 정답 2번
```
"다음 중 모바일 기기에서 사용되는 리눅스 운영체제로 틀린 것은?"

1. Android
2. Mint
3. LiMo
4. Bada OS
```

이 문제의 핵심은 "모바일 기기에서 사용되는 리눅스 계열인가?"를 보는 문제입니다.

각각 보면 

### Android
구글이 만든 모바일 운영체제이고, **Linux 커널을 사용**합니다.

즉
```
Linux Kernel
   ↓
Android
   ↓
스마트폰 / 태블릿
```

그래서 확실히 모바일 Linux 계열입니다. 삼성도 Android가 Linux 커널을 사용한다고 설명합니다.

### Mint

정확히는 Linux Mint 입니다.  
Ubuntu/Debian 계열의 **데스크톱 Linux 배포판**으로 보는 게 핵심입니다.

```
Linux Mint
→ PC / 노트북
→ Desktop Linux
```

따라서 문제에서 말하는 모바일 기기용 Linux 운영체제**에 해당하지 않습니다.

### LiMo
`Limo`는 Linux Mobile이라고 생각하면 기억하기 쉽습니다.

LiMo Foundation이 모바일 기기를 위해 만든 **Linux 기반 모바일 플랫폼**입니다.  
실제 LiMo Foundation의 목표도 모바일 장치용 개방형 Linux 기반 플랫폼 구축이었습니다.

위에서 설명한 모블린(Moblin)과 같이 "모바일 리눅스"라고 불려서 헷갈리 수 있는데, **주로 겨냥한 기기와 주도 세력이 다릅니다.**  
핵심을 간단히 잡자변 Limo는 주요 대상이 휴대폰/스마트폰이고 Moblin은 넷북, MID, Atom 기반 모바일 컴퓨터 입니다.

### Bada OS

삼성전자가 스마트폰용으로 개발했던 모바일 플랫폼입니다.

특히 삼성의 Wave(웨이브) 스마트폰에서 사용됐습니다. 삼성도 당시 bada를 자체 개발한 모바일 운영 체제로 소개했습니다.

- 기존의 자바 가상머신과는 다른 가상머신인 달빅(Dalvik) 가상머신을 통해 자바로 작성된 응용 프로그램을 별도의 프로세스에서 실행하는 구조로 되어 있습니다.

1. 바다(Bada) OS

- 리눅스 커널 위에서 동작 -> Linux Kernel을 기반으로 함 
- C/C++ 라이브러리 포함 -> Android 시스템의 네이티브 라이브러리 계층
- Dalvik 가상머신 -> 초기 Android의 대표적인 실행 환경
- 2007년 11월 공개 -> Android 및 OHA 발표 시기
- OHA(Open Handset Alliance) -> Google 중심의 모바일 기기 연합

## 문제 6번 : 정답 1번
```
"다음 중 최근 운영체제의 동향으로 틀린 것은?"

1. 단일 사용자 시스템 기반 다중 작업 시스템을 지원한다.
2. 편리한 사용자 인터페이스를 제공한다.
3. 가상화 기술을 지원하여 자원의 효율성을 최대화한다.
4. 스마트폰과 태블릿 등 모바일 운영체제가 보편화되었다.
```

이번 문제는 "최근 운영체제가 어떤 방햐으로 발전했는가"를 묻는 문제인데, 1번만 시대 흐름과 반대입니다.  
1번이 왜 틀렸는가를 설명하려면 문장에 있는 두 개념을 분리해서 보면 됩니다.

- 단일 사용자(Single User) : 한 명의 사용자 중심
- 다중 작업(Multitasking) : 여러 프로그램을 동시에 실행

예를 들어 내가 혼자 PC에서 Chrome, VS Code, 음악을 동시에 실행하면 단일 사용자 + 다중 작업 이라고 할 수 있습니다.  
그래서 **"단일 사용자 시스템에서도 다중 작업이 가능하다"** 자체가 기술적으로 완전히 말이 안 되는 것은 아닙니다.

하지만 문제는 **"최근 운영체제의 동향"**을 묻고 있습니다.  
최근의 Linux, Unix, Windows 같은 운영체제는 보통 **다중 사용자(Multi-user) + 다중 작업(Multitasking) 환경을  기본적으로 지원하는 방향으로 발전했습니다.

그렇기 때문에 **"현대 운영체제는 단일 사용자 기반으로 발전한 것이 아니라, 다중 사용자 다중 사용자·다중 작업을 지원하는**  
**방향으로 발전했으므로 1번이 틀렸습니다."**

우선 Tizen은 처음에는 **모바일 운영체제**로 확산하려고 했습니다. 하지만 스마트폰 시장에서는 Android, IOS에 밀려서 크게 자리 잡지 못했습니다.

Limo는 전에 설명 했듯이 Linux Mobile 계열의 모바일 플랫폼입니다.

Android는 Google, Linux Kurnel, Dalvik, ART, OHA 이 키워드가 핵심입니다.

## 문제 8번 : 정답 2번
```
"다음에서 설명하는 것으로 알맞은 것은?"

- 메모리 공간이 가득 차서 프로그램을 실행시킬 수 없게 될 경우, 실행할 수 있도록 예비 공간 역할을 하는 영역입니다.
- free 명령어로 해당 영역의 용량을 확인할 수 있다.
- 단점으로는 동적으로 크기를 조정할 수 없어 하드디스크의 공간을 차지한다.

1. 페이징(Paging)
2. 스왑(Swap)
3. 루틴(Routine)
4. 링크(Link)
```

정답은 스왑입니다. 이 문제는 **"RAM이 부족할 때 디스크 일부를 임시 메모리처럼 사용하는 공간"** 이라는 설명을 보고 `Swap`을 고르면 됩니다.

컴퓨터에서 프로그램은 기본적으로 **RAM(메모리)**을 사용해서 실행됩니다.
그런데 RAM이 부족해지면
```
RAM 8GB

Chrome     3GB
VS Code    2GB
Database   2GB
기타       1GB
─────────────
총         8GB  ← 꽉 참
```

새 프로그램이 메모리를 필요로 한는데 공간이 없습니다.  
이럴 때 Linux는 디스크에 마련해 둔 **Swap 영역**을 활용할 수 있습니다.

```
RAM
[████████████] 꽉 참
       ↓
일부 데이터를 디스크로 이동
       ↓
Swap
[████░░░░░░░░]
```
즉 Swap은 쉽게 말하자면 **RAM이 부족할 때 사용하는 비상용 임시 공간** 입니다.  
다만 중요한 점이 있습니다. Swap은 SSD/HDD를 사용하기 때문에 **RAM 보다 훨씬 느립니다.**

free 명령어도 결정적인 힌트입니다. Linux에서 `free -h`를 실행하면 보통 아래와 같은 형식으로 나옵니다.
```
               total    used    free
Mem:            16Gi     8Gi     8Gi
Swap:            4Gi     1Gi     3Gi
```

여기서

```
Mem  → 실제 RAM
Swap → 스왑 영역
```

을 확인할 수 있습니다.

따라서 문제에 **free 명령어로 확인**이라는 표현까지 나왔다면 거의 바로 Swap을 떠올리면 됩니다.

### Paging

Paging은 **메모리를 일정한 크기의 조각(Page)으로 나눠서 관리하는 기법입니다.

예를 들어

```
메모리
┌──────┐
│Page 1│
├──────┤
│Page 2│
├──────┤
│Page 3│
└──────┘
```

즉, **Paging = 메모리를 페이지 단위로 나누어 관리** 입니다.  
Swap과 관계가 아예 없는 건 아니지만, **"디스크에 마련한 예비 메모리 공간"자체를 Paging이라고 부른는 것은 아닙니다.**

### Routine
Routine은 어떤 **특정 작업을 처리하는 코드 또는 프로그램의 일부분**을 의미합니다.

예를 들어 함수나 서브루틴 같은 개념과 관련됩니다.

```
Routine
→ 특정 기능을 수행하는 코드
```

메모리 부족과는 관계가 없습니다.

### Link
Link는 말 그대로 **연결**입니다.

Linux에서는 특히
```
Routine
→ 특정 기능을 수행하는 코드
```
같은 파일 링크 개념이 자주 등장합니다.

## 문제 9번 : 정답 2번

```
"다음 중 운영체제의 특징으로 틀린 것은?"

1. 운영체제는 커널, 미들웨어, 응용 프로그램 실행환경과 사용자 인터페이스 프레임 워크를 모두 포괄하여 정의될 수 있다.

3. 스마트폰과 태블릿에 설치되는 모바일 운영체제, 웹 브라우저만 있으면 사용 가능한 웹 운영체제도 사용되고 있다.

```

정확한 흐름은 단순 순차 처리 -> 다중 프로그래밍 -> 시불할 -> 다중 모드 -> 분산 네트워크 -> 모바일 임베디드 라고 되어 있습니다.  
2번이 틀린 이유는 **분산 네트워크가 너무 앞에 와 있습니다.

다중 프로그래밍이 먼저 등장하고, 그 뒤에 시분할 다중 모드 같은 발전을 거쳐 분산 네트워크 환경으로 발전했다고 보는게 맞습니다.

| 발전 단계        | 쉽게 말하면                       |
| ------------ | ---------------------------- |
| **단순 순차 처리** | 한 번에 하나씩 순서대로 처리             |
| **다중 프로그래밍** | 여러 프로그램을 메모리에 올려 CPU를 놀리지 않음 |
| **시분할**      | CPU 시간을 잘게 나눠 여러 사용자/작업이 사용  |
| **다중 모드**    | 여러 처리 방식을 복합적으로 지원           |
| **분산 네트워크**  | 여러 컴퓨터가 네트워크로 연결되어 작업 분담     |
| **모바일·임베디드** | 스마트폰, IoT, 각종 장치로 OS 영역 확대   |

나머지도 확인해보면 1번은 운영체제를 좁게 보면 커널 중심이지만, 넓게 보면 **커널 + 미들웨어 + 실행 환경 + UI 프레임워크**까지 포함해서  
설명할 수 있습니다. 3번도 맞습니다. 스마트폰과 태블릿의 모바일 OS와 웹 기반 환경이 사용되고 있다는 설명입니다. 4번도 맞습니다. 현대 OS는 가상화 기능을  
지원해서 CPU, 메모리 등의 자원을 효율적으로 사용할 수 있게 합니다.

### 미들웨어(Middlleware)

미들웨어(Middlleware)는 이름 그대로 **중간(Middle)에 끼어 있는 소프트웨어**라고 이해하면 됩니다.  
정확히는 **운영체제의 핵심 기능과 응용 프로그램 사이에서 공통 기능을 제공해주는 소프트웨어 계층**입니다.

예를 들어 구조를 아주 단순화하면 

```
응용 프로그램
   ↓
미들웨어
   ↓
운영체제 / 커널
   ↓
하드웨어
```

앱이 매번 네트워크 통신, 데이터베이스 연결, 메시지 전달, 인증 같은 기능을 전부 직접 구현하면 너무 힘들겠죠.  
미들웨어가 이런 공통 기능을 중간에서 대신 제공해줍니다.

예를 들어 백엔드 개발 관정에서는 이런 것들도 넓게 보면 미들웨어에 해당할 수 있습니다.
- 웹 서버 / WAS
- 메시지 브로커
- DB 연결 계층
- RPC
- 인증 / 통신 관련 공통 서비스

즉 아주 쉽게 말하면:

> Middleware = 프로그램과 시스템 사이에서 자주 필요한 기능을 중간에서 제공해주는 소프트웨어

입니다.

### 운영체제는 커널, 미들웨어, 응용 프로그램 실행환경, 사용자 인터페이스 프레임워크를 모두 포괄하여 정의될 수 있다.

이게 왜 가능한지를 이해하려면 **"운영체제를 좁게 보는 경우와 넓게 보는 경우"**를 구분해야 합니다.

#### 좁게 보면 운영체제 => 커널 

가장 핵심적인 부분만 보면

```
프로그램
   ↓
Kernel
   ↓
CPU / RAM / Disk / Network
```

커널이 CPU, 메모리, 프로세스, 장치 같은 하드웨어 자원을 관리하니깐 운영체제의 핵심은 커널입니다.  
그래서 우리가 앞에서 **Linux는 엄밀하게는 커널이다.**라고 했던 것입니다.

#### 그런데 사용자는 커널만 가지고 컴퓨터를 쓸 수 없습니다.

Linux 커널 파일 하나만 컴퓨터에 던져준다고 생각해보겠습니다.

사용자가 갑자기 "좋아! 이제 Chrome 실행해야지." 할 수 있을까요? 안 됩니다.  
실제로 컴퓨터나 스마트폰을 편하게 사용하려면 커널 위에 많은 것들이 필요합니다.

```
┌─────────────────────────┐
│ 응용 프로그램            │
│ Chrome / 앱 / 게임       │
├─────────────────────────┤
│ 사용자 인터페이스        │
│ 창 / 버튼 / 메뉴 / 터치  │
├─────────────────────────┤
│ 응용 프로그램 실행환경   │
│ JVM / ART / Runtime 등   │
├─────────────────────────┤
│ 미들웨어                 │
│ 통신 / DB / 미디어 등    │
├─────────────────────────┤
│ Kernel                  │
│ CPU / RAM / 장치 관리    │
├─────────────────────────┤
│ Hardware                │
└─────────────────────────┘
```

우리가 실제로 **"Android 운영체제", "Windows 운영체제"**라고 부를 때는 커널 파일 하나만 말하는 게 아니라 이런  
**전체 시스템 소프트웨어 묶음**을 의미하는 경우가 많습니다.

그래서 넓은 의미의 OS라고 하는 겁니다.

#### 긱긱 무슨 역할인지 한 번에 보면 

| 계층               | 하는 일                   | 쉽게 말하면    |
| ---------------- | ---------------------- | --------- |
| **Kernel**       | CPU, RAM, 장치 관리        | 하드웨어 관리자  |
| **Middleware**   | 프로그램이 공통으로 필요한 기능 제공   | 중간 도우미    |
| **Runtime**      | 프로그램을 실행할 환경 제공        | 프로그램 실행기  |
| **UI Framework** | 화면, 버튼, 창 등을 만드는 기능 제공 | 사용자 화면 도구 |

## 문제 10번 : 정답 1번
```
"다음에 제시된 운영체제 관련 기술 중 물리적 메모리의 용량 한계를 극복하기 위한 기술로 가장 알맞은 것은?"

1. 가상 메모리
2. 가상 콘솔
3. 라이브러리
4. 파이프
```

### 가상 메모리(Virtual Memory)
물리 메모리, 즉 **RAM의 한계를 보안하기 위한 기술**입니다.

예를 들어 RAM이 8GB라고 해도 운영체제가 디스크의 일부 공간까지 활용해서 프로그램들에게 더 큰 메모리 공간이  
있는 것처럼 보여줄 수 있습니다.

```
프로그램
   ↓
가상 메모리
   ↓
RAM + 필요 시 디스크 영역
```

### 가상 콘솔(Virtual Console)
이건 메모리와 관계가 없습니다. 하나의 Linux 시스템에서 여러 개의 **가상 터미널 화면**을 사용할 수 있게 하는 기능입니다.  

예를 들면
```
tty1
tty2
tty3
tty4
```

이런 식으로 여러 콘솔 세션을 따로 열어둘 수 있습니다.  
리눅스에서는 환경에 따라 Ctrl + Alt + F1 ~ F6 같은 조합으로 가상 콘솔을 전환하기도 합니다.

### 라이브러리(Library)
라이브라리는 **자주 사용하는 기능을 미리 만들어 모아둔 코드 집합**입니다.  
개발자로 보면 바로 이해할 수 있습니다.

예를 들어 프로그램마다 문자열 처리, 파일 입출력, 네트워크 기능을 전부 직접 구현하면 비효율적입니다.  

그래서
```
프로그램
   ↓
라이브러리 함수 호출
   ↓
미리 구현된 기능 사용
```

예를 들어 C에서는

```
printf()
malloc()
strlen()
```

같은 함수들이 라이브러리와 연결됩니다.

### 파이프(Pipe)
파이프는 **프로세스 간 통신(IPC)** 방법입니다.

한 프로그램의 출력 결과를 다른 프로그램의 입력으로 넘겨줄 수 있습니다.  
Linux에서는 `|` 기호가 대표적입니다.

```
ps aux | grep nginx
```

## 문제 11번 : 정답 3번
```
"다음 중 관련 라이선스가 정용된 소스코드를 수정하여 만든 2차적 저작물에 대해 소스코드의 비공개가 가능한 라이선스로 틀린 것은?"

1. BSD
2. Apache Licence
3. GPL
4. MIT
```

### 라이선스

우선 이번 문제는 라이선스에 대한 문제인데 먼저 **"라이선스가 왜 필요한가?"** 부터 잡으면 이해가 편해집니다.  
라이선스가 뭐냐면 누군가 프로그램의 소스코드를 만들었다고 해보겠습니다.

```
개발자 A
  ↓
프로그램 소스코드 작성
  ↓
"이 코드를 다른 사람이 어디까지 써도 되지?"
```

코드를 인터넷에 공개했다고 해서 다른 사람이 자동으로 마음대로 복사하고, 수정하고, 회사 제품에 넣고, 돈 받고 팔고 할 수 있는 것은 아닙니다.
소스코드에도 **저작권**이 있기 때문입니다. 그래서 개발자가 "내 코드를 이런 조건으로 사용해도 됩니다." 라고 허락하는 규칙이 **Lincence(라이선스)**입니다.

쉽게 비유하면 **사용 설명서 + 사용 허가서**라고 보면 됩니다.

예를 들어 내가 어떤 코드를 GitHub에 공개하면서 "가져가서 사용해도 됩니다. 수정해도 됩니다.  
상업적으로 써도 됩니다. 대신 내 저작권 표시는 남겨주세요" 라고 조건으 붙였다면 그 조건이 라이선스인 겁니다.

그래서 라이선스를 보면 결국 이런 걸 판단하는 겁니다.

| 궁금한 것            | 라이선스가 정함 |
| ---------------- | -------- |
| 가져다 써도 돼?        | O/X      |
| 수정해도 돼?          | O/X      |
| 회사 서비스에 넣어도 돼?   | O/X      |
| 돈 받고 팔아도 돼?      | O/X      |
| 수정한 코드를 공개해야 해?  | O/X      |
| 원 저작권 표시를 남겨야 해? | O/X      |

#### 그럼 오픈소스 라이선스는?

소스코드를 공개하면서 다른 사람이 사용할 수 있도록 허용하는 라이선스입니다.  
그런데 모든 오픈소스 라이선스가 **똑같이 자유로운 것은 아닙니다.**  
여기서 MIT, BSD, Apache, GPL의 차이가 생깁니다.

#### MIT

굉장히 자유로운 편입니다.  
"가져가서 써도 되고 수정해도 되고 상업적으로 사용해도 돼. 대신 원래 저작권/라이선스 표시는 남겨줘."

그래서

```
MIT 코드
 ↓
내 회사에서 수정
 ↓
상용 서비스에 사용
 ↓
수정 코드 비공개
```
도 가능합니다.

#### BSD

MIT와 상당히 비슷합니다.  
"자유롭게 사용 수정 배포해도 돼. 조건만 지켜줘" 

#### Apache License

얘도 MIT/BSD처럼 자유로운 편입니다.
```
사용 O
수정 O
상업 이용 O
비공개 O
```

그런데 한 가지 특정이 있습니다. **특허(Patent) 관련 조건이 명확하다.** 

#### GPL

얘가 성격이 다릅니다.

GPL 코드를 수정해서 배포한다면 수정된 코드도 GPL 조건에 맞게 소스코드를 제공해야 하는 경우가 생깁니다.
```
GPL 코드
 ↓
내가 수정
 ↓
다른 사람에게 배포
 ↓

수정된 소스도 공개해야 함
```

이런 성격을 Copyleft(카피레프트)라고 합니다.

이번 문제는 **가상 메모리에서 RAM과 디스크 사이로 데이터를 옮기는 동작 자체**를 묻고 있습니다.

여기서 교체한다 = Swapping 이라고 보면 됩니다.

### Swapoo과 Swapping 차이

앞에서 봤던 **Swap**이랑 이번 **Swapping**은 연결된 개념입니다.

```
Swap
→ 디스크에 마련해 둔 보조 메모리 공간

Swapping
→ RAM ↔ Swap 공간 사이에서 데이터를 옮기는 동작
```

예를 들어 RAM이 꽉 찼다고 가정해보겠습니다.

```
RAM
[A][B][C][D]  ← 가득 참

새로운 프로그램 E를 실행해야 함
```

운영체제가 지금 당장 잘 안 쓰는 `A`를 디스크의 Swap의 영역으로 옮깁니다.

```
RAM             Swap
[B][C][D][ ]     [A]
```

그리고 빈 RAM 공간에 E를 올립니다.

```
RAM             Swap
[B][C][D][E]     [A]
```

나중에 다시 A가 필요하면 

```
Swap의 A
   ↓
RAM으로 다시 가져옴
```

이런 **RAM <-> 디스크 간 이동**을 스와핑이라고 이해하면 됩니다.

### 각 보기는 이렇게 구분하면 됩니다.

| 보기                  | 의미                          | 핵심 키워드          |
| ------------------- | --------------------------- | --------------- |
| **Pipe**            | 한 프로세스의 출력을 다른 프로세스 입력으로 전달 | 프로세스 간 데이터 전달   |
| **Swapping**        | RAM과 디스크의 메모리 영역을 교체        | **가상 메모리 / 교체** |
| **Redirection**     | 입력·출력 방향을 파일 등으로 변경         | `>`, `<`, `>>`  |
| **Virtual Console** | 하나의 시스템에서 여러 콘솔 사용          | 여러 터미널          |

#### 1. Pipe

예를 들어 

```
ps aux | grep nginx
```

흐름은 

```
ps aux 출력
   ↓
  Pipe |
   ↓
grep nginx 입력
```

즉 **프로그램끼리 데이터를 연결**하는 기술입니다.

#### 2. Swapping

RAM <-> 디스크 교체라고 연결하면 됩니다.

틀히 문제에 이런 말이 나오면 Swapping을 의심해야 됩니다.
- 주기억장치
- 보조기억장치
- 가상 메모리
- 교체
- Swap 영역

#### 3. Redirection

리다이렉션은 명령어의 입력이나 출력 방향을 바꾸는 것입니다.

예를 들어

```
ls > list.txt
```

원래는 

```
ls
 ↓
화면에 출력
```

인데 `>`를 사용하면

```
ls
 ↓
list.txt 파일에 저장
```

가 됩니다.

리눅스의 Redirection(리다이렉션)은 종류가 몇 개 있습니다.  
핵심은 **표준 입력/출력/에러의 방향을 바꾸는 것**입니다.

먼저 이것부터 잡으면 됩니다.

|  번호 | 이름     | 의미    |
| --: | ------ | ----- |
| `0` | stdin  | 표준 입력 |
| `1` | stdout | 표준 출력 |
| `2` | stderr | 표준 에러 |

그리고 주요 리다이렉션은 아래처럼 보면 됩니다.

| 문법     | 의미                            |
| ------ | ----------------------------- |
| `>`    | 표준 출력을 파일에 저장, 기존 내용 덮어씀      |
| `>>`   | 표준 출력을 파일 뒤에 추가               |
| `<`    | 파일 내용을 명령어의 입력으로 사용           |
| `<<`   | 여러 줄 입력을 직접 전달, Here Document |
| `2>`   | 에러 출력만 파일에 저장                 |
| `2>>`  | 에러 출력을 파일 뒤에 추가               |
| `2>&1` | 에러 출력을 표준 출력과 같은 곳으로 보냄       |
| `&>`   | 정상 출력 + 에러 출력을 모두 같은 파일로 보냄   |


#### 4. Virtual Console

가상 콘솔은 하나의 Linux 시스템에서 **여러 콘솔 화면을 별도로 사용할 수 있게 하는 기능**입니다.

```
tty1
tty2
tty3
tty4
...
```

즉 **Virtual Console = 여러 터미널 화면** 입니다.

### 1번 네트워크 지원

정학하게 해설하자면 1번은 **"리눅스가 여러 종류의 네트워크 연결 방식과 통신 규칙을 지원한다."**는 뜻입니다.  
문장을 두 덩어리로 나누면 훨씬 쉽습니다. 

> Ethernet, SLIP, PPP  
> -> "어떻게 연결해서 데이터를 주고받을 거냐?"

> TCP/IP, IPX  
> -> "연결된 뒤 어떤 규칙으로 통신할 거냐"

| 용어       | 정체                  | 쉽게 말하면         |
| -------- | ------------------- | -------------- |
| Ethernet | 유선 LAN 기술           | 랜선으로 네트워크 연결   |
| SLIP     | 직렬선에서 IP 전달         | 옛날 모뎀/시리얼 연결   |
| PPP      | 점대점 연결 프로토콜         | 두 장비를 직접 연결    |
| TCP/IP   | 인터넷 통신 프로토콜 모음      | 현재 인터넷의 기본     |
| IPX      | 과거 Novell 네트워크 프로토콜 | 옛날 사내망/게임 네트워크 |


#### Ethernet

이더넷은 쉽게 설명하자면 **"컴퓨터들을 가까운 거리에서 서로 연결해서 데이터를 주고받게 하는 대표적인 유선 네트워크 기술"**입니다.  
집에서 컴퓨터에 랜선을 꽂는다고 생각하면 됩니다. 

```
내 컴퓨터
   │
 랜선
   │
공유기
   │
 다른 컴퓨터
```

여기서 단순히 **"랜선 자체가 Ethernet"**인 것은 아닙니다.

Ethernet은 
- 어떤 케이블을 사용할지
- 데이터를 어떤 모양으로 보낼지
- 어떤 컴퓨터에게 보내는지
- 네트워크 장비들이 데이터를 어떻게 주고받을지
같은 규칙까지 포함하는 **LAN 통신 기술**입니다.

간단하게 교실에 있는 아이들이 있다고 해보겠습니다.

```
유찬 ───── 철수
  \       /
   \     /
     선생님
```

아이들이 서로 편지를 전달하고 싶습니다.  
그런데 아무렇게나 편지를 던지면 안 되겠죠?

그래서 "편지는 이 통로를 통해 보내고 받는 사람 이름을 앞에 적자." 라는 규칙을 만들었습니다.  
이런 역할을 하는게 **Ethernet**이라고 보면 됩니다.

##### Ethernet에서 중요한 것 : MAC 주소

Ethernet에서는 네트워크 장치를 구분할 **MAC 주소**를 사용합니다.

예를 들어 
```
컴퓨터 A
MAC: AA-AA-AA

컴퓨터 B
MAC: BB-BB-BB
```

컴퓨터 A가 "이 데이터는 BB-BB-BB에게 보내!" 라고 할 수 있는 겁니다.

#### SLIP (Serial Line Internet Protocol)

SLIP는 한글로 생각하면 **직렬선을 이용해서 IP 데이터를 보내자** 입니다.  
옛날에는 지금처럼 랜선과 Wi-Fi가 흔하지 않았습니다. 

컴퓨터끼리 이런 **직렬 연결(Serial)을 사용하기도 했습니다.

```
컴퓨터 A
    │
  직렬선
    │
컴퓨터 B
```

그런데 이 선으로 인터넷의 IP 데이터를 보내고 싶었던 겁니다.  
그래서 나온 것이 SLIP = Serial Line으로 IP 보내기 입니다.

#### PPP(Point-to-Point Protocol)

PPP는 이름 그대로 **한 지점(Point)과 다른 한 지점(Point)을 직접 연결하는 규칙** 입니다. 

```
A ●────────────● B
      PPP
```

예를 들어 옛날 전화 모뎀 인터넷을 생각해볼 수 있습니다. 

```
내 컴퓨터
    │
 전화선
    │
인터넷 회사(ISP)
```

컴퓨터와 인터넷 회사가 1:1로 연결되어 통신하는 것입니다.

##### SLIP하고 뭐가 다른가?
둘 다 비슷해 보입니다. 

하지만 SLIP는 PPP 보다 단순합니다. 

```
SLIP
→ "일단 IP 데이터 보내!"
```

PPP는 조금 더 똑똑합니다. 

```
PPP
→ 상대방 확인
→ 인증 가능
→ 오류 검사
→ 여러 프로토콜 전달 가능
```

그래서 ***PPP = SLIP보다 발전된 Point-to-Point 연결 방식** 정도로 이해하면 됩니다.

#### TCP는 뭐냐?

TCP는 데이터가 제대로 전달되었는지 확인하는 역할 입니다.

예를 들어 내가 책 100장을 택배로 보낸다고 해보겠습니다.  
IP만 생각하면 "일단 목적지는 저기니까 보내!" 입니다.

TCP는 추가로
```
"1번부터 100번까지 전부 도착했어?"
"47번이 빠졌네. 다시 보내!"
```
라고 확인합니다.

```
데이터 1 → 도착
데이터 2 → 도착
데이터 3 → 분실
             ↓
        "3번 다시 보내!"
```

그래서

```
IP  → 어디로 보낼까?
TCP → 제대로 도착했나?
```

라고 기억하면 아주 쉽습니다.

#### IPX

IPX는 Internetwork Packet Exchange 입니다.

이건 예전에 Novell NetWare라는 네트워크 운영체제에서 많이 사용하던 네트워크 프로토콜입니다.  
지금은 거의 사용하지 않습니다.

옛날에는
```
회사 컴퓨터들
   ↓
Novell NetWare
   ↓
IPX
```
같은 환경이 있었습니다.

그런데 인터넷이 발전하면서 TCP/IP 가 사실상 표준이 되어버렸습니다.

그래서 IPX는 현재 시험에서 거의 IPX = Novell NetWare 라는 역사적 키워드로 등장합니다.

### 문제 2번 FAT32 / NTFS / SMB / CIFS / 저널링 파일 시스템

#### FAT32

`FAT32 = File Allocation Table 32`  

아주 쉽게 말하면 **"파일이 디스크 어디에 저장돼 있는지 표로 관리하는 오래된 파일 시스템"** 입니다. 

예를 들어 USB 안에 파일이 있다고 가정해 보겠습니다.
```
USB
├─ 사진.jpg
├─ 문서.pdf
└─ 음악.mp3
```
컴퓨터는 실제로 파일을 디스크 여기저기에 저장합니다. FAT32는 

```
사진.jpg → 10번 블록
문서.pdf → 21번 블록
음악.mp3 → 35번 블록
```

이런 식으로 **파일 위치를 표(Table)로 관리**하는 방식이라고 보면 됩니다.

FAT32는 오래됐지만 호환성이 좋아서
- Windows
- Linux
- macOS
- USB 메모리
- SD 카드
- 게임기
- 카메라
등 다양한 장치에서 읽을 수 있습니다.

대신 단점이 있습니다. **파일 하나의 최대 크기가 약 4GB** 입니다.

#### NTFS

`NTFS = New Technology File System` 

Microsoft가 Windows NT 계열을 위해 만든 파일 시스템입니다.  
FAT32보다 훨씬 발전된 파일 시스템이라고 보면 됩니다. 

```
FAT32
  ↓ 발전
NTFS
```
NTFS는 다음 같은 기능을 지원합니다.
- 큰 파일 지원
- 파일/폴더 권한
- 암호화
- 압축
- 저널링
- 대용량 디스크

특히 시험에서 중요한 게 **저널링(Jorunaling)**입니다.

NTFS는 파일 시스템 변경 사항을 기록해두기 때문에 갑자기 전원이 나가거나 장애가 발생했을 때 복구하기가 더 유리합니다.

```
파일 수정 예정
   ↓
변경 내용 기록
   ↓
실제 파일 수정
```
중간에 전원이 나가도 기록을 보고 어느 정도 복구할 수 있는 겁니다.


## 문제 16번 : 정답 3번
```
"다음 중 리눅스 배포판의 종류와 설명으로 틀린 것은?"

1. 수세 : 1994년 독일에서 배포된 상용 소프트웨어로 패키지 관리를 위해 YaST 유틸리티 제공
2. 우분투 : 데비안 리눅스를 기초로 만든 리눅스 배포판으로 고유한 데스크탑 환경인 유니티를 사용
3. Rocky Linux : 현재까지 유상으로 배포 되고 있으며, RPM 패키지 방식을 사용
4. 데비안 : 패키지의 설치, 삭제 등은 dpkg 명령어로 수행되고 apt를 이용하면 쉬운 설치나 업데이트가 가능
```

이 문제는 각 배포판마다 **"어디서 나왔고, 어떤 패키지 관리 방식을 쓰고, 무료/유료인지"**를 구분하는 문제입니다.

| 보기             |       판단 | 핵심                        |
| -------------- | -------: | ------------------------- |
| 1. SUSE        |        O | 독일 계열, YaST               |
| 2. Ubuntu      | O로 출제 의도 | Debian 기반, 과거 Unity 사용    |
| 3. Rocky Linux |    **X** | 무료 오픈소스 배포판인데 “유상 배포”라고 함 |
| 4. Debian      |        O | `dpkg` + `apt`            |

### SUSE
SUSE는 독일에서 시작된 리눅스 배포판 계열입니다. 시험에서 제일 중요한 키워드는 **SUSE -> YaST**입니다.  
쉽게 말하면 SUSE에서 시스템 설정이나 패키지 관리 등을 쉽게 해주는 관리 도구입니다.

```
SUSE
 ↓
YaST
 ↓
설치 / 설정 / 패키지 관리
```

### Ubuntu
Ubuntu는 **Debian을 기반으로 만든 배포판**입니다. 

즉 계보를 보면
```
Debian
  ↓
Ubuntu
```
그래서 Ubuntu도 Debian 계열의 `.deb`, `apt`, `dpkg` 같은 패키지 생태계를 사용합니다.

문제에 나온 **Unity**는 Ubuntu가 과거 기본 데스크톱 환경으로 개발 사용했던 UI입니다.

다만 이 문제는 오래된 표현을 사용하고 있습니다. 현재 Ubuntu Desktop은 Unity가 아니라 **GNOME을 기본 데스크톱으로 사용**합니다. Ubuntu 17.10 부터 GNOME을 기본으로 전환했습니다. 

### Rocky Linux

Rocky Linux 자체는 **무료로 제공되는 오픈소스 엔터프라이즈 Linux 배포판**입니다.  
Rocky Linux 공식 사이트도 RHEL 호한을 목표로 하면서 무료로 제공한다고 명시하고 있습니다.

즉
```
Rocky Linux
→ RHEL 호환 계열
→ Enterprise Linux
→ 무료 오픈소스
→ RPM 계열
```
입니다.

### Debian
이건 패키지 관리 구조를 묻는 설명입니다.

Debian은 `.deb` 패키지를 사용하고, 그 핵심 도구가 `dpkg`입니다.  
예를 들어
```
dpkg -i package.deb
```
처럼 직접 패키지를 설치할 수 있습니다.

그런데 `dpkg`는 비교적 저수준 도구라서 의존성까지 편하게 관리하기 어렵습니다.

그래서 위에 **APT**가 있습니다.
```
사용자
 ↓
apt
 ↓
dpkg
 ↓
.deb 패키지 설치
```
Debian 공식 문서도 `dpkg`를 저수준 패키지 관리 시스템으로, `apt`를 그 위에서 패키지 설치·제거·업데이트와 의존성 처리를 편하게 수행하는 도구로 설명합니다.

그래서
```
apt install nginx
```
라고 하면 APT가 필요한 패키지를 찾고 의존성도 해결한 뒤 내부적으로 `dpkg`등을 위용해서 설치합니다.

> Debian / Ubuntu → .deb + dpkg + apt  
> RHEL / Rocky / Fedora → .rpm + RPM/DNF 계열
> GNOME = 리눅스의 화면/바탕화면 환경
> RHEL = 하나의 리눅스 배포판

## 문제 17번 : 정답 4번
```
"다음 설명으로 알맞은 것은?"

라이브러리가 메모리에 한번 적재되고 나면 여러 프로세스가 매번 동일한 라이브러리를 로드 할 필요 없이 한 번만 로드하여 공용으로 사용할 수 있다.

1. 계층적이니 파일 구조
2. 장치와 파일화
3. 가상메모리
4. 동적 라이브러리
```

이 문제의 핵심은 딱 한 문장입니다. **"라이브러리를 메모리에 한 번 올려두고 여러 프로세스가 공용으로 사용한다."** 이게 바로  
**동적 라이브러리**의 대표적인 특징입니다.

### 먼저 라이브러리가 뭐였지?

라이브러리는 프로그램들이 자주 사용하는 기능을 미리 만들어둔 코드 묶음입니다.

예를 들어 프로그램 A,B,C가 모두 같은 기능을 사용한다고 해보겠습니다.
```
프로그램 A → 문자열 처리 기능 필요
프로그램 B → 문자열 처리 기능 필요
프로그램 C → 문자열 처리 기능 필요
```

각 프로그램이 똑같은 코드를 전부 따로 가지고 있으면 낭비겠죠.

그래서 공통 기능을
```
[라이브러리]
문자열 처리
파일 처리
수학 계산
...
```
처럼 따로 만들어서 사용합니다.

### 정적 라이브러리와 비교하면 더 쉬움

동적 라이브러리를 이해하려면 **정적 라이브러리(Static Library)**와 비교하면 됩니다.

**정적 라이브러리**  
프로그램을 만들 때 라이브러리 코드가 **프로그램 안으로 들어갑니다.**

```
프로그램 A
├─ 내 코드
└─ 라이브러리 코드

프로그램 B
├─ 내 코드
└─ 같은 라이브러리 코드
```
그러면 A와 B가 같은 라이브러리를 사용하더라도 각각 포함할 수 있어서 실행 파일 크기도 커질 수 있습니다.

Linux에서는 대표적으로 `.a` 파일이 정적 라이브러리입니다.

**동적 라이브러리**  
라이브러리를 프로그램마다 집어넣는 대신 따로 둡니다.

```
프로그램 A ─┐
프로그램 B ─┼→ library.so
프로그램 C ─┘
```

그래서

> Static = 프로그램 안에 포함  
> Dynamic = 실행할 때 외부 라이브러리 연결

로 기억하면 됩니다.
