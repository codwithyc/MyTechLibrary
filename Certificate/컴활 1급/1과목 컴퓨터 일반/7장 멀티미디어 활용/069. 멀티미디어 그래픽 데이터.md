## 069. 멀티미디어 그래픽 데이터

### 1. 비트맵(Bitmap)과 벡터(Vector)

| 구분 | 비트맵(래스터) | 벡터 |
| --- | --- | --- |
| 표현 방식 | **픽셀(점)의 집합** | **점과 선의 수학적 계산** |
| 확대 시 | **계단 현상(깨짐) 발생** | **선명함 유지** |
| 파일 크기 | 상대적으로 큼 | 상대적으로 작음 |
| 표현 대상 | 사진, 실사 이미지 | 로고, 도형, 글꼴, 캐릭터 |
| 형식 | BMP, JPG, GIF, PNG, TIF | WMF, AI, SVG, DXF |
| 편집 도구 | 포토샵, 그림판 | 일러스트레이터, 코렐드로우 |

#### 왜 사진은 벡터로 표현하지 않을까?

벡터는 "선을 어디서 어디까지 긋고 어떤 색으로 채워라"라는 **수식**으로 이미지를 표현합니다.

로고나 도형처럼 **면과 선이 명확한 그림**은 수식으로 표현하기 쉽습니다.

그러나 사진은 픽셀 하나하나의 색이 미세하게 모두 다릅니다.  
이를 수식으로 표현하려면 **수식이 픽셀 수만큼 필요**해져 오히려 더 복잡해집니다.

그래서

- **사진 → 비트맵**
- **도형·로고 → 벡터**

로 나누어 사용합니다.

### 2. 그래픽 파일 형식

| 형식 | 특징 |
| --- | --- |
| **BMP** | Windows 표준 비트맵 형식입니다. **압축하지 않아 파일 크기가 매우 큽니다.** |
| **JPG(JPEG)** | **손실 압축** 방식으로 압축률이 높습니다. **약 1,677만 컬러(24비트)** 를 표현하며 **사진에 적합**합니다. |
| **GIF** | **무손실 압축**이며 **최대 256색(8비트)** 만 표현합니다. **투명 배경과 애니메이션**을 지원합니다. |
| **PNG** | **무손실 압축**이며 **투명도(알파 채널)** 를 지원합니다. GIF보다 많은 색을 표현하지만 **애니메이션은 지원하지 않습니다.** |
| **TIF(TIFF)** | 고품질 이미지 형식으로, 인쇄와 출판 분야에서 사용합니다. 파일 크기가 큽니다. |
| **WMF** | Windows에서 사용하는 **벡터** 형식입니다. |
| **PCX** | 초기 그래픽 프로그램에서 사용하던 형식입니다. |
| **AI / SVG** | 대표적인 벡터 형식입니다. SVG는 웹에서 널리 사용됩니다. |

#### JPG vs GIF vs PNG (가장 자주 출제)

| 구분 | JPG | GIF | PNG |
| --- | --- | --- | --- |
| 압축 | **손실** | 무손실 | 무손실 |
| 색상 수 | **약 1,677만 색** | **256색** | 1,677만 색 이상 |
| 투명 지원 | ✕ | **○** | **○ (부드러운 투명)** |
| 애니메이션 | ✕ | **○** | ✕ |
| 적합한 용도 | **사진** | 단순 그림, 애니메이션 | 로고, 투명 배경 이미지 |

#### 왜 사진은 JPG, 로고는 PNG로 저장할까?

**사진**은 색이 매우 다양하고, 미세한 손실이 눈에 잘 띄지 않습니다.  
그래서 손실 압축인 JPG를 쓰면 **품질 저하는 거의 없이 용량을 크게 줄일 수 있습니다.**

**로고나 텍스트가 있는 이미지**는 색 경계가 뚜렷합니다.  
JPG로 저장하면 경계 주변에 **얼룩(노이즈)** 이 생겨 지저분해집니다.

또한 로고는 배경이 투명해야 어디에나 얹을 수 있는데, **JPG는 투명을 지원하지 않습니다.**

그래서 로고는 무손실이면서 투명을 지원하는 **PNG**가 적합합니다.

#### 왜 GIF는 256색밖에 표현하지 못할까?

GIF는 **8비트 색상**을 사용합니다.

2⁸ = 256이므로 최대 256가지 색만 표현할 수 있습니다.

이 때문에 사진을 GIF로 저장하면 색이 뭉개져 보입니다.

대신 색이 단순한 아이콘이나 도형에서는 용량이 매우 작고,  
**여러 장의 이미지를 담아 애니메이션**을 만들 수 있다는 강점이 있습니다.

### 3. 색상 표현

| 방식 | 설명 | 용도 |
| --- | --- | --- |
| **RGB** | 빛의 삼원색(**Red, Green, Blue**)을 혼합합니다. 섞을수록 **밝아지는 가산 혼합**입니다. | 모니터, TV 등 **화면 출력** |
| **CMYK** | 색의 삼원색(**Cyan, Magenta, Yellow**) + **Black**을 혼합합니다. 섞을수록 **어두워지는 감산 혼합**입니다. | **인쇄** |
| HSB | 색상(Hue), 채도(Saturation), 명도(Brightness)로 표현합니다. | 색 선택 |

#### 왜 화면은 RGB, 인쇄는 CMYK를 쓸까?

**모니터**는 스스로 **빛을 내서** 색을 만듭니다.  
빛을 더할수록 밝아지고, 세 가지 빛을 모두 합치면 **흰색**이 됩니다. → **가산 혼합**

**인쇄물**은 스스로 빛을 내지 않습니다.  
종이에 닿은 빛 중 **일부를 잉크가 흡수하고, 남은 빛만 반사**되어 색으로 보입니다.  
잉크를 더할수록 흡수가 많아져 **어두워집니다.** → **감산 혼합**

#### 왜 CMYK에 Black(K)이 따로 있을까?

이론상 C, M, Y를 모두 섞으면 검은색이 되어야 합니다.

그러나 실제 잉크는 순수하지 않아, 세 색을 섞으면 **탁한 갈색에 가깝게** 나옵니다.

또한 검은 글씨를 인쇄할 때마다 잉크 세 가지를 쓰면 **비용도 크고 종이가 젖습니다.**

그래서 검정 잉크(K)를 별도로 두어 **선명함과 경제성**을 확보합니다.

### 4. 해상도와 색상 수

| 용어 | 설명 |
| --- | --- |
| **해상도(Resolution)** | 이미지를 구성하는 **픽셀의 수**입니다. 높을수록 선명하지만 파일 크기가 커집니다. |
| **픽셀(Pixel)** | 이미지를 구성하는 **최소 단위의 점**입니다. |
| **색 깊이(Color Depth)** | 한 픽셀이 표현할 수 있는 **색의 수**를 비트로 나타냅니다. |

| 비트 수 | 표현 가능한 색상 수 |
| --- | --- |
| 1비트 | 2색 (흑백) |
| 4비트 | 16색 |
| **8비트** | **256색** |
| 16비트 | 65,536색 (하이 컬러) |
| **24비트** | **약 1,677만 색 (트루 컬러)** |

#### 왜 24비트를 "트루 컬러"라고 할까?

24비트는 RGB 각각에 8비트씩(256단계) 배정합니다.

256 × 256 × 256 = 약 1,677만 가지 색을 표현할 수 있습니다.

사람의 눈이 구별할 수 있는 색은 대략 **1,000만 가지 수준**이라고 알려져 있으므로,  
1,677만 색이면 **사람 눈으로는 실제와 구별할 수 없는 수준**이 됩니다.

그래서 "진짜 색(True Color)"이라고 부릅니다.

**이미지 용량 계산**

`파일 크기(byte) = 가로 픽셀 수 × 세로 픽셀 수 × 색 깊이(bit) ÷ 8`

예) 1024 × 768 크기의 24비트 이미지  
→ 1024 × 768 × 24 ÷ 8 = 2,359,296 byte ≈ **2.25MB**

### 한 줄 정리

**비트맵은 픽셀 기반(확대 시 깨짐), 벡터는 수식 기반(확대해도 선명)** 이며,  
**JPG는 손실·1,677만 색·사진용**, **GIF는 256색·투명·애니메이션**, **PNG는 무손실·투명·애니메이션 불가**이고,  
**화면은 RGB(가산), 인쇄는 CMYK(감산)** 를 사용합니다.
