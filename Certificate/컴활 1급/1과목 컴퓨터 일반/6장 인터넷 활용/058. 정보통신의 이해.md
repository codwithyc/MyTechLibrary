## 058. 정보통신의 이해

### 1. 정보 통신 시스템의 구성

정보 통신 시스템은 **데이터 전송계**와 **데이터 처리계**로 구성됩니다.

| 구분 | 구성 요소 |
| --- | --- |
| **데이터 전송계** | 단말 장치(DTE), 신호 변환 장치(DCE), 통신 회선, 통신 제어 장치(CCU) |
| **데이터 처리계** | 컴퓨터(하드웨어), 소프트웨어 |

| 장치 | 역할 |
| --- | --- |
| **단말 장치(DTE)** | 데이터를 입력하고 결과를 출력하는 장치입니다. |
| **신호 변환 장치(DCE)** | 데이터를 통신 회선에 맞는 신호로 변환합니다. (모뎀, DSU, 코덱) |
| **통신 제어 장치(CCU)** | 데이터의 전송 순서와 오류를 제어합니다. |

#### 왜 신호 변환 장치가 필요할까?

컴퓨터는 **디지털 신호(0과 1)** 로 데이터를 처리합니다.

그런데 전화선처럼 오래된 통신 회선은 **아날로그 신호**만 전달할 수 있습니다.

신호 변환 장치는 이 둘 사이를 이어 주는 장치입니다.

| 장치 | 변환 |
| --- | --- |
| **모뎀(MODEM)** | 디지털 ↔ 아날로그 (변조 / 복조) |
| **DSU** | 디지털 신호를 디지털 전송로에 맞게 변환 |
| **코덱(CODEC)** | 아날로그 ↔ 디지털 |

즉, 모뎀의 이름 자체가 **변조(MOdulation) + 복조(DEModulation)** 에서 온 것입니다.

---

### 2. 데이터 전송 방식

**전송 방향에 따른 분류**

| 방식 | 설명 | 예 |
| --- | --- | --- |
| **단방향(Simplex)** | 한쪽 방향으로만 전송합니다. | 라디오, TV 방송 |
| **반이중(Half Duplex)** | 양방향 전송이 가능하지만 **동시에는 불가능**합니다. | 무전기 |
| **전이중(Full Duplex)** | 양방향으로 **동시에** 전송할 수 있습니다. | 전화, 인터넷 |

#### 왜 반이중과 전이중을 나눌까?

전송로를 몇 개 사용하느냐의 차이입니다.

- **반이중** : 통로가 하나 → 한 번에 한 방향만 → 순서를 정해 번갈아 사용
- **전이중** : 통로가 둘(또는 분리된 채널) → 동시에 양방향 가능

무전기는 하나의 주파수를 함께 쓰므로 "오버"라고 말한 뒤 상대에게 넘겨야 하지만,  
전화는 통로가 분리되어 있어 동시에 말하고 들을 수 있습니다.

### 3. 통신 방식(동기화)

| 방식 | 특징 |
| --- | --- |
| **비동기식 전송** | **문자 단위**로 전송하며, 각 문자 앞뒤에 시작 비트와 정지 비트를 붙입니다. 저속 전송에 적합합니다. |
| **동기식 전송** | **블록(프레임) 단위**로 전송하며, 송·수신 측이 타이밍을 맞춥니다. 고속 전송에 적합합니다. |

#### 왜 동기식이 더 효율적일까?

비동기식은 문자 하나마다 시작·정지 비트를 붙입니다.

8비트 문자에 2비트를 추가한다면, **전체의 20%가 실제 데이터가 아닌 부가 정보**가 됩니다.

동기식은 여러 문자를 하나의 블록으로 묶어 전송하므로,  
부가 정보의 비율이 훨씬 낮아 **전송 효율이 높습니다.**

대신 송·수신 측이 정확히 **시간을 맞춰야 하므로 구현이 복잡**합니다.

### 4. 회선 교환과 패킷 교환

| 방식 | 특징 |
| --- | --- |
| **회선 교환 방식** | 통신 전에 **전용 통로를 미리 확보**하고, 통신이 끝날 때까지 독점합니다. (전화망) |
| **패킷 교환 방식** | 데이터를 **패킷 단위로 나누어** 전송하며, 여러 사용자가 회선을 공유합니다. (인터넷) |

#### 왜 인터넷은 패킷 교환 방식을 쓸까?

회선 교환은 **통화처럼 계속 데이터가 오가는 상황**에는 적합합니다.

하지만 인터넷 사용은 다릅니다.  
웹 페이지를 읽는 동안에는 데이터가 전혀 오가지 않습니다.

이때 회선을 독점하고 있으면 **대부분의 시간 동안 회선이 놀게 됩니다.**

패킷 교환은 데이터를 잘게 나누어 보내고, 빈 시간에는 **다른 사용자의 패킷이 그 회선을 사용**합니다.

즉, 패킷 교환은  
**회선을 잘게 나누어 여러 사용자가 함께 쓰게 함으로써 효율을 높이는 방식**입니다.

또한 패킷마다 다른 경로로 갈 수 있으므로,  
**중간의 어느 한 경로가 끊겨도 다른 길로 우회**할 수 있어 안정적입니다.

### 5. 오류 검출과 정정

| 방식 | 설명 |
| --- | --- |
| **패리티 검사(Parity Check)** | 데이터에 검사 비트 1개를 추가하여 1의 개수가 짝수(또는 홀수)가 되게 합니다. **오류 검출만 가능**하며, 2개 이상의 오류는 검출하지 못합니다. |
| **CRC(순환 중복 검사)** | 다항식을 이용한 검사 방식으로, **집단 오류(연속된 오류)도 검출**할 수 있습니다. |
| **해밍 코드(Hamming Code)** | **오류를 검출하고 스스로 정정**까지 할 수 있는 코드입니다. |
| **블록합 검사** | 패리티 검사를 가로·세로 양방향으로 수행합니다. |

**오류 정정 방식**

| 방식 | 설명 |
| --- | --- |
| **전진 오류 수정(FEC)** | 수신 측에서 **스스로 오류를 정정**합니다. 재전송이 필요 없습니다. (해밍 코드) |
| **후진 오류 수정(BEC)** | 오류를 발견하면 **송신 측에 재전송을 요청**합니다. (패리티, CRC, ARQ) |

#### 왜 패리티 검사는 2개의 오류를 못 잡을까?

패리티는 **1의 개수가 짝수인지 홀수인지**만 확인합니다.

비트 하나가 뒤집히면 개수의 홀짝이 바뀌므로 오류를 알 수 있습니다.

하지만 **두 개가 뒤집히면 홀짝이 원래대로 돌아오므로**,  
정상인 것처럼 보이게 됩니다.

간단해서 널리 쓰이지만, 신뢰도가 중요한 곳에서는 CRC나 해밍 코드를 사용합니다.

---

### 한 줄 정리

정보 통신 시스템은 **전송계(단말·신호 변환·회선·통신 제어)와 처리계(컴퓨터)** 로 구성되며,  
**모뎀은 디지털↔아날로그, 코덱은 아날로그↔디지털**을 변환하고,  
인터넷은 회선을 나눠 쓰는 **패킷 교환 방식**을 사용합니다.
