## 053. 소프트웨어의 개요

### 1. 소프트웨어의 분류

소프트웨어는 크게 **시스템 소프트웨어**와 **응용 소프트웨어**로 나뉩니다.

| 구분 | 설명 | 예 |
| --- | --- | --- |
| **시스템 소프트웨어** | 컴퓨터 **하드웨어를 제어하고 관리**하며, 응용 소프트웨어가 동작할 환경을 제공합니다. | 운영체제, 컴파일러, 어셈블러, 링커, 로더, 장치 드라이버, 유틸리티 |
| **응용 소프트웨어** | 사용자가 **특정한 목적의 작업을 수행**하기 위해 사용합니다. | 워드프로세서, 스프레드시트, 데이터베이스, 그래픽 프로그램, 웹 브라우저 |

#### 왜 시스템 소프트웨어가 따로 필요할까?

응용 프로그램이 하드웨어를 직접 제어해야 한다면,  
프로그램마다 **모든 종류의 CPU, 메모리, 디스크, 프린터를 다룰 줄 알아야** 합니다.

이는 현실적으로 불가능합니다.

시스템 소프트웨어는 하드웨어 제어를 대신 맡아 주고,  
응용 프로그램에는 **"이렇게 요청하면 된다"는 통일된 방법**만 제공합니다.

즉, 시스템 소프트웨어는  
**하드웨어의 복잡함을 감추어 응용 프로그램이 본래 목적에만 집중하게 해 주는 계층**입니다.

---

### 2. 언어 번역 프로그램

사람이 작성한 프로그램을 **컴퓨터가 이해할 수 있는 기계어로 바꾸는 프로그램**입니다.

| 종류 | 특징 |
| --- | --- |
| **어셈블러(Assembler)** | 어셈블리어를 기계어로 번역합니다. |
| **컴파일러(Compiler)** | 고급 언어로 작성된 원시 프로그램을 **한꺼번에 번역**하여 목적 프로그램을 만듭니다. (C, C++, Java) |
| **인터프리터(Interpreter)** | 원시 프로그램을 **한 줄씩 읽어 즉시 실행**합니다. 목적 프로그램을 만들지 않습니다. (Python, JavaScript, BASIC) |

**컴파일러 vs 인터프리터**

| 구분 | 컴파일러 | 인터프리터 |
| --- | --- | --- |
| 번역 단위 | 전체 프로그램 | 한 줄씩 |
| 목적 프로그램 | **생성함** | **생성하지 않음** |
| 번역 속도 | 느림 | 빠름 |
| **실행 속도** | **빠름** | **느림** |
| 메모리 사용 | 많음 | 적음 |
| 오류 발견 | 번역이 끝난 후 한꺼번에 | 실행 중 그 줄에서 즉시 |

#### 왜 컴파일러는 실행이 빠를까?

컴파일러는 프로그램을 **미리 전부 기계어로 번역해 둡니다.**  
실행할 때는 이미 번역된 결과를 그대로 돌리기만 하면 됩니다.

반면 인터프리터는 **실행할 때마다 한 줄씩 다시 번역**합니다.  
반복문 안의 코드는 실행 횟수만큼 반복 번역되므로 느릴 수밖에 없습니다.

책에 비유하면

- **컴파일러** : 책 전체를 미리 번역해 두고 읽음 → 준비는 오래 걸리지만 읽기는 빠름
- **인터프리터** : 읽으면서 그때그때 통역 → 바로 시작할 수 있지만 읽는 속도가 느림

---

### 3. 프로그램 실행 과정

**원시 프로그램(Source) → [컴파일러] → 목적 프로그램(Object) → [링커] → 로드 모듈 → [로더] → 실행**

| 프로그램 | 역할 |
| --- | --- |
| **컴파일러** | 원시 프로그램을 목적 프로그램으로 번역합니다. |
| **링커(Linker)** | 목적 프로그램과 라이브러리를 연결하여 **실행 가능한 로드 모듈**을 만듭니다. |
| **로더(Loader)** | 로드 모듈을 **주기억장치에 적재하여 실행**할 수 있게 합니다. |

#### 왜 링커가 필요할까?

프로그램은 보통 **여러 개의 파일로 나누어 작성**되고,  
자주 쓰는 기능은 이미 만들어진 **라이브러리**를 가져다 씁니다.

각각 따로 번역된 조각들은 서로가 어디에 있는지 모릅니다.

링커는 이 조각들을 **하나로 연결하여 완성된 실행 파일**을 만드는 역할을 합니다.

### 4. 사용 권한에 따른 분류

| 종류 | 특징 |
| --- | --- |
| **상용 소프트웨어(Commercial)** | 정식 대가를 지불하고 사용하는 소프트웨어입니다. |
| **셰어웨어(Shareware)** | **일정 기간 또는 일부 기능만 무료로 사용**해 보고, 계속 사용하려면 대가를 지불합니다. |
| **프리웨어(Freeware)** | **무료로 사용**할 수 있지만, 배포와 수정에는 제한이 있을 수 있습니다. |
| **공개 소프트웨어(Open Source)** | **소스 코드가 공개**되어 있어 자유롭게 사용·수정·재배포할 수 있습니다. |
| **데모 버전(Demo)** | 프로그램을 홍보하기 위해 **주요 기능만 시연**하는 버전입니다. |
| **트라이얼 버전(Trial)** | **사용 기간에 제한**을 두고 무료로 제공하는 버전입니다. |
| **알파 버전(Alpha)** | 개발사 **내부에서 테스트**하는 초기 버전입니다. |
| **베타 버전(Beta)** | 정식 발표 전 **일반 사용자에게 배포하여 테스트**하는 버전입니다. |
| **패치 프로그램(Patch)** | 이미 배포된 프로그램의 **오류를 수정하거나 일부를 보완**하는 프로그램입니다. |
| **번들(Bundle)** | 하드웨어나 다른 소프트웨어를 구입할 때 **함께 제공**되는 소프트웨어입니다. |
| **벤치마크 테스트** | 하드웨어나 소프트웨어의 **성능을 비교·평가**하는 테스트입니다. |

#### 셰어웨어 vs 프리웨어 vs 공개 소프트웨어

혼동하기 쉬운 세 가지를 비교하면 다음과 같습니다.

| 구분 | 비용 | 소스 코드 | 핵심 |
| --- | --- | --- | --- |
| 셰어웨어 | **조건부 무료** (기간·기능 제한) | 비공개 | "먼저 써 보고 마음에 들면 구입" |
| 프리웨어 | **무료** | 비공개 | "공짜지만 내부는 못 봄" |
| 공개 소프트웨어 | 무료인 경우가 많음 | **공개** | "코드까지 열려 있어 수정 가능" |

#### 왜 알파 버전과 베타 버전을 나눌까?

소프트웨어의 오류는 개발자가 예상하지 못한 방식으로 사용될 때 드러납니다.

- **알파** : 내부에서 기본 동작을 점검하는 단계
- **베타** : 실제 사용자들이 다양한 환경에서 사용하며 예상 못 한 문제를 찾아내는 단계

즉, 베타 테스트는 **개발자가 만들 수 없는 "현실의 다양성"을 확보하기 위한 과정**입니다.

### 5. 유틸리티 프로그램

컴퓨터를 더 편리하게 사용하도록 돕는 보조 프로그램입니다.

- 압축 프로그램, 백신 프로그램, 화면 캡처 프로그램, 파일 복구 프로그램, 디스크 관리 도구 등
- 시스템의 기본 동작에는 필수적이지 않지만, **작업 효율을 높여 줍니다.**

**압축 프로그램**

- 파일의 크기를 줄여 **저장 공간을 절약하고 전송 시간을 단축**합니다.
- **여러 파일을 하나로 묶을 수 있습니다.**
- 이미 압축된 파일(JPG, MP3, ZIP 등)은 **다시 압축해도 크기가 거의 줄지 않습니다.**
- 압축률은 파일의 종류와 압축 방식에 따라 달라집니다.

#### 왜 이미 압축된 파일은 더 줄지 않을까?

압축은 데이터 안의 **반복되는 규칙(중복)** 을 찾아 짧게 바꾸는 방식입니다.

한 번 압축한 파일은 이미 중복이 대부분 제거된 상태이므로,  
더 이상 줄일 여지가 남아 있지 않습니다.

오히려 압축 정보가 추가되어 **크기가 조금 늘어나는 경우**도 있습니다.

---

### 한 줄 정리

소프트웨어는 **시스템 소프트웨어와 응용 소프트웨어**로 나뉘며,  
**컴파일러는 전체를 번역해 목적 프로그램을 만들고 실행이 빠른 반면, 인터프리터는 한 줄씩 번역하여 실행이 느립니다.**  
사용 권한에 따라 **셰어웨어(조건부 무료), 프리웨어(무료), 공개 소프트웨어(소스 공개)** 로 구분합니다.
