# 분석 거버넌스 체계

분석 거버넌스 체계는 조직이 데이터 분석을 일회성 프로젝트로 끝내지 않고, **지속적으로 관리하고 활용할 수 있도록 만드는 운영 체계**다.

분석을 잘하려면 분석가만 있으면 되는 것이 아니다.
분석 조직, 분석 프로세스, 분석 시스템, 데이터, 인력, 문화가 함께 갖춰져야 한다.

```markdown id="1r1xwd"
분석 거버넌스 = 조직이 데이터 분석을 지속적으로 수행하고 관리하기 위한 체계
```

이번 단원은 크게 세 영역으로 나누어 보면 된다.

| 구분         | 핵심                              |
| ---------- | ------------------------------- |
| 분석 거버넌스    | 분석 조직, 인력, 프로세스, 시스템, 데이터 관리 체계 |
| 데이터 거버넌스   | 데이터 품질, 표준, 보안, 메타데이터 관리 체계     |
| 소프트웨어 프로세스 | 소프트웨어 개발 프로세스 품질과 성숙도 관리        |

기존 정리처럼 개념 설명을 먼저 보고 표로 압축하면 시험 직전 복습에 좋다.

# 01. 분석 거버넌스

## 1) 분석 거버넌스 체계 정의

## 분석 거버넌스 체계의 개념

**분석 거버넌스 체계**란 조직이 데이터 분석을 체계적으로 수행하기 위해 필요한 조직, 프로세스, 시스템, 인력, 데이터를 관리하는 체계를 의미한다.

분석 거버넌스가 없으면 다음과 같은 문제가 발생할 수 있다.

```markdown id="5i6epw"
분석 과제가 중복된다.
분석 결과의 품질이 일정하지 않다.
분석 결과가 실제 업무에 활용되지 않는다.
분석 조직과 현업 조직의 역할이 불명확하다.
데이터 품질과 보안이 관리되지 않는다.
```

따라서 분석 거버넌스는 분석을 개인 역량이 아니라 **조직의 역량으로 정착시키기 위한 관리 체계**라고 보면 된다.

```markdown id="wlhr68"
분석 거버넌스 체계 = 분석을 조직 차원에서 지속적으로 운영하기 위한 관리 구조
```

---

## 분석 거버넌스 체계 구성 요소, POSHD

분석 거버넌스 체계는 보통 **POSHD**로 정리한다.

```markdown id="4fmgzy"
POSHD = Process + Organization + System + Human Resource + Data
```

| 구성 요소          | 의미   | 설명                           |
| -------------- | ---- | ---------------------------- |
| Process        | 프로세스 | 분석 과제 발굴, 수행, 평가, 활용 절차      |
| Organization   | 조직   | 분석 전담 조직, 현업 조직, 의사결정 구조     |
| System         | 시스템  | 분석 플랫폼, 분석 도구, 데이터 처리 환경     |
| Human Resource | 인력   | 분석가, 데이터 엔지니어, 현업 담당자, 의사결정자 |
| Data           | 데이터  | 분석에 필요한 데이터, 품질, 표준, 보안 관리   |

---

### ① Process, 프로세스

프로세스는 분석 과제를 어떻게 발굴하고, 수행하고, 평가하고, 활용할 것인지에 대한 절차다.

분석 프로세스가 없으면 과제가 임의로 수행되고, 결과 품질도 일정하지 않다.

| 항목    | 설명                       |
| ----- | ------------------------ |
| 과제 발굴 | 비즈니스 문제를 분석 과제로 전환       |
| 과제 선정 | 가치와 실행 가능성을 기준으로 우선순위 결정 |
| 분석 수행 | 데이터 준비, 분석, 모델링, 결과 해석   |
| 결과 평가 | 분석 결과의 정확성, 활용성, 성과 평가   |
| 결과 활용 | 업무 프로세스나 시스템에 분석 결과 반영   |

```markdown id="cpcjpx"
Process = 분석 과제를 체계적으로 수행하기 위한 절차
```

---

### ② Organization, 조직

조직은 분석을 수행하고 관리하는 역할과 책임 구조다.

분석 전담 조직이 있는지, 현업 부서와 어떻게 협업하는지, 분석 과제의 의사결정은 누가 하는지 등이 포함된다.

| 항목       | 설명                    |
| -------- | --------------------- |
| 분석 전담 조직 | 분석 과제 수행과 분석 역량 축적    |
| 현업 조직    | 문제 제기, 데이터 해석, 결과 활용  |
| IT 조직    | 데이터 수집, 저장, 시스템 연계 지원 |
| 의사결정 조직  | 과제 선정, 예산, 우선순위 결정    |

```markdown id="p967go"
Organization = 분석을 수행하고 관리하는 역할과 책임 구조
```

---

### ③ System, 시스템

시스템은 분석을 수행하기 위한 기술 환경이다.

분석 도구, 데이터 저장소, 분석 플랫폼, 시각화 도구, 모델 운영 환경 등이 포함된다.

| 항목        | 설명                          |
| --------- | --------------------------- |
| 분석 플랫폼    | 데이터 분석을 수행하는 공통 환경          |
| 분석 도구     | 통계, 머신러닝, 시각화 도구            |
| 데이터 처리 환경 | 수집, 저장, 정제, 변환 인프라          |
| 운영 시스템    | 분석 결과를 실제 서비스나 업무에 적용하는 시스템 |

```markdown id="nfl83z"
System = 분석을 수행하고 운영하기 위한 기술 환경
```

---

### ④ Human Resource, 인력

인력은 분석을 수행하고 활용하는 사람과 역량을 의미한다.

분석가는 모델을 만들고, 데이터 엔지니어는 데이터를 처리하며, 현업 담당자는 문제를 정의하고 결과를 활용한다.

| 역할         | 핵심                       |
| ---------- | ------------------------ |
| 데이터 분석가    | 데이터 탐색, 분석, 모델링, 결과 해석   |
| 데이터 엔지니어   | 데이터 수집, 저장, 처리, 파이프라인 구축 |
| 데이터 사이언티스트 | 고급 분석, 머신러닝, 예측 모델 개발    |
| 현업 담당자     | 문제 정의와 결과 활용             |
| 의사결정자      | 분석 결과 기반 의사결정            |

```markdown id="h13wie"
Human Resource = 분석을 수행하고 활용할 수 있는 인력과 역량
```

---

### ⑤ Data, 데이터

데이터는 분석의 기반이다.

분석에 필요한 데이터가 존재하는지, 품질이 적절한지, 표준과 보안이 관리되는지가 중요하다.

| 항목     | 설명                    |
| ------ | --------------------- |
| 데이터 확보 | 분석에 필요한 데이터 존재 여부     |
| 데이터 품질 | 결측치, 오류, 중복, 정합성 관리   |
| 데이터 표준 | 용어, 형식, 코드, 기준 통일     |
| 데이터 보안 | 개인정보, 접근 권한, 보안 정책 관리 |

```markdown id="t7fcg7"
Data = 분석에 필요한 데이터의 확보, 품질, 표준, 보안 관리
```

---

## POSHD 암기

```markdown id="v75scn"
POSHD는 분석 거버넌스 체계의 구성 요소이다.

P는 Process로 분석 과제 수행 절차,
O는 Organization으로 분석 조직과 역할,
S는 System으로 분석 플랫폼과 도구,
H는 Human Resource로 분석 인력과 역량,
D는 Data로 데이터 품질과 표준, 보안 관리를 의미한다.
```

## 2) 데이터 분석 준비도

## 데이터 분석 준비도의 개념

**데이터 분석 준비도**란 조직이 데이터 분석을 수행할 준비가 얼마나 되어 있는지 진단하는 것이다.

분석 준비도가 낮은 조직은 분석 과제를 수행하려 해도 데이터, 인력, 조직, 시스템이 부족해 실패할 가능성이 높다.

```markdown id="n06jnw"
데이터 분석 준비도 = 조직이 데이터 분석을 수행할 수 있는 준비 수준
```

---

## 6가지 영역별 데이터 분석 준비도

데이터 분석 준비도는 일반적으로 다음 6가지 영역으로 진단한다.

| 영역         | 설명                          |
| ---------- | --------------------------- |
| 분석 업무      | 분석 과제가 존재하고 업무와 연결되어 있는가    |
| 분석 인력 및 조직 | 분석을 수행할 인력과 조직이 있는가         |
| 분석 기법      | 적절한 분석 방법론과 기법을 활용할 수 있는가   |
| 분석 데이터     | 분석에 필요한 데이터가 확보되고 품질이 적절한가  |
| 분석 문화      | 데이터 기반 의사결정 문화가 있는가         |
| 분석 인프라     | 분석 도구, 플랫폼, 시스템 환경이 갖춰져 있는가 |

---

### ① 분석 업무

분석 업무는 조직 내에 데이터 분석이 필요한 업무와 과제가 존재하는지를 보는 영역이다.

| 항목       | 설명                  |
| -------- | ------------------- |
| 분석 과제 존재 | 해결해야 할 분석 과제가 있는가   |
| 업무 연계성   | 분석 과제가 실제 업무와 연결되는가 |
| 성과 목표    | 분석 결과의 기대 효과가 명확한가  |

```markdown id="jc6riz"
분석 업무 = 분석할 과제와 업무 활용 목적이 명확한가
```

---

### ② 분석 인력 및 조직

분석 인력 및 조직은 분석을 수행할 수 있는 사람과 조직 구조가 있는지를 보는 영역이다.

| 항목       | 설명                    |
| -------- | --------------------- |
| 분석 전담 인력 | 데이터 분석가, 데이터 엔지니어 등   |
| 분석 조직    | 분석 전담 조직 또는 협업 체계     |
| 역할과 책임   | 현업, IT, 분석 조직 간 책임 구분 |

```markdown id="ev6c52"
분석 인력 및 조직 = 분석을 수행할 사람과 조직 체계가 있는가
```

---

### ③ 분석 기법

분석 기법은 분석 과제에 맞는 방법론과 분석 기술을 활용할 수 있는지를 보는 영역이다.

| 항목      | 설명                     |
| ------- | ---------------------- |
| 통계 분석   | 기초 통계, 검정, 회귀 등        |
| 데이터 마이닝 | 분류, 군집, 연관분석 등         |
| 머신러닝    | 예측 모델, 학습 알고리즘 등       |
| 분석 방법론  | SEMMA, KDD, CRISP-DM 등 |

```markdown id="i87nd0"
분석 기법 = 분석 문제에 적합한 방법과 모델을 사용할 수 있는가
```

---

### ④ 분석 데이터

분석 데이터는 분석에 필요한 데이터를 확보하고 관리할 수 있는지를 보는 영역이다.

| 항목      | 설명                    |
| ------- | --------------------- |
| 데이터 존재  | 분석에 필요한 데이터가 있는가      |
| 데이터 품질  | 결측, 오류, 중복이 관리되는가     |
| 데이터 접근성 | 필요한 데이터에 접근할 수 있는가    |
| 데이터 통합  | 여러 출처의 데이터를 결합할 수 있는가 |

```markdown id="4an2yz"
분석 데이터 = 분석에 필요한 데이터를 확보하고 신뢰할 수 있는가
```

---

### ⑤ 분석 문화

분석 문화는 조직이 데이터를 기반으로 의사결정하려는 문화를 가지고 있는지를 보는 영역이다.

| 항목          | 설명                      |
| ----------- | ----------------------- |
| 데이터 기반 의사결정 | 직관보다 데이터 근거를 중시하는가      |
| 분석 결과 신뢰    | 분석 결과를 업무에 반영하는가        |
| 현업 참여       | 현업이 분석 과제 발굴과 활용에 참여하는가 |
| 변화 수용성      | 새로운 분석 방식과 시스템을 받아들이는가  |

```markdown id="knq5xg"
분석 문화 = 조직이 데이터를 근거로 의사결정하려는 문화를 가지고 있는가
```

---

### ⑥ 분석 인프라

분석 인프라는 분석을 수행할 수 있는 도구와 시스템 환경이 있는지를 보는 영역이다.

| 항목      | 설명                     |
| ------- | ---------------------- |
| 분석 도구   | 통계, 머신러닝, 시각화 도구       |
| 데이터 저장소 | DW, 데이터마트, 데이터레이크 등    |
| 처리 환경   | 대용량 처리, 분산 처리, 클라우드 환경 |
| 운영 환경   | 모델 배포, 대시보드, 모니터링 시스템  |

```markdown id="0sazgr"
분석 인프라 = 분석을 수행하고 운영할 수 있는 기술 환경
```

## 3) 데이터 분석 성숙도

## 데이터 분석 수준 진단

**데이터 분석 성숙도**란 조직이 데이터 분석을 얼마나 체계적으로 수행하고 활용하는지 나타내는 수준이다.

분석 준비도가 “분석할 준비가 되었는가”를 보는 것이라면,
분석 성숙도는 “분석을 얼마나 잘 운영하고 있는가”를 보는 것이다.

| 구분     | 의미                |
| ------ | ----------------- |
| 분석 준비도 | 분석 수행을 위한 준비 수준   |
| 분석 성숙도 | 분석을 조직적으로 활용하는 수준 |

```markdown id="0k7do4"
분석 성숙도 = 조직이 데이터 분석을 체계적으로 수행하고 활용하는 수준
```

---

## 분석 성숙도 모델

분석 성숙도 모델은 일반적으로 다음 5단계로 이해하면 된다.

| 단계  | 수준     | 설명                          |
| --- | ------ | --------------------------- |
| 1단계 | 도입 단계  | 분석 필요성을 인식하고 일부 분석을 시도      |
| 2단계 | 활용 단계  | 특정 부서나 업무에서 분석을 활용          |
| 3단계 | 확산 단계  | 여러 부서로 분석 활용이 확대            |
| 4단계 | 최적화 단계 | 분석이 업무 프로세스에 통합되고 의사결정에 활용  |
| 5단계 | 혁신 단계  | 분석을 기반으로 새로운 가치와 비즈니스 모델 창출 |

---

### ① 도입 단계

분석의 필요성을 인식하고 일부 부서나 개인이 분석을 시도하는 단계다.

```markdown id="tltkjl"
도입 단계 = 분석을 시작하는 초기 단계
```

---

### ② 활용 단계

특정 업무나 부서에서 분석을 활용하는 단계다.

분석이 일부 업무 개선에 사용되지만, 조직 전체로 확산되지는 않은 상태다.

```markdown id="xyyrwv"
활용 단계 = 특정 업무에서 분석을 활용하는 단계
```

---

### ③ 확산 단계

분석이 여러 부서나 업무로 확대되는 단계다.

분석 과제와 조직, 데이터 활용 범위가 점차 넓어진다.

```markdown id="dwfzx2"
확산 단계 = 분석 활용이 조직 내 여러 영역으로 확대되는 단계
```

---

### ④ 최적화 단계

분석이 업무 프로세스에 통합되고, 의사결정에 체계적으로 활용되는 단계다.

```markdown id="kxtm0c"
최적화 단계 = 분석이 업무와 의사결정에 체계적으로 통합되는 단계
```

---

### ⑤ 혁신 단계

분석을 활용해 새로운 서비스, 비즈니스 모델, 조직 혁신을 만들어내는 단계다.

```markdown id="q631va"
혁신 단계 = 분석을 통해 새로운 가치와 비즈니스 혁신을 창출하는 단계
```

---

## 분석 성숙도 암기

```markdown id="xl55sy"
분석 성숙도는 도입, 활용, 확산, 최적화, 혁신 단계로 발전한다.

도입은 분석을 시작하는 단계,
활용은 특정 업무에서 분석을 사용하는 단계,
확산은 조직 전반으로 분석이 확대되는 단계,
최적화는 분석이 업무와 의사결정에 통합되는 단계,
혁신은 분석을 통해 새로운 가치를 창출하는 단계이다.
```

## 4) 분석 플랫폼

## 분석 플랫폼의 개념

**분석 플랫폼**은 데이터 수집, 저장, 처리, 분석, 시각화, 모델 운영을 지원하는 통합 환경이다.

분석 플랫폼이 있으면 분석가는 매번 분석 환경을 새로 만들 필요 없이,
조직이 공통으로 제공하는 환경에서 분석을 수행할 수 있다.

```markdown id="w0qrfn"
분석 플랫폼 = 데이터 분석을 수행하고 운영하기 위한 공통 기술 환경
```

---

## 분석 플랫폼의 주요 기능

| 기능     | 설명                      |
| ------ | ----------------------- |
| 데이터 수집 | 내부·외부 데이터를 수집           |
| 데이터 저장 | DW, 데이터마트, 데이터레이크 등에 저장 |
| 데이터 처리 | 정제, 변환, 통합, 전처리 수행      |
| 데이터 분석 | 통계 분석, 데이터 마이닝, 머신러닝 수행 |
| 시각화    | 대시보드, 리포트, 차트 제공        |
| 모델 운영  | 분석 모델 배포, 모니터링, 재학습 관리  |
| 보안 관리  | 접근 권한, 개인정보, 데이터 보안 관리  |

분석 플랫폼의 핵심은 분석 전 과정을 연결하는 것이다.

```markdown id="hjvml5"
분석 플랫폼은 데이터 수집부터 분석 결과 활용까지 지원하는 통합 환경이다.
```

# 02. 데이터 거버넌스

## 1) 데이터 거버넌스 개념

## 데이터 거버넌스의 정의

**데이터 거버넌스**란 조직의 데이터를 정확하고 안전하며 일관되게 관리하기 위한 정책, 절차, 조직, 시스템의 체계다.

분석 거버넌스가 분석 활동 전체를 관리하는 개념이라면,
데이터 거버넌스는 그중에서도 **데이터 자체의 관리**에 초점을 둔다.

```markdown id="2h3xnm"
데이터 거버넌스 = 데이터의 품질, 표준, 보안, 활용을 관리하는 체계
```

---

## 데이터 거버넌스가 필요한 이유

데이터가 많아져도 데이터 품질이 낮으면 좋은 분석을 할 수 없다.

예를 들어 다음과 같은 문제가 있으면 분석 결과를 신뢰하기 어렵다.

```markdown id="fc4uey"
같은 고객이 시스템마다 다른 ID로 관리된다.
부서마다 매출 기준이 다르다.
데이터에 결측치와 중복이 많다.
개인정보 접근 권한이 제대로 관리되지 않는다.
데이터의 출처와 의미를 알 수 없다.
```

따라서 데이터 거버넌스는 데이터의 신뢰성과 활용성을 높이기 위해 필요하다.

---

## 데이터 거버넌스 주요 관리 대상

| 관리 대상   | 설명                         |
| ------- | -------------------------- |
| 데이터 표준  | 용어, 코드, 형식, 기준을 통일         |
| 데이터 품질  | 정확성, 완전성, 일관성, 적시성 관리      |
| 메타데이터   | 데이터의 의미, 구조, 출처, 생성 기준 관리  |
| 데이터 보안  | 접근 권한, 개인정보, 암호화, 보안 정책 관리 |
| 데이터 흐름  | 데이터 생성, 이동, 저장, 활용 과정 관리   |
| 마스터 데이터 | 고객, 상품, 조직 등 핵심 기준 데이터 관리  |

시험에서는 이렇게 이해하면 된다.

```markdown id="qkq57d"
데이터 거버넌스는 데이터 표준, 품질, 메타데이터, 보안, 데이터 흐름, 마스터 데이터를 관리한다.
```

---

## 2) 데이터 거버넌스 구성 요소

## 구성 요소

데이터 거버넌스는 일반적으로 다음 요소로 구성된다.

| 구성 요소 | 설명                         |
| ----- | -------------------------- |
| 원칙    | 데이터를 어떻게 관리할 것인지에 대한 기본 방향 |
| 조직    | 데이터 관리 책임자와 담당 조직          |
| 프로세스  | 데이터 표준, 품질, 보안, 변경 관리 절차   |
| 정책    | 데이터 접근, 활용, 보안, 품질 관리 규칙   |
| 시스템   | 데이터 관리와 모니터링을 지원하는 도구      |
| 표준    | 데이터 용어, 코드, 형식, 메타데이터 기준   |

---

## 데이터 거버넌스 체계 요소

데이터 거버넌스 체계는 다음과 같은 요소로 운영된다.

| 체계 요소       | 설명                        |
| ----------- | ------------------------- |
| 데이터 표준화     | 용어, 코드, 도메인, 형식 등을 표준화    |
| 데이터 품질 관리   | 오류, 결측, 중복, 정합성 문제를 관리    |
| 메타데이터 관리    | 데이터의 의미, 구조, 출처, 이력을 관리   |
| 마스터 데이터 관리  | 고객, 상품, 조직 등 핵심 기준 데이터 관리 |
| 데이터 보안 관리   | 접근 권한, 개인정보, 암호화 등 보안 관리  |
| 데이터 생명주기 관리 | 생성, 저장, 활용, 폐기까지 전 과정 관리  |

---

### ① 데이터 표준화

데이터 표준화는 조직 내 데이터 용어, 코드, 형식, 규칙을 통일하는 것이다.

```markdown id="hwh9p3"
데이터 표준화 = 데이터 표현과 기준을 일관되게 맞추는 것
```

---

### ② 데이터 품질 관리

데이터 품질 관리는 데이터가 정확하고, 완전하고, 일관되며, 적시에 활용될 수 있도록 관리하는 것이다.

```markdown id="hrncvj"
데이터 품질 관리 = 신뢰할 수 있는 데이터를 유지하는 활동
```

---

### ③ 메타데이터 관리

메타데이터는 데이터에 대한 데이터다.

즉, 특정 데이터가 무엇을 의미하는지, 어디서 왔는지, 어떤 형식인지, 어떻게 생성되었는지를 설명하는 정보다.

```markdown id="ptxy74"
메타데이터 관리 = 데이터의 의미, 구조, 출처, 이력을 관리하는 것
```

---

### ④ 마스터 데이터 관리

마스터 데이터는 고객, 상품, 조직, 거래처처럼 조직 전체에서 공통으로 사용하는 핵심 기준 데이터다.

```markdown id="38kq82"
마스터 데이터 관리 = 조직의 핵심 기준 데이터를 일관되게 관리하는 것
```

---

### ⑤ 데이터 보안 관리

데이터 보안 관리는 데이터 접근 권한, 개인정보 보호, 암호화, 감사 로그 등을 관리하는 것이다.

```markdown id="m6fnzr"
데이터 보안 관리 = 데이터를 안전하게 보호하고 접근을 통제하는 것
```

---

### ⑥ 데이터 생명주기 관리

데이터 생명주기 관리는 데이터가 생성되고, 저장되고, 활용되고, 보관되며, 폐기되는 전 과정을 관리하는 것이다.

```markdown id="q1t5m1"
데이터 생명주기 관리 = 데이터의 생성부터 폐기까지 전 과정을 관리하는 것
```

---

## 데이터 거버넌스 암기

```markdown id="sbqhe3"
데이터 거버넌스는 데이터 표준화, 품질 관리, 메타데이터 관리,
마스터 데이터 관리, 보안 관리, 생명주기 관리를 통해
데이터를 일관되고 안전하며 신뢰할 수 있게 관리하는 체계이다.
```

## 3) 빅데이터 거버넌스 특징

## 빅데이터 거버넌스의 개념

**빅데이터 거버넌스**는 대용량, 다양한 유형, 빠른 속도로 생성되는 빅데이터를 효과적으로 관리하기 위한 거버넌스 체계다.

기존 데이터 거버넌스가 주로 정형 데이터와 내부 데이터를 관리했다면,
빅데이터 거버넌스는 비정형 데이터, 외부 데이터, 실시간 데이터까지 관리해야 한다.

---

## 빅데이터 거버넌스의 특징

| 특징             | 설명                            |
| -------------- | ----------------------------- |
| 대용량 데이터 관리     | 대규모 데이터를 저장, 처리, 관리해야 한다      |
| 다양한 데이터 유형     | 정형, 반정형, 비정형 데이터를 함께 관리한다     |
| 실시간성           | 빠르게 생성되는 데이터를 적시에 처리해야 한다     |
| 데이터 품질 다양성     | 출처와 형식이 다양해 품질 관리가 어렵다        |
| 개인정보와 보안 중요    | 대량의 개인·민감 정보가 포함될 수 있다        |
| 메타데이터 중요성 증가   | 데이터 의미와 출처를 관리해야 활용 가능성이 높아진다 |
| 데이터 생명주기 관리 필요 | 수집, 저장, 활용, 폐기 기준이 필요하다       |

시험에서는 이렇게 이해하면 된다.

```markdown id="pp84e6"
빅데이터 거버넌스는 대용량, 다양성, 실시간성, 비정형성, 보안 위험을 고려해 데이터를 관리하는 체계이다.
```

# 03. 소프트웨어 프로세스

소프트웨어 프로세스는 소프트웨어를 개발하고 유지보수하기 위한 활동과 절차를 의미한다.

ADsP에서는 데이터 분석 자체보다, 분석 시스템이나 분석 플랫폼을 구축할 때 필요한 **프로세스 품질 관리 개념**으로 이해하면 된다.

```markdown id="2ybce8"
소프트웨어 프로세스 = 소프트웨어 개발과 유지보수를 수행하기 위한 절차와 활동
```

---

# 1) 소프트웨어 프로세스 품질

## CMMI 모델 5단계

**CMMI**는 Capability Maturity Model Integration의 약자로,
조직의 소프트웨어 개발 프로세스 성숙도를 평가하는 모델이다.

CMMI는 조직의 프로세스가 얼마나 체계적이고 성숙하게 운영되는지 5단계로 구분한다.

| 단계  | 수준                             | 설명                      |
| --- | ------------------------------ | ----------------------- |
| 1단계 | Initial, 초기                    | 프로세스가 비정형적이고 개인 역량에 의존  |
| 2단계 | Managed, 관리                    | 프로젝트 단위로 일정, 비용, 품질을 관리 |
| 3단계 | Defined, 정의                    | 조직 차원의 표준 프로세스가 정의되고 적용 |
| 4단계 | Quantitatively Managed, 정량적 관리 | 프로세스를 측정하고 정량적으로 관리     |
| 5단계 | Optimizing, 최적화                | 지속적 개선을 통해 프로세스를 최적화    |

---

### CMMI 단계별 개념

```markdown id="7i9dus"
1단계 Initial = 개인 역량에 의존
2단계 Managed = 프로젝트 단위 관리
3단계 Defined = 조직 표준 프로세스 정의
4단계 Quantitatively Managed = 정량적 측정과 관리
5단계 Optimizing = 지속적 개선과 최적화
```

시험에서는 단계 순서가 중요하다.

```markdown id="d7s77d"
CMMI = 초기 → 관리 → 정의 → 정량적 관리 → 최적화
```

# 2) SPICE

## SPICE의 개념

**SPICE**는 Software Process Improvement and Capability dEtermination의 약자로,
소프트웨어 프로세스 개선과 수행 능력 평가를 위한 국제 표준 모델이다.

SPICE는 소프트웨어 프로세스를 범주별로 나누고, 각 프로세스의 수행 능력을 단계적으로 평가한다.

```markdown id="s98loh"
SPICE = 소프트웨어 프로세스 개선과 수행 능력 평가 모델
```

---

## SPICE의 5개 프로세스 범주

SPICE는 프로세스를 다음 5개 범주로 구분한다.

| 범주          | 설명                                |
| ----------- | --------------------------------- |
| 고객-공급자 프로세스 | 고객과 공급자 간 계약, 요구사항, 인수 관련 프로세스    |
| 공학 프로세스     | 요구사항 분석, 설계, 구현, 테스트 등 개발 관련 프로세스 |
| 지원 프로세스     | 품질보증, 형상관리, 검증, 문서화 등 지원 활동       |
| 관리 프로세스     | 프로젝트 관리, 품질 관리, 위험 관리 등 관리 활동     |
| 조직 프로세스     | 조직 차원의 프로세스 개선, 교육, 기반 구축         |

암기 방식은 다음과 같다.

```markdown id="s7y1w1"
SPICE 프로세스 범주 = 고객-공급자, 공학, 지원, 관리, 조직
```

---

## SPICE의 프로세스 수행 능력 단계

SPICE는 프로세스 수행 능력을 일반적으로 6단계로 구분한다.

| 단계  | 수준              | 설명                      |
| --- | --------------- | ----------------------- |
| 0단계 | Incomplete, 불완전 | 프로세스가 수행되지 않거나 목적 달성 실패 |
| 1단계 | Performed, 수행   | 프로세스가 수행되고 목적을 어느 정도 달성 |
| 2단계 | Managed, 관리     | 프로세스가 계획되고 관리됨          |
| 3단계 | Established, 확립 | 표준 프로세스가 정의되고 적용됨       |
| 4단계 | Predictable, 예측 | 프로세스가 측정되고 예측 가능하게 관리됨  |
| 5단계 | Optimizing, 최적화 | 지속적으로 개선됨               |

시험에서는 단계 순서를 암기해야 한다.

```markdown id="jiywfb"
SPICE = 불완전 → 수행 → 관리 → 확립 → 예측 → 최적화
```

# 3) ISO/IEC 12207

## ISO/IEC 12207의 개념

**ISO/IEC 12207**은 소프트웨어 생명주기 프로세스에 대한 국제 표준이다.

소프트웨어를 개발하고 운영하고 유지보수하는 전체 생명주기에서 필요한 프로세스를 정의한다.

```markdown id="2d33ia"
ISO/IEC 12207 = 소프트웨어 생명주기 프로세스 국제 표준
```

---

## ISO/IEC 12207 프로세스 종류

ISO/IEC 12207은 보통 다음 3가지 프로세스 종류로 정리한다.

| 프로세스 종류      | 설명                                    |
| ------------ | ------------------------------------- |
| 기본 생명주기 프로세스 | 소프트웨어 개발, 운영, 유지보수와 직접 관련된 핵심 프로세스    |
| 지원 생명주기 프로세스 | 품질보증, 검증, 확인, 형상관리, 문서화 등 지원 프로세스     |
| 조직 생명주기 프로세스 | 조직의 관리, 기반 구축, 프로세스 개선, 교육 훈련 관련 프로세스 |

---

### ① 기본 생명주기 프로세스

기본 생명주기 프로세스는 소프트웨어를 직접 개발하고 운영하는 핵심 활동이다.

| 프로세스 | 설명                      |
| ---- | ----------------------- |
| 획득   | 소프트웨어나 서비스를 외부에서 획득     |
| 공급   | 고객에게 소프트웨어나 서비스를 공급     |
| 개발   | 요구사항 분석, 설계, 구현, 테스트 수행 |
| 운영   | 소프트웨어를 실제 환경에서 운영       |
| 유지보수 | 오류 수정, 기능 개선, 변경 반영     |

```markdown id="x96ckx"
기본 생명주기 프로세스 = 획득, 공급, 개발, 운영, 유지보수
```

---

### ② 지원 생명주기 프로세스

지원 생명주기 프로세스는 개발과 운영이 제대로 수행되도록 돕는 활동이다.

대표적으로 품질보증, 검증, 확인, 형상관리 등이 있다.

```markdown id="1y3h98"
지원 생명주기 프로세스 = 품질보증, 검증, 확인, 형상관리, 문서화 등
```

---

### ③ 조직 생명주기 프로세스

조직 생명주기 프로세스는 조직 차원에서 소프트웨어 프로세스를 운영하고 개선하기 위한 활동이다.

대표적으로 관리, 기반 구조, 개선, 교육 훈련 등이 있다.

```markdown id="evge8k"
조직 생명주기 프로세스 = 관리, 기반 구조, 개선, 교육 훈련 등
```
