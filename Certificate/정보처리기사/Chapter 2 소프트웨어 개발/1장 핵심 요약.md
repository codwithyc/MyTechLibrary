## 028 자료 구조
### 1. 자료 구조의 분류
- 선형 구조 : 배열(Array), 선형 리스트(Linear List), 스택(Stack), 큐(Queue), 데크(Deque)
- 비선형 구조 : 트리(Tree), 그래프(Graph)

### 2. 연결 리스트(Linked List)
- 노드의 삽입﹒삭제 작업이 용이하다.
- 연결을 위한 링크(포인터) 부분이 필요하다.
- 연결을 위한 포인터를 찾는 시간이 필요하기 때문에 접근 속도가 느리다.
- 중간 노드의 연결이 끊어지면 그 다음 노드를 찾기 힘들다.

### 3. 스택(Stack)
- 리스트의 한쪽 끝으로만 자료의 삽입, 삭제 작업이 이루어지는 자료 구조이다.
- 스택은 가장 나중에 삽입된 자료가 가장 먼저 삭제되는 후입선출(LIFO) 방식으로 자료를 처리한다.
- 스택을 이용한 연산은 '재귀 호출, 후위(Postfix) 표기법, 깊이 우선 탐색'과 같이 왔던 길을 되돌아가는 경우에 사용한다.
- 스택의 모든 기억 공간이 꽉 채워져 있는 상태에서 데이터가 삽입되면 오버플로(Overflow)가 발생하며, 더이상 삭제할 데이터가 없는 상태에서 데이터를 삭제하면 언더플로(Underflow)가 발생한다.

### 4. 스택의 응용 분야
- 함수 호출의 순서 제어
- 인터럽트의 처리
- 수식 계산 및 수식 표기법
- 서브루틴 호출 및 복귀 주소 저장

### 5. 스택의 삽입(Push)과 삭제(Pop)
PUSH는 스택 자료에 자료를 입력하는 명령이고, POP은 스택에서 자료를 출력하는 명령이다.

예) 순서가 A, B, C, D로 정해진 입력 자료를 스택에 입력하였다가 B, C, D, A 순서로 출력하는 과정을 나열하시요

```Mermaid
flowchart LR
    S0["[ ]"]
    S1["[ A ]"]
    S2["[ A, B ]"]
    S3["[ A ]"]
    S4["[ A, C ]"]
    S5["[ A ]"]
    S6["[ A, D ]"]
    S7["[ A ]"]
    S8["[ ]"]

    S0 -->|"PUSH A"| S1
    S1 -->|"PUSH B"| S2
    S2 -->|"POP → B"| S3
    S3 -->|"PUSH C"| S4
    S4 -->|"POP → C"| S5
    S5 -->|"PUSH D"| S6
    S6 -->|"POP → D"| S7
    S7 -->|"POP → A"| S8
```

### 6. 큐(Queue)
- 리스트의 한쪽에서는 삽입 작업이 이루어지고 다른 한쪽에서는 삭제 작업이 이루어지도록 구성한 자료 구조이다.
- 큐는 가장 먼저 삽입된 자료가 가장 먼저 삭제되는 선입선출(FIFO) 방식으로 처리한다.

### 7. 데크(Deque)
- 삽입과 삭제가 리스트의 양쪽 끝에서 모두 발생할 수 있는 자료구조이다.
- 입력이 한쪽에서만 발생하고 출력은 양쪽에서 일어날 수 있는 입력 제한과, 입력은 양쪽에서 일어나고 출력은 한 곳에서만 이루어지는 출력 제한이 있다.

### 8. 방향/무방향 그래프의 최대 간선 수
n개의 장점으로 구성된 무방향 그래프에서 최대 간선 수는 $$\frac{n(n-1)}{2}$$ 이고, 방향 그래프에서 최대 간선 수는 n(n-1)이다.

### 9. 인접행렬을 이용한 그래프 표현 방법
- 방향 그래프에서 $V_i V_j$ 관계를 나타내는 행렬의 원소를 $P_u$라 할 때, 방향 간선이 있으면 행렬의 $P_{ij}$ = 1, 없으면 $P_{ij}$ = 0 이다.
- 무방향 그래프에서 $V_i$와 $V_j$가 서로 인접하면 $P_{ij}$ = 1 인접하지 않으면 $P_{ij}$ = 0 이다.

## 029 트리(Tree)

### 1. 트리의 개요
트리는 정점(Node)과 선분(Branch)을 이용하여 사이클을 이루지 않도록 구성한 그래프의 특수한 형태입니다. 

```Mermaid
flowchart TD
    A((A))
    B((B))
    C((C))
    D((D))
    E((E))
    F((F))
    G((G))

    A --- B
    A --- C

    B --- D
    B --- E

    C --- F
    C --- G
```

- 디그리(Degree, 차수) : 각 노드에서 뻗어나온 가지의 수 

> 예 : A = 3, B = 2, C = 1, D = 3

- 단말 노드(Terminal Node) : 자식이 하나도 없는 노드, 즉 디그리가 0인 노드

> 예 : K, L, F, G, M, I, J

### 2. 트리의 운행법
> 예 : 다음 트리를 Inorder, Preorder, Postorder 방법으로 운행했을 떄 각 노드의 순서는?

#### Preorder 운행법의 방문 순서
1. Preorder는 Root -> Left -> Right이므로 A13이 된다.
2. 1은 B2E이므로 AB2E3이 된다.
3. 2은 DHI이므로 ABDHIE3이 된다.
4. 3은 CFG이므로 ABDHIECFG가 된다.

방문 순서 : ABDHIECFG

#### Inorder 운행법의 방문 순서
1. Inorder는 Left -> Root -> Right이므로 1A3이 된다.
2. 2은 HDI이므로 HDIBEA3이 된다.
3. 3은 FCG이므로 HIDIBEAFCG가 된다.

방문 순서 : HDIBEAFCG

#### Postorder 방문 순서
1. Postorder는 Left -> Right -> Root 이므로 13A가 된다.
2. 1은 2EB이므로 2EB3A 된다.
3. 2는 HID이므로 HIDEB3A가 된다.
4. 3은 FGC이므로 HIDEBFGCA가 된다.

방문 순서 : HIDEBEFGCA

### 3. 수식의 표기법
Infix로 표기된 수식에서 연산자를 해당 피연산자 두 개의 뒤(오른쪽)에 오도록 이동하면 Postfix가 된다.

`X = A / B * (C + D) + E -> X A B / C D + * E + =`

1. 연산 우선순위에 따라 괄호로 묶는다. (X = ((A / B) * (C + D)+ E))
2. 연산자를 해당 괄호의 뒤로 옮긴다.
3. 괄호를 제거한다.

## 030 정렬(Sort)

정렬(Sort)은 데이터를 특정 기준에 따라 **오름차순(Ascending)** 또는 **내림차순(Descending)**으로 재배열하는 작업입니다.

대표적인 정렬 알고리즘에는 **삽입 정렬, 선택 정렬, 버블 정렬, 퀵 정렬, 힙 정렬** 등이 있습니다.

---

### 1. 삽입 정렬(Insertion Sort)

삽입 정렬은 이미 정렬된 데이터 영역에 새로운 데이터를 **적절한 위치에 삽입**하면서 정렬하는 방식입니다.

```text
초기 상태
5  3  4  1

5에 3 삽입
3  5  4  1

3, 5 사이에 4 삽입
3  4  5  1

맨 앞에 1 삽입
1  3  4  5
```

#### 특징

* 두 번째 데이터부터 시작하여 앞의 데이터들과 비교합니다.
* 현재 데이터를 정렬된 영역의 적절한 위치에 삽입합니다.
* 데이터가 이미 어느 정도 정렬되어 있을 경우 효율적입니다.
* 구현이 간단하지만 데이터가 많으면 성능이 떨어집니다.

#### 시간 복잡도

| 구분 | 시간 복잡도   |
| -- | -------- |
| 최선 | (O(n))   |
| 평균 | (O(n^2)) |
| 최악 | (O(n^2)) |

---

### 2. 선택 정렬(Selection Sort)

선택 정렬은 정렬되지 않은 데이터 중에서 **가장 작은 값 또는 가장 큰 값을 선택하여 순서대로 배치**하는 방식입니다.

```text
초기 상태
5  3  4  1

최솟값 1 선택
1  3  4  5

나머지 중 최솟값 3 선택
1  3  4  5

나머지 중 최솟값 4 선택
1  3  4  5
```

#### 특징

* 정렬되지 않은 영역에서 최솟값을 찾습니다.
* 찾은 값을 정렬되지 않은 영역의 첫 번째 데이터와 교환합니다.
* 데이터의 상태와 관계없이 비교 횟수가 거의 일정합니다.
* 데이터 교환 횟수는 비교적 적습니다.

#### 시간 복잡도

| 구분 | 시간 복잡도   |
| -- | -------- |
| 최선 | (O(n^2)) |
| 평균 | (O(n^2)) |
| 최악 | (O(n^2)) |

비교 횟수는 다음과 같습니다.

[
\frac{n(n-1)}{2}
]

---

### 3. 버블 정렬(Bubble Sort)

버블 정렬은 **서로 인접한 두 데이터를 비교하여 순서가 잘못되어 있으면 교환**하는 과정을 반복하는 방식입니다.

```text
초기 상태
5  3  4  1

5와 3 비교
3  5  4  1

5와 4 비교
3  4  5  1

5와 1 비교
3  4  1  5

→ 가장 큰 값 5가 마지막으로 이동
```

이 과정을 반복하면 최종적으로 다음과 같이 정렬됩니다.

```text
1  3  4  5
```

#### 특징

* 인접한 두 데이터를 반복적으로 비교합니다.
* 큰 값이 뒤쪽으로 이동하는 모습이 거품이 올라오는 것과 비슷하여 버블 정렬이라고 합니다.
* 구현은 매우 간단하지만 데이터가 많을 경우 비효율적입니다.
* 비교와 교환이 많이 발생합니다.

#### 시간 복잡도

| 구분 | 시간 복잡도           |
| -- | ---------------- |
| 최선 | (O(n)) ※ 최적화된 경우 |
| 평균 | (O(n^2))         |
| 최악 | (O(n^2))         |

---

### 4. 퀵 정렬(Quick Sort)

퀵 정렬은 특정 데이터를 **피벗(Pivot)**으로 선택한 후, 피벗보다 작은 값과 큰 값을 나누어 정렬하는 **분할 정복(Divide and Conquer)** 방식의 정렬 알고리즘입니다.

```text
5  3  7  1  6  2  4
             ↑
          Pivot = 4
```

피벗을 기준으로 데이터를 분할합니다.

```text
피벗보다 작은 값    Pivot    피벗보다 큰 값

3  1  2             4        5  7  6
```

각 영역에서 다시 피벗을 선택하여 동일한 과정을 반복합니다.

```text
1  2  3  4  5  6  7
```

#### 특징

* 피벗을 기준으로 데이터를 두 영역으로 분할합니다.
* 분할된 영역을 다시 반복적으로 정렬합니다.
* 평균적으로 매우 빠른 정렬 알고리즘입니다.
* 피벗을 어떻게 선택하느냐에 따라 성능이 달라질 수 있습니다.
* 이미 정렬된 데이터를 잘못된 방식으로 피벗 선택하면 성능이 크게 저하될 수 있습니다.

#### 시간 복잡도

| 구분 | 시간 복잡도        |
| -- | ------------- |
| 최선 | (O(n \log n)) |
| 평균 | (O(n \log n)) |
| 최악 | (O(n^2))      |

---

### 5. 힙 정렬(Heap Sort)

힙 정렬은 데이터를 **힙(Heap) 자료구조**로 구성한 후, 루트 노드를 반복적으로 제거하면서 정렬하는 방식입니다.

오름차순 정렬에서는 일반적으로 **최대 힙(Max Heap)**을 사용합니다.

```text
        9
      /   \
     7     5
    / \   /
   3   1 2
```

최대 힙에서는 부모 노드가 자식 노드보다 크거나 같습니다.

```text
부모 ≥ 자식
```

루트의 최댓값을 제거하고 마지막 데이터와 교환한 후 다시 힙을 구성합니다.

```text
9 제거
↓
나머지 데이터를 다시 최대 힙으로 구성
↓
다음 최댓값 제거
↓
반복
```

최종적으로 정렬된 데이터를 얻습니다.

#### 특징

* 완전 이진 트리 형태의 힙 자료구조를 사용합니다.
* 최댓값이나 최솟값을 빠르게 찾을 수 있습니다.
* 최악의 경우에도 (O(n \log n))의 성능을 보장합니다.
* 퀵 정렬에 비해 평균적인 실제 수행 속도는 느릴 수 있지만 성능이 안정적입니다.

#### 시간 복잡도

| 구분 | 시간 복잡도        |
| -- | ------------- |
| 최선 | (O(n \log n)) |
| 평균 | (O(n \log n)) |
| 최악 | (O(n \log n)) |

---

### 정렬 알고리즘 비교

| 정렬    | 기본 원리             |            평균 |            최악 | 특징             |
| ----- | ----------------- | ------------: | ------------: | -------------- |
| 삽입 정렬 | 적절한 위치에 삽입        |      (O(n^2)) |      (O(n^2)) | 거의 정렬된 데이터에 유리 |
| 선택 정렬 | 최솟값을 선택하여 교환      |      (O(n^2)) |      (O(n^2)) | 교환 횟수가 적음      |
| 버블 정렬 | 인접한 데이터를 비교·교환    |      (O(n^2)) |      (O(n^2)) | 가장 단순한 정렬 방식   |
| 퀵 정렬  | 피벗을 기준으로 분할       | (O(n \log n)) |      (O(n^2)) | 평균적으로 매우 빠름    |
| 힙 정렬  | 힙을 이용해 최댓값·최솟값 추출 | (O(n \log n)) | (O(n \log n)) | 최악의 경우에도 성능 보장 |

### 핵심 정리

* **삽입 정렬** → 정렬된 영역의 적절한 위치에 데이터를 삽입
* **선택 정렬** → 가장 작은 데이터를 선택하여 앞으로 이동
* **버블 정렬** → 인접한 데이터를 계속 비교하여 교환
* **퀵 정렬** → 피벗을 기준으로 데이터를 분할하여 정렬
* **힙 정렬** → 힙 자료구조를 이용하여 최댓값 또는 최솟값을 반복적으로 추출

## 031 검색 - 이분 검색 / 해싱
### 1. 이분 검색(이진 검색)
- 반드시 순서화(정렬)된 파일이어야 검색할 수 있다.
- 비교 횟수를 거듭할 때마다 검색 대상이 되는 데이터의 수가 절반으로 줄어든다.
- 탐색 효율이 좋고 탐색 시가이 적게 소요된다.
- 중간 레코드 번호(M) : $$\frac{F + L}{2}$$

### 2. 주요 해식 함수
- 제산법(Division) : 레코드 키(K)를 해시표(Hash Table)의 크기보다 큰 수 중에서 가장 작은 소수(Prime, Q)로 나눈 나머지를 홈 주소로 삼는 방식
- 제곱법(Mid-Square) : 레코드 키 값(K)을 제곱한 후 그 중간 부분의 값을 홈 주소로 삼는 방식
- 폴딩법(Foliding) : 레코드 키 값(K)을 여러 부분으로 나눈 후 각 부분의 값을 홈 주소로 삼는 방식
- 숫자 분석법(Digit Analysis) : 키 값을 이루는 숫자의 분포를 분석하여 비교적 고른 자리를 필요한 만큼 태개서 홈 주소로 삼는 방식

### 3. 체이닝(Chaining)
Collision이 발생하면 버킷에 할 할당된 연결 리스트(Linked List)에 데이터를 저장하여 문제를 해결하는 방법이다.

## 032 데이터베이스 개요
### 1. DBMS의 필수 기능
- 정의 기능(Definition) : 모든 응용 프로그램들이 요구하는 데이터 구조를 지원하기 위해 데이터베이스에 저잦ㅇ될 데이터의 형(Type)과 구조에 대한 정의, 이용 방식, 제약 조건 등을 명시하는 기능
- 조작 기능(Manipulation) : 데이터 검색, 갱신, 삽입, 삭제 등을 체계적으로 처리하기 위해 사용자와 데이터베이스 사이의 인터페이스 수단으로 제공하는 기능
- 제어 기능(Control) : 데이터베이스를 접근하는 갱신, 삽입, 삭제 작업이 정확하게 수행되어 데이터의 무결성이 유지되도록 제어하는 기능

### 2. 스키마 3계층
- 외부 스키마 : 사용자나 응용 프로그래머가 각 개인의 입장에서 필요로 하는 데이터베이스의 논리적 구조를 정의한 것
- 개념 스키마 : 데이터베이스의 전체적인 논리적 구조로서, 개체 간의 관계와 제약 조건을 나타내고, 데이터베이스의 접근 권한, 보안 및 무결성 규칙에 권한 명세를 정의함
- 내부 스키마 : 데이터베이스의 입장에서 본 데이터베이스 구조로서, 실제로 데이터베이스에 저장될 레코드의 형식을 정의하고 저장 데이터 항목의 표현 방법, 내부 레코드의 물리적 순서 등을 나타냄
