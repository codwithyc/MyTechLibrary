## 030. Windows 시스템 - 작업 관리자 / 명령 프롬프트

### 1. 작업 관리자의 개요

작업 관리자는 **현재 실행 중인 앱과 프로세스, 시스템 자원 사용 현황을 확인하고 관리**하는 도구입니다.

- 실행 방법
  - **`Ctrl` + `Shift` + `Esc`** (바로 실행)
  - `Ctrl` + `Alt` + `Delete` → [작업 관리자]
  - 작업 표시줄 바로 가기 메뉴 → [작업 관리자]

#### 왜 작업 관리자가 필요할까?

프로그램이 응답하지 않으면 창을 닫을 수도, 종료할 수도 없습니다.

이때 운영체제 차원에서 **강제로 프로세스를 종료할 수단**이 필요합니다.

또한 컴퓨터가 갑자기 느려졌을 때,  
**무엇이 자원을 많이 쓰고 있는지 확인할 방법**도 필요합니다.

작업 관리자는 이 두 가지를 모두 담당하는 도구입니다.

---

### 2. 작업 관리자의 탭

| 탭 | 기능 |
| --- | --- |
| **프로세스** | 실행 중인 앱과 백그라운드 프로세스를 표시하고, **CPU·메모리·디스크·네트워크 사용률**을 보여 줍니다. [작업 끝내기]로 강제 종료할 수 있습니다. |
| **성능** | CPU, 메모리, 디스크, 네트워크(Wi-Fi), GPU의 사용 현황을 **그래프**로 표시합니다. |
| 앱 기록 | 앱별 리소스 사용 기록을 표시합니다. |
| **시작프로그램** | 부팅 시 자동 실행되는 프로그램을 **사용 / 사용 안 함** 으로 설정하고, **시작 시 영향**을 확인합니다. |
| 사용자 | 로그인한 사용자별 자원 사용량을 표시하고, 연결을 끊거나 로그오프할 수 있습니다. |
| 세부 정보 | 프로세스의 PID, 상태, 사용자 이름, 우선 순위 등 상세 정보를 표시합니다. |
| 서비스 | 실행 중인 서비스의 상태를 확인하고 시작·중지합니다. |

- [파일] → [새 작업 실행]에서 **프로그램을 실행하거나 Windows 탐색기를 다시 시작**할 수 있습니다.

#### 왜 "시작 시 영향"을 표시할까?

시작 프로그램이 많아지면 부팅이 느려집니다.  
하지만 어떤 프로그램이 얼마나 영향을 주는지는 사용자가 알 수 없습니다.

작업 관리자는 각 프로그램의 영향을 **높음 / 중간 / 낮음**으로 표시하여,  
**어떤 것부터 꺼야 효과가 큰지** 판단할 수 있게 해 줍니다.

#### 작업 관리자에서 할 수 없는 것

- 프로그램의 **설치와 제거**는 할 수 없습니다.
- **시스템 설정 변경**은 할 수 없습니다.
- 실행 중인 프로그램의 **내용을 편집할 수 없습니다.**

### 3. 명령 프롬프트(Command Prompt)

명령 프롬프트는 **명령어를 문자로 입력하여 작업을 수행하는 CUI 환경**입니다.

- 실행 방법
  - [실행(`⊞` + `R`)] → **`cmd`** 입력
  - [시작] → [Windows 시스템] → [명령 프롬프트]
- 종료 : **`exit`** 입력

#### 왜 GUI 시대에도 명령 프롬프트를 쓸까?

GUI는 직관적이지만, 다음과 같은 경우에는 한계가 있습니다.

- **같은 작업을 수십 번 반복**해야 할 때
- **정확한 옵션을 지정**해야 할 때
- **화면이 정상적으로 뜨지 않는 상황**에서 시스템을 복구해야 할 때

명령 프롬프트는 명령을 **글로 정확하게 지시**할 수 있고,  
여러 명령을 묶어 **배치 파일(`.BAT`)로 자동화**할 수도 있습니다.

---

### 4. 주요 명령어

| 명령어 | 기능 |
| --- | --- |
| `dir` | 현재 폴더의 파일과 하위 폴더 목록을 표시합니다. |
| `cd` | 현재 폴더를 변경합니다. |
| `md` (`mkdir`) | 폴더를 만듭니다. |
| `rd` (`rmdir`) | 폴더를 삭제합니다. |
| `copy` | 파일을 복사합니다. |
| `move` | 파일을 이동합니다. |
| `del` | 파일을 삭제합니다. (**휴지통을 거치지 않습니다.**) |
| `ren` | 파일 이름을 변경합니다. |
| `type` | 텍스트 파일의 내용을 표시합니다. |
| `cls` | 화면을 지웁니다. |
| `format` | 디스크를 포맷합니다. |
| `chkdsk` | 디스크의 오류를 검사합니다. |
| `systeminfo` | 시스템 정보를 표시합니다. |
| `tasklist` | 실행 중인 프로세스 목록을 표시합니다. |
| `taskkill` | 프로세스를 강제 종료합니다. |
| `exit` | 명령 프롬프트를 종료합니다. |

**네트워크 관련 명령어**

| 명령어 | 기능 |
| --- | --- |
| **`ipconfig`** | IP 주소, 서브넷 마스크, 기본 게이트웨이 등 **네트워크 설정 정보**를 표시합니다. |
| **`ping`** | 상대 컴퓨터와의 **연결 상태와 응답 시간**을 확인합니다. |
| **`tracert`** | 목적지까지 **거쳐 가는 경로**를 추적합니다. |
| `netstat` | 현재 연결된 네트워크 상태와 포트 정보를 표시합니다. |
| `nslookup` | 도메인 이름에 해당하는 IP 주소를 조회합니다. |
| `finger` | 특정 사용자의 정보를 확인합니다. |

#### 왜 `ping`과 `tracert`를 구분해서 쓸까?

네트워크 문제를 확인할 때 알아야 할 것은 두 가지입니다.

- **연결이 되는가?** → `ping`
- **어디에서 막히는가?** → `tracert`

`ping`은 목적지까지 통신이 되는지만 알려 주고,  
`tracert`는 **중간에 거쳐 가는 각 구간을 하나씩 보여 주므로**  
문제가 발생한 지점을 특정할 수 있습니다.

---

### 5. Windows PowerShell

- 명령 프롬프트보다 **기능이 확장된 명령줄 환경**입니다.
- 명령 프롬프트의 명령어를 대부분 사용할 수 있으며, 스크립트 작성과 시스템 관리 자동화에 강점이 있습니다.

---

### 한 줄 정리

작업 관리자는 **`Ctrl` + `Shift` + `Esc`** 로 실행하여 **프로세스 강제 종료와 자원 사용 현황 확인, 시작 프로그램 관리**를 수행하고,  
명령 프롬프트는 **`cmd`** 로 실행하며 **`ipconfig`(설정 확인), `ping`(연결 확인), `tracert`(경로 추적)** 가 대표적인 네트워크 명령어입니다.
