## 070. 멀티미디어 오디오 / 비디오 데이터

### 1. 오디오 데이터 형식

| 형식 | 특징 |
| --- | --- |
| **WAV** | Windows의 표준 오디오 형식입니다. **압축하지 않아 음질이 좋지만 파일 크기가 매우 큽니다.** |
| **MP3** | **MPEG-1 Layer 3** 방식의 **손실 압축** 형식입니다. 원본의 약 1/10 크기로 줄이면서도 음질 저하가 적습니다. |
| **MIDI** | 소리가 아닌 **연주 정보(악보)** 를 저장합니다. **용량이 매우 작지만 사람의 음성은 표현할 수 없습니다.** |
| **FLAC** | **무손실 압축** 형식으로, 음질 손실 없이 용량을 줄입니다. |
| **AAC** | MP3보다 압축 효율이 높은 손실 압축 형식입니다. |
| **WMA** | Microsoft가 개발한 오디오 형식입니다. |
| **OGG** | 특허 제약이 없는 개방형 손실 압축 형식입니다. |

#### 왜 MP3는 크기를 1/10로 줄여도 들을 만할까?

MP3는 **사람의 청각 특성**을 이용합니다.

- 사람이 들을 수 없는 주파수 대역의 소리
- 큰 소리에 가려 들리지 않는 작은 소리(마스킹 효과)

이런 정보를 **과감히 삭제**합니다.

즉, MP3는 "소리를 균등하게 줄이는" 것이 아니라  
**"어차피 못 듣는 부분을 골라내어 버리는" 방식**입니다.

그래서 데이터의 90%를 버려도 사람 귀에는 큰 차이가 없습니다.

#### 왜 MIDI에는 사람 목소리가 없을까?

MIDI는 **"어떤 악기로, 어떤 음을, 언제, 얼마나 세게 연주하라"** 는 명령만 저장합니다.

실제 소리는 재생하는 기기의 **음원(악기 소리 모음)** 에서 만들어집니다.

사람의 목소리는 악기처럼 정해진 음정과 음색으로 표현할 수 없으므로,  
MIDI로는 담을 수 없습니다.

같은 이유로, **재생 기기에 따라 소리가 다르게 들릴 수 있습니다.**

**오디오 파일 용량 계산**

`용량(byte) = 샘플링률(Hz) × 샘플링 비트 수 ÷ 8 × 채널 수 × 시간(초)`

예) 44,100Hz / 16bit / 스테레오(2채널) / 60초  
→ 44,100 × 16 ÷ 8 × 2 × 60 = 10,584,000 byte ≈ **약 10MB**

### 2. 비디오 데이터 형식

| 형식 | 특징 |
| --- | --- |
| **AVI** | Windows의 표준 동영상 형식입니다. 다양한 코덱을 담을 수 있는 **컨테이너 형식**입니다. |
| **MPEG** | 동영상 압축의 국제 표준 방식입니다. |
| **MP4** | MPEG-4 기반의 형식으로, 현재 가장 널리 사용됩니다. |
| **MOV** | Apple의 QuickTime 형식입니다. |
| **WMV** | Microsoft의 동영상 형식으로, 스트리밍에 적합합니다. |
| **ASF** | Microsoft의 스트리밍 전용 형식입니다. |
| **DivX** | MPEG-4 기반의 고압축 코덱입니다. |

**MPEG 규격**

| 규격 | 용도 |
| --- | --- |
| **MPEG-1** | 비디오 CD, MP3 오디오 |
| **MPEG-2** | DVD, 디지털 TV 방송 |
| **MPEG-4** | 인터넷 스트리밍, 모바일 영상 (낮은 대역폭에서도 효율적) |
| **MPEG-7** | 멀티미디어 **내용 검색**을 위한 메타데이터 표준 |
| **MPEG-21** | 멀티미디어 **유통과 저작권 관리**를 위한 표준 |

#### 왜 확장자와 코덱은 다른 개념일까?

`.avi`나 `.mp4`는 **컨테이너(그릇)** 입니다.  
그 안에 영상과 음성 데이터를 담아 두는 상자와 같습니다.

**코덱**은 그 안의 데이터를 **어떤 방식으로 압축했는지**를 나타냅니다.

같은 `.avi` 파일이라도 내부에 DivX, XviD, H.264 등 **서로 다른 코덱**이 쓰일 수 있습니다.

그래서

- 확장자가 같아도 **어떤 파일은 재생되고 어떤 파일은 안 되는** 현상이 생기고
- 이는 대부분 **해당 코덱이 설치되지 않았기 때문**입니다.

#### 왜 동영상은 압축이 반드시 필요할까?

압축하지 않은 영상의 용량을 계산해 보면 이유가 분명해집니다.

1920 × 1080 해상도, 24비트 컬러, 초당 30프레임이라면

- 한 프레임 : 1920 × 1080 × 3byte ≈ 6.2MB
- 1초 : 6.2MB × 30 ≈ **186MB**
- 2시간 영화 : 약 **1.3TB**

이 정도 용량은 저장도 전송도 불가능합니다.

동영상 압축은 다음 원리를 이용합니다.

- **공간적 중복 제거** : 한 화면 안에서 비슷한 색이 모여 있는 부분을 묶음
- **시간적 중복 제거** : 앞 프레임과 **달라진 부분만** 저장

특히 시간적 중복 제거가 핵심입니다.  
정지된 배경 앞에서 사람만 움직인다면, **배경은 다시 저장하지 않아도** 되기 때문입니다.

### 3. 스트리밍(Streaming)

- 파일을 **모두 내려받기 전에 재생을 시작**하는 기술입니다.
- 대표 형식 : ASF, WMV, RAM, MP4
- 인터넷 방송, VOD, 화상 회의 등에 사용됩니다.

#### 왜 스트리밍은 저장 공간을 차지하지 않을까?

스트리밍은 데이터를 **버퍼(임시 저장 공간)** 에 조금씩 받아 재생하고,  
**재생이 끝난 부분은 버립니다.**

즉, 파일 전체가 컴퓨터에 남지 않습니다.

이 때문에 **네트워크 속도가 느려지면 버퍼가 비어 영상이 멈추는 현상(버퍼링)** 이 발생합니다.

### 4. 오디오/비디오 관련 용어

| 용어 | 설명 |
| --- | --- |
| **코덱(CODEC)** | 압축(Coder)과 복원(Decoder)을 담당하는 기술입니다. |
| **프레임 레이트(fps)** | 1초에 표시되는 화면 수입니다. 높을수록 부드럽습니다. |
| **비트 레이트(bps)** | 1초에 처리되는 데이터 양입니다. 높을수록 품질이 좋고 용량이 큽니다. |
| **버퍼링(Buffering)** | 재생할 데이터를 미리 받아 두는 과정입니다. |
| **인코딩 / 디코딩** | 데이터를 압축(변환)하는 것과 복원하는 것입니다. |
| **샘플링** | 아날로그 신호를 디지털로 변환하는 과정입니다. |

---

### 한 줄 정리

**WAV는 무압축·고음질·대용량**, **MP3는 손실 압축(1/10)**, **MIDI는 연주 정보만 저장(음성 표현 불가)** 이며,  
동영상은 **앞 프레임과 달라진 부분만 저장**하는 방식으로 압축하고,  
**확장자(컨테이너)와 코덱은 서로 다른 개념**입니다.
