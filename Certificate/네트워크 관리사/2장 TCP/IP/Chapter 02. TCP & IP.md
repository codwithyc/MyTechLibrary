# TCP/IP 계층

## 2-1. TCP/IP의 정의와 구조

### 1) TCP/IP 정의와 유래

TCP/IP는 인터넷에서 컴퓨터들이 서로 통신하기 위해 사용하는 **표준 통신 프로토콜 집합**입니다.
여기서 TCP와 IP는 각각 다른 역할을 담당합니다.

1. TCP

   * Transmission Control Protocol의 약자입니다.
   * 데이터를 신뢰성 있게 전달하기 위한 전송 계층 프로토콜입니다.
   * 데이터의 순서 보장, 오류 제어, 흐름 제어, 재전송 등을 수행합니다.

2. IP

   * Internet Protocol의 약자입니다.
   * 데이터를 목적지까지 전달하기 위한 인터넷 계층 프로토콜입니다.
   * IP 주소를 사용하여 목적지를 구분하고, 패킷을 전달합니다.

TCP/IP는 원래 미국 국방성의 ARPANET에서 사용되던 통신 구조에서 발전하였고, 현재는 인터넷의 기본 통신 구조로 사용됩니다.

#### 한 줄 정리

```text
TCP/IP = 인터넷 통신을 위한 표준 프로토콜 집합
TCP = 신뢰성 있는 전송 담당
IP = 목적지까지 패킷 전달 담당
```

### 2) TCP/IP의 구조와 특징

TCP/IP는 OSI 7계층보다 단순하게 네트워크 통신 구조를 **4개의 계층**으로 나누어 설명합니다.

| 계층  | 이름         | 핵심 역할                  | 대표 프로토콜                    |
| --- | ---------- | ---------------------- | -------------------------- |
| 4계층 | 애플리케이션 계층  | 사용자에게 네트워크 서비스 제공      | HTTP, FTP, SMTP, DNS, DHCP |
| 3계층 | 전송 계층      | 종단 간 데이터 전송            | TCP, UDP                   |
| 2계층 | 인터넷 계층     | IP 주소 기반 경로 설정 및 패킷 전달 | IP, ICMP, ARP, RARP        |
| 1계층 | 네트워크 접근 계층 | 실제 네트워크 매체를 통한 데이터 전송  | Ethernet, Wi-Fi, PPP       |

1. TCP/IP의 특징

   * 인터넷에서 실제로 사용하는 통신 모델입니다.
   * OSI 7계층보다 구조가 단순합니다.
   * 각 계층이 독립적인 역할을 수행합니다.
   * 서로 다른 네트워크 환경에서도 통신할 수 있도록 설계되었습니다.
   * IP 주소를 기반으로 전 세계 네트워크 간 통신이 가능합니다.

#### 데이터 흐름

```text
송신 측
애플리케이션 계층
→ 전송 계층
→ 인터넷 계층
→ 네트워크 접근 계층

수신 측
네트워크 접근 계층
→ 인터넷 계층
→ 전송 계층
→ 애플리케이션 계층
```

#### 한 줄 정리

```text
TCP/IP 4계층 = 애플리케이션 계층, 전송 계층, 인터넷 계층, 네트워크 접근 계층
```

### 3) TCP/IP의 구조와 OSI 7계층의 비교

TCP/IP 4계층은 OSI 7계층과 완전히 1:1로 일치하지는 않지만, 역할 기준으로 아래처럼 대응할 수 있습니다.

| TCP/IP 4계층 | OSI 7계층                             | 핵심 역할                   |
| ---------- | ----------------------------------- | ----------------------- |
| 애플리케이션 계층  | 7계층 응용 계층<br>6계층 표현 계층<br>5계층 세션 계층 | 사용자 서비스, 데이터 표현, 세션 관리  |
| 전송 계층      | 4계층 전송 계층                           | 종단 간 통신, 포트 번호, TCP/UDP |
| 인터넷 계층     | 3계층 네트워크 계층                         | IP 주소 기반 패킷 전달, 라우팅     |
| 네트워크 접근 계층 | 2계층 데이터 링크 계층<br>1계층 물리 계층          | MAC 주소 기반 전송, 실제 신호 전송  |

#### OSI 7계층과 TCP/IP 4계층 차이

| 구분   | OSI 7계층              | TCP/IP 4계층    |
| ---- | -------------------- | ------------- |
| 성격   | 이론적 표준 모델            | 실제 인터넷 기반 모델  |
| 계층 수 | 7계층                  | 4계층           |
| 목적   | 네트워크 통신 과정을 세분화하여 설명 | 실제 인터넷 통신 구현  |
| 특징   | 계층 구분이 명확함           | 실용적이고 구현 중심적임 |
| 사용   | 학습, 표준 설명, 장애 분석     | 실제 인터넷 통신     |

#### 한 줄 정리

```text
OSI 7계층 = 통신 과정을 자세히 설명하는 이론 모델
TCP/IP 4계층 = 인터넷에서 실제로 사용하는 실용 모델
```

## 2-2. TCP/IP 4계층

### 1) 네트워크 접근 계층(Network Access Layer)

네트워크 접근 계층은 TCP/IP 모델의 가장 아래 계층입니다.
실제 네트워크 장비와 전송 매체를 통해 데이터를 전송하는 역할을 합니다.

OSI 7계층으로 보면 **물리 계층과 데이터 링크 계층**에 해당합니다.

1. 네트워크 접근 계층의 주요 역할

   * 데이터를 실제 네트워크 매체를 통해 전송합니다.
   * MAC 주소를 사용하여 같은 네트워크 안의 장치를 식별합니다.
   * 데이터를 프레임 단위로 전송합니다.
   * 케이블, 무선, 광섬유 등 물리적 전송 매체와 관련됩니다.
   * 오류 검출 기능을 수행할 수 있습니다.

| 구분        | 내용                                     |
| --------- | -------------------------------------- |
| TCP/IP 계층 | 네트워크 접근 계층                             |
| OSI 대응 계층 | 데이터 링크 계층, 물리 계층                       |
| 데이터 단위    | 프레임, 비트                                |
| 주소 체계     | MAC 주소                                 |
| 주요 역할     | 실제 네트워크 매체를 통한 데이터 전송                  |
| 관련 장비     | 랜카드, 스위치, 허브, 리피터, 무선 AP               |
| 대표 기술     | Ethernet, Wi-Fi, PPP, Token Ring, FDDI |

#### 네트워크 접근 계층에 포함되는 것

| 구분        | 포함 내용                                     |
| --------- | ----------------------------------------- |
| LAN 기술    | Ethernet, Fast Ethernet, Gigabit Ethernet |
| 무선 LAN    | Wi-Fi, IEEE 802.11                        |
| WAN 접속 기술 | PPP, HDLC, Frame Relay                    |
| 주소        | MAC 주소                                    |
| 장비        | 랜카드, 스위치, 허브, 리피터, 무선 AP                  |
| 전송 매체     | UTP 케이블, 광섬유, 동축 케이블, 무선 전파               |

#### 주요 개념

1. MAC 주소

   * 네트워크 장비에 부여된 물리적 주소입니다.
   * 같은 네트워크 안에서 장치를 식별하는 데 사용됩니다.

2. 프레임

   * 네트워크 접근 계층에서 사용하는 데이터 전송 단위입니다.
   * 상위 계층에서 내려온 패킷을 프레임으로 감싸서 전송합니다.

3. Ethernet

   * 가장 널리 사용되는 LAN 기술입니다.
   * MAC 주소를 기반으로 같은 네트워크 안에서 데이터를 전달합니다.

#### 한 줄 정리

```text
네트워크 접근 계층 = 실제 네트워크 매체를 통해 프레임을 전송하는 계층
```

### 2) 인터넷 계층(Internet Layer)

인터넷 계층은 데이터를 목적지까지 전달하기 위한 계층입니다.
IP 주소를 사용하여 목적지를 식별하고, 라우팅을 통해 패킷을 전달합니다.

OSI 7계층으로 보면 **네트워크 계층**에 해당합니다.

1. 인터넷 계층의 주요 역할

   * IP 주소를 기반으로 목적지를 식별합니다.
   * 데이터를 패킷 단위로 전송합니다.
   * 서로 다른 네트워크 간 통신을 가능하게 합니다.
   * 라우팅을 통해 목적지까지의 경로를 결정합니다.
   * 오류 보고와 네트워크 상태 확인에 필요한 기능을 제공합니다.

| 구분        | 내용                        |
| --------- | ------------------------- |
| TCP/IP 계층 | 인터넷 계층                    |
| OSI 대응 계층 | 네트워크 계층                   |
| 데이터 단위    | 패킷                        |
| 주소 체계     | IP 주소                     |
| 주요 역할     | 경로 설정, 패킷 전달              |
| 관련 장비     | 라우터, L3 스위치               |
| 대표 프로토콜   | IP, ICMP, ARP, RARP, IGMP |

#### 인터넷 계층의 주요 프로토콜

| 프로토콜 | 전체 이름                              | 핵심 역할                    |
| ---- | ---------------------------------- | ------------------------ |
| IP   | Internet Protocol                  | IP 주소를 기반으로 패킷을 목적지까지 전달 |
| ICMP | Internet Control Message Protocol  | 오류 보고와 네트워크 상태 확인        |
| ARP  | Address Resolution Protocol        | IP 주소를 MAC 주소로 변환        |
| RARP | Reverse ARP                        | MAC 주소를 IP 주소로 변환        |
| IGMP | Internet Group Management Protocol | 멀티캐스트 그룹 관리              |

#### IP

IP는 인터넷 계층의 핵심 프로토콜입니다.
출발지와 목적지의 IP 주소를 사용하여 패킷을 전달합니다.

1. IP의 특징

   * 비연결형 프로토콜입니다.
   * 패킷을 목적지까지 전달하는 역할을 합니다.
   * 신뢰성 보장은 하지 않습니다.
   * 패킷의 순서 보장, 재전송, 오류 복구는 전송 계층에서 담당합니다.

```text
IP = 목적지 주소를 보고 패킷을 보내는 프로토콜
```

#### ICMP

ICMP는 네트워크 통신 중 발생하는 오류를 알리거나, 네트워크 상태를 확인하는 데 사용됩니다.

1. ICMP의 특징

   * 오류 메시지를 전달합니다.
   * 네트워크 상태를 진단하는 데 사용됩니다.
   * ping 명령어에서 사용됩니다.

```text
ICMP = 오류 보고와 네트워크 상태 확인
```

#### ARP

ARP는 IP 주소를 MAC 주소로 변환하는 프로토콜입니다.
같은 네트워크 안에서 실제 데이터를 보내려면 IP 주소뿐 아니라 MAC 주소도 필요합니다.

```text
ARP = IP 주소 → MAC 주소
```

예를 들어 같은 LAN 안에서 `192.168.0.10`에게 데이터를 보내야 한다면, ARP를 통해 해당 IP를 가진 장비의 MAC 주소를 알아냅니다.

#### RARP

RARP는 ARP와 반대로 MAC 주소를 이용해 IP 주소를 알아내는 프로토콜입니다.

```text
RARP = MAC 주소 → IP 주소
```

현재는 DHCP가 널리 사용되기 때문에 RARP는 거의 사용되지 않습니다.

#### IGMP

IGMP는 멀티캐스트 그룹을 관리하기 위한 프로토콜입니다.
특정 그룹에 속한 장비들에게만 데이터를 전송할 때 사용됩니다.

```text
IGMP = 멀티캐스트 그룹 관리
```

#### 인터넷 계층 주요 개념

| 개념    | 설명                             |
| ----- | ------------------------------ |
| IP 주소 | 네트워크에서 장치를 식별하는 논리적 주소         |
| 패킷    | 인터넷 계층의 데이터 전송 단위              |
| 라우팅   | 목적지까지의 경로를 선택하는 과정             |
| 라우터   | 서로 다른 네트워크를 연결하고 패킷을 전달하는 장비   |
| TTL   | 패킷이 네트워크에서 무한히 순환하지 않도록 제한하는 값 |
| 서브넷   | 하나의 네트워크를 더 작은 네트워크로 나눈 것      |

#### 한 줄 정리

```text
인터넷 계층 = IP 주소를 기반으로 목적지까지 패킷을 전달하는 계층
```

```text
ARP = IP를 MAC으로 변환
RARP = MAC을 IP로 변환
ICMP = 오류 보고와 상태 확인
IGMP = 멀티캐스트 그룹 관리
```

### 3) 전송 계층(Transport Layer)

전송 계층은 송신 측과 수신 측의 프로그램 사이에서 데이터 전송을 담당합니다.
포트 번호를 사용하여 어떤 프로그램에게 데이터를 전달할지 구분합니다.

OSI 7계층으로 보면 **전송 계층**에 해당합니다.

1. 전송 계층의 주요 역할

   * 종단 간 데이터 전송을 담당합니다.
   * 포트 번호를 사용하여 응용 프로그램을 구분합니다.
   * TCP 또는 UDP를 사용합니다.
   * TCP는 신뢰성 있는 전송을 제공합니다.
   * UDP는 빠른 전송을 제공합니다.
   * 흐름 제어, 오류 제어, 혼잡 제어와 관련됩니다.

| 구분        | 내용          |
| --------- | ----------- |
| TCP/IP 계층 | 전송 계층       |
| OSI 대응 계층 | 전송 계층       |
| 데이터 단위    | 세그먼트, 데이터그램 |
| 주소 체계     | 포트 번호       |
| 주요 역할     | 종단 간 데이터 전송 |
| 대표 프로토콜   | TCP, UDP    |

#### TCP 헤더 구성

TCP는 신뢰성 있는 전송을 위해 다양한 제어 정보를 헤더에 포함합니다.

| TCP 헤더 필드             | 의미                          |
| --------------------- | --------------------------- |
| Source Port           | 송신 측 포트 번호                  |
| Destination Port      | 수신 측 포트 번호                  |
| Sequence Number       | 데이터 순서를 보장하기 위한 번호          |
| Acknowledgment Number | 다음에 받을 데이터 번호를 알려주는 확인 번호   |
| Header Length         | TCP 헤더의 길이                  |
| Control Flags         | 연결 설정, 종료, 확인 등에 사용하는 제어 비트 |
| Window Size           | 수신 가능한 데이터 크기, 흐름 제어에 사용    |
| Checksum              | 오류 검출                       |
| Urgent Pointer        | 긴급 데이터 위치 표시                |
| Options               | 추가 기능 정보                    |

#### TCP 주요 플래그

| 플래그 | 의미             | 역할            |
| --- | -------------- | ------------- |
| SYN | Synchronize    | 연결 설정 요청      |
| ACK | Acknowledgment | 수신 확인         |
| FIN | Finish         | 연결 종료 요청      |
| RST | Reset          | 연결 강제 종료      |
| PSH | Push           | 데이터를 즉시 전달 요청 |
| URG | Urgent         | 긴급 데이터 표시     |

#### UDP 헤더 구성

UDP는 단순하고 빠른 전송을 위해 헤더 구성이 간단합니다.

| UDP 헤더 필드        | 의미                 |
| ---------------- | ------------------ |
| Source Port      | 송신 측 포트 번호         |
| Destination Port | 수신 측 포트 번호         |
| Length           | UDP 헤더와 데이터의 전체 길이 |
| Checksum         | 오류 검출              |

#### TCP vs UDP 비교

| 구분     | TCP           | UDP                 |
| ------ | ------------- | ------------------- |
| 방식     | 연결형           | 비연결형                |
| 신뢰성    | 높음            | 낮음                  |
| 속도     | 상대적으로 느림      | 상대적으로 빠름            |
| 데이터 순서 | 순서 보장         | 순서 보장 없음            |
| 재전송    | 지원            | 지원하지 않음             |
| 흐름 제어  | 지원            | 지원하지 않음             |
| 혼잡 제어  | 지원            | 지원하지 않음             |
| 헤더 크기  | 비교적 큼         | 작음                  |
| 사용 예시  | 웹, 이메일, 파일 전송 | DNS, 스트리밍, 음성/영상 통화 |

#### TCP 3-Way Handshake

TCP는 데이터를 보내기 전에 연결을 설정합니다.
이 연결 설정 과정이 3-Way Handshake입니다.

```text
1. 클라이언트 → 서버 : SYN
2. 서버 → 클라이언트 : SYN + ACK
3. 클라이언트 → 서버 : ACK
```

```text
3-Way Handshake = TCP 연결 설정 과정
```

#### TCP 연결 종료

TCP 연결 종료는 보통 FIN과 ACK를 사용하여 진행됩니다.

```text
FIN → ACK → FIN → ACK
```

```text
TCP 연결 종료 = FIN과 ACK를 이용해 연결을 정리
```

#### 포트 번호

포트 번호는 하나의 컴퓨터 안에서 어떤 프로그램으로 데이터를 전달할지 구분하는 번호입니다.

| 포트 번호 범위      | 의미                        |
| ------------- | ------------------------- |
| 0 ~ 1023      | 잘 알려진 포트, Well-Known Port |
| 1024 ~ 49151  | 등록된 포트, Registered Port   |
| 49152 ~ 65535 | 동적 포트, Dynamic Port       |

#### 주요 포트 번호

| 서비스     | 프로토콜    | 포트 번호  |
| ------- | ------- | ------ |
| FTP 데이터 | TCP     | 20     |
| FTP 제어  | TCP     | 21     |
| SSH     | TCP     | 22     |
| Telnet  | TCP     | 23     |
| SMTP    | TCP     | 25     |
| DNS     | TCP/UDP | 53     |
| DHCP    | UDP     | 67, 68 |
| HTTP    | TCP     | 80     |
| POP3    | TCP     | 110    |
| IMAP    | TCP     | 143    |
| HTTPS   | TCP     | 443    |

#### 한 줄 정리

```text
전송 계층 = 포트 번호를 이용해 프로그램 간 데이터 전송을 담당하는 계층
```

```text
TCP = 신뢰성 중심
UDP = 속도 중심
```

### 4) 애플리케이션 계층(Application Layer)

애플리케이션 계층은 사용자가 네트워크 서비스를 이용할 수 있도록 제공하는 계층입니다.
TCP/IP 모델에서는 OSI 7계층의 응용 계층, 표현 계층, 세션 계층의 역할을 포함합니다.

1. 애플리케이션 계층의 주요 역할

   * 사용자에게 네트워크 서비스를 제공합니다.
   * 웹, 이메일, 파일 전송, 원격 접속, 도메인 조회 등의 기능을 제공합니다.
   * 데이터 표현, 암호화, 압축, 세션 관리 기능을 포함할 수 있습니다.
   * TCP 또는 UDP 기반으로 동작합니다.
   * 응용 프로그램과 가장 가까운 계층입니다.

| 구분        | 내용                                                         |
| --------- | ---------------------------------------------------------- |
| TCP/IP 계층 | 애플리케이션 계층                                                  |
| OSI 대응 계층 | 응용 계층, 표현 계층, 세션 계층                                        |
| 데이터 단위    | 데이터                                                        |
| 주요 역할     | 사용자에게 네트워크 서비스 제공                                          |
| 관련 기능     | 웹, 이메일, 파일 전송, 원격 접속, 도메인 조회                               |
| 대표 프로토콜   | HTTP, HTTPS, FTP, SMTP, POP3, IMAP, DNS, DHCP, SSH, Telnet |

#### TCP/IP 4계층의 주요 역할과 관련 개념

| TCP/IP 계층  | 주요 역할          | 관련 개념                      |
| ---------- | -------------- | -------------------------- |
| 애플리케이션 계층  | 사용자 서비스 제공     | HTTP, FTP, SMTP, DNS, DHCP |
| 전송 계층      | 프로그램 간 데이터 전송  | TCP, UDP, 포트 번호            |
| 인터넷 계층     | 네트워크 간 패킷 전달   | IP, ICMP, ARP, 라우팅         |
| 네트워크 접근 계층 | 실제 네트워크 매체로 전송 | Ethernet, Wi-Fi, MAC 주소    |

#### 애플리케이션 계층 관련 서비스

| 서비스       | 프로토콜   | 주요 역할                      |
| --------- | ------ | -------------------------- |
| 웹 서비스     | HTTP   | 웹 페이지 데이터 전송               |
| 보안 웹 서비스  | HTTPS  | 암호화된 웹 페이지 데이터 전송          |
| 파일 전송     | FTP    | 파일 업로드 및 다운로드              |
| 이메일 송신    | SMTP   | 이메일 전송                     |
| 이메일 수신    | POP3   | 이메일을 클라이언트로 내려받음           |
| 이메일 동기화   | IMAP   | 서버와 클라이언트 간 이메일 동기화        |
| 도메인 이름 변환 | DNS    | 도메인 이름을 IP 주소로 변환          |
| IP 자동 할당  | DHCP   | IP 주소, 게이트웨이, DNS 서버 자동 설정 |
| 원격 접속     | Telnet | 원격 접속, 암호화 없음              |
| 보안 원격 접속  | SSH    | 암호화된 원격 접속                 |

#### 주요 프로토콜별 정리

1. HTTP

   * 웹 브라우저와 웹 서버가 데이터를 주고받을 때 사용하는 프로토콜입니다.
   * 기본 포트 번호는 80번입니다.

2. HTTPS

   * HTTP에 보안 기능이 추가된 프로토콜입니다.
   * TLS를 사용하여 데이터를 암호화합니다.
   * 기본 포트 번호는 443번입니다.

3. FTP

   * 파일을 업로드하거나 다운로드할 때 사용하는 프로토콜입니다.
   * 제어 연결은 21번 포트, 데이터 연결은 20번 포트를 사용합니다.

4. SMTP

   * 이메일을 보낼 때 사용하는 프로토콜입니다.
   * 기본 포트 번호는 25번입니다.

5. POP3

   * 이메일 서버에서 클라이언트로 메일을 내려받을 때 사용하는 프로토콜입니다.
   * 기본 포트 번호는 110번입니다.

6. IMAP

   * 이메일을 서버에 보관하면서 여러 기기에서 동기화할 때 사용하는 프로토콜입니다.
   * 기본 포트 번호는 143번입니다.

7. DNS

   * 사람이 읽기 쉬운 도메인 이름을 IP 주소로 변환합니다.
   * 기본 포트 번호는 53번입니다.

8. DHCP

   * 클라이언트에게 IP 주소, 서브넷 마스크, 게이트웨이, DNS 서버 정보를 자동으로 할당합니다.
   * UDP 67번, 68번 포트를 사용합니다.

9. SSH

   * 암호화된 원격 접속을 제공합니다.
   * 기본 포트 번호는 22번입니다.

10. Telnet

    * 원격 접속을 제공하지만 암호화가 되지 않아 보안에 취약합니다.
    * 기본 포트 번호는 23번입니다.

#### 한 줄 정리

```text
애플리케이션 계층 = 사용자가 이용하는 네트워크 서비스를 제공하는 계층
```

```text
HTTP = 웹
FTP = 파일 전송
SMTP = 메일 송신
POP3/IMAP = 메일 수신
DNS = 도메인 이름을 IP로 변환
DHCP = IP 자동 할당
SSH = 보안 원격 접속
```

## TCP/IP 4계층 핵심 요약 표

| 계층  | 이름         | OSI 대응 계층 | 데이터 단위     | 주소/식별 정보    | 대표 프로토콜                    |
| --- | ---------- | --------- | ---------- | ----------- | -------------------------- |
| 4계층 | 애플리케이션 계층  | 7, 6, 5계층 | 데이터        | 서비스/응용 프로그램 | HTTP, FTP, SMTP, DNS, DHCP |
| 3계층 | 전송 계층      | 4계층       | 세그먼트/데이터그램 | 포트 번호       | TCP, UDP                   |
| 2계층 | 인터넷 계층     | 3계층       | 패킷         | IP 주소       | IP, ICMP, ARP, RARP, IGMP  |
| 1계층 | 네트워크 접근 계층 | 2, 1계층    | 프레임/비트     | MAC 주소      | Ethernet, Wi-Fi, PPP       |

## 계층별 핵심 암기

```text
네트워크 접근 계층 = MAC 주소, 프레임, Ethernet, Wi-Fi
인터넷 계층 = IP 주소, 패킷, 라우팅, ARP, ICMP
전송 계층 = 포트 번호, TCP, UDP
애플리케이션 계층 = HTTP, FTP, SMTP, DNS, DHCP
```

## 시험용 최종 암기

```text
TCP/IP 4계층 = 네트워크 접근 → 인터넷 → 전송 → 애플리케이션

네트워크 접근 = 실제 전송
인터넷 = IP 기반 경로 설정
전송 = TCP/UDP와 포트 번호
애플리케이션 = 사용자 서비스
```

```text
ARP = IP → MAC
RARP = MAC → IP
ICMP = 오류 보고와 상태 확인
TCP = 신뢰성 있는 연결형 전송
UDP = 빠른 비연결형 전송
DNS = 도메인 이름을 IP 주소로 변환
DHCP = IP 주소 자동 할당
```
