## 086. 프로시저(Procedure)
### 1. 프로시저(Procedure) 개요

프로시저(Stored Procedure)는 **자주 사용하는 SQL문이나 여러 개의 SQL 처리 절차를 하나의 이름으로 저장해 두고 필요할 때 호출하여 실행하는 데이터베이스 객체**이다.

반복되는 작업을 하나의 프로시저로 정의하면 SQL을 매번 작성하지 않고 재사용할 수 있다.

| 특징          | 설명                                  |
| ----------- | ----------------------------------- |
| **재사용성**    | 자주 사용하는 SQL 로직을 저장하여 반복 사용 가능       |
| **모듈화**     | 복잡한 SQL 로직을 하나의 단위로 구성              |
| **성능 향상**   | 반복적인 SQL 처리의 실행 효율을 높일 수 있음         |
| **보안성 향상**  | 사용자가 테이블에 직접 접근하지 않고 프로시저를 통해 접근 가능 |
| **유지보수 용이** | 공통 로직을 한 곳에서 관리 가능                  |

#### 기본 구조

```sql
CREATE PROCEDURE 프로시저명
AS
BEGIN
    SQL문;
END;
```

프로시저는 보통 다음과 같은 작업에 사용한다.

```text
데이터 조회
데이터 삽입
데이터 수정
데이터 삭제
여러 SQL문의 일괄 처리
조건문 / 반복문 처리
```

> **프로시저 = 여러 SQL 처리 과정을 하나로 묶어 저장한 프로그램**

---

### 2. 프로시저 생성 / 실행 / 제거

프로시저는 일반적으로 **생성 → 실행 → 제거**의 형태로 사용한다.

| 작업 | 명령어                | 의미           |
| -- | ------------------ | ------------ |
| 생성 | `CREATE PROCEDURE` | 새로운 프로시저를 생성 |
| 실행 | `EXECUTE` / `CALL` | 저장된 프로시저를 실행 |
| 제거 | `DROP PROCEDURE`   | 프로시저를 삭제     |

---

#### 프로시저 생성

프로시저를 생성할 때는 `CREATE PROCEDURE`를 사용한다.

```sql
CREATE PROCEDURE 프로시저명
AS
BEGIN
    SQL문;
END;
```

예를 들어 모든 학생을 조회하는 프로시저를 생성하면 다음과 같다.

```sql
CREATE PROCEDURE GET_STUDENT
AS
BEGIN
    SELECT *
    FROM STUDENT;
END;
```

```text
GET_STUDENT
    ↓
SELECT *
FROM STUDENT
    ↓
학생 전체 조회
```

---

#### 매개변수가 있는 프로시저

프로시저에는 값을 전달하기 위한 **매개변수(Parameter)**를 지정할 수도 있다.

예를 들어 특정 학번의 학생을 조회하는 프로시저는 다음과 같이 만들 수 있다.

```sql
CREATE PROCEDURE GET_STUDENT_BY_ID
    @STUDENT_ID INT
AS
BEGIN
    SELECT *
    FROM STUDENT
    WHERE STUDENT_ID = @STUDENT_ID;
END;
```

| 구성 요소               | 의미             |
| ------------------- | -------------- |
| `GET_STUDENT_BY_ID` | 프로시저 이름        |
| `@STUDENT_ID`       | 매개변수           |
| `INT`               | 매개변수의 데이터 타입   |
| `SELECT`            | 프로시저에서 수행할 SQL |

---

#### 프로시저 실행

생성된 프로시저를 실행할 때는 DBMS에 따라 `EXEC`, `EXECUTE`, `CALL` 등을 사용한다.

SQL Server 계열에서는 다음과 같이 사용한다.

```sql
EXEC GET_STUDENT;
```

또는

```sql
EXECUTE GET_STUDENT;
```

매개변수가 있는 경우:

```sql
EXEC GET_STUDENT_BY_ID 1;
```

MySQL에서는 일반적으로 `CALL`을 사용한다.

```sql
CALL GET_STUDENT();
```

```text
프로시저 호출
     ↓
저장된 SQL 실행
     ↓
결과 반환
```

---

#### 프로시저 제거

프로시저를 삭제할 때는 `DROP PROCEDURE`를 사용한다.

```sql
DROP PROCEDURE 프로시저명;
```

예:

```sql
DROP PROCEDURE GET_STUDENT;
```

프로시저 자체만 삭제되며, 프로시저가 사용하던 테이블이나 데이터가 자동으로 삭제되는 것은 아니다.

---

### 프로시저 처리 과정

```text
CREATE PROCEDURE
      ↓
프로시저 생성
      ↓
EXEC / CALL
      ↓
프로시저 실행
      ↓
DROP PROCEDURE
      ↓
프로시저 제거
```

### 핵심 정리

| 구분      | SQL                       |
| ------- | ------------------------- |
| 프로시저 생성 | `CREATE PROCEDURE`        |
| 프로시저 실행 | `EXEC`, `EXECUTE`, `CALL` |
| 프로시저 제거 | `DROP PROCEDURE`          |

> **CREATE PROCEDURE = 만든다 / EXEC·CALL = 실행한다 / DROP PROCEDURE = 삭제한다**

참고로 프로시저 문법은 **MySQL, Oracle, SQL Server 등 DBMS마다 조금씩 다르기 때문에**, 시험에서는 개념과 `CREATE PROCEDURE → EXECUTE/CALL → DROP PROCEDURE` 흐름을 중심으로 기억하면 됩니다.


## 087. 트리거(Triger)
### 1. 트리거(Trigger)의 개요

트리거(Trigger)는 **테이블이나 뷰에서 특정 이벤트가 발생했을 때 DBMS가 자동으로 실행하는 데이터베이스 객체**이다.

주로 데이터의 **무결성 유지, 변경 이력 기록, 관련 데이터 자동 처리** 등에 사용한다.

```text
INSERT / UPDATE / DELETE 발생
            ↓
       Trigger 감지
            ↓
      자동으로 실행
            ↓
관련 SQL 또는 로직 수행
```

| 특징         | 설명                                      |
| ---------- | --------------------------------------- |
| **자동 실행**  | 사용자가 직접 호출하지 않아도 특정 이벤트 발생 시 자동 실행      |
| **이벤트 기반** | `INSERT`, `UPDATE`, `DELETE` 등의 이벤트에 반응 |
| **무결성 유지** | 데이터 변경 시 규칙을 자동으로 적용할 수 있음              |
| **이력 관리**  | 데이터 변경 내용을 별도의 로그 테이블에 기록 가능            |
| **연쇄 처리**  | 한 테이블의 변경에 따라 다른 데이터를 자동으로 변경 가능        |

#### 프로시저와 트리거 비교

| 구분    | 프로시저(Procedure)  | 트리거(Trigger)                        |
| ----- | ---------------- | ----------------------------------- |
| 실행 방식 | 사용자가 직접 호출       | 이벤트 발생 시 자동 실행                      |
| 실행 명령 | `CALL`, `EXEC` 등 | 별도 호출 필요 없음                         |
| 주요 목적 | 반복적인 업무 처리       | 데이터 변경 감지 및 자동 처리                   |
| 실행 조건 | 사용자가 실행          | `INSERT`, `UPDATE`, `DELETE` 등의 이벤트 |

> **프로시저 = 호출해서 실행 / 트리거 = 이벤트가 발생하면 자동 실행**

---

### 2. 트리거의 구성

트리거는 기본적으로 **이벤트(Event), 조건(Condition), 동작(Action)**으로 구성된다.

이를 **ECA(Event-Condition-Action) 규칙**이라고 한다.

| 구성 요소         | 의미                 | 예                            |
| ------------- | ------------------ | ---------------------------- |
| **Event**     | 트리거를 발생시키는 사건      | `INSERT`, `UPDATE`, `DELETE` |
| **Condition** | 트리거 동작 여부를 판단하는 조건 | 특정 값 변경 여부                   |
| **Action**    | 조건을 만족했을 때 실행되는 작업 | 로그 기록, 데이터 변경                |

```text
Event
  ↓
이벤트 발생
INSERT / UPDATE / DELETE
  ↓
Condition
  ↓
조건 확인
  ↓
Action
  ↓
SQL 자동 실행
```

#### 주요 이벤트

| 이벤트      | 의미               |
| -------- | ---------------- |
| `INSERT` | 새로운 데이터가 삽입되었을 때 |
| `UPDATE` | 기존 데이터가 변경되었을 때  |
| `DELETE` | 기존 데이터가 삭제되었을 때  |

트리거는 실행 시점에 따라 `BEFORE`와 `AFTER`로도 구분할 수 있다.

| 실행 시점    | 의미                    |
| -------- | --------------------- |
| `BEFORE` | 데이터 변경 작업이 수행되기 전에 실행 |
| `AFTER`  | 데이터 변경 작업이 수행된 후 실행   |

```text
BEFORE TRIGGER
      ↓
INSERT / UPDATE / DELETE
      ↓
AFTER TRIGGER
```

#### OLD와 NEW

트리거에서는 변경 전과 변경 후의 데이터를 참조하기 위해 일반적으로 `OLD`와 `NEW`를 사용한다.

| 구분       | OLD       | NEW       |
| -------- | --------- | --------- |
| `INSERT` | 없음        | 새로 삽입되는 값 |
| `UPDATE` | 변경 전 값    | 변경 후 값    |
| `DELETE` | 삭제되는 기존 값 | 없음        |

예를 들어:

```sql
OLD.NAME
NEW.NAME
```

은 각각 **변경 전 이름과 변경 후 이름**을 의미한다.

---

### 3. 트리거의 생성 / 제거

트리거를 생성할 때는 `CREATE TRIGGER`, 제거할 때는 `DROP TRIGGER`를 사용한다.

| 작업     | 명령어              |
| ------ | ---------------- |
| 트리거 생성 | `CREATE TRIGGER` |
| 트리거 제거 | `DROP TRIGGER`   |

#### 트리거 생성

기본적인 형태는 다음과 같다.

```sql
CREATE TRIGGER 트리거명
실행시점 이벤트
ON 테이블명
FOR EACH ROW
BEGIN
    실행할 SQL문;
END;
```

MySQL에서 학생이 등록될 때 로그를 남기는 예시는 다음과 같다.

```sql
CREATE TRIGGER STUDENT_INSERT_TRIGGER
AFTER INSERT
ON STUDENT
FOR EACH ROW
BEGIN
    INSERT INTO STUDENT_LOG (
        STUDENT_ID,
        ACTION
    )
    VALUES (
        NEW.STUDENT_ID,
        'INSERT'
    );
END;
```

처리 과정은 다음과 같다.

```text
STUDENT에 INSERT 발생
        ↓
STUDENT_INSERT_TRIGGER 실행
        ↓
NEW.STUDENT_ID 확인
        ↓
STUDENT_LOG에 기록
```

---

#### UPDATE 트리거

학생의 이름이 변경되었을 때 이전 이름과 새로운 이름을 기록할 수 있다.

```sql
CREATE TRIGGER STUDENT_UPDATE_TRIGGER
AFTER UPDATE
ON STUDENT
FOR EACH ROW
BEGIN
    INSERT INTO STUDENT_LOG (
        STUDENT_ID,
        OLD_NAME,
        NEW_NAME
    )
    VALUES (
        NEW.STUDENT_ID,
        OLD.NAME,
        NEW.NAME
    );
END;
```

```text
홍길동 → 김철수

OLD.NAME → 홍길동
NEW.NAME → 김철수
```

---

#### DELETE 트리거

데이터가 삭제될 때 삭제된 정보를 기록할 수도 있다.

```sql
CREATE TRIGGER STUDENT_DELETE_TRIGGER
AFTER DELETE
ON STUDENT
FOR EACH ROW
BEGIN
    INSERT INTO STUDENT_LOG (
        STUDENT_ID,
        ACTION
    )
    VALUES (
        OLD.STUDENT_ID,
        'DELETE'
    );
END;
```

DELETE에서는 삭제되기 전 데이터를 참조하므로 `OLD`를 사용한다.

---

#### 트리거 제거

트리거를 삭제할 때는 `DROP TRIGGER`를 사용한다.

```sql
DROP TRIGGER 트리거명;
```

예:

```sql
DROP TRIGGER STUDENT_INSERT_TRIGGER;
```

트리거가 삭제되더라도 **트리거가 연결되어 있던 테이블의 데이터는 삭제되지 않는다.**

---

### 트리거 핵심 정리

| 항목                 | 내용                           |
| ------------------ | ---------------------------- |
| **Trigger**        | 특정 이벤트 발생 시 자동 실행            |
| **Event**          | `INSERT`, `UPDATE`, `DELETE` |
| **Condition**      | 실행 여부를 결정하는 조건               |
| **Action**         | 트리거가 수행할 작업                  |
| **BEFORE**         | 이벤트 수행 전 실행                  |
| **AFTER**          | 이벤트 수행 후 실행                  |
| **OLD**            | 변경 이전의 데이터                   |
| **NEW**            | 변경 이후의 데이터                   |
| **CREATE TRIGGER** | 트리거 생성                       |
| **DROP TRIGGER**   | 트리거 제거                       |

```text
INSERT → NEW
UPDATE → OLD + NEW
DELETE → OLD
```

시험에서는 특히 **`트리거 = 자동 실행`**, **`ECA = Event + Condition + Action`**, **`INSERT = NEW / DELETE = OLD / UPDATE = OLD + NEW`**를 묶어서 기억하면 됩니다.

## 088. 사용자 정의 함수
### 1. 사용자 정의 함수의 개요

사용자 정의 함수(User Defined Function, UDF)는 **사용자가 필요한 연산이나 처리 로직을 직접 정의하여 사용할 수 있도록 만든 함수**이다.

입력값을 받아 내부에서 특정 연산을 수행한 뒤 **결과값을 반환**하는 것이 기본적인 특징이다.

```text
입력값
  ↓
사용자 정의 함수
  ↓
연산 및 처리
  ↓
결과값 반환
```

| 특징               | 설명                                   |
| ---------------- | ------------------------------------ |
| **사용자 정의**       | 사용자가 필요한 기능을 직접 정의                   |
| **매개변수 사용**      | 함수에 값을 전달할 수 있음                      |
| **결과 반환**        | 실행 결과를 `RETURN`을 통해 반환               |
| **재사용 가능**       | 한 번 생성하면 여러 SQL문에서 반복 사용 가능          |
| **SQL문에서 호출 가능** | `SELECT`, `WHERE` 등의 SQL문 내부에서 사용 가능 |
| **모듈화**          | 반복되는 계산이나 로직을 하나의 함수로 구성             |

예를 들어 두 숫자를 더하는 기능을 함수로 정의하면 다음과 같은 개념이다.

```text
ADD_NUMBER(10, 20)
        ↓
     10 + 20
        ↓
       30
```

#### 프로시저와 사용자 정의 함수 비교

| 구분        | 프로시저(Procedure)  | 사용자 정의 함수(Function)         |
| --------- | ---------------- | --------------------------- |
| 주요 목적     | 일련의 작업 처리        | 값 계산 및 반환                   |
| 반환값       | 필수가 아님           | 일반적으로 반환값 필요                |
| 호출        | `CALL`, `EXEC` 등 | SQL 표현식에서 호출 가능             |
| SQL문 내 사용 | 제한적              | `SELECT`, `WHERE` 등에서 사용 가능 |
| 주요 특징     | 처리 중심            | 반환값 중심                      |

> **프로시저 = 작업을 수행 / 함수 = 값을 반환**

---

### 2. 사용자 정의 함수의 생성 / 실행 / 제거

사용자 정의 함수는 일반적으로 **생성 → 호출(실행) → 제거**의 과정으로 사용한다.

| 작업 | 명령어               | 의미            |
| -- | ----------------- | ------------- |
| 생성 | `CREATE FUNCTION` | 사용자 정의 함수를 생성 |
| 실행 | 함수명 호출            | 생성된 함수를 호출    |
| 제거 | `DROP FUNCTION`   | 사용자 정의 함수를 삭제 |

---

#### 사용자 정의 함수 생성

함수를 생성할 때는 `CREATE FUNCTION`을 사용한다.

기본적인 형식은 다음과 같다.

```sql
CREATE FUNCTION 함수명(매개변수)
RETURNS 반환자료형
BEGIN
    처리문;
    RETURN 반환값;
END;
```

예를 들어 두 숫자를 더하는 함수를 생성하면 다음과 같다.

```sql
CREATE FUNCTION ADD_NUMBER(
    NUM1 INT,
    NUM2 INT
)
RETURNS INT
BEGIN
    RETURN NUM1 + NUM2;
END;
```

각 구성 요소의 의미는 다음과 같다.

| 구성 요소             | 의미         |
| ----------------- | ---------- |
| `CREATE FUNCTION` | 함수 생성      |
| `ADD_NUMBER`      | 함수 이름      |
| `NUM1`, `NUM2`    | 입력 매개변수    |
| `RETURNS INT`     | 반환할 데이터 타입 |
| `RETURN`          | 결과값 반환     |

```text
NUM1 + NUM2
     ↓
   RETURN
     ↓
결과값 반환
```

---

#### 사용자 정의 함수 실행

생성된 함수는 일반적으로 `SELECT`문 등에서 호출한다.

```sql
SELECT ADD_NUMBER(10, 20);
```

결과:

```text
30
```

테이블의 속성을 매개변수로 전달할 수도 있다.

예를 들어 점수에 10점을 추가하는 함수를 만들었다고 가정하면,

```sql
SELECT NAME, ADD_NUMBER(SCORE, 10)
FROM STUDENT;
```

과 같이 사용할 수 있다.

함수는 조건절에서도 사용할 수 있다.

```sql
SELECT *
FROM STUDENT
WHERE ADD_NUMBER(SCORE, 10) >= 90;
```

---

#### RETURN

사용자 정의 함수에서는 `RETURN`을 이용하여 **함수의 실행 결과를 반환**한다.

```sql
RETURN NUM1 + NUM2;
```

처리 흐름은 다음과 같다.

```text
함수 호출
   ↓
매개변수 전달
   ↓
함수 내부 연산
   ↓
RETURN
   ↓
결과값 반환
```

---

#### 사용자 정의 함수 제거

생성된 함수를 삭제할 때는 `DROP FUNCTION`을 사용한다.

#### 기본 형식

```sql
DROP FUNCTION 함수명;
```

예:

```sql
DROP FUNCTION ADD_NUMBER;
```

함수를 삭제하더라도 **함수가 사용하던 테이블이나 데이터 자체가 삭제되는 것은 아니다.**

---

### 사용자 정의 함수 핵심 정리

| 구분                  | 내용             |
| ------------------- | -------------- |
| **사용자 정의 함수**       | 사용자가 직접 정의한 함수 |
| **CREATE FUNCTION** | 함수 생성          |
| **RETURNS**         | 반환할 데이터 타입 지정  |
| **RETURN**          | 결과값 반환         |
| **함수명(...)**        | 함수 호출          |
| **DROP FUNCTION**   | 함수 제거          |

```text
CREATE FUNCTION
      ↓
함수 생성
      ↓
함수명(매개변수)
      ↓
함수 실행
      ↓
RETURN
      ↓
결과 반환
      ↓
DROP FUNCTION
      ↓
함수 제거
```

핵심적으로 **`CREATE FUNCTION = 생성`, `RETURN = 값 반환`, `함수명() = 실행`, `DROP FUNCTION = 제거`** 로 기억하면 됩니다.


## 089. DBNS 접속 기술
### 1. JDBC(Java Database Connectivity)

JDBC는 **Java 프로그램에서 데이터베이스에 접속하고 SQL을 실행하기 위한 표준 API**이다.

Java 애플리케이션은 JDBC를 이용하여 MySQL, Oracle, PostgreSQL 등의 DBMS와 통신할 수 있다.

```text
Java Application
      ↓
     JDBC
      ↓
 JDBC Driver
      ↓
    DBMS
```

| 구성 요소               | 설명                            |
| ------------------- | ----------------------------- |
| `DriverManager`     | JDBC 드라이버를 관리하고 데이터베이스 연결을 생성 |
| `Connection`        | 데이터베이스와의 연결을 나타냄              |
| `Statement`         | SQL문을 실행                      |
| `PreparedStatement` | 매개변수를 사용하는 SQL문을 미리 준비하여 실행   |
| `ResultSet`         | SELECT문의 조회 결과를 저장            |

#### 기본 처리 과정

```text
1. JDBC Driver 준비
        ↓
2. DB 연결(Connection)
        ↓
3. SQL문 준비
        ↓
4. SQL 실행
        ↓
5. 결과 처리(ResultSet)
        ↓
6. 연결 종료
```

#### 예시

```java
Connection conn = DriverManager.getConnection(
    "jdbc:mysql://localhost:3306/test",
    "root",
    "password"
);

PreparedStatement pstmt =
    conn.prepareStatement(
        "SELECT * FROM student WHERE id = ?"
    );

pstmt.setInt(1, 1);

ResultSet rs = pstmt.executeQuery();
```

#### Statement와 PreparedStatement

| 구분               | `Statement` | `PreparedStatement` |
| ---------------- | ----------- | ------------------- |
| SQL 작성           | 문자열로 직접 작성  | `?`를 이용해 매개변수 지정    |
| 재사용              | 상대적으로 불리    | 반복 실행에 적합           |
| SQL Injection 대응 | 취약할 수 있음    | 안전하게 값 바인딩 가능       |
| 사용               | 단순 SQL      | 일반적으로 권장            |

> **JDBC = Java와 데이터베이스를 연결하는 표준 API**

---

### 2. ODBC(Open Database Connectivity)

ODBC는 **응용 프로그램이 DBMS의 종류에 관계없이 데이터베이스에 접근할 수 있도록 만든 표준 데이터베이스 연결 인터페이스**이다.

특정 프로그래밍 언어나 특정 DBMS에 종속되지 않는 것이 특징이다.

```text
Application
     ↓
    ODBC
     ↓
 ODBC Driver
     ↓
    DBMS
```

예를 들어 하나의 애플리케이션에서 각각의 ODBC 드라이버를 이용해 여러 DBMS에 연결할 수 있다.

```text
             ┌─ MySQL Driver  ─→ MySQL
Application ─┼─ Oracle Driver ─→ Oracle
             └─ SQL Server Driver → SQL Server
```

| 특징           | 설명                        |
| ------------ | ------------------------- |
| **DBMS 독립성** | 다양한 DBMS에 동일한 방식으로 접근 가능  |
| **표준 인터페이스** | 데이터베이스 접근 방식을 표준화         |
| **드라이버 사용**  | 각 DBMS에 맞는 ODBC Driver 필요 |
| **언어 독립성**   | 특정 프로그래밍 언어에 종속되지 않음      |

### JDBC와 ODBC 비교

| 구분     | JDBC                       | ODBC                       |
| ------ | -------------------------- | -------------------------- |
| 전체 이름  | Java Database Connectivity | Open Database Connectivity |
| 대상     | Java 애플리케이션                | 다양한 애플리케이션                 |
| 주요 특징  | Java 기반 DB 접근              | 범용 DB 접근 표준                |
| 드라이버   | JDBC Driver                | ODBC Driver                |
| 언어 종속성 | Java 중심                    | 특정 언어에 종속되지 않음             |

```text
JDBC → Java 중심
ODBC → 범용 데이터베이스 연결
```

---

### 3. MyBatis

MyBatis는 **Java 객체와 SQL 사이의 매핑을 지원하는 SQL Mapper 프레임워크**이다.

개발자가 SQL을 직접 작성하면서도 JDBC에서 반복적으로 작성해야 하는 연결, 매개변수 설정, 결과 매핑 등의 작업을 줄여준다.

```text
Java Application
      ↓
    MyBatis
      ↓
 작성한 SQL
      ↓
     JDBC
      ↓
     DBMS
```

#### JDBC와 비교

JDBC를 직접 사용하면 다음과 같은 처리가 필요하다.

```text
Connection 생성
     ↓
PreparedStatement 생성
     ↓
Parameter 설정
     ↓
SQL 실행
     ↓
ResultSet 처리
     ↓
Java 객체로 변환
     ↓
자원 반환
```

MyBatis에서는 이러한 반복 작업의 상당 부분을 프레임워크가 처리한다.

```text
Mapper 호출
    ↓
MyBatis가 SQL 실행
    ↓
결과를 객체로 매핑
```

#### Mapper 예시

```java
public interface StudentMapper {
    Student findById(Long id);
}
```

XML:

```xml
<select id="findById"
        resultType="Student">
    SELECT
        student_id,
        name,
        department
    FROM student
    WHERE student_id = #{id}
</select>
```

호출:

```java
Student student =
    studentMapper.findById(1L);
```

### 주요 특징

| 특징                   | 설명                             |
| -------------------- | ------------------------------ |
| **SQL 직접 작성**        | 개발자가 SQL을 직접 제어                |
| **객체 매핑**            | 조회 결과를 Java 객체로 자동 변환          |
| **파라미터 바인딩**         | Java 값을 SQL 파라미터에 연결           |
| **동적 SQL**           | 조건에 따라 SQL문을 동적으로 생성 가능        |
| **XML / Annotation** | SQL을 XML 또는 Annotation으로 정의 가능 |

### JDBC와 MyBatis 비교

| 구분       | JDBC  | MyBatis   |
| -------- | ----- | --------- |
| DB 연결 처리 | 직접 처리 | 대부분 자동 처리 |
| SQL 작성   | 직접 작성 | 직접 작성     |
| 파라미터 설정  | 직접 설정 | 자동 바인딩    |
| 결과 매핑    | 직접 구현 | 자동 매핑     |
| 반복 코드    | 많음    | 적음        |
| SQL 제어   | 높음    | 높음        |

> **MyBatis = SQL은 직접 작성하고, 반복적인 JDBC 처리는 줄여주는 SQL Mapper**

---

### 4. 동적 SQL(Dynamic SQL)

동적 SQL은 **실행 시점의 조건이나 입력값에 따라 SQL문의 일부가 동적으로 변경되는 SQL**이다.

검색 조건이 선택적으로 적용되는 경우에 많이 사용한다.

예를 들어 사용자가 이름을 입력했을 때만 이름 조건을 추가한다고 가정한다.

```sql
SELECT *
FROM student
WHERE 1 = 1
```

이름이 입력된 경우:

```sql
SELECT *
FROM student
WHERE 1 = 1
  AND name = '홍길동'
```

학과까지 입력된 경우:

```sql
SELECT *
FROM student
WHERE 1 = 1
  AND name = '홍길동'
  AND department = '컴퓨터공학과'
```

즉,

```text
입력 조건
   ↓
조건 확인
   ↓
필요한 SQL 구문만 추가
   ↓
SQL 실행
```

### MyBatis의 동적 SQL

MyBatis에서는 XML 태그를 이용하여 동적 SQL을 쉽게 작성할 수 있다.

#### if

특정 조건을 만족할 때만 SQL을 추가한다.

```xml
<select id="findStudents"
        resultType="Student">

    SELECT *
    FROM student

    WHERE 1 = 1

    <if test="name != null">
        AND name = #{name}
    </if>

    <if test="department != null">
        AND department = #{department}
    </if>

</select>
```

#### where

`WHERE`절을 자동으로 처리할 수 있다.

```xml
<select id="findStudents"
        resultType="Student">

    SELECT *
    FROM student

    <where>
        <if test="name != null">
            AND name = #{name}
        </if>

        <if test="department != null">
            AND department = #{department}
        </if>
    </where>

</select>
```

`<where>`는 필요한 경우에만 `WHERE`를 추가하고, 앞쪽의 불필요한 `AND`나 `OR`도 처리해 준다.

#### 주요 동적 SQL 태그

| 태그            | 역할                  |
| ------------- | ------------------- |
| `<if>`        | 조건에 따라 SQL 추가       |
| `<choose>`    | 여러 조건 중 하나를 선택      |
| `<when>`      | `choose` 내부의 조건     |
| `<otherwise>` | 조건이 모두 맞지 않을 때 실행   |
| `<where>`     | WHERE절 동적 생성        |
| `<set>`       | UPDATE문의 SET절 동적 생성 |
| `<foreach>`   | Collection을 반복 처리   |

#### foreach 예시

여러 개의 ID를 `IN` 조건으로 검색하는 경우이다.

```xml
<select id="findByIds"
        resultType="Student">

    SELECT *
    FROM student
    WHERE student_id IN

    <foreach
        collection="ids"
        item="id"
        open="("
        separator=","
        close=")">

        #{id}

    </foreach>

</select>
```

결과적으로 다음과 같은 SQL이 만들어질 수 있다.

```sql
SELECT *
FROM student
WHERE student_id IN (1, 2, 3);
```

### 핵심 비교

| 구분              | 역할                               |
| --------------- | -------------------------------- |
| **JDBC**        | Java에서 DB에 접근하기 위한 표준 API        |
| **ODBC**        | 다양한 환경에서 DB에 접근하기 위한 범용 표준 인터페이스 |
| **MyBatis**     | SQL과 Java 객체를 연결하는 SQL Mapper    |
| **Dynamic SQL** | 조건에 따라 SQL문을 동적으로 구성             |

```text
JDBC
→ Java ↔ DB 연결

ODBC
→ Application ↔ DB 범용 연결

MyBatis
→ Java 객체 ↔ SQL 매핑

Dynamic SQL
→ 조건에 따라 SQL 변경
```

시험에서는 특히 **`JDBC = Java DB 연결`, `ODBC = 범용 DB 연결`, `MyBatis = SQL Mapper`, `동적 SQL = 실행 조건에 따라 SQL이 변경`** 으로 구분하면 됩니다.
