### 1. 프로세스 조회 — `ps`

**옵션 스타일이 두 가지**입니다. 둘 다 알아야 합니다.

```bash
$ ps aux                    # ⭐ BSD 스타일 (하이픈 없음)
USER  PID %CPU %MEM   VSZ   RSS TTY STAT START TIME COMMAND
root    1  0.0  0.3 172400 13624 ?  Ss   09:00 0:03 /usr/lib/systemd/systemd

$ ps -ef                    # ⭐ System V 스타일 (PPID 포함)
UID   PID  PPID  C STIME TTY   TIME     CMD
root    1     0  0 09:00 ?     00:00:03 /usr/lib/systemd/systemd
```

| 열 | 의미 |
| --- | --- |
| **PID** | 프로세스 ID |
| **PPID** | **부모 PID** (`ps -ef`에만) |
| **%CPU / %MEM** | CPU·메모리 사용률 |
| **VSZ** | 가상 메모리 크기(KB) |
| **RSS** | **실제 물리 메모리(KB)** ⭐ |
| **TTY** | 터미널 (`?`=데몬) |
| **STAT** | 상태 |
| **TIME** | 누적 CPU 시간 |

#### 자주 쓰는 조합

```bash
$ ps -ef | grep nginx                        # 특정 프로세스 ⭐
$ ps -ef | grep [n]ginx                      # ⭐ grep 자기 자신 제외 트릭
$ ps aux --sort=-%cpu | head -6              # ⭐ CPU 상위
$ ps aux --sort=-%mem | head -6              # ⭐ 메모리 상위
$ ps -eo pid,ppid,ni,pri,stat,%cpu,%mem,comm # ⭐ 원하는 열만
$ ps -ef --forest                            # ⭐ 트리 형태
$ ps -u devuser                              # 특정 사용자
$ ps -C httpd                                # 명령어 이름으로
$ ps -eLf                                    # 스레드까지
$ ps -p 1234 -o etime,cmd                    # 실행 경과 시간
```

| 옵션 | 의미 |
| --- | --- |
| `a` | 다른 사용자 포함 |
| `u` | 사용자 중심 형식 |
| `x` | 터미널 없는 프로세스 포함 |
| **`-e`** | 모든 프로세스 |
| **`-f`** | **전체 형식 (PPID 포함)** |
| `-l` | 긴 형식 (PRI, NI) |
| **`-o`** | **출력 열 지정** ⭐ |
| `--sort` | 정렬 |

#### 프로세스 상태 (STAT)

| 기호 | 의미 |
| --- | --- |
| **`R`** | 실행 중 / 실행 대기 |
| **`S`** | 대기 (인터럽트 가능) |
| **`D`** | **대기 (인터럽트 불가)** — `kill -9`도 안 통함 ❗ |
| **`T`** | 중지됨 (`Ctrl+Z`) |
| **`Z`** | **좀비** |
| `s` | 세션 리더 |
| `+` | 포그라운드 |
| `<` / `N` | 높은 / 낮은 우선순위 |

```bash
# ⭐ 좀비 프로세스 찾기
$ ps -eo pid,ppid,stat,comm | awk '$3 ~ /^Z/'
  PID  PPID STAT COMMAND
 5678  1234 Z    myapp <defunct>
# → 부모(1234)를 종료해야 정리됨

# D 상태 프로세스 (I/O 대기)
$ ps -eo pid,stat,wchan,comm | awk '$2 ~ /D/'
```

### 3. 실시간 모니터링 — `top`

```bash
$ top
top - 06:25:15 up 5 days, load average: 4.25, 3.98, 2.75
Tasks: 215 total, 3 running, 212 sleeping, 0 stopped, 1 zombie
%Cpu(s): 25.3 us, 10.2 sy, 0.0 ni, 34.1 id, 30.2 wa, 0.0 hi, 0.2 si, 0.0 st
MiB Mem: 15884.5 total, 1234.2 free, 11245.1 used, 3405.2 buff/cache
```

#### CPU 지표 읽기 (매우 중요)

| 지표 | 의미 | 높으면 |
| --- | --- | --- |
| **`us`** | 사용자 프로세스 | **애플리케이션 연산 과다** |
| **`sy`** | 커널 | 시스템 호출·인터럽트 과다 |
| **`id`** | 유휴 | 여유로움 |
| **`wa`** | **I/O 대기** ⭐ | **디스크 병목** |
| `si` | 소프트 인터럽트 | 네트워크 부하 |
| `st` | 뺏긴 시간 | **가상화 호스트 과부하** |

#### 실행 중 단축키

| 키 | 기능 |
| --- | --- |
| **`P`** | **CPU 사용률순 정렬** ⭐ |
| **`M`** | **메모리 사용률순 정렬** ⭐ |
| `T` | 실행 시간순 |
| **`1`** | **CPU 코어별 표시** ⭐ |
| **`k`** | 프로세스 종료 |
| **`r`** | 우선순위 변경 |
| `u` | 특정 사용자만 |
| `c` | 전체 명령줄 표시 |
| `H` | 스레드 표시 |
| `f` | 표시 열 선택 |
| `W` | 설정 저장 |
| **`q`** | 종료 |

```bash
$ top -d 2                   # 2초 간격
$ top -u nginx               # 특정 사용자
$ top -p 1234,5678           # 특정 PID
$ top -b -n 1 > top.txt      # ⭐ 배치 모드 (스크립트·기록용)
$ htop                       # 더 편한 대체 도구
```

### 4. 프로세스 검색·종료

```bash
# 검색
$ pgrep nginx                       # PID만
$ pgrep -a nginx                    # ⭐ 명령줄까지
$ pgrep -u devuser                  # 사용자별
$ pgrep -f "python app.py"          # ⭐ 전체 명령줄로 매칭
$ pidof nginx                       # PID 조회

# 종료
$ kill 1234                         # ⭐ SIGTERM(15) — 기본
$ kill -15 1234
$ kill -9 1234                      # ⭐ SIGKILL — 강제 (최후 수단)
$ kill -HUP 1234                    # ⭐ 설정 다시 읽기
$ kill -l                           # 시그널 목록

$ pkill nginx                       # 이름으로
$ pkill -f "python app.py"          # ⭐ 정확한 매칭
$ pkill -u devuser                  # 사용자의 모든 프로세스
$ pkill -9 -f "myscript"
$ killall httpd                     # 같은 이름 전부
$ killall -9 httpd
```

#### 주요 시그널

| 번호 | 이름 | 의미 | 무시 가능 |
| --- | --- | --- | --- |
| **1** | **SIGHUP** | **설정 재읽기** (데몬) | 가능 |
| **2** | **SIGINT** | `Ctrl + C` | 가능 |
| 3 | SIGQUIT | `Ctrl + \` + 코어 덤프 | 가능 |
| **9** | **SIGKILL** | **강제 종료** | **불가** ❗ |
| **15** | **SIGTERM** | **정상 종료 (기본값)** | 가능 |
| 18 | SIGCONT | 재개 | 가능 |
| 19 | SIGSTOP | 강제 중지 | **불가** |
| **20** | **SIGTSTP** | `Ctrl + Z` | 가능 |

> **종료 순서 (실무 원칙)** ⭐
> ```bash
> $ sudo systemctl stop httpd     # ① 서비스는 systemctl로
> $ kill 1234                     # ② SIGTERM
> (몇 초 대기)
> $ kill 1234                     # ③ 한 번 더
> $ kill -9 1234                  # ④ 최후의 수단
> ```
> `kill -9`는 프로세스가 **신호를 받지도 못하고** 즉시 제거되어  
> 저장하지 않은 데이터·임시 파일·락 파일이 그대로 남습니다.

> **`D` 상태는 `kill -9`로도 안 죽습니다.**  
> 디스크·NFS I/O를 기다리는 중이라 시그널을 처리할 수 없기 때문입니다.  
> **저장장치나 네트워크 마운트 문제**를 봐야 합니다.

### 5. 우선순위 — `nice` / `renice`

```
NI 범위 :  -20  ←──────────→  +19
          (높은 우선순위)   (낮은 우선순위)
```

```bash
$ nice -n 10 ./backup.sh            # ⭐ 낮은 우선순위로 실행
$ sudo nice -n -5 ./critical.sh     # 높은 우선순위 (root만)
$ nice ./script.sh                  # 기본 +10

$ renice -n 5 -p 1234               # ⭐ 실행 중 변경
$ sudo renice -n -10 -p 1234        # 우선순위 높이기 (root)
$ renice -n 5 -u devuser            # 사용자의 모든 프로세스
$ renice -n 5 -g developers         # 그룹

$ ps -eo pid,ni,pri,comm | head
```

| 항목 | 값 |
| --- | --- |
| 범위 | **-20 ~ 19** |
| 기본값 | **0** |
| **작을수록** | **우선순위 높음** ⭐ |
| **음수 지정** | **root만 가능** |

> **이름의 유래** : "nice(친절한)" — 값이 **클수록 남에게 양보**하는 착한 프로세스.  
> 그래서 값이 클수록 우선순위가 **낮습니다.** 직관과 반대라 시험에 자주 나옵니다.

### 6. 잡 컨트롤 (백그라운드)

```bash
$ ./long_task.sh &          # ⭐ 백그라운드 실행
[1] 5678
 │    └── PID
 └── 작업 번호

$ jobs                      # ⭐ 작업 목록
[1]+  Running    ./long_task.sh &
[2]-  Stopped    vi report.txt

$ fg %1                     # ⭐ 포그라운드로
$ bg %2                     # 백그라운드에서 재개
$ fg                        # 가장 최근 작업

Ctrl + Z                    # ⭐ 일시 중지
Ctrl + C                    # 종료
```

#### 로그아웃 후에도 실행 유지

```bash
$ nohup ./task.sh &                 # ⭐ SIGHUP 무시
$ nohup ./task.sh > out.log 2>&1 &  # ⭐ 로그 지정

$ ./task.sh &
$ disown -h %1                       # 잡 목록에서 분리

$ setsid ./task.sh                   # 새 세션으로

# ⭐ 실무 권장 — tmux / screen
$ tmux new -s work
(작업)
Ctrl+B, D                            # 분리 (detach)
$ tmux attach -t work                # 다시 접속
$ tmux ls                            # 세션 목록

$ screen -S work
Ctrl+A, D
$ screen -r work
```

> **장시간 작업은 반드시 `tmux`나 `screen`을 쓰세요.**  
> 네트워크가 끊겨도 세션이 살아 있어 **다시 붙을 수 있습니다.**  
> `nohup`은 실행은 유지되지만 **화면을 다시 볼 수 없습니다.**

### 7. systemd 서비스 관리

```bash
# 기본 제어
$ sudo systemctl start httpd
$ sudo systemctl stop httpd
$ sudo systemctl restart httpd          # 중단 발생
$ sudo systemctl reload httpd           # ⭐ 무중단 (설정만 재읽기)
$ sudo systemctl reload-or-restart httpd

# 자동 시작
$ sudo systemctl enable httpd
$ sudo systemctl disable httpd
$ sudo systemctl enable --now httpd     # ⭐ 등록 + 즉시 시작
$ sudo systemctl mask httpd             # ⭐ 완전 차단 (start 불가)
$ sudo systemctl unmask httpd

# 상태 확인
$ systemctl status httpd                # ⭐
$ systemctl is-active httpd
$ systemctl is-enabled httpd
$ systemctl is-failed httpd

# 목록
$ systemctl list-units --type=service --state=running   # ⭐
$ systemctl list-unit-files --state=enabled
$ systemctl --failed                    # ⭐⭐ 실패한 서비스 (장애 점검 1순위)

# 의존 관계
$ systemctl list-dependencies httpd

# 유닛 파일
$ systemctl cat httpd                   # 내용 보기
$ sudo systemctl edit httpd             # ⭐ 오버라이드 (원본 유지)
$ sudo systemctl daemon-reload          # ⭐⭐ 유닛 수정 후 필수
```

> **`daemon-reload`를 빠뜨리면** systemd가 변경을 인식하지 못합니다.  
> 유닛 파일을 만들거나 수정한 뒤 **반드시 실행**해야 합니다.

> **`disable` vs `mask`**  
> `disable` : 자동 시작만 해제 → **수동 start는 가능**  
> `mask` : `/dev/null`로 링크 → **start 자체가 불가능** ⭐

#### 타깃 (런레벨)

```bash
$ systemctl get-default                          # ⭐ 현재 기본 타깃
$ sudo systemctl set-default multi-user.target   # ⭐ 텍스트 모드
$ sudo systemctl set-default graphical.target    # GUI
$ sudo systemctl isolate multi-user.target       # 즉시 전환
$ runlevel                                        # 구 방식 확인
```

| 런레벨 | 타깃 |
| --- | --- |
| 0 | `poweroff.target` |
| 1 | `rescue.target` |
| **3** | **`multi-user.target`** ⭐ |
| **5** | **`graphical.target`** ⭐ |
| 6 | `reboot.target` |

#### 부팅 분석

```bash
$ systemd-analyze                   # 부팅 총 시간
$ systemd-analyze blame | head      # ⭐ 서비스별 소요 시간
$ systemd-analyze critical-chain
$ systemd-cgtop                     # cgroup별 자원 사용
```

# ⭐ 가장 자주 쓰는 조합
$ journalctl -xeu httpd              # 설명 포함 + 마지막부터 + 서비스별

$ sudo journalctl --vacuum-size=500M

| **`-u`** | **서비스(유닛)별** |

| **`-p`** | 우선순위 필터 |
| **`-k`** | 커널 메시지 |
| `-x` | 설명 추가 |

### 9. 자원 사용 확인

#### 메모리

```bash
$ free -h                    # ⭐
              total  used   free  shared  buff/cache  available
Mem:           15Gi  11Gi  1.2Gi   128Mi       3.3Gi       3.1Gi
Swap:         2.0Gi  1.5Gi  512Mi

$ free -m                    # MB
$ free -h -s 2               # 2초마다 갱신
$ cat /proc/meminfo | head
$ vmstat 1 5                 # ⭐ 종합 (si/so로 스왑 확인)
```

> **`free`가 적다고 걱정할 필요 없습니다.**  
> 리눅스는 **남는 메모리를 디스크 캐시로 활용**합니다.  
> 실제로 봐야 할 것은 **`available`** 입니다.
>
> **`vmstat`의 `si`/`so`가 0이 아니면** 실제로 스와핑 중이므로 **메모리 부족**입니다. ⭐

#### 디스크

```bash
$ df -hT                     # ⭐ 파일시스템 사용량
$ df -i                      # ⭐ inode 사용량
$ du -sh /var                # ⭐ 디렉터리 크기
$ du -h --max-depth=1 /var | sort -rh | head    # ⭐ 큰 것부터
$ lsblk                      # ⭐ 블록 장치 트리
$ iostat -x 1 3              # ⭐ I/O 상세
$ sudo iotop -o              # ⭐ I/O 사용 프로세스
```

| `iostat` 지표 | 정상 기준 |
| --- | --- |
| **`%util`** | **80% 미만** (100%면 포화) |
| **`await`** | HDD 10ms / SSD 1ms 미만 |

#### CPU·부하

```bash
$ uptime                     # ⭐ Load Average
$ nproc                      # ⭐ CPU 코어 수
$ lscpu                      # CPU 상세
$ mpstat -P ALL 1 3          # 코어별 사용률
$ sar -u 1 3                 # CPU
$ sar -u                     # ⭐ 오늘 하루 추이
$ sar -u -s 03:00:00 -e 04:00:00     # ⭐ 특정 시간대 (과거 분석)
```

> **Load Average는 CPU 코어 수와 비교**해야 합니다. ⭐  
> 4코어에서 **4.0이면 100% 포화**, 8.0이면 과부하입니다.

#### `sar` — 과거 데이터 분석 ⭐

```bash
$ sudo dnf install sysstat
$ sudo systemctl enable --now sysstat

$ sar -u          # CPU
$ sar -r          # 메모리
$ sar -b          # I/O
$ sar -d          # 장치별 I/O
$ sar -n DEV      # 네트워크
$ sar -q          # Load Average
$ sar -W          # 스왑
$ sar -A          # 전부
$ sar -f /var/log/sa/sa15        # ⭐ 15일자 데이터
```

> **`top`은 지금만, `sar`는 과거를 봅니다.**  
> "어제 새벽에 왜 느렸는지"는 `sar` 없이는 알 수 없습니다.  
> **서버 구축 시 가장 먼저 켜야 할 도구** 중 하나입니다.

### 10. 프로세스 상세 추적

```bash
# 시스템 호출 추적
$ strace -p 1234                     # ⭐ 실행 중인 프로세스에 붙기
$ strace -c ls                       # 통계
$ strace -f -o out.txt ./app         # 자식까지, 파일 저장
$ strace -e trace=open,read ls       # 특정 호출만

# 라이브러리 호출
$ ltrace ./app

# 열린 파일·소켓 ⭐
$ lsof -p 1234                       # 프로세스가 연 파일
$ lsof -u devuser                    # 사용자별
$ lsof -i :80                        # ⭐ 포트를 쓰는 프로세스
$ lsof /var/log/messages             # 파일을 쓰는 프로세스
$ lsof | grep deleted                # ⭐ 삭제됐지만 열린 파일

# /proc 직접 조회
$ cat /proc/1234/status
$ cat /proc/1234/cmdline | tr '\0' ' '
$ ls -l /proc/1234/cwd               # 작업 디렉터리
$ ls -l /proc/1234/exe               # 실행 파일
$ ls -l /proc/1234/fd/               # ⭐ 열린 파일 디스크립터
$ cat /proc/1234/limits              # 자원 제한

# 프로파일링
$ sudo perf top
$ sudo perf record -a sleep 10 && sudo perf report
```

> **"프로세스가 멈춘 것 같다"** 는 상황에서 **`strace -p PID`** 가 가장 빠른 진단입니다.  
> 어떤 시스템 호출에서 대기 중인지 즉시 보입니다.

### 11. 자원 제한 — `ulimit`

```bash
$ ulimit -a                  # ⭐ 전체 확인
core file size       (blocks, -c) 0
open files                   (-n) 1024
max user processes           (-u) 15043

$ ulimit -n 4096             # ⭐ 열 수 있는 파일 수
$ ulimit -u 2048             # 프로세스 수
$ ulimit -c unlimited        # 코어 덤프 허용
$ ulimit -Hn                 # Hard 제한
$ ulimit -Sn                 # Soft 제한
```

| 옵션 | 대상 |
| --- | --- |
| **`-n`** | **열 수 있는 파일 수** ⭐ |
| **`-u`** | 최대 프로세스 수 |
| `-c` | 코어 덤프 크기 |
| `-f` | 파일 크기 |
| `-v` | 가상 메모리 |

```bash
# 영구 설정
$ sudo vi /etc/security/limits.conf
devuser  soft  nofile  4096
devuser  hard  nofile  8192
@developers  soft  nproc  2048

# ⭐ systemd 서비스는 limits.conf가 적용되지 않음
$ sudo systemctl edit httpd
[Service]
LimitNOFILE=65536
LimitNPROC=4096
```

> **"Too many open files"** 오류는 **`nofile` 제한 초과**입니다.  
> 웹·DB 서버는 기본값 1024가 부족한 경우가 많습니다.

### 12. 작업 예약 — `cron` / `at`

```bash
# crontab
$ crontab -e                 # ⭐ 편집
$ crontab -l                 # 목록
$ crontab -r                 # ❗전체 삭제 (주의)
$ sudo crontab -l -u devuser # 다른 사용자

# 형식: 분 시 일 월 요일 명령
0 3 * * *      /usr/local/bin/backup.sh      # 매일 새벽 3시
*/5 * * * *    /usr/local/bin/check.sh       # 5분마다
30 2 * * 0     /usr/local/bin/weekly.sh      # 매주 일요일 2:30
0 0 1 * *      /usr/local/bin/monthly.sh     # 매월 1일 자정
@reboot        /usr/local/bin/startup.sh     # 부팅 시

# at (일회성)
$ echo "/usr/local/bin/task.sh" | at 03:00
$ at now + 30 minutes
$ atq                        # ⭐ 예약 목록
$ atrm 5                     # 삭제
$ at -c 5                    # 내용 확인

# 로그 확인
$ sudo grep CRON /var/log/cron | tail    # ⭐
```

> **cron 실패의 90%는 PATH 문제**입니다.  
> cron은 **매우 제한된 환경**에서 실행되므로 **명령은 절대 경로**로 쓰세요. ⭐
> ```bash
> 0 3 * * * /usr/bin/mysqldump ... >> /var/log/backup.log 2>&1
> ```

### 14. 실무 진단 관용구

```bash
# ⭐ CPU 상위 프로세스
$ ps aux --sort=-%cpu | head -6

# ⭐ 메모리 상위 프로세스
$ ps aux --sort=-%mem | head -6

# ⭐ 좀비 프로세스
$ ps -eo pid,ppid,stat,comm | awk '$3 ~ /^Z/'

# ⭐ 특정 포트를 쓰는 프로세스
$ sudo lsof -i :80
$ sudo ss -tulnp | grep :80

# ⭐ 삭제됐지만 디스크를 점유 중인 파일 (df ≠ du)
$ sudo lsof | grep deleted

# ⭐ 실패한 서비스
$ systemctl --failed

# ⭐ 부팅 후 에러 로그
$ journalctl -p err -b --no-pager | head -20

# ⭐ 오래 실행 중인 프로세스
$ ps -eo pid,etime,cmd --sort=-etime | head

# ⭐ 특정 사용자의 프로세스 전부 종료
$ sudo pkill -u devuser

# ⭐ I/O를 많이 쓰는 프로세스
$ sudo iotop -o -b -n 1 | head

# ⭐ 시스템 부하 원인 종합 진단
$ uptime && echo "---" && \
  top -b -n 1 | head -5 && echo "---" && \
  free -h && echo "---" && \
  iostat -x 1 2 | tail -20
```

### 15. 명령어 요약

| 목적 | 명령어 |
| --- | --- |
| **프로세스 조회** | **`ps aux`**, **`ps -ef`**, `pstree -p` |
| **실시간 모니터링** | **`top`** (`P`=CPU, `M`=메모리) |
| **검색** | **`pgrep -a`**, `pidof` |
| **종료** | **`kill`(15)** → `kill -9`, `pkill -f` |
| **설정 재읽기** | **`kill -HUP`** |
| **우선순위** | **`nice`**, **`renice`** (작을수록 높음) |
| **백그라운드** | `&`, `jobs`, `fg`, `bg`, **`nohup`**, **`tmux`** |
| **서비스** | **`systemctl`** (`enable --now`, `reload`) |
| **유닛 수정 후** | **`systemctl daemon-reload`** |
| **로그** | **`journalctl -xeu`**, `-f`, `-p err` |
| **메모리** | **`free -h`**, `vmstat` |
| **디스크** | **`df -hT`**, **`df -i`**, `du -sh`, `iostat -x` |
| **부하** | **`uptime`**, `sar` |
| **과거 분석** | **`sar`** ⭐ |
| **추적** | **`strace -p`**, **`lsof`** |
| **자원 제한** | **`ulimit`**, `limits.conf` |
| **예약** | **`crontab -e`**, `at` |
| **커널 모듈** | **`lsmod`**, **`modprobe`** |
| **커널 파라미터** | **`sysctl`** |

### 한 줄 정리

프로세스는 **`ps aux`/`ps -ef`로 조회하고 `top`(`P`/`M`)으로 실시간 감시**하며,  
종료는 **SIGTERM(15) → 안 되면 SIGKILL(9)**, 설정 재읽기는 **`kill -HUP`**,  
서비스는 **`systemctl`(수정 후 `daemon-reload` 필수)** 로 관리하고,  
성능 진단은 **`uptime`(Load) → `top`(어느 자원) → `iostat`/`free`/`sar`(상세)** 순으로 좁혀 갑니다.
