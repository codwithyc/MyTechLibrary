# 1장 데이터 모델링의 이해

## 제1절 데이터 모델의 이해

* **현실 → DB 구조화** → 데이터 모델링
* **설계도** → 데이터 모델
* **큰 그림 / 업무 중심** → 개념적 모델링
* **정규화 / PK / FK / 속성** → 논리적 모델링
* **데이터타입 / 인덱스 / DBMS** → 물리적 모델링
* **사용자 관점** → 외부 스키마
* **DB 전체 구조** → 개념 스키마
* **저장 구조 / 파일 / 인덱스** → 내부 스키마
* **외부 ↔ 개념** → 논리적 독립성
* **개념 ↔ 내부** → 물리적 독립성
* **반복 저장** → 중복성
* **변경에 취약** → 비유연성
* **같은 데이터가 서로 다름** → 비일관성

## 제2절 엔터티

* **관리 대상의 종류** → 엔터티
* **실제 데이터 한 건** → 인스턴스
* **2개 이상 인스턴스** → 엔터티 특징
* **원래 존재** → 기본 엔터티
* **핵심 업무** → 중심 엔터티
* **업무 상세 기록** → 행위 엔터티

## 제3절 속성

* **대상을 설명하는 정보** → 속성
* **실제 들어간 값** → 속성값
* **들어갈 수 있는 값의 범위** → 도메인
* **원래 있는 정보** → 기본 속성
* **관리하려고 새로 만든 값** → 설계 속성
* **계산해서 만든 값** → 파생 속성
* **하나의 속성 = 하나의 값** → 속성 특징

## 제4절 관계

* **엔터티끼리 연결** → 관계
* **소속 / 존재 자체 연결** → 존재 관계
* **주문 / 수강 / 행동으로 연결** → 행위 관계
* **하나 ↔ 하나** → 1:1
* **하나 ↔ 여러 개** → 1:M
* **여러 개 ↔ 여러 개** → M:N
* **○** → 0 / 선택
* **|** → 1 / 필수
* **까치발** → N / 여러 개
* **○<** → 0개 이상
* **|<** → 1개 이상
* **관계명, 관계차수(Cardinality), 관계선택사양(Optionality)을 봅니다.**

## 제5절 식별자

* **데이터 구별 이름표** → 식별자
* **대표 식별자** → 주식별자
* **대표가 아닌 후보** → 보조식별자
* **같은 값 금지** → 유일성
* **최소한의 속성만** → 최소성
* **값 변경 최소화** → 불변성
* **NULL 금지** → 존재성
* **내 엔터티에서 생성** → 내부식별자
* **다른 엔터티에서 가져옴 / FK** → 외부식별자
* **속성 하나로 식별** → 단일식별자
* **여러 속성 조합** → 복합식별자
* **업무에서 원래 존재** → 본질식별자
* **시스템이 새로 생성** → 인조식별자

시험 직전에는 이것만 보면 됩니다:

```text
큰 그림 → 개념적
정규화 → 논리적
타입/인덱스 → 물리적

사용자 → 외부 스키마
전체 → 개념 스키마
저장 → 내부 스키마

관리 대상 → 엔터티
한 건 → 인스턴스
설명 정보 → 속성
연결 → 관계
구별 → 식별자

원래 있음 → 기본
업무 중심 → 중심
상세 기록 → 행위

원래 값 → 기본 속성
새로 만듦 → 설계 속성
계산함 → 파생 속성

유최불존
유일성 / 최소성 / 불변성 / 존재성
```

# 2장 데이터 모델과 SQL — 초간단 키워드 모음

## 제 1절 정규화

* **중복 제거 / 테이블 분리** → 정규화
* **INSERT 문제** → 삽입 이상
* **UPDATE 여러 건 수정** → 수정 이상
* **DELETE했는데 다른 정보도 사라짐** → 삭제 이상
* **A → B** → A가 B를 결정 / 함수적 종속
* **한 칸에 여러 값** → 1NF 위반
* **원자값 / 한 칸에 하나** → 1NF
* **복합키 일부 → 일반 속성** → 2NF 위반
* **부분 함수 종속 제거** → 2NF
* **일반 속성 → 일반 속성** → 3NF 위반
* **PK → 일반 → 일반** → 이행 함수 종속
* **이행 함수 종속 제거** → 3NF

```text
1NF → 한 칸에 하나
2NF → 키 일부에 기대지 마
3NF → 일반끼리 기대지 마
```

---

## 제 2절 관계와 조인의 이해

* **엔터티끼리 연결** → 관계
* **테이블 데이터를 붙여 조회** → JOIN
* **내 식별자** → PK
* **다른 테이블의 식별자 가져옴** → FK
* **1 : 1** → 하나 ↔ 하나
* **1 : M** → 하나 ↔ 여러 개
* **1 : M의 FK** → 보통 M쪽
* **M : N** → 중간 엔터티 필요
* **학생 ↔ 수강 ↔ 과목** → M:N 해소
* **`=`로 JOIN** → EQUI JOIN
* **`>`, `<`, `BETWEEN` 등** → NON-EQUI JOIN
* **JOIN 조건 없음** → Cartesian Product
* **전부 × 전부** → Cartesian Product
* **N건 × M건** → N × M건

```text
관계 → 설계에서 연결
JOIN → SQL에서 연결

= → EQUI
범위/비교 → NON-EQUI
조건 없음 → 전부 × 전부
```

---

## 제 3절 모델이 표현하는 트랜잭션의 이해

* **하나의 업무 단위** → 트랜잭션
* **여러 작업을 하나로 묶음** → 트랜잭션
* **모두 성공 / 모두 실패** → 트랜잭션
* **계좌이체** → 대표적인 트랜잭션 예
* **작업 확정** → COMMIT
* **작업 취소 / 원상복구** → ROLLBACK
* **주문 + 주문상세 같이 처리** → 하나의 업무 흐름
* **일부만 성공** → 트랜잭션 관점에서 문제

```text
Transaction
→ 같이 처리
→ 같이 성공
→ 문제 생기면 같이 취소

COMMIT   → 확정
ROLLBACK → 취소
```

※ `필수/선택 관계`는 단순히 트랜잭션이 같은지 여부만으로 결정한다기보다 **해당 관계에 반드시 참여해야 하는지**를 함께 판단하면 됩니다.

---

## 제 4절 NULL 속성의 이해

* **값을 모름 / 미정 / 존재하지 않음** → NULL
* **숫자 0** → NULL 아님
* **공백** → NULL 아님
* **NULL 확인** → `IS NULL`
* **NULL 아님 확인** → `IS NOT NULL`
* **`= NULL`** → X
* **NULL + 숫자** → NULL
* **SUM / AVG / MIN / MAX** → NULL 제외
* **COUNT(컬럼)** → NULL 제외
* **COUNT(*)** → NULL 포함하여 행 수 계산

```text
NULL ≠ 0
NULL ≠ 공백

NULL 비교
→ IS NULL
→ IS NOT NULL
```

※ Oracle에서는 `''` 빈 문자열을 NULL처럼 취급한다는 점은 SQL 문제에서 따로 기억하면 됩니다.

---

## 제 5절 본질식별자 vs 인조식별자

* **업무에서 원래 존재하는 식별자** → 본질식별자
* **업무적 의미 있음** → 본질식별자
* **시스템이 새로 만든 ID** → 인조식별자
* **일련번호 / Sequence / Auto Increment** → 인조식별자
* **UUID** → 인조식별자로 사용 가능
* **관리 편의상 새로 생성** → 인조식별자

```text
본질식별자
→ 원래 업무에 있던 식별값

인조식별자
→ 시스템이 새로 만든 식별값
```

# 2장 시험 직전 초압축

```text
[정규화]
중복 제거 → 정규화
INSERT 문제 → 삽입 이상
UPDATE 문제 → 수정 이상
DELETE 문제 → 삭제 이상

1NF → 한 칸 하나
2NF → 복합키 일부 → 일반 X
3NF → 일반 → 일반 X


[관계/JOIN]
관계 → 설계 연결
JOIN → SQL 연결
PK → 내 번호
FK → 다른 테이블 번호
1:M → M쪽 FK
M:N → 중간 엔터티
= → EQUI
범위 → NON-EQUI
조건 없음 → Cartesian Product


[트랜잭션]
하나의 업무 단위 → Transaction
성공 확정 → COMMIT
작업 취소 → ROLLBACK
모두 성공 / 모두 실패


[NULL]
모름 / 미정 → NULL
NULL ≠ 0
NULL 비교 → IS NULL
NULL 연산 → NULL
COUNT(*) → 전체 행


[식별자]
업무에서 원래 존재 → 본질식별자
시스템이 새로 생성 → 인조식별자
```

특히 **2장에서는 `1NF → 2NF → 3NF`와 `PK/FK → JOIN` 두 축을 확실하게 잡는 게 핵심**입니다.
