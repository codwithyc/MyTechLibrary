# LINUX

## 1. LINUX 개요

### 개요

* **Linux는 Unix 계열의 오픈소스 운영체제**입니다.
* 일반적으로 Linux라고 부르는 것은 Linux 커널만을 의미하기도 하지만, 실제 사용 환경에서는 Linux 커널에 Shell, 명령어, 패키지 관리자, 파일 시스템, 네트워크 도구 등이 포함된 **Linux 배포판**을 의미하는 경우가 많습니다.
* 대표적인 Linux 배포판으로는 Ubuntu, Debian, CentOS, Rocky Linux, AlmaLinux, Fedora 등이 있습니다.
* Linux는 서버, 네트워크 장비, 클라우드, 임베디드 시스템, 보안 장비 등 다양한 환경에서 사용됩니다.
* 네트워크관리사 2급에서는 Linux를 **서버 운영체제**, **네트워크 서비스 운영 환경**, **파일 권한 관리 시스템** 관점에서 이해하는 것이 중요합니다.

```text
Linux 배포판
= Linux Kernel
+ Shell
+ 기본 명령어
+ 파일 시스템
+ 패키지 관리자
+ 네트워크 도구
+ 시스템 서비스
```

| 다중 사용자  | 여러 사용자가 동시에 시스템에 접속하여 사용할 수 있습니다.                           |

## 2. LINUX 구조

### 개요

* Linux는 사용자와 하드웨어 사이에서 Kernel, Shell, 응용 프로그램이 계층적으로 동작하는 구조입니다.
* 사용자는 직접 Kernel을 다루지 않고, Shell이나 응용 프로그램을 통해 Kernel에 작업을 요청합니다.
* Kernel은 CPU, 메모리, 디스크, 네트워크 카드 같은 하드웨어 자원을 관리합니다.

```text
사용자
 ↓
응용 프로그램
 ↓
Shell
 ↓
Kernel
 ↓
Hardware
```

---

### Linux 구조 구성 요소

| 구성 요소               | 설명                                            |
| ------------------- | --------------------------------------------- |
| 사용자 User            | 명령어를 입력하거나 프로그램을 실행하는 주체입니다.                  |
| 응용 프로그램 Application | vi, ssh, samba, apache, mysql 같은 사용자 프로그램입니다. |
| Shell               | 사용자의 명령어를 해석하여 Kernel에 전달하는 명령어 해석기입니다.       |
| Kernel              | 운영체제의 핵심으로 시스템 자원과 하드웨어를 관리합니다.               |
| Hardware            | CPU, 메모리, 디스크, 네트워크 카드 등 실제 장치입니다.            |

---

### Kernel

#### 개요

* **Kernel은 Linux 운영체제의 핵심 부분**입니다.
* 하드웨어와 소프트웨어 사이에서 중간 관리자 역할을 수행합니다.
* 사용자가 실행하는 프로그램은 직접 하드웨어를 제어하지 않고, Kernel을 통해 시스템 자원을 사용합니다.

#### Kernel의 주요 역할

| 역할        | 설명                                       |
| --------- | ---------------------------------------- |
| 프로세스 관리   | 실행 중인 프로그램의 생성, 종료, 우선순위, CPU 사용을 관리합니다. |
| 메모리 관리    | RAM을 어떤 프로세스에 얼마나 할당할지 관리합니다.            |
| 파일 시스템 관리 | 파일 읽기, 쓰기, 삭제, 저장장치 접근을 처리합니다.           |
| 장치 관리     | 디스크, 키보드, 마우스, 네트워크 카드 같은 장치를 제어합니다.     |
| 네트워크 관리   | TCP/IP 통신과 네트워크 인터페이스를 관리합니다.            |
| 시스템 호출 제공 | 프로그램이 Kernel 기능을 사용할 수 있도록 인터페이스를 제공합니다. |

---

### Shell

#### 개요

* **Shell은 사용자와 Kernel 사이에서 명령어를 해석하는 프로그램**입니다.
* 사용자가 입력한 명령어를 Kernel이 이해할 수 있는 요청으로 바꾸어 전달합니다.
* Linux 서버에서는 대부분 Shell을 통해 시스템을 관리합니다.

```text
사용자 명령 입력
→ Shell이 명령 해석
→ Kernel에 요청
→ Kernel이 처리
→ 결과 출력
```

#### Shell의 종류

| Shell | 설명                               |
| ----- | -------------------------------- |
| sh    | Unix 계열의 기본 Shell입니다.            |
| bash  | Linux에서 가장 많이 사용하는 대표 Shell입니다.  |
| zsh   | 자동완성, 플러그인 등 확장 기능이 강한 Shell입니다. |
| csh   | C 언어 문법과 유사한 Shell입니다.           |
| ksh   | Korn Shell로 Unix 환경에서 사용됩니다.     |

> 시험에서는 보통 **bash는 Linux의 대표적인 Shell** 정도로 기억하면 됩니다.

---

### Linux 디렉터리 구조

* Linux는 Windows처럼 `C:\`, `D:\` 드라이브 중심으로 관리하지 않습니다.
* Linux는 `/` 루트 디렉터리를 기준으로 모든 파일과 디렉터리가 하나의 트리 구조로 구성됩니다.

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── sbin
├── tmp
├── usr
└── var
```

---

### 주요 디렉터리

| 디렉터리     | 설명                                    |
| -------- | ------------------------------------- |
| `/`      | 최상위 루트 디렉터리입니다.                       |
| `/bin`   | 일반 사용자가 사용하는 기본 명령어가 저장됩니다.           |
| `/sbin`  | 시스템 관리자가 사용하는 관리 명령어가 저장됩니다.          |
| `/boot`  | 부팅에 필요한 커널과 부트로더 관련 파일이 저장됩니다.        |
| `/dev`   | 디스크, 터미널, 장치 파일이 저장됩니다.               |
| `/etc`   | 시스템 설정 파일이 저장됩니다.                     |
| `/home`  | 일반 사용자들의 홈 디렉터리가 위치합니다.               |
| `/root`  | root 관리자 계정의 홈 디렉터리입니다.               |
| `/lib`   | 프로그램 실행에 필요한 라이브러리가 저장됩니다.            |
| `/usr`   | 사용자 프로그램, 라이브러리, 문서 등이 저장됩니다.         |
| `/var`   | 로그, 메일, 캐시처럼 자주 변경되는 데이터가 저장됩니다.      |
| `/tmp`   | 임시 파일이 저장됩니다.                         |
| `/proc`  | 프로세스와 Kernel 정보를 제공하는 가상 파일 시스템입니다.   |
| `/mnt`   | 임시 마운트 지점으로 사용됩니다.                    |
| `/media` | USB, CD-ROM 같은 외부 장치가 자동 마운트되는 위치입니다. |
| `/opt`   | 추가 응용 프로그램이 설치되는 위치입니다.               |

---

### 정리

**Linux 구조는 사용자, Shell, Kernel, Hardware의 계층 구조로 이해할 수 있으며, Shell은 명령어를 해석하고 Kernel은 시스템 자원과 하드웨어를 관리합니다.**

## 3. LINUX 파일 시스템

### 개요

* Linux 파일 시스템은 `/` 루트 디렉터리를 기준으로 계층적으로 구성됩니다.
* Linux에서는 일반 파일뿐만 아니라 디렉터리, 장치, 프로세스 정보도 파일처럼 관리합니다.
* 따라서 Linux를 잘 사용하려면 파일 시스템 구조, 마운트, 권한 관리를 이해해야 합니다.

---

### Linux 파일 종류

`ls -l` 명령어를 실행하면 맨 앞 글자를 통해 파일 종류를 확인할 수 있습니다.

```bash
-rw-r--r--  1 user user  1000 May 12 memo.txt
drwxr-xr-x  2 user user  4096 May 12 docs
lrwxrwxrwx  1 user user    10 May 12 link -> memo.txt
```

| 맨 앞 문자 | 파일 종류    | 설명                          |
| ------ | -------- | --------------------------- |
| `-`    | 일반 파일    | 텍스트 파일, 실행 파일, 이미지 파일 등입니다. |
| `d`    | 디렉터리     | Windows의 폴더와 비슷한 개념입니다.     |
| `l`    | 심볼릭 링크   | 바로가기와 비슷한 파일입니다.            |
| `b`    | 블록 장치 파일 | 하드디스크 같은 블록 단위 장치입니다.       |
| `c`    | 문자 장치 파일 | 키보드, 터미널 같은 문자 단위 장치입니다.    |
| `p`    | 파이프      | 프로세스 간 통신에 사용됩니다.           |
| `s`    | 소켓       | 네트워크 통신에 사용됩니다.             |

---

### Linux 대표 파일 시스템

| 파일 시스템 | 설명                                   |
| ------ | ------------------------------------ |
| ext2   | 오래된 Linux 파일 시스템이며 저널링 기능이 없습니다.     |
| ext3   | ext2에 저널링 기능이 추가된 파일 시스템입니다.         |
| ext4   | 현재 Linux에서 많이 사용하는 대표 파일 시스템입니다.     |
| XFS    | 대용량 파일과 고성능 서버 환경에 적합한 파일 시스템입니다.    |
| Btrfs  | 스냅샷, 체크섬 등 고급 기능을 제공하는 파일 시스템입니다.    |
| swap   | 메모리가 부족할 때 디스크 일부를 메모리처럼 사용하는 영역입니다. |

> 시험에서는 **ext4는 Linux 대표 파일 시스템**, **swap은 메모리 보조 공간**으로 기억하면 됩니다.

## 3.1 파일 시스템 관리

### 마운트 Mount

#### 개요

* Linux에서 디스크나 파티션을 사용하려면 특정 디렉터리에 연결해야 합니다.
* 이 작업을 **마운트 Mount**라고 합니다.
* Windows는 드라이브 문자를 사용하지만, Linux는 디렉터리에 장치를 연결합니다.

```text
/dev/sdb1 디스크 장치
→ /data 디렉터리에 연결
→ /data 경로를 통해 디스크 사용
```

#### 마운트 명령어

```bash
mount /dev/sdb1 /data
```

#### 마운트 해제 명령어

```bash
umount /data
```

> 주의할 점은 명령어가 `unmount`가 아니라 **umount**입니다.

---

### 자동 마운트 설정

* 서버가 재부팅되어도 자동으로 디스크가 마운트되도록 하려면 `/etc/fstab` 파일을 설정합니다.

```text
/dev/sdb1   /data   ext4   defaults   0   0
```

| 항목          | 의미               |
| ----------- | ---------------- |
| `/dev/sdb1` | 마운트할 장치명입니다.     |
| `/data`     | 마운트할 디렉터리 위치입니다. |
| `ext4`      | 파일 시스템 형식입니다.    |
| `defaults`  | 기본 마운트 옵션입니다.    |
| `0`         | dump 백업 여부입니다.   |
| `0`         | fsck 검사 순서입니다.   |

---

### 디스크 사용량 확인

| 명령어    | 설명                        |
| ------ | ------------------------- |
| `df`   | 파일 시스템 전체 디스크 사용량을 확인합니다. |
| `du`   | 특정 파일이나 디렉터리의 사용량을 확인합니다. |
| `fsck` | 파일 시스템 오류를 검사하고 복구합니다.    |

#### 전체 디스크 사용량 확인

```bash
df -h
```

#### 특정 디렉터리 용량 확인

```bash
du -sh /var/log
```

#### 파일 시스템 검사

```bash
fsck /dev/sdb1
```

> `fsck`는 일반적으로 마운트가 해제된 상태에서 실행해야 안전합니다.

## 3.2 명령 프롬프트

### 개요

* Linux 명령 프롬프트는 현재 사용자, 호스트명, 현재 디렉터리, 권한 상태를 표시합니다.
* 일반 사용자는 `$`, root 관리자는 `#` 기호로 표시됩니다.

```bash
user@server:~$
root@server:/etc#
```

| 표시       | 의미                 |
| -------- | ------------------ |
| `user`   | 현재 로그인한 사용자입니다.    |
| `server` | 현재 시스템의 호스트명입니다.   |
| `~`      | 현재 사용자의 홈 디렉터리입니다. |

## 3.3 권한 관리

### 개요

* Linux는 파일과 디렉터리에 접근할 수 있는 권한을 엄격하게 관리합니다.
* 권한은 사용자, 그룹, 기타 사용자 기준으로 부여됩니다.
* 각 대상에게 읽기, 쓰기, 실행 권한을 줄 수 있습니다.

| 대상              | 설명                      |
| --------------- | ----------------------- |
| 사용자 User, Owner | 파일의 소유자입니다.             |
| 그룹 Group        | 파일의 소유 그룹입니다.           |
| 기타 Others       | 소유자와 그룹에 속하지 않은 사용자입니다. |

---

### 권한 표시 방식

```bash
-rwxr-xr--
```

이를 나누면 다음과 같습니다.

```text
-   rwx   r-x   r--
│    │     │     │
│    │     │     └─ 기타 사용자 권한
│    │     └─────── 그룹 권한
│    └───────────── 소유자 권한
└────────────────── 파일 종류
```

| 권한  | 의미         | 숫자 |
| --- | ---------- | -- |
| `r` | 읽기 Read    | 4  |
| `w` | 쓰기 Write   | 2  |
| `x` | 실행 Execute | 1  |
| `-` | 권한 없음      | 0  |

---

### 숫자 권한 계산

| 권한    | 계산        | 숫자 |
| ----- | --------- | -- |
| `r--` | 4         | 4  |
| `rw-` | 4 + 2     | 6  |
| `r-x` | 4 + 1     | 5  |
| `rwx` | 4 + 2 + 1 | 7  |
| `---` | 0         | 0  |

예시:

```bash
chmod 755 script.sh
```

`755`의 의미는 다음과 같습니다.

```text
7 = 소유자 rwx
5 = 그룹 r-x
5 = 기타 r-x
```

결과는 다음과 같습니다.

```text
-rwxr-xr-x
```

---

### 자주 사용하는 권한

| 숫자  | 문자          | 의미                        |
| --- | ----------- | ------------------------- |
| 777 | `rwxrwxrwx` | 모든 사용자가 읽기, 쓰기, 실행 가능     |
| 755 | `rwxr-xr-x` | 소유자는 모든 권한, 나머지는 읽기/실행 가능 |
| 700 | `rwx------` | 소유자만 모든 권한                |
| 644 | `rw-r--r--` | 소유자는 읽기/쓰기, 나머지는 읽기 가능    |
| 600 | `rw-------` | 소유자만 읽기/쓰기 가능             |
| 400 | `r--------` | 소유자만 읽기 가능                |

> `777`은 모든 사용자가 수정할 수 있으므로 보안상 매우 위험합니다.

---

### 권한 관리 명령어

| 명령어     | 설명                     |
| ------- | ---------------------- |
| `chmod` | 파일 또는 디렉터리 권한을 변경합니다.  |
| `chown` | 파일 또는 디렉터리 소유자를 변경합니다. |
| `chgrp` | 파일 또는 디렉터리 그룹을 변경합니다.  |

#### chmod

```bash
chmod 755 file.sh
chmod 644 memo.txt
```

기호 방식도 사용할 수 있습니다.

```bash
chmod u+x script.sh
chmod g-w file.txt
chmod o+r file.txt
```

| 기호  | 의미            |
| --- | ------------- |
| `u` | 사용자 Owner     |
| `g` | 그룹 Group      |
| `o` | 기타 사용자 Others |
| `a` | 전체 All        |
| `+` | 권한 추가         |
| `-` | 권한 제거         |
| `=` | 권한 지정         |

#### chown

```bash
chown user file.txt
chown user:group file.txt
```

#### chgrp

```bash
chgrp developers memo.txt
```

---

### 파일 권한과 디렉터리 권한의 차이

| 권한  | 파일에서 의미            | 디렉터리에서 의미                |
| --- | ------------------ | ------------------------ |
| `r` | 파일 내용을 읽을 수 있습니다.  | 디렉터리 목록을 볼 수 있습니다.       |
| `w` | 파일 내용을 수정할 수 있습니다. | 디렉터리 안에 파일 생성/삭제가 가능합니다. |
| `x` | 파일을 실행할 수 있습니다.    | 디렉터리 안으로 진입할 수 있습니다.     |

> 디렉터리에서 `x` 권한이 없으면 해당 디렉터리 안으로 들어갈 수 없습니다.

---

### 정리

**Linux 파일 시스템은 `/` 루트 디렉터리를 기준으로 계층 구조를 가지며, 파일과 디렉터리는 사용자, 그룹, 기타 사용자 기준으로 r, w, x 권한을 부여하여 관리합니다.**

## 6.1 프로세스

### 개요

* **프로세스는 실행 중인 프로그램**입니다.

## 6.3 RPM

### 개요

* **RPM은 Red Hat Package Manager의 약어**입니다.
* Red Hat 계열 Linux에서 사용하는 패키지 관리 형식이자 명령어입니다.
* RPM 패키지 파일은 보통 `.rpm` 확장자를 가집니다.
* RHEL, CentOS, Rocky Linux, AlmaLinux, Fedora 등에서 사용됩니다.

```text
httpd-2.4.57-1.el9.x86_64.rpm
```

---

### 패키지란?

* 패키지는 프로그램 설치에 필요한 파일을 하나로 묶어놓은 것입니다.
* 실행 파일, 설정 파일, 라이브러리, 문서, 의존성 정보가 포함될 수 있습니다.

| 구성         | 설명                          |
| ---------- | --------------------------- |
| 실행 파일      | 실제 프로그램 실행 파일입니다.           |
| 설정 파일      | `/etc` 아래에 저장되는 설정 파일입니다.   |
| 라이브러리      | 프로그램 실행에 필요한 공통 파일입니다.      |
| 문서         | 매뉴얼이나 설명 파일입니다.             |
| 의존성 정보     | 실행에 필요한 다른 패키지 정보입니다.       |
| 설치/삭제 스크립트 | 설치 또는 삭제 과정에서 실행되는 스크립트입니다. |

---

### RPM 명령어

| 명령어              | 설명                          |
| ---------------- | --------------------------- |
| `rpm -i 패키지.rpm` | 패키지를 설치합니다.                 |
| `rpm -U 패키지.rpm` | 패키지를 업그레이드합니다.              |
| `rpm -e 패키지명`    | 패키지를 삭제합니다.                 |
| `rpm -qa`        | 설치된 전체 패키지를 조회합니다.          |
| `rpm -qi 패키지명`   | 패키지 정보를 확인합니다.              |
| `rpm -ql 패키지명`   | 패키지가 설치한 파일 목록을 확인합니다.      |
| `rpm -qf 파일경로`   | 특정 파일이 어느 패키지에 포함되는지 확인합니다. |
| `rpm -V 패키지명`    | 패키지 무결성을 검증합니다.             |

---

### RPM의 단점

* RPM은 개별 패키지 파일을 직접 설치하는 방식입니다.
* 따라서 필요한 의존성 패키지를 자동으로 설치하지 못하는 경우가 있습니다.

```text
A 패키지 설치
→ B 패키지가 필요함
→ C 패키지가 필요함
→ 사용자가 직접 의존성 패키지를 찾아 설치해야 함
```

이러한 문제를 해결하기 위해 YUM이나 DNF를 사용합니다.

---

### RPM, YUM, DNF 차이

| 구분  | 설명                                  |
| --- | ----------------------------------- |
| RPM | 개별 `.rpm` 패키지를 직접 설치하고 관리합니다.       |
| YUM | 저장소를 이용하여 패키지와 의존성을 자동으로 관리합니다.     |
| DNF | YUM의 개선 버전으로 최신 Red Hat 계열에서 사용됩니다. |

예시:

```bash
dnf install samba
yum install samba
```

---

### 정리

**RPM은 Red Hat 계열 Linux에서 사용하는 패키지 관리 방식이며, 의존성 문제를 해결하기 위해 YUM이나 DNF 같은 상위 패키지 관리 도구를 함께 사용합니다.**

---

## 6.4 SAMBA

### 개요

* **SAMBA는 Linux/Unix 시스템에서 Windows와 파일 및 프린터를 공유할 수 있게 해주는 서비스**입니다.
* Windows는 파일 공유에 SMB/CIFS 프로토콜을 사용합니다.
* Linux는 기본적으로 Windows 파일 공유 방식과 다르기 때문에, Windows 클라이언트가 Linux 서버의 파일을 공유 폴더처럼 사용하려면 SAMBA가 필요합니다.

```text
Windows PC ↔ SMB/CIFS ↔ SAMBA Server Linux
```

즉, SAMBA는 **Linux 서버를 Windows 파일 서버처럼 사용할 수 있게 해주는 서비스**입니다.

---

### SAMBA가 필요한 이유

* 회사나 학교 환경에서는 Windows PC와 Linux 서버가 함께 사용되는 경우가 많습니다.
* Windows 사용자는 파일 탐색기에서 다음과 같은 방식으로 공유 폴더에 접근합니다.

```text
\\192.168.0.10\share
\\fileserver\public
```

* 이때 Linux 서버가 Windows 공유 폴더처럼 동작하려면 SAMBA가 필요합니다.

---

### SAMBA의 주요 용도

| 용도              | 설명                                          |
| --------------- | ------------------------------------------- |
| 파일 공유           | Linux 디렉터리를 Windows에서 공유 폴더처럼 접근할 수 있게 합니다. |
| 프린터 공유          | Linux에 연결된 프린터를 Windows에서 사용할 수 있게 합니다.     |
| 사용자 인증          | 사용자 계정과 비밀번호를 기반으로 접근을 제어합니다.               |
| Windows 네트워크 연동 | Workgroup 또는 Domain 환경과 연동할 수 있습니다.         |
| NAS 구축          | Linux 서버를 파일 서버 또는 NAS처럼 활용할 수 있습니다.        |

---

### SAMBA 관련 프로토콜과 포트

| 프로토콜/서비스         | 포트      | 설명                        |
| ---------------- | ------- | ------------------------- |
| SMB              | TCP 445 | Windows 파일 공유의 핵심 포트입니다.  |
| NetBIOS Session  | TCP 139 | NetBIOS 기반 세션 통신에 사용됩니다.  |
| NetBIOS Name     | UDP 137 | NetBIOS 이름 해석에 사용됩니다.     |
| NetBIOS Datagram | UDP 138 | NetBIOS 데이터그램 서비스에 사용됩니다. |

> 시험에서는 **SMB = TCP 445**, **NetBIOS = 137, 138, 139**를 기억하면 좋습니다.

---

### SAMBA 주요 데몬

| 데몬         | 역할                                     |
| ---------- | -------------------------------------- |
| `smbd`     | 파일 공유, 프린터 공유, 사용자 인증을 담당합니다.          |
| `nmbd`     | NetBIOS 이름 해석과 네트워크 브라우징 기능을 담당합니다.    |
| `winbindd` | Windows 도메인 계정과 Linux 계정을 연동할 때 사용합니다. |

핵심은 다음과 같습니다.

```text
smbd = 실제 파일/프린터 공유 담당
nmbd = Windows 이름 서비스 담당
winbindd = Windows 도메인 계정 연동 담당
```

---

### SAMBA 설정 파일

* SAMBA의 대표 설정 파일은 다음과 같습니다.

```bash
/etc/samba/smb.conf
```

* 이 파일에서 공유 이름, 공유 경로, 접근 권한, 인증 방식, 작업 그룹 등을 설정합니다.

---

### smb.conf 기본 구조

`smb.conf`는 크게 `[global]` 영역과 공유 영역으로 구성됩니다.

```ini
[global]
    전역 설정

[share]
    공유 폴더 설정
```

예시:

```ini
[global]
    workgroup = WORKGROUP
    server string = Samba Server
    security = user

[public]
    path = /srv/samba/public
    browseable = yes
    writable = yes
    guest ok = yes
```

---

### [global] 설정

| 설정              | 설명                            |
| --------------- | ----------------------------- |
| `workgroup`     | Windows 작업 그룹 이름입니다.          |
| `server string` | 서버 설명입니다.                     |
| `security`      | 인증 방식을 설정합니다.                 |
| `map to guest`  | 게스트 사용자 매핑 방식을 설정합니다.         |
| `interfaces`    | SAMBA가 사용할 네트워크 인터페이스를 지정합니다. |
| `hosts allow`   | 접근을 허용할 IP 대역을 지정합니다.         |
| `log file`      | 로그 파일 위치를 지정합니다.              |

예시:

```ini
[global]
    workgroup = WORKGROUP
    server string = Linux File Server
    security = user
```

### 공유 폴더 설정

| 설정               | 설명                          |
| ---------------- | --------------------------- |
| `[share]`        | Windows에서 보이는 공유 이름입니다.     |
| `path`           | 실제 Linux 디렉터리 경로입니다.        |
| `browseable`     | 네트워크 목록에 표시할지 설정합니다.        |
| `writable`       | 쓰기 가능 여부를 설정합니다.            |
| `read only`      | 읽기 전용 여부를 설정합니다.            |
| `guest ok`       | 게스트 접근 허용 여부를 설정합니다.        |
| `valid users`    | 접근 가능한 사용자를 지정합니다.          |
| `write list`     | 쓰기 가능한 사용자를 지정합니다.          |
| `create mask`    | 새로 생성되는 파일의 기본 권한을 지정합니다.   |
| `directory mask` | 새로 생성되는 디렉터리의 기본 권한을 지정합니다. |

### 익명 공유 설정 예시

```ini
[public]
    path = /srv/samba/public
    browseable = yes
    writable = yes
    guest ok = yes
    read only = no
```

| 설정                 | 의미                                  |
| ------------------ | ----------------------------------- |
| `[public]`         | Windows에서 보이는 공유 이름입니다.             |
| `path`             | 실제 공유 디렉터리는 `/srv/samba/public`입니다. |
| `browseable = yes` | 네트워크 목록에 표시됩니다.                     |
| `writable = yes`   | 쓰기가 가능합니다.                          |
| `guest ok = yes`   | 로그인 없이 접근할 수 있습니다.                  |
| `read only = no`   | 읽기 전용이 아닙니다.                        |

> 익명 쓰기 공유는 편리하지만 보안상 위험할 수 있으므로 실제 운영 환경에서는 주의해야 합니다.

### 사용자 인증 공유 설정 예시

```ini
[private]
    path = /srv/samba/private
    browseable = yes
    writable = yes
    valid users = yuchan
```

| 설정                     | 의미                                   |
| ---------------------- | ------------------------------------ |
| `[private]`            | Windows에서 보이는 공유 이름입니다.              |
| `path`                 | 실제 공유 디렉터리는 `/srv/samba/private`입니다. |
| `browseable = yes`     | 네트워크 목록에 표시됩니다.                      |
| `writable = yes`       | 쓰기가 가능합니다.                           |
| `valid users = yuchan` | yuchan 사용자만 접근 가능합니다.                |

### SAMBA 사용자 계정

* SAMBA 사용자는 Linux 사용자 계정을 기반으로 등록합니다.
* 먼저 Linux 사용자가 존재해야 합니다.
* 이후 `smbpasswd` 명령어로 SAMBA 암호를 등록합니다.

#### Linux 사용자 생성

```bash
useradd yuchan
passwd yuchan
```

#### SAMBA 사용자 등록

```bash
smbpasswd -a yuchan
```

#### SAMBA 사용자 활성화

```bash
smbpasswd -e yuchan
```

#### SAMBA 사용자 삭제

```bash
smbpasswd -x yuchan
```

중요한 점은 다음과 같습니다.

```text
Linux 사용자 계정이 있어야 SAMBA 사용자로 등록할 수 있다.
Linux 비밀번호와 SAMBA 비밀번호는 별도로 관리될 수 있다.
```

---

### SAMBA 디렉터리 권한

* SAMBA에서 쓰기 권한을 허용해도 Linux 파일 시스템 권한이 막혀 있으면 실제로 쓰기 작업이 불가능합니다.
* 따라서 SAMBA 권한과 Linux 권한을 함께 확인해야 합니다.

```text
SAMBA 설정 권한
+ Linux 파일 시스템 권한
= 실제 접근 가능 여부
```

예시:

```bash
mkdir -p /srv/samba/share
chown -R yuchan:yuchan /srv/samba/share
chmod 755 /srv/samba/share
```

그룹 공유 방식 예시:

```bash
groupadd smbusers
usermod -aG smbusers yuchan
chown -R root:smbusers /srv/samba/share
chmod -R 2770 /srv/samba/share
```

> `2770`에서 앞의 `2`는 setgid를 의미합니다.
> 디렉터리에 setgid가 설정되면 새로 생성되는 파일과 디렉터리가 부모 디렉터리의 그룹을 상속받습니다.

---

### SAMBA 서비스 시작

Red Hat 계열에서는 다음과 같이 실행합니다.

```bash
systemctl start smb
systemctl start nmb
```

부팅 시 자동 시작:

```bash
systemctl enable smb
systemctl enable nmb
```

상태 확인:

```bash
systemctl status smb
systemctl status nmb
```

Ubuntu/Debian 계열에서는 서비스명이 다음처럼 다를 수 있습니다.

```bash
systemctl status smbd
systemctl status nmbd
```

### 방화벽 설정

SAMBA를 사용하려면 방화벽에서 관련 포트를 허용해야 합니다.

Red Hat 계열 firewalld 기준:

```bash
firewall-cmd --permanent --add-service=samba
firewall-cmd --reload
```

포트 기준으로 허용하면 다음과 같습니다.

```bash
firewall-cmd --permanent --add-port=445/tcp
firewall-cmd --permanent --add-port=139/tcp
firewall-cmd --permanent --add-port=137/udp
firewall-cmd --permanent --add-port=138/udp
firewall-cmd --reload
```

### Windows에서 SAMBA 접속

Windows 파일 탐색기 주소창에 다음과 같이 입력합니다.

```text
\\192.168.0.10\public
```

또는 서버 이름으로 접근할 수 있습니다.

```text
\\fileserver\public
```

사용자 인증 공유라면 SAMBA에 등록한 사용자명과 비밀번호를 입력해야 합니다.

공유 목록 확인:

```bash
smbclient -L //192.168.0.10 -U yuchan
```

공유 폴더 접속:

```bash
smbclient //192.168.0.10/private -U yuchan
```

### SAMBA 설정 검사

`smb.conf` 설정 파일의 문법을 검사하려면 다음 명령어를 사용합니다.

```bash
testparm
```

설정 수정 후 일반적인 확인 순서는 다음과 같습니다.

```text
smb.conf 수정
→ testparm으로 문법 검사
→ smb/nmb 또는 smbd/nmbd 재시작
→ 방화벽 확인
→ Windows에서 접속 테스트
```

### SAMBA 문제 해결 체크리스트

| 확인 항목           | 확인 방법                                           |
| --------------- | ----------------------------------------------- |
| 서비스 실행 여부       | `systemctl status smb`, `systemctl status smbd` |
| 설정 문법 오류        | `testparm`                                      |
| 포트 열림 여부        | `ss -tulnp`                                     |
| 방화벽 허용 여부       | `firewall-cmd --list-all`                       |
| 공유 경로 존재 여부     | `ls -ld /srv/samba/share`                       |
| Linux 권한 문제     | `chmod`, `chown` 확인                             |
| SAMBA 사용자 등록 여부 | `pdbedit -L` 또는 `smbpasswd -a`                  |
| Windows 접근 경로   | `\\서버IP\공유이름`                                   |
| SELinux 차단 여부   | Red Hat 계열에서 추가 확인 필요                           |

### SAMBA에서 자주 헷갈리는 부분

#### 1. SAMBA 권한과 Linux 권한은 다르다

`smb.conf`에 다음처럼 되어 있어도:

```ini
writable = yes
```

Linux 디렉터리 권한이 쓰기를 막고 있으면 쓰기 작업은 실패합니다.

```bash
dr-xr-xr-x /srv/samba/share
```

따라서 반드시 **SAMBA 설정 권한과 Linux 파일 시스템 권한을 함께 확인**해야 합니다.

---

#### 2. 공유 이름과 실제 경로는 다르다

```ini
[public]
    path = /srv/samba/public
```

Windows에서 보이는 이름은 다음입니다.

```text
public
```

Linux 실제 경로는 다음입니다.

```text
/srv/samba/public
```

Windows 접속 경로는 다음입니다.

```text
\\192.168.0.10\public
```

---

#### 3. Linux 계정과 SAMBA 계정은 연결되지만 암호는 별도다

Linux 사용자 생성:

```bash
useradd yuchan
```

Linux 비밀번호 설정:

```bash
passwd yuchan
```

SAMBA 비밀번호 설정:

```bash
smbpasswd -a yuchan
```

즉, Linux 사용자가 있어야 SAMBA 사용자로 등록할 수 있지만, SAMBA 인증 정보는 별도로 설정해야 합니다.

### SAMBA 핵심 암기표

| 키워드                   | 의미                                 |
| --------------------- | ---------------------------------- |
| SAMBA                 | Linux와 Windows 간 파일/프린터 공유 서비스입니다. |
| SMB/CIFS              | Windows 파일 공유 프로토콜입니다.             |
| `smbd`                | 파일 공유, 프린터 공유, 인증을 담당합니다.          |
| `nmbd`                | NetBIOS 이름 해석을 담당합니다.              |
| `winbindd`            | Windows 도메인 계정 연동을 담당합니다.          |
| `/etc/samba/smb.conf` | SAMBA 설정 파일입니다.                    |
| `smbpasswd`           | SAMBA 사용자 암호 관리 명령어입니다.            |
| `testparm`            | SAMBA 설정 문법 검사 명령어입니다.             |
| TCP 445               | SMB 기본 포트입니다.                      |
| TCP 139               | NetBIOS Session 포트입니다.             |
| UDP 137               | NetBIOS Name 포트입니다.                |
| UDP 138               | NetBIOS Datagram 포트입니다.            |
| `\\IP\공유명`            | Windows에서 SAMBA 공유에 접근하는 방식입니다.    |

---

### 정리

**SAMBA는 Linux 서버를 Windows 파일 서버처럼 사용할 수 있게 해주는 서비스로, SMB/CIFS 프로토콜을 사용하며 핵심 데몬은 smbd와 nmbd, 설정 파일은 `/etc/samba/smb.conf`, 주요 포트는 TCP 445, TCP 139, UDP 137, UDP 138입니다.**

## 최종 암기 문장

> Linux는 Unix 계열의 오픈소스 운영체제로, 서버와 네트워크 환경에서 안정성, 보안성, 자동화, 네트워크 기능이 뛰어난 운영체제입니다.

> Linux 구조는 사용자, Shell, Kernel, Hardware로 이해할 수 있으며, Shell은 명령어를 해석하고 Kernel은 시스템 자원을 관리합니다.

> Linux 파일 시스템은 `/` 루트 디렉터리를 기준으로 계층 구조를 가지며, `/etc`는 설정 파일, `/home`은 사용자 홈, `/var`는 로그와 변동 데이터를 저장합니다.

> Linux 권한은 사용자, 그룹, 기타 사용자 기준으로 r, w, x 권한을 부여하며, 숫자로는 r=4, w=2, x=1로 계산합니다.

> vi는 Linux 서버에서 설정 파일을 수정할 때 사용하는 대표 편집기이며, 명령 모드, 입력 모드, 마지막 행 모드를 구분해서 사용합니다.

> 프로세스는 실행 중인 프로그램이고, 데몬은 백그라운드에서 지속적으로 실행되며 서비스를 제공하는 프로세스입니다.

> RPM은 Red Hat 계열 Linux에서 사용하는 패키지 관리 방식이며, YUM과 DNF는 의존성을 자동으로 처리하는 상위 패키지 관리 도구입니다.

> SAMBA는 Linux 서버를 Windows 파일 서버처럼 사용할 수 있게 해주는 서비스이며, SMB/CIFS 프로토콜을 사용합니다.
