## 070. 트랜잭션 분석 / CRUD 분석
### 1. 트랜잭션(Transaction)의 정의
데이터베이스의 상태를 변환시키는 하나의 논리적 기능을 수해하기 위한 작업의 단위 또는 한꺼번에 모두 수행되어야 할 일련의 연산드을 의미한다.

### 2. 트랜잭션의 상태
- 활동(Active) : 트랜잭션이 실행 중인 상태
- 실패(Failed) : 트랜잭션 실행에 오류가 발생하여 중단된 상태
- 철회(Aborted) : 트랜잭션이 비정상적으로 종료되어 Rollback 연산을 수행한 상태
- 부분 완료(Partialy Committed) : 트랜잭션을 모두 성공적으로 실행한 후 Commit 연산이 실행되기 직전인 성태
- 완료(Committed) : 트랜잭션을 모두 성공적으로 실행한 후 Commit 연산을 실행한 후의 상태이다.

### 3. 트랜잭션의 특성
- Atomicity(원자성) : 트랜잭션의 연산은 데이터베이스에 모두 반영되도록 완료(Commit)되든지 아니면 전혀 반영되지 않도록 복구(Rollback)되어야 함
- Consistency(일관성) : 트랜잭션이 그 실행을 성공적으로 완료하면 언제나 일관성 있는 데이터베이스 상태로 변환함
- Isolation(독립성) : 둘 이상의 트랜잭션이 동시에 병행 실행되는 경우 어느 하나의 트랜잭션 실행중에 다른 트랜잭션의 연산이 끼어들 수 없음
- Durabiltity(영속성) : 성공적으로 완료된 트랜잭션의 결과는 시스템이 고장나더라도 영구적으로 반영되어야 함

### 4. CRUD 분석
- CRUD는 '생성(Create), 읽기(Read), 갱신(Update), 삭제(Delete)'의 앞 글자만 모아서 만든 용어이다.
- CRUD 분석은 데이터베이스 테이블에 변화를 주는 트랜잭션의 CRUD 연산에 대해 CRUD 매트릭스를 작성하여 분석하는 것이다.

## 071. 인덱스 설계
### 1. 인덱스(Index)의 개요
- 데이터 레코드를 빠르게 접근하기 위해 <키 값, 포인터> 쌍으로 구성되는 데이터 구조이다.
- 인덱스를 통해서 파일의 레코드에 대한 액세서를 빠르게 수행할 수 있다.
- 데이터 정의어(DDL)를 이용하여 사용자가 생성(CREATE), 변경(ALTER), 제거(DROP)할 수 있다.

## 072. 뷰(View) 설계
### 1. 뷰(View)의 특징
- 사용자에게 접근이 허용된 자료만을 제한적으로 보여주기 위해 하나 이상의 기본 테이블로부터 유도된, 이름을 가지는 가상 테이블이다.
- 뷰는 저장장치 내에 물리적으로 존재하지 않지만, 사용자에게는 있는 것처럼 간주된다.
- 기본 테이블의 기본키를 포함한 속성(열) 집합으로 뷰를 구성해야만 삽입, 삭제, 갱신 연산이 가능하다.
- 뷰가 저의된 기본 테이블이나 뷰를 삭제하면 그 테이블이나 뷰를 기초로 정의된 다른 뷰도 자동으로 삭제된다.
- 뷰는 데이터 접근 제어를 통해 보안을 제공한다.
- 뷰는 데이터 접근 제어를 통해 보안을 제공한다.
- 독립적인 인덱스를 가질 수 없다.
- 뷰를 정의할 때는 CREATE문, 제거할 때는 DROP문을 사용한다.

## 073. 파티션 설계
### 1. 파티션의 종류
- 범위 분할 (Range Partitioning) : 지정한 열의 값을 기준으로 범위를 저장하여 분할함
- 해시 분할 (Hash Partitioning) 
    - 해시 함수를 적용한 결과 값에 따라 데이터를 분할한다.
    - 특정 파티션에 데이터가 집중되는 범위 분할의 단점을 보안한 것으로, 데이터를 고르게 분산할 때 유용하다.
    - 특정 데이터가 어디에 있는지 판단할 수 없다.
    - 고객번호, 주민번호 등과 같이데이터가 고른 컬럼에 효과적이다.
- 조합 분할(Composite Partitioning)
    - 범위 분할로 분할한 다음 해시 함수를 적용하여 다시 분할하는 방식이다.
    - 범위 분할한 파티션이 너무 커서 관리가 어려울 때 유용하다.
- 목록 분할(List Partitioning) : 지정한 열 값에 대한 목록을 만들어 이를 기준으로 분할함
- 라운드 로빈 분할(Round Robin Partitioning)
    - 레코드를 균일하게 분배하는 방식이다.
    - 각 레코드가 순차적으로 분배되며, 기본키가 필요 없다.

## 074. 분산 데이터베이스 설계
### 1. 분산 데이터베이스의 구성 요소

분산 데이터베이스(Distributed Database)는 **물리적으로 여러 장소에 분산된 데이터베이스를 네트워크로 연결하여 하나의 데이터베이스처럼 사용하는 시스템**이다.

| 구성 요소                               | 설명                                      |
| ----------------------------------- | --------------------------------------- |
| **분산 처리기(Distributed Processor)**   | 각 지역의 데이터를 처리하고 다른 지역의 시스템과 협력하여 작업을 수행 |
| **분산 데이터베이스(Distributed Database)** | 여러 지역에 물리적으로 분산되어 저장된 데이터의 집합           |
| **통신 네트워크(Communication Network)**  | 분산된 데이터베이스와 처리기 사이에서 데이터 및 명령을 전달       |

```text
분산 처리기
    │
통신 네트워크
    │
분산 데이터베이스
```

---

### 2. 분산 데이터베이스의 목표

분산 데이터베이스의 주요 목표는 사용자가 데이터가 실제로 어디에 저장되어 있는지 신경 쓰지 않고 **하나의 데이터베이스처럼 사용할 수 있도록 하는 것**이다.

이를 **분산 투명성(Distribution Transparency)**이라고 한다.

| 목표                                   | 의미                                          |
| ------------------------------------ | ------------------------------------------- |
| **위치 투명성(Location Transparency)**    | 데이터가 어느 지역에 저장되어 있는지 알 필요 없이 접근 가능          |
| **중복 투명성(Replication Transparency)** | 동일한 데이터가 여러 장소에 복제되어 있어도 사용자는 이를 의식할 필요가 없음 |
| **병행 투명성(Concurrency Transparency)** | 여러 사용자가 동시에 데이터를 사용해도 일관된 결과를 제공            |
| **장애 투명성(Failure Transparency)**     | 일부 시스템이나 네트워크에 장애가 발생해도 전체 시스템에 미치는 영향을 최소화 |

#### 핵심 정리

```text
위치 투명성 → 어디에 있는지 몰라도 됨
중복 투명성 → 몇 개가 복제되어 있는지 몰라도 됨
병행 투명성 → 여러 사용자가 동시에 사용 가능
장애 투명성 → 일부 장애가 전체 장애로 이어지지 않도록 함
```

---

### 3. 분산 데이터베이스의 장﹒단점

| 구분     | 내용                                      |
| ------ | --------------------------------------- |
| **장점** | 지역별 데이터의 공유성이 향상됨                       |
| **장점** | 시스템의 신뢰성과 가용성이 향상됨                      |
| **장점** | 특정 지역에 장애가 발생해도 다른 지역에서 서비스를 계속할 수 있음   |
| **장점** | 데이터가 사용되는 지역에 가까이 존재하여 응답 속도를 향상시킬 수 있음 |
| **장점** | 시스템의 점진적인 확장이 용이함                       |
| **단점** | 데이터베이스 구조와 관리가 복잡함                      |
| **단점** | 데이터의 무결성과 일관성을 유지하기 어려움                 |
| **단점** | 통신 네트워크에 대한 의존도가 높음                     |
| **단점** | 데이터 복제 및 동기화에 추가 비용이 발생함                |
| **단점** | 보안 및 장애 관리가 복잡해짐                        |

### 장﹒단점 핵심 정리

| 장점               | 단점         |
| ---------------- | ---------- |
| 신뢰성·가용성 향상       | 관리 복잡성 증가  |
| 지역별 데이터 접근 성능 향상 | 일관성 유지 어려움 |
| 시스템 확장 용이        | 통신 비용 증가   |
| 장애에 대한 대응력 향상    | 보안 관리 어려움  |

### 4. 분할(Fragment)

분할(Fragmentation)은 **하나의 릴레이션을 여러 개의 작은 단위(Fragment)로 나누어 각 지역에 분산 저장하는 방법**이다.

분할된 데이터는 필요할 경우 다시 결합하여 **원래의 릴레이션으로 복원할 수 있어야 한다.**

| 분할 방식                               | 설명                        | 기준        |
| ----------------------------------- | ------------------------- | --------- |
| **수평 분할(Horizontal Fragmentation)** | 릴레이션의 튜플(Row)을 기준으로 분할    | 행(Row)    |
| **수직 분할(Vertical Fragmentation)**   | 릴레이션의 속성(Column)을 기준으로 분할 | 열(Column) |
| **혼합 분할(Mixed Fragmentation)**      | 수평 분할과 수직 분할을 함께 사용       | 행 + 열     |

#### 수평 분할

**행(Row)을 기준으로 데이터를 나누는 방식**이다.

기존 학생 테이블:

| 학번 | 이름  | 지역 |
| -- | --- | -- |
| 1  | 김철수 | 서울 |
| 2  | 이영희 | 부산 |
| 3  | 박민수 | 서울 |

서울 지역과 부산 지역으로 나누면:

```text
서울 Fragment
→ 김철수, 박민수

부산 Fragment
→ 이영희
```

즉, 다음과 같은 형태이다.

```text
전체 릴레이션
     ↓
 ┌───┴───┐
서울     부산
행 분할   행 분할
```

#### 수직 분할

**열(Column)을 기준으로 데이터를 나누는 방식**이다.

기존 릴레이션:

| 학번 | 이름 | 학과 | 전화번호 |
| -- | -- | -- | ---- |

이를 다음처럼 분리할 수 있다.

| 학생 기본정보 |
| ------- |
| 학번      |
| 이름      |

| 학생 상세정보 |
| ------- |
| 학번      |
| 학과      |
| 전화번호    |

수직 분할에서는 분할된 릴레이션을 다시 결합할 수 있도록 일반적으로 **기본키를 각 Fragment에 포함**한다.

```text
전체 릴레이션
      ↓
 ┌────┴────┐
학번, 이름   학번, 학과, 전화번호
```

#### 혼합 분할

수평 분할과 수직 분할을 **동시에 적용하는 방식**이다.

```text
전체 릴레이션
      ↓
   수평 분할
   /       \
서울       부산
 ↓          ↓
수직 분할   수직 분할
```

### 분할 방식 핵심 정리

| 방식        | 쉽게 기억하기      |
| --------- | ------------ |
| **수평 분할** | 행을 나눈다       |
| **수직 분할** | 열을 나눈다       |
| **혼합 분할** | 행과 열을 모두 나눈다 |

> **수평 = Row(튜플), 수직 = Column(속성)** 으로 기억하면 가장 쉽습니다.


## 075. 데이터베이스 보안 / 암호화
### 1. 암호화(Encryption)
- 데이터를 보낼 때 송신자가 지정한 수신자 이외에는 그 내용을 알 수 없도록 평문을 암호문으로 변환하는 것이다.
- 암호화(Encrption) 과정 : 암호화되지 않은 평문을 정보 보호를 위해 암호문으로 바꾸는 과정

## 076. 데이터베이스 보안 - 접근통제
### 1. 접근통제 기술

접근통제(Access Control)는 **사용자가 시스템이나 데이터 등의 자원에 접근할 수 있는 권한을 제한하고 관리하는 보안 기술**이다.

접근통제 방식은 크게 **DAC, MAC, RBAC**으로 구분한다.

| 구분       | 명칭                                         | 특징                                      | 권한 결정 기준        |
| -------- | ------------------------------------------ | --------------------------------------- | --------------- |
| **DAC**  | 임의적 접근통제<br>(Discretionary Access Control) | 자원의 **소유자가 접근 권한을 설정**                  | 사용자 신원, 소유자의 판단 |
| **MAC**  | 강제적 접근통제<br>(Mandatory Access Control)     | 시스템이 정한 **보안 등급에 따라 접근을 통제**            | 보안 등급(Label)    |
| **RBAC** | 역할 기반 접근통제<br>(Role-Based Access Control)  | 사용자에게 직접 권한을 주지 않고 **역할(Role)에 권한을 부여** | 사용자의 역할         |

#### DAC — 임의적 접근통제

자원의 소유자(Owner)가 다른 사용자에게 접근 권한을 직접 부여하거나 회수하는 방식이다.

```text
사용자
  ↓
자원 소유자가 권한 결정
  ↓
읽기 / 쓰기 / 실행
```

* 구현이 비교적 간단함
* 사용자가 자신의 자원에 대한 권한을 관리
* 사용자에 의해 권한이 전달될 수 있어 보안 관리가 어려워질 수 있음
* 대표적인 구현: **ACL(Access Control List)**

---

#### MAC — 강제적 접근통제

사용자와 데이터에 **보안 등급(Security Level)** 을 부여하여 시스템이 강제로 접근을 통제하는 방식이다.

```text
사용자 보안 등급
       ↓
   등급 비교
       ↓
데이터 보안 등급
```

예:

```text
Top Secret  → 극비
Secret      → 비밀
Confidential → 대외비
Unclassified → 일반
```

* 사용자가 임의로 권한을 변경할 수 없음
* 보안성이 높음
* 군사·정부 등 높은 보안 수준을 요구하는 환경에서 사용
* **Bell-LaPadula 모델**이 대표적인 MAC 기반 보안 모델

---

#### RBAC — 역할 기반 접근통제

사용자에게 권한을 직접 부여하지 않고 **역할(Role)에 권한을 부여한 뒤 사용자에게 역할을 할당**하는 방식이다.

```text
사용자
  ↓
역할(Role)
  ↓
권한(Permission)
  ↓
자원(Resource)
```

예:

| 사용자 | 역할     | 권한             |
| --- | ------ | -------------- |
| 홍길동 | 관리자    | 조회, 등록, 수정, 삭제 |
| 김철수 | 일반 사용자 | 조회             |
| 이영희 | 운영자    | 조회, 등록, 수정     |

#### 접근통제 방식 비교

| 구분    | DAC      | MAC           | RBAC       |
| ----- | -------- | ------------- | ---------- |
| 기준    | 사용자 신원   | 보안 등급         | 역할         |
| 권한 설정 | 자원 소유자   | 시스템           | 관리자        |
| 유연성   | 높음       | 낮음            | 높음         |
| 보안 수준 | 상대적으로 낮음 | 높음            | 높음         |
| 특징    | 소유자 중심   | 등급 중심         | 역할 중심      |
| 대표 예  | ACL      | Bell-LaPadula | 조직의 직무별 권한 |

> **핵심 암기:**
> DAC = **소유자**, MAC = **보안 등급**, RBAC = **역할**

---

### 2. 벨 라파듈라 모델(Bell-LaPadula Model)

벨 라파듈라(Bell-LaPadula) 모델은 **정보의 기밀성(Confidentiality)을 보장하기 위한 보안 모델**이다.

사용자와 정보에 보안 등급을 부여하고, 등급에 따라 정보의 **읽기와 쓰기를 제한**한다.

```text
높음  ┌─────────────────┐
      │ Top Secret      │
      ├─────────────────┤
      │ Secret          │
      ├─────────────────┤
      │ Confidential    │
      ├─────────────────┤
낮음  │ Unclassified    │
      └─────────────────┘
```

핵심 원칙은 다음 두 가지이다.

| 원칙                | 의미          | 설명                             |
| ----------------- | ----------- | ------------------------------ |
| **No Read Up**    | 상위 등급 읽기 금지 | 자신의 보안 등급보다 높은 정보는 읽을 수 없음     |
| **No Write Down** | 하위 등급 쓰기 금지 | 자신의 보안 등급보다 낮은 곳에 정보를 기록할 수 없음 |

### No Read Up

자신보다 **높은 보안 등급의 정보를 읽을 수 없다.**

```text
Top Secret
     ↑
Secret 사용자   ✕ 읽기 불가
     │
Confidential
```

예를 들어 `Secret` 등급의 사용자는:

| 데이터 등급       | 읽기 가능 여부 |
| ------------ | -------- |
| Top Secret   | ❌        |
| Secret       | ✅        |
| Confidential | ✅        |
| Unclassified | ✅        |

즉,

```text
낮은 등급 → 높은 등급

읽기 금지
```

이를 **단순 보안 속성(Simple Security Property)** 이라고 한다.

> **Simple Security Property = No Read Up**

---

### No Write Down

자신보다 **낮은 보안 등급에 정보를 기록할 수 없다.**

```text
Top Secret
     │
Secret 사용자
     ↓
Confidential     ✕ 쓰기 불가
```

`Secret` 사용자가 하위 등급인 `Confidential`에 기밀 정보를 작성할 수 있다면 Secret 정보가 낮은 등급으로 유출될 수 있기 때문이다.

예를 들어 `Secret` 등급의 사용자는:

| 데이터 등급       | 쓰기 가능 여부 |
| ------------ | -------- |
| Top Secret   | ✅        |
| Secret       | ✅        |
| Confidential | ❌        |
| Unclassified | ❌        |

즉,

```text
높은 등급 → 낮은 등급

쓰기 금지
```

이를 ***-속성(Star Property)**이라고 한다.

> ***-Property = No Write Down**

---

### 벨 라파듈라의 주요 보안 속성

| 보안 속성                               | 원칙            | 설명                        |
| ----------------------------------- | ------------- | ------------------------- |
| **Simple Security Property**        | No Read Up    | 상위 보안 등급의 정보를 읽을 수 없음     |
| ***-Property**                      | No Write Down | 하위 보안 등급으로 정보를 쓸 수 없음     |
| **Discretionary Security Property** | 접근 행렬 기반 통제   | 사용자·객체 간 접근 권한을 접근 행렬로 관리 |

### 전체 흐름

```text
                  Top Secret
                  ──────────
                     ↑ 쓰기 가능
                     │
                  Secret
              ──────────────
             사용자 등급 = Secret
              ──────────────
              ↙              ↘
     읽기 가능 ↓              ↑ 쓰기 금지
        Confidential
        ────────────
             ↓
        Unclassified
```

쉽게 기억하면 다음과 같다.

```text
읽기(Read)  → 위로 가지 마라
              No Read Up

쓰기(Write) → 아래로 가지 마라
              No Write Down
```

### Bell-LaPadula 핵심 정리

| 항목                           | 내용                      |
| ---------------------------- | ----------------------- |
| **목적**                       | 기밀성(Confidentiality) 보장 |
| **접근통제 방식**                  | MAC(강제적 접근통제)           |
| **No Read Up**               | 상위 등급 정보 읽기 금지          |
| **No Write Down**            | 하위 등급으로 정보 쓰기 금지        |
| **Simple Security Property** | No Read Up              |
| ***-Property**               | No Write Down           |

> **Bell-LaPadula = 기밀성 = No Read Up + No Write Down**
> 이 세 가지를 묶어서 기억하면 됩니다.

## 077. 데이터베이스 백업
### 1. 데이터베이스 백업
- 전산 장비의 장애에 대비하여 데이터베이스에 저장된 데이터를 보호하고 복구하기 위한 작업이다.
- 치명적인 데이터 손실을 막기 위해서는 데이터베이스를 정기적으로 백업해야 한다.

## 078. 스토리지
### 1. DAS(Direct Attached Storage)

DAS는 **저장장치를 서버나 컴퓨터에 직접 연결하여 사용하는 저장 방식**이다.

네트워크를 거치지 않고 서버와 저장장치가 직접 연결되므로 구조가 단순하고 빠른 데이터 접근이 가능하다.

```text
┌──────────────┐
│    Server    │
└──────┬───────┘
       │ 직접 연결
       │ SATA / SAS / SCSI
       ▼
┌──────────────┐
│   Storage    │
│  HDD / SSD   │
└──────────────┘
```

| 항목           | 내용                 |
| ------------ | ------------------ |
| **연결 방식**    | 서버와 저장장치를 직접 연결    |
| **접근 방식**    | Block 단위 접근        |
| **주요 인터페이스** | SATA, SAS, SCSI 등  |
| **네트워크 사용**  | 사용하지 않음            |
| **구성 난이도**   | 단순함                |
| **성능**       | 직접 연결되므로 비교적 빠름    |
| **확장성**      | 낮음                 |
| **공유성**      | 여러 서버 간 직접 공유가 어려움 |

#### 장점

* 구조가 단순하여 구축과 관리가 쉬움
* 별도의 스토리지 네트워크가 필요하지 않음
* 직접 연결하므로 데이터 접근 속도가 빠름
* 구축 비용이 비교적 저렴함

#### 단점

* 저장장치가 특정 서버에 종속됨
* 여러 서버에서 저장공간을 공유하기 어려움
* 서버가 증가할수록 저장장치를 개별적으로 관리해야 함
* 대규모 환경에서는 확장성과 관리 효율성이 떨어짐

> **DAS = 서버와 스토리지를 직접(Direct) 연결**

---

### 2. SAN(Storage Area Network)

SAN은 **서버와 저장장치를 전용 고속 네트워크로 연결하여 여러 서버가 저장장치를 공유할 수 있도록 구성한 저장 방식**이다.

서버 입장에서는 네트워크를 통해 연결되어 있지만, 일반적으로 저장공간을 **로컬 디스크와 같은 Block Storage 형태**로 사용한다.

```text
┌──────────┐   ┌──────────┐   ┌──────────┐
│ Server A │   │ Server B │   │ Server C │
└────┬─────┘   └────┬─────┘   └────┬─────┘
     │              │              │
     └──────────────┼──────────────┘
                    │
             ┌──────▼──────┐
             │ SAN Network │
             │ FC / iSCSI  │
             └──────┬──────┘
                    │
             ┌──────▼──────┐
             │   Storage   │
             └─────────────┘
```

| 항목          | 내용                         |
| ----------- | -------------------------- |
| **연결 방식**   | 전용 스토리지 네트워크를 통해 연결        |
| **접근 방식**   | Block 단위 접근                |
| **주요 기술**   | Fibre Channel(FC), iSCSI 등 |
| **네트워크 사용** | 스토리지 전용 네트워크 사용            |
| **구성 난이도**  | 복잡함                        |
| **성능**      | 고속 데이터 전송 가능               |
| **확장성**     | 높음                         |
| **공유성**     | 여러 서버에서 스토리지 사용 가능         |

#### 장점

* 여러 서버에서 대용량 스토리지를 사용할 수 있음
* 중앙 집중식 스토리지 관리가 가능함
* 높은 성능과 확장성을 제공함
* 서버와 저장장치를 독립적으로 확장할 수 있음
* 대규모 데이터베이스나 기업 시스템에 적합함

#### 단점

* 구축 비용이 높음
* 네트워크와 스토리지 구성이 복잡함
* 전문적인 관리 기술이 필요함
* SAN 장비 및 전용 네트워크가 필요할 수 있음

---

### DAS와 SAN 비교

| 구분         | DAS                     | SAN                  |
| ---------- | ----------------------- | -------------------- |
| **의미**     | Direct Attached Storage | Storage Area Network |
| **연결**     | 서버에 직접 연결               | 전용 네트워크로 연결          |
| **데이터 접근** | Block                   | Block                |
| **공유성**    | 낮음                      | 높음                   |
| **확장성**    | 낮음                      | 높음                   |
| **구축 난이도** | 낮음                      | 높음                   |
| **비용**     | 비교적 저렴                  | 높음                   |
| **관리**     | 서버별 관리                  | 중앙 집중식 관리            |
| **적합 환경**  | 소규모 시스템                 | 대규모·기업 시스템           |

```text
DAS
Server ───── Storage
       직접 연결


SAN
Server A ─┐
Server B ─┼─ SAN Network ─ Storage
Server C ─┘
       네트워크 연결
```

> **핵심:**
> **DAS = 서버에 스토리지를 직접 연결**
> **SAN = 전용 네트워크를 통해 여러 서버와 스토리지를 연결**
