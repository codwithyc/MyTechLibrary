## 055. 운영체제의 운영 방식

### 1. 일괄 처리 시스템(Batch Processing System)

일정 기간 또는 일정량의 데이터를 **모아 두었다가 한꺼번에 처리**하는 방식입니다.

- 예 : 급여 계산, 공과금 처리, 연말 정산
- 초기 컴퓨터에서 사용되던 가장 오래된 방식입니다.

#### 왜 모아서 처리할까?

초기 컴퓨터는 매우 비쌌기 때문에, **놀리는 시간을 최소화**하는 것이 중요했습니다.

작업을 하나씩 처리하면 준비 시간이 반복적으로 발생합니다.  
비슷한 작업을 모아 한 번에 처리하면 **준비 과정을 한 번만 거치면 되므로 효율적**입니다.

지금도 **즉시 응답이 필요 없고 양이 많은 작업**에는 일괄 처리가 적합합니다.

---

### 2. 실시간 처리 시스템(Real Time Processing System)

데이터가 발생하는 즉시 처리하여 **정해진 시간 안에 결과를 제공**하는 방식입니다.

- 예 : 항공기 좌석 예약, 은행 업무, 교통 제어, 미사일 제어
- 응답 시간이 **정해진 한계를 넘으면 안 됩니다.**

#### 왜 실시간 처리가 필요할까?

어떤 작업은 **결과가 늦으면 아예 의미가 없어집니다.**

- 항공기 좌석 예약이 늦으면 이미 다른 사람이 예약했을 수 있습니다.
- 자동차의 제동 제어가 늦으면 사고로 이어집니다.

이런 작업은 "정확한 결과"만큼 **"정해진 시간 안의 결과"** 가 중요합니다.

---

### 3. 시분할 시스템(Time Sharing System)

CPU의 사용 시간을 **아주 짧은 단위(타임 슬라이스)로 나누어** 여러 사용자에게 번갈아 할당하는 방식입니다.

- 각 사용자는 **자신이 혼자 컴퓨터를 사용하는 것처럼** 느낍니다.
- **대화식 처리(Interactive)** 가 가능합니다.

#### 왜 혼자 쓰는 것처럼 느껴질까?

CPU가 사용자 A → B → C → A → B → C ... 순으로 전환하는데,  
이 전환이 **사람이 인지할 수 없을 만큼 빠르게** 일어나기 때문입니다.

사람의 반응 속도는 CPU에 비하면 매우 느리므로,  
그 짧은 순서 대기 시간을 느끼지 못합니다.

즉, 시분할은  
**"빠르게 번갈아 하면 동시에 하는 것처럼 보인다"는 원리**를 이용한 방식입니다.

---

### 4. 다중 프로그래밍 / 다중 처리 시스템

| 방식 | 설명 |
| --- | --- |
| **다중 프로그래밍(Multi-Programming)** | **하나의 CPU**로 여러 개의 프로그램을 번갈아 처리하여, CPU의 유휴 시간을 줄입니다. |
| **다중 처리(Multi-Processing)** | **여러 개의 CPU(또는 코어)** 를 사용하여 여러 프로그램을 **실제로 동시에** 처리합니다. |

#### 왜 다중 프로그래밍이 효율적일까?

프로그램은 실행 중에 **입출력을 기다리는 시간**이 많습니다.  
사용자의 입력을 기다리거나, 디스크에서 데이터가 오기를 기다립니다.

이 시간 동안 CPU는 아무 일도 하지 않고 놀게 됩니다.

다중 프로그래밍은 **한 프로그램이 기다리는 동안 다른 프로그램을 실행**하여,  
CPU가 쉬는 시간을 없앱니다.

> **다중 프로그래밍은 "번갈아", 다중 처리는 "실제로 동시에"** 라는 점이 핵심 차이입니다.

---

### 5. 분산 처리 시스템(Distributed Processing System)

여러 대의 컴퓨터를 네트워크로 연결하여 **작업을 나누어 처리**하는 방식입니다.

- 각 컴퓨터는 독립적으로 동작하면서도 서로 자원을 공유합니다.
- 한 대에 문제가 생겨도 **전체 시스템이 멈추지 않습니다.**
- 시스템 확장이 쉽습니다.

#### 왜 분산 처리를 사용할까?

한 대의 컴퓨터 성능을 무한히 높이는 데는 **물리적·비용적 한계**가 있습니다.

또한 모든 처리를 한 대에 집중하면,  
그 컴퓨터가 고장 났을 때 **전체 서비스가 중단**됩니다.

여러 대에 나누어 처리하면

- 성능을 필요에 따라 **확장**할 수 있고
- 일부가 고장 나도 **나머지가 계속 동작**합니다.

오늘날의 클라우드 서비스가 대표적인 분산 처리 환경입니다.

---

### 6. 임베디드 시스템(Embedded System)

특정 기능을 수행하기 위해 **하드웨어에 내장된 형태로 동작하는 시스템**입니다.

- 예 : 스마트 가전, 자동차 제어 장치, 의료 기기, 산업용 제어 장비
- 제한된 자원에서 **정해진 기능만 안정적으로 수행**하도록 설계됩니다.

---

### 7. 그 밖의 운영 방식

| 방식 | 설명 |
| --- | --- |
| **듀얼 시스템(Dual System)** | 두 개의 시스템이 **동시에 같은 작업을 처리**하고 결과를 비교합니다. 신뢰도가 매우 높습니다. |
| **듀플렉스 시스템(Duplex System)** | 한 시스템이 작동하고, **다른 하나는 대기**하다가 문제가 생기면 즉시 대체합니다. |
| **클러스터링(Clustering)** | 여러 컴퓨터를 묶어 하나의 시스템처럼 사용합니다. |
| **온라인 처리** | 데이터가 발생한 곳에서 통신 회선을 통해 직접 처리합니다. |

#### 듀얼 vs 듀플렉스

| 구분 | 듀얼 시스템 | 듀플렉스 시스템 |
| --- | --- | --- |
| 두 시스템의 상태 | **둘 다 동작** | 하나는 동작, **하나는 대기** |
| 목적 | 결과 비교를 통한 **정확성 확보** | 고장 시 **연속성 확보** |
| 비용 | 높음 | 상대적으로 낮음 |

두 방식 모두 **한 대가 고장 나도 서비스가 멈추지 않게 하는 것**이 목적이지만,  
듀얼은 "정확성", 듀플렉스는 "가용성"에 무게를 둡니다.

---

### 한 줄 정리

운영 방식은 **일괄 처리(모아서) → 실시간(즉시) → 시분할(번갈아 나눠서) → 분산(여러 대에 나눠서)** 로 발전했으며,  
**다중 프로그래밍은 하나의 CPU로 번갈아, 다중 처리는 여러 CPU로 실제 동시에** 처리한다는 점이 핵심 차이입니다.
