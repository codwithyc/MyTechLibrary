### 1. 사용자 정보 조회

```bash
$ whoami                    # 현재 사용자 이름
masterway

$ id                        # ⭐ UID·GID·소속 그룹 전부
uid=1000(masterway) gid=1000(masterway) groups=1000(masterway),10(wheel)

$ id -u                     # UID만
$ id -g                     # 주 GID만
$ id -G                     # 모든 GID
$ id -Gn                    # ⭐ 소속 그룹 이름
$ id devuser                # 다른 사용자

$ groups                    # 소속 그룹
$ groups devuser

$ getent passwd devuser     # ⭐ 계정 정보 (LDAP/NIS 포함)
$ getent group developers   # ⭐ 그룹 정보
$ getent shadow devuser
```

> **`getent`가 중요한 이유**  
> `/etc/passwd`를 직접 읽으면 **로컬 계정만** 보입니다.  
> `getent`는 **`/etc/nsswitch.conf`의 순서**를 따라 LDAP·NIS 계정까지 조회합니다.  
> 중앙 인증 환경에서 계정 확인은 반드시 **`getent passwd`** 로 해야 합니다.

```bash
$ users                     # 이름만 나열

```

#### 로그인 이력

```bash
$ last                      # ⭐ 로그인 성공 이력 (/var/log/wtmp)
$ last -n 10                # 최근 10건
$ last masterway            # 특정 사용자
$ last reboot               # ⭐ 재부팅 이력
$ last -F                   # 전체 시각 표시

$ sudo lastb                # ⭐⭐ 로그인 실패 이력 (/var/log/btmp)
$ sudo lastb -n 20

$ lastlog                   # ⭐ 사용자별 마지막 로그인
$ lastlog -u devuser
$ lastlog -b 90             # ⭐ 90일 이상 미접속 (휴면 계정 점검)
$ lastlog -t 7              # 최근 7일 이내 접속
```

| 명령어 | 로그 파일 | 내용 |
| --- | --- | --- |
| **`who`, `w`** | `/var/run/utmp` | **현재 접속 중** |

| **`lastb`** | **`/var/log/btmp`** | **로그인 실패 이력** ⭐ |
| **`lastlog`** | `/var/log/lastlog` | 사용자별 마지막 로그인 |

>     4521 203.0.113.55

### 3. 사용자 계정 관리

#### 생성 — `useradd`

```bash
$ sudo useradd devuser                        # 기본 생성
$ sudo useradd -m devuser                     # ⭐ 홈 디렉터리 생성
$ sudo useradd -m -s /bin/bash devuser        # 셸 지정
$ sudo useradd -u 1500 -g developers -G wheel,docker \
               -d /home/devuser -s /bin/bash \
               -c "Dev User" -m devuser
$ sudo useradd -M -s /sbin/nologin svcuser    # ⭐ 서비스 전용 계정
$ sudo useradd -r sysuser                     # 시스템 계정 (UID<1000)
$ sudo useradd -e 2026-12-31 tempuser         # 만료일 지정

$ sudo passwd devuser                          # ⭐ 비밀번호 설정 (필수)
```

| 옵션 | 의미 |
| --- | --- |
| **`-m`** | **홈 디렉터리 생성** ⭐ |
| `-M` | 홈 디렉터리 생성 안 함 |
| **`-u`** | UID 지정 |
| **`-g`** | **주 그룹** (1개) |
| **`-G`** | **보조 그룹** (여러 개) |
| **`-d`** | 홈 경로 |
| **`-s`** | 로그인 셸 |
| `-c` | 설명(GECOS) |
| `-e` | 계정 만료일 |
| `-r` | 시스템 계정 |
| `-k` | 스켈레톤 디렉터리 |

> **서비스 전용 계정 만들기** ⭐  
> 데몬을 root로 돌리지 않기 위해 계정을 만들 때는  
> **`-M`(홈 없음) + `-s /sbin/nologin`(로그인 차단)** 조합을 씁니다.
> ```bash
> $ sudo useradd -r -M -s /sbin/nologin nginx
> ```

#### 수정 — `usermod`

```bash
$ sudo usermod -c "New Name" devuser          # 설명 변경
$ sudo usermod -s /bin/zsh devuser            # 셸 변경
$ sudo usermod -l newname oldname             # 로그인명 변경
$ sudo usermod -u 2000 devuser                # UID 변경
$ sudo usermod -d /data/devuser -m devuser    # ⭐ 홈 이동 (-m: 내용도 이동)
$ sudo usermod -g newgroup devuser            # 주 그룹 변경
$ sudo usermod -aG docker devuser             # ⭐⭐ 보조 그룹 추가
$ sudo usermod -G docker devuser              # ❗기존 보조 그룹 전부 사라짐
$ sudo usermod -e 2026-12-31 devuser          # 만료일
$ sudo usermod -L devuser                     # ⭐ 계정 잠금
$ sudo usermod -U devuser                     # 잠금 해제
$ sudo usermod -s /sbin/nologin devuser       # ⭐ 로그인 완전 차단
```

> **⚠️ `-aG` 와 `-G`의 차이 — 가장 흔한 사고**  
> **`-G`** : 보조 그룹을 **지정한 것으로 교체** → 기존 그룹에서 **전부 제외됨** ❗  
> **`-aG`** : 기존 그룹에 **추가** ✅  
>
> `sudo usermod -G docker admin` 을 실행하면 admin이 **wheel 그룹에서 빠져** sudo를 못 쓰게 됩니다.

#### 삭제 — `userdel`

```bash
$ sudo userdel devuser              # 계정만 (홈 남음)
$ sudo userdel -r devuser           # ⭐ 홈·메일 스풀까지 삭제
$ sudo userdel -f devuser           # 로그인 중이어도 강제

# 삭제 후 잔여 파일 정리 ⭐
$ sudo find / -nouser -o -nogroup 2>/dev/null
```

### 4. 비밀번호 관리

```bash
$ passwd                            # 본인 비밀번호 변경
$ sudo passwd devuser               # 다른 사용자 (root만)

$ sudo passwd -S devuser            # ⭐ 상태 확인
devuser PS 2026-02-09 0 99999 7 -1
        │
        └── PS=사용가능, LK=잠김, NP=비밀번호없음

$ sudo passwd -l devuser            # 잠금
$ sudo passwd -u devuser            # 해제
$ sudo passwd -d devuser            # ❗비밀번호 삭제 (위험)
$ sudo passwd -e devuser            # ⭐ 다음 로그인 시 변경 강제
$ sudo passwd -n 1 -x 90 -w 7 devuser   # 최소1일 최대90일 경고7일
```

#### `chage` — 유효기간 관리

```bash
$ sudo chage -l devuser             # ⭐ 현재 설정 조회
Last password change            : Feb 09, 2026
Password expires                : never
Account expires                 : never
Minimum number of days          : 0
Maximum number of days          : 99999
Number of days of warning       : 7

$ sudo chage -M 90 devuser          # ⭐ 최대 사용 90일
$ sudo chage -m 1 devuser           # 최소 사용 1일
$ sudo chage -W 7 devuser           # 만료 7일 전 경고
$ sudo chage -I 30 devuser          # 만료 후 30일 비활성
$ sudo chage -E 2026-12-31 devuser  # ⭐ 계정 만료일
$ sudo chage -E -1 devuser          # 만료 해제
$ sudo chage -d 0 devuser           # ⭐⭐ 다음 로그인 시 변경 강제
```

| 옵션 | 의미 |
| --- | --- |
| **`-l`** | **조회** |
| **`-M`** | 최대 사용일 |
| `-m` | 최소 사용일 |
| **`-W`** | 경고일 |
| `-I` | 비활성일 |
| **`-E`** | **계정 만료일** |
| **`-d 0`** | **즉시 변경 강제** ⭐ |

> **신규 계정 발급 시 관용구** ⭐
> ```bash
> $ sudo useradd -m newuser
> $ sudo passwd newuser
> $ sudo chage -d 0 newuser     # 첫 로그인 시 반드시 변경하게
> ```

### 5. 계정 잠금의 여러 방법 (차이 이해)

| 방법 | 차단 범위 |
| --- | --- |
| `passwd -l` / `usermod -L` | **비밀번호 로그인만** (SSH 키는 통과) ❗ |
| **`usermod -s /sbin/nologin`** | **셸 로그인 차단** (SSH 키도 차단) ⭐ |
| **`chage -E 0`** | **계정 자체 만료** (가장 확실) ⭐ |
| `/etc/nologin` 파일 생성 | **root 외 전체 로그인 차단** |

```bash
# 완전 차단 (권장 조합) ⭐
$ sudo usermod -L devuser
$ sudo usermod -s /sbin/nologin devuser
$ sudo chage -E 0 devuser

# 전체 사용자 임시 차단 (점검 시)
$ sudo touch /etc/nologin
$ sudo rm /etc/nologin
```

> **`passwd -l`만으로는 부족합니다.**  
> SSH 공개키가 등록되어 있으면 **비밀번호 없이도 로그인**됩니다.  
> 퇴사자 처리 시 반드시 **셸 차단 또는 계정 만료**를 함께 해야 합니다.

### 6. 그룹 관리

```bash
# 생성·수정·삭제
$ sudo groupadd developers
$ sudo groupadd -g 1500 developers        # GID 지정
$ sudo groupadd -r sysgroup               # 시스템 그룹
$ sudo groupmod -n newname oldname        # 이름 변경
$ sudo groupmod -g 1600 developers        # GID 변경
$ sudo groupdel developers                # ❗주 그룹으로 쓰이면 삭제 불가

# 멤버 관리
$ sudo usermod -aG developers devuser     # ⭐ 추가 (권장)
$ sudo gpasswd -a devuser developers      # 추가
$ sudo gpasswd -d devuser developers      # ⭐ 제거
$ sudo gpasswd -A admin developers        # 그룹 관리자 지정
$ sudo gpasswd -M user1,user2 developers  # 멤버 전체 교체

# 조회
$ getent group developers                 # ⭐
$ groups devuser
$ grep developers /etc/group

# 주 그룹 임시 전환
$ newgrp developers                       # ⭐ 새 파일이 이 그룹 소유가 됨
```

> **`/etc/group`의 멤버 필드에는 보조 그룹 멤버만 표시됩니다.**  
> **주 그룹**으로 속한 사용자는 나타나지 않으므로,  
> 정확한 확인은 **`id 사용자`** 로 해야 합니다.

### 7. 권한 변경

#### `chmod`

```bash
# 숫자 방식 (r=4, w=2, x=1)
$ chmod 755 script.sh          # rwxr-xr-x
$ chmod 644 data.txt           # rw-r--r--
$ chmod 600 ~/.ssh/id_rsa      # ⭐ 개인키 (rw-------)
$ chmod 700 ~/.ssh             # ⭐ SSH 디렉터리
$ chmod -R 755 /var/www

# 기호 방식
$ chmod u+x script.sh          # 소유자에게 실행 추가
$ chmod g-w data.txt           # 그룹 쓰기 제거
$ chmod o=r data.txt           # 기타는 읽기만
$ chmod a+r data.txt           # 모두에게 읽기
$ chmod ug+rw,o-rwx file       # 조합

# 특수 권한 ⭐
$ chmod 4755 file              # SetUID  (-rwsr-xr-x)
$ chmod 2775 dir               # SetGID  (drwxrwsr-x)
$ chmod 1777 dir               # Sticky  (drwxrwxrwt)
$ chmod u+s file               # SetUID (기호)
$ chmod g+s dir                # SetGID
$ chmod o+t dir                # Sticky

# 참조 복사
$ chmod --reference=a.txt b.txt
```

| 권한 조합 | 용도 |
| --- | --- |
| **644** | 일반 파일 |
| **755** | 실행 파일·디렉터리 |
| **600** | **개인키·비밀 설정** ⭐ |
| **700** | 개인 디렉터리 |
| **1777** | `/tmp` (Sticky) |
| **2775** | 협업 디렉터리 (SetGID) |

> **디렉터리와 파일에 다른 권한 적용** ⭐
> ```bash
> $ find /var/www -type d -exec chmod 755 {} +
> $ find /var/www -type f -exec chmod 644 {} +
> # 또는 대문자 X 사용 (디렉터리와 이미 실행 가능한 파일에만 x)
> $ chmod -R a+rX /var/www
> ```

#### `chown` / `chgrp`

```bash
$ sudo chown devuser file.txt
$ sudo chown devuser:developers file.txt      # ⭐ 소유자+그룹
$ sudo chown :developers file.txt             # 그룹만
$ sudo chown -R apache:apache /var/www        # 재귀
$ sudo chown --reference=a.txt b.txt
$ sudo chgrp developers file.txt
```

> **소유자 변경은 root만 가능합니다.**  
> 일반 사용자가 파일을 남에게 넘길 수 있으면 **디스크 쿼터를 우회**할 수 있기 때문입니다.

#### `umask`

```bash
$ umask                    # 확인
0022
$ umask -S                 # 기호로
u=rwx,g=rx,o=rx

$ umask 022                # ⭐ 파일 644, 디렉터리 755
$ umask 077                # 파일 600, 디렉터리 700 (보안 강화)
$ umask 002                # 파일 664, 디렉터리 775 (협업)

# 영구 적용
$ echo "umask 022" >> ~/.bashrc
```

**계산** : 파일 = **666 − umask**, 디렉터리 = **777 − umask**

### 8. 특수 권한 이해와 점검

| 권한 | 값 | 표시 | 효과 |
| --- | --- | --- | --- |
| **SetUID** | **4** | 소유자 `x` → **`s`** | **파일 소유자 권한으로 실행** |
| **SetGID** | **2** | 그룹 `x` → **`s`** | 그룹 권한 실행 / **디렉터리는 그룹 상속** |
| **Sticky** | **1** | 기타 `x` → **`t`** | **소유자만 삭제 가능** |

```bash
# 대표 예시
$ ls -l /usr/bin/passwd
-rwsr-xr-x. 1 root root 33544 ... /usr/bin/passwd      ← SetUID

$ ls -ld /tmp
drwxrwxrwt. 15 root root 4096 ... /tmp                 ← Sticky

# 협업 디렉터리 (SetGID) ⭐
$ sudo mkdir /project
$ sudo chgrp developers /project
$ sudo chmod 2775 /project
# → 이 안에 만드는 모든 파일이 developers 그룹 소유가 됨
```

> **대문자 `S`/`T`는 실행 권한(`x`)이 없다는 뜻**이며, 설정만 되고 **효과가 없습니다.**

#### 보안 점검

```bash
# SetUID 파일 목록 ⭐
$ sudo find / -perm -4000 -type f 2>/dev/null

# 기준선 저장 후 변화 감시 ⭐
$ sudo find / -perm -4000 -type f 2>/dev/null | sort > /root/setuid.baseline
# 나중에
$ sudo find / -perm -4000 -type f 2>/dev/null | sort | diff /root/setuid.baseline -

# 누구나 쓰기 가능한 파일 (위험) ⭐
$ sudo find / -type f -perm -o+w -not -path "/proc/*" 2>/dev/null

# Sticky 없이 누구나 쓰기 가능한 디렉터리
$ sudo find / -type d -perm -o+w ! -perm -1000 2>/dev/null
```

### 9. ACL — 세밀한 권한

```bash
$ getfacl file.txt                        # ⭐ 확인
# file: file.txt
# owner: masterway
# group: developers
user::rw-
group::r--
other::r--

$ setfacl -m u:devuser:rw file.txt        # ⭐ 특정 사용자에게 권한
$ setfacl -m g:testers:r file.txt         # 특정 그룹
$ setfacl -R -m u:devuser:rwx /project    # 재귀
$ setfacl -d -m u:devuser:rwx /project    # ⭐ 기본 ACL (새 파일에도 적용)
$ setfacl -x u:devuser file.txt           # 특정 항목 제거
$ setfacl -b file.txt                     # 전체 제거

# ACL이 설정된 파일은 ls -l 에 + 표시 ⭐
$ ls -l file.txt
-rw-rw-r--+ 1 masterway developers 1024 ... file.txt
          └── ACL 있음
```

> **ACL이 필요한 경우** : 기본 권한(소유자/그룹/기타)만으로는  
> **"이 사용자 한 명에게만" 권한을 줄 수 없습니다.**  
> 그룹을 새로 만들 만큼은 아닐 때 ACL이 유용합니다.

### 10. 파일 속성 — `chattr`

```bash
$ lsattr file.txt
$ sudo chattr +i /etc/passwd       # ⭐ 변경 불가 (root도 삭제 불가)
$ sudo chattr -i /etc/passwd       # 해제
$ sudo chattr +a /var/log/app.log  # ⭐ 추가만 가능 (로그 보호)
```

| 속성 | 의미 |
| --- | --- |
| **`i`** | **immutable — 수정·삭제·이름변경 불가** |
| **`a`** | **append only — 추가만 가능** |
| `c` | 압축 저장 |
| `s` | 안전 삭제 |

> **침해 조사 시 `lsattr`도 확인하세요.**  
> 공격자가 백도어 파일에 `+i`를 걸어 **삭제를 막는 경우**가 있습니다.

### 11. 권한 상승 — `su` / `sudo`

```bash
# su
$ su - devuser              # ⭐ 로그인 셸 (환경 완전 전환)
$ su devuser                # 현재 환경 유지 (비권장)
$ su -                      # root로 전환
$ su - -c "명령"            # 명령 하나만

# sudo
$ sudo 명령
$ sudo -u devuser 명령      # 특정 사용자 권한으로
$ sudo -i                   # root 로그인 셸
$ sudo -s                   # root 셸 (환경 유지)
$ sudo -l                   # ⭐ 내가 쓸 수 있는 sudo 명령 확인
$ sudo -k                   # 인증 캐시 삭제
$ sudo !!                   # ⭐ 직전 명령을 sudo로 재실행
```

> **`su -`(하이픈)를 써야 하는 이유** ⭐  
> 하이픈이 없으면 **PATH 등 환경 변수가 이전 사용자 것 그대로**입니다.  
> `/sbin`이 PATH에 없어 **관리자 명령을 찾지 못하는** 문제가 생깁니다.

#### `sudoers` 설정

```bash
$ sudo visudo                              # ⭐ 반드시 visudo 사용
$ sudo visudo -f /etc/sudoers.d/devuser    # 개별 파일 (권장) ⭐
```

```
# 사용자  호스트=(실행권한자)  명령
root      ALL=(ALL)    ALL
%wheel    ALL=(ALL)    ALL                 # wheel 그룹 전체
devuser   ALL=(ALL)    NOPASSWD: /usr/bin/systemctl restart httpd
appuser   ALL=(ALL)    /usr/bin/tail /var/log/app.log
```

> **`visudo`를 반드시 써야 하는 이유** ⭐  
> `/etc/sudoers`에 문법 오류가 있으면 **sudo 자체가 동작하지 않습니다.**  
> root 로그인이 막혀 있다면 **시스템 관리가 불가능**해집니다.  
> `visudo`는 저장 전에 **문법을 검사**합니다.

```bash
# sudo 사용 기록 확인 ⭐
$ sudo grep sudo /var/log/secure | grep COMMAND | tail -10
Feb  9 06:00:11 server sudo: masterway : TTY=pts/0 ; PWD=/home/masterway ;
    USER=root ; COMMAND=/usr/bin/systemctl restart httpd
```

### 13. 보안 점검 관용구

```bash
# ⭐ UID 0 계정 (root만 있어야 함)
$ awk -F: '$3 == 0 {print $1}' /etc/passwd

# ⭐ 비밀번호 없는 계정
$ sudo awk -F: '$2 == "" {print $1}' /etc/shadow

# 로그인 가능한 계정 목록
$ grep -vE "nologin|false" /etc/passwd | cut -d: -f1

# 일반 사용자 목록 (UID 1000 이상)
$ awk -F: '$3>=1000 && $3<65534 {print $1}' /etc/passwd

# ⭐ 90일 이상 미접속 계정 (휴면 계정)
$ lastlog -b 90

# ⭐ 로그인 실패 급증 IP
$ sudo lastb | awk '{print $3}' | sort | uniq -c | sort -rn | head

# 중복 UID 점검
$ cut -d: -f3 /etc/passwd | sort | uniq -d

# sudo 권한 보유자
$ getent group wheel
$ sudo grep -vE "^#|^$" /etc/sudoers

# ⭐ SetUID 파일
$ sudo find / -perm -4000 -type f 2>/dev/null

# 비밀번호 만료 정책 미적용 계정
$ for u in $(awk -F: '$3>=1000 {print $1}' /etc/passwd); do
    echo -n "$u: "; sudo chage -l $u | grep "Maximum"
  done
```

### 한 줄 정리

계정 확인은 **`id`·`getent passwd`**, 보안 점검은 **`lastb`(실패 이력)·`find -perm -4000`(SetUID)** 가 핵심이고,  
보조 그룹은 **반드시 `usermod -aG`**(`-G`는 기존 그룹을 날림), 신규 계정은 **`chage -d 0`** 로 첫 변경을 강제하며,  
**`passwd -l`만으로는 SSH 키 로그인을 못 막으므로** 셸 차단이나 계정 만료를 함께 적용해야 합니다.
