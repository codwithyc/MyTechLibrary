## 제 1절 정규화
> 정규화는 중복되는 데이터를 줄이고, 데이터가 이상하게 꼬이지 않도록 테이블을 나누는 작업입니다.

아주 쉽게 정리 하자면
```
한 테이블에 이것저것 다 넣지 말고
각자 맡은 정보끼리 나눠서 관리하자.
```

| 학생번호 | 학생명 | 학과     | 학과전화번호  |
| ---: | --- | ------ | ------- |
|    1 | 철수  | 컴퓨터공학과 | 02-1111 |
|    2 | 영희  | 컴퓨터공학과 | 02-1111 |
|    3 | 민수  | 컴퓨터공학과 | 02-1111 |

여기서는 컴퓨터공학과, 02-1111이 계속 반복됩니다.

그래서

```
학생
학생번호 | 학생명 | 학과코드


학과
학과코드 | 학과명 | 학과전화번호
```

처럼 나누는 것이 정규화입니다.

### 1. 왜 정규화를 하는가?
핵심은 두 가지입니다.

> 중복 줄이기 + 이상현상 없애기

정규화가 안 되어 있으면 **삽입 이상, 수정 이상, 삭제 이상**이 발생할 수 있습니다.

#### 삽입 이상
> 넣고 싶은 데이터만 따로 넣을 수 없는 문제

예를 들어 학생 + 학과가 한 테이블에 있는데 아직 학생이 한 명도 없는 `AI학과`를 등록하고 싶다면 학생 정보까지 같이 넣어야 할 수도 있습니다. 

```
"학과만 넣고 싶은데 학생도 넣으라고?"
→ 삽입 이상
```

#### 수정 이상
> 한 값을 바꾸려면 여러 곳을 전부 수정해야 하는 문제

```
컴퓨터공학과 전화번호
02-1111 → 02-9999
```

컴퓨터공학과 하생이 100명이면 100줄을 수정해야 합니다.
한 줄이라도 안 바꾸면 데이터가 서로 달라집니다.

```
"하나 바꾸려고 여러 줄 수정"
→ 수정 이상
```

#### 삭제 이상
> 필요한 데이터 하나를 지웠는데 다른 중요한 정보까지 사라지는 문제

컴퓨터공학과의 마지막 학생을 삭제했더니 그 행에 같이 있던 `컴퓨터공학과 전화번호`까지 사라집니다.

```
"학생만 지웠는데 학과 정보까지 사라짐"
→ 삭제 이상
```

```
INSERT 문제 → 삽입 이상
UPDATE 문제 → 수정 이상
DELETE 문제 → 삭제 이상
```

### 2. 함수적 종속성
> A 값을 알면 B 값을 정확히 하나 알 수 있다면 B는 A에 종속된다.

표현
```
A -> B
```

### 정규형
| 정규형 | 무엇을 보면 됨?         | 초간단         |
| --- | ----------------- | ----------- |
| 1NF | 한 칸에 여러 값?        | 한 칸에 하나     |
| 2NF | 복합키 일부가 일반 속성 결정? | 키 일부에 기대지 마 |
| 3NF | 일반 속성이 일반 속성 결정?  | 일반끼리 기대지 마  |

1NF
→ 한 칸에 여러 값 제거

2NF
→ 부분 함수 종속 제거
→ 복합키 일부 → 일반 속성 X

3NF
→ 이행 함수 종속 제거
→ 일반 속성 → 일반 속성 X


## 제 2절 관계와 조인의 이해
> 관계 = 데이터 모델에서 엔터티끼리 연결하는 것  
> JOIN = 그 관계를 이용해서 실제 테이블의 데이터를 붙여서 조회하는 것

쉽게 말하면

```
설계할 때 -> 관계(Relationship)
조회할 때 -> JOIN
```

예를 들어

```
학생 - 소속된다 - 학과
```

DB에서는
```
학생
- 학생번호
- 이름
- 학과코드(FK)

학과
- 학과코드(PK)
- 학과명
```
처럼 연결할 수 있습니다.  
그리고 SQL에서 학생의 학과명까지 보고 싶다면

```SQL
SELECT 학생.이름, 학과.학과명
FROM 학생
JOIN 학과
  ON 학생.학과코드 = 학과.학과코드;
```

즉 **관계로 연결해 놓은 데이터를 JOIN으로 같이 조회한다.**

### 1. 관계와 PK / FK
두 테이블을 연결할 때 가장 많이 사용하는 것이 PK와 FK입니다.

예
```
학과
학과코드(PK)
   ↑
   │
   │
학과코드(FK)
학생
```

여기서 
- 학과.학과코드 -> PK
- 학생.학과코드 -> FK

쉽게 PK = 내 번호, FK = 다른 테이블의 번호를 가져와 연결

예
```
학과

C01 → 컴퓨터공학과
C02 → 경영학과

학생:

1001 → 철수 → C01
1002 → 영희 → C02

C01을 이용해서:

철수 → C01 → 컴퓨터공학과
```
라고 연결할 수 있습니다. 

### 2. 1 : 1 관계
> 한쪽 하나가 반대쪽 하나와 연결

예
```
회원 1 ───── 1 회원상세
```

```
회원
회원번호(PK)

회원상세
회원번호(PK/FK)
```

한 회원에게 회원상세가 하나만 존재한다면 1:1입니다.

### 3. 1 : M 관계
> 한쪽 하나가 반대쪽 여러 개와 연결

가장 많이 나오는 관계입니다.

예
```
학생 1 - M 학생
```

하나의 학과에 여러 학생이 있을 수 있습니다.

```
학과
C01 컴퓨터공학과

학생
1001 철수 C01
1002 영희 C01
1003 민수 C01
```

여기서 중요한 규칙 
> 1 : M에서는 보통 M 쪽에 FK가 들어갑니다.

```
학과 1 ───── M 학생
              ↑
          학과코드(FK)
```

### 4. M : N 관계
> 양쪽 모두 여러 개와 연결

예 
```
학생 M ───── N 과목
```

학생 한 명이 여러 과목을 들을 수 있고, 과목 하나도 여러 학생이 들을 수 있습니다.
이걸 그대로 테이블로 만들기 어렵기 때문에 **중간 엔터티**를 만듭니다.

```
학생 1 - M 수강 M - 1 과목
```

예
```
학생
- 학생번호(PK)

과목
- 과목번호(PK)

수강
- 학생번호(PK, FK)
- 과목번호(PK, FK)
```

### 5. JOIN이란?
> JOIN은 서로 관련 있는 두 테이블을 조건에 맞게 붙여서 조회하는 것

예
| 학생번호 | 이름 | 학과코드 |
| ---: | -- | ---- |
| 1001 | 철수 | C01  |
| 1002 | 영희 | C02  |

학과
| 학과코드 | 학과명    |
| ---- | ------ |
| C01  | 컴퓨터공학과 |
| C02  | 경영학과   |

JOIN
```
SELECT A.이름, B.학과명
FROM 학생 A
JOIN 학과 B
  ON A.학과코드 = B.학과코드;
```

결과
| 이름 | 학과명    |
| -- | ------ |
| 철수 | 컴퓨터공학과 |
| 영희 | 경영학과   |

간단하게 말하자면 같은 값을 찾아서 두 테이블을 붙인다.

### 6. EQUI JOIN
> `=` 를 사용해서 연결하는 JOIN

### 7. NON-EQUI JOIN
> `=`가 아닌 조건으로 연결하는 JOIN

예를 들어 점수에 따라 등급을 찾는다고 해보겠습니다.

등급
| 최소점수 | 최대점수 | 등급 |
| ---: | ---: | -- |
|   90 |  100 | A  |
|   80 |   89 | B  |
|   70 |   79 | C  |

학생 점수가 `85`라면

```SQL
ON 학생.점수 BETWEEN 등급.최소점수 AND 등급.최대점수
```
를 이용해서 B를 찾을 수 있습니다.

즉 **NON-EQUI JOIN = 이외의 조건**

대표적으로 >, <. >= <=, BETWEEN

### 8. JOIN 조건이 없으면?
두 테이블을 연결하면서 JOIN 조건을 제대로 주지 않으면 **모든 조합이 만들어질 수 있습니다.**

학생
```
철수
영희
```

학과
```
컴퓨터공학과
경영학과
```

조건 없이 전부 붙이면

```
철수 + 컴퓨터공학과
철수 + 경영학과
영희 + 컴퓨터공학과
영희 + 경영학과
2명 × 2학과 = 4건입니다.
```

이걸 카티션 곱(Cartesian Product)이라고 합니다.
> JOIN 조건 없음 → 전부 × 전부

### 9. 관계와 JOIN에서 중요한 차이

#### 관계
> 데이터 모델 설계에서 엔터티가 서로 연결되어 있다는 의미

#### JOIN
> SQL을 실행할 때 실제 데이터를 붙이는 방법

## 제 3절 모델이 표현하는 트랜잭션의 이해
> 트랜잭션 (Transaction) = 하나로 묶어서 처리해야 하는 업무 단위 
> 쉽게 말하자면 "이 일들은 따로 하면 안 되고 같이 성공하거나 같이 취소되어야 함"

하나의 트랜잭션 안에는 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 같은 여러 SQL 작업이 포함될 수 있습니다.

### 1. 트랜잭션이란?

가장 대표적인 예시가 **계좌이체**입니다.

A가 B에게 10,000원을 보냅니다.
```
① A 계좌에서 10,000원 빼기
② B 계좌에 10,000원 넣기
```

둘 중 하나만 성공하면 어떻게 될까요?

```
A에서 돈 빠짐      ✅
B에게 돈 안 들어감 ❌
```

돈이 사라지게 됩니다.

따라서 반드시
```
① 성공 + ② 성공
        또는
① 취소 + ② 취소
```

즉 **전부 성공하거나 전부 실패한다** 이것이 트랜잭션의 가장 기본적인 개념입니다.

### 2. COMMIT 과 ROLLBACK

#### COMMIT
> 작업을 성공적으로 확정

#### ROLLBACK
> 문제가 생기면 작업을 취소하고 원래대로

### 3. 왜 데이터 모델에서 트랜잭션을 보는가?
> 데이터 모델의 관계를 보면 "이 두 데이터가 업무적으로 같이 처리되어야 하는가?" 를 파악할 수 있기 때문입니다.

예
```
주문 ───── 주문상세
```

주문이 발생하면 주문에 포함된 상품들의 주문상세도 함께 발생합니다.

```
주문 생성
   ↓
주문상세 생성
```

즉 데이터 모델의 관계를 통해 **업무가 어떤 단위로 함께 처리되는지** 파악할 수 있습니다.

### 4. 트랜잭션 필수 관계
> 하나의 트랜잭션으로 반드시 함께 처리되어야 하는 관계 -> 필수적 관계  
> 서로 독립적으로 처리할 수 있는 관계 -> 선택적 관계 

## 제 4절 Null 속성의 이해

> **NULL = 값이 없는 것이 아니라, 아직 모르거나 정해지지 않은 상태**

초간단 키워드:

* **NULL** → 값 모름 / 값 없음 / 미정
* **0** → 숫자 0
* **''** → 빈 문자열
* **NULL ≠ 0**
* **NULL ≠ 공백**
* **NULL 비교** → `IS NULL`, `IS NOT NULL`
* **`= NULL` 사용 X**
* **NULL과 연산** → 결과도 보통 NULL
* **집계함수** → 대부분 NULL 제외
* **COUNT(*)** → NULL 상관없이 행 수 계산

예:

```text
전화번호 = NULL
→ 전화번호를 아직 모름
```

```text
재고수량 = 0
→ 재고가 없다는 값을 알고 있음
```

핵심:

> **NULL = 모르는 상태**
> **0 = 0이라는 값을 아는 상태**

## 제 5절 본질식별자 vs 인조식별자

### 본질식별자

> **업무에서 원래 의미를 가지고 존재하는 식별자**

예:

```text
사원번호
학번
주문번호
```

초간단:

> **본질 = 업무에서 원래 쓰던 식별값**

---

### 인조식별자

> **시스템에서 관리하기 쉽게 새로 만든 식별자**

예:

```text
ID = 1
ID = 2
ID = 3
```

또는:

```text
AUTO_INCREMENT
SEQUENCE
UUID
```

초간단:

> **인조 = 시스템이 새로 만든 ID**
```
