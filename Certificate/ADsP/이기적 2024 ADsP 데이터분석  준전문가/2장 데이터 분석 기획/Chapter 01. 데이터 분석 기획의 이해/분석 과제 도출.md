# 분석 과제 도출

분석 과제 도출은 데이터 분석을 바로 수행하는 단계가 아니라, **어떤 문제를 분석 대상으로 삼을지 정하고,  
그 문제가 실제로 분석 가능한지 판단하는 과정**이다.

즉, 분석 과제 도출의 핵심은 다음과 같다.

```markdown
문제 인식 → 분석 가능성 검토 → 분석 과제 정의 → 수행 방안 수립
```

ADsP 시험에서는 이 파트에서 주로 다음 내용을 묻는다.

* 분석 기획이 무엇인가  
* 분석 주제 유형 4가지를 구분할 수 있는가  
* 단기 과제 중심 접근과 장기 마스터플랜 방식을 구분할 수 있는가  
* 분석 기획 시 고려해야 할 요소를 알고 있는가  

---

## 01. 분석 기획

## 1) 분석 기획의 정의 및 특징

### 분석 기획의 정의

**분석 기획**이란 데이터 분석을 수행하기 전에, 분석의 목적과 방향을 정하고 분석 과제를 구체화하는 과정이다.  

단순히 데이터를 가지고 무언가를 해보는 것이 아니라,  
**비즈니스 문제를 데이터 분석이 가능한 과제로 바꾸는 사전 계획 작업**이라고 이해하면 된다.

예를 들어,  
“매출이 떨어졌다”는 것은 단순한 문제 상황이다.  
이를 분석 기획 단계에서는 다음과 같이 분석 가능한 질문으로 바꾼다.

```markdown
최근 매출 하락의 원인은 무엇인가?
특정 고객군의 구매 빈도가 감소했는가?
상품별, 지역별, 기간별 매출 변화에 차이가 있는가?
분석 결과를 통해 어떤 개선 전략을 세울 수 있는가?
```

즉, 분석 기획은 **문제를 분석 가능한 형태로 정리하고, 어떤 데이터를 활용해 어떤 방식으로 해결할지 계획하는 단계**이다.  

---

### 분석 기획의 핵심 질문

| 질문     | 의미                  |
| ------ | ------------------- |
| What   | 무엇을 분석할 것인가?        |
| Why    | 왜 분석해야 하는가?         |
| Data   | 어떤 데이터를 사용할 것인가?    |
| How    | 어떤 방법으로 분석할 것인가?    |
| Result | 분석 결과를 어떻게 활용할 것인가? |

이 표에서 가장 중요한 것은 **Why와 Result**다.

분석은 단순히 모델을 만들거나 통계를 계산하는 작업이 아니다.
분석 결과가 실제 의사결정이나 업무 개선에 연결되어야 한다.

따라서 시험에서는 분석 기획을 다음처럼 이해하면 된다.

```markdown
분석 기획 = 분석 전에 문제, 데이터, 방법, 활용 방안을 정하는 과정
```

---

### 분석 기획의 특징

| 특징          | 설명                                 |
| ----------- | ---------------------------------- |
| 사전 계획 작업    | 분석을 수행하기 전에 방향을 잡는 단계              |
| 목표 중심       | 분석 자체가 목적이 아니라 비즈니스 문제 해결이 목적      |
| 과제 정의       | 어떤 문제를 분석 과제로 삼을지 정한다              |
| 관리 방안 포함    | 일정, 자원, 위험, 결과 활용 방안까지 고려한다        |
| 균형 잡힌 역량 필요 | 비즈니스 이해, 통계 지식, IT/데이터 처리 역량이 필요하다 |

분석 기획의 핵심 특징은 **분석 전 단계**라는 점이다.

데이터 분석을 잘하려면 데이터와 알고리즘만 알아서는 부족하다.  
현업의 문제를 이해해야 하고, 그 문제를 분석 가능한 형태로 바꾸어야 하며, 분석 결과가 실제로 활용될 수 있어야 한다.  

그래서 분석 기획에는 다음 역량이 함께 필요하다.

---

### 데이터 분석 기획에 필요한 역량

| 역량           | 설명                             |
| ------------ | ------------------------------ |
| 비즈니스 이해      | 문제 상황, 업무 흐름, 의사결정 구조를 이해하는 능력 |
| 수학·통계 지식     | 데이터를 해석하고 모델링할 수 있는 분석 능력      |
| IT·데이터 처리 기술 | 데이터를 수집, 저장, 처리, 분석 도구로 다루는 능력 |

암기할 때는 이렇게 외우면 된다.

```markdown
분석 기획 역량 = 비즈니스 이해 + 통계 지식 + IT 기술
```

여기서 **비즈니스 이해**는 “무엇이 문제인지 아는 능력”이고,  
**통계 지식**은 “데이터를 해석하는 능력”이며,  
**IT 기술**은 “데이터를 실제로 다루는 능력”이다.

---

## 2) 분석 주제 유형

분석 주제 유형은 ADsP에서 자주 나오는 개념이다.

핵심 기준은 2가지다.

```markdown
분석 대상이 명확한가? = What
분석 방법이 명확한가? = How
```

즉, 분석 주제는 **무엇을 분석할지 알고 있는지**,
그리고 **어떻게 분석할지 알고 있는지**에 따라 4가지로 나뉜다.

| 구분 | 분석 대상 What | 분석 방법 How | 유형           |
| -- | ---------- | --------- | ------------ |
| 1  | Known      | Known     | Optimization |
| 2  | Known      | Unknown   | Solution     |
| 3  | Unknown    | Known     | Insight      |
| 4  | Unknown    | Unknown   | Discovery    |

---

### ① Optimization, 최적화

**Optimization**은 분석 대상도 알고 있고, 분석 방법도 알고 있는 경우다.

즉, 이미 알고 있는 문제에 대해 이미 알고 있는 분석 방법을 적용해서  
**더 나은 결과를 만드는 것**이다.

예를 들어,  
배송 비용을 줄여야 한다는 문제를 알고 있고,  
경로 최적화 알고리즘을 적용하면 된다는 방법도 알고 있다면 Optimization이다.

| 구분    | 내용                              |
| ----- | ------------------------------- |
| 분석 대상 | 알고 있음                           |
| 분석 방법 | 알고 있음                           |
| 핵심    | 기존 문제를 더 좋게 개선                  |
| 예시    | 배송 경로 최적화, 재고 수준 최적화, 광고 예산 최적화 |

시험에서는 이렇게 판단하면 된다.

```markdown
문제도 알고 방법도 안다 → 최적화
```

---

### ② Solution, 해법 도출

**Solution**은 분석 대상은 알고 있지만, 분석 방법은 모르는 경우다.

즉, 해결해야 할 문제는 명확하지만  
그 문제를 어떤 분석 기법으로 해결해야 할지는 아직 정해지지 않은 상태다.

예를 들어,  
고객 이탈률이 증가했다는 문제는 알고 있다.  
하지만 이탈 예측 모델을 만들지, 고객 군집 분석을 할지, 설문 데이터를 분석할지 모른다면 Solution이다.

| 구분    | 내용                                   |
| ----- | ------------------------------------ |
| 분석 대상 | 알고 있음                                |
| 분석 방법 | 모름                                   |
| 핵심    | 문제는 명확하지만 해결 방법을 찾아야 함               |
| 예시    | 고객 이탈 원인은 알고 싶지만 어떤 모델을 써야 할지 모르는 경우 |

시험에서는 이렇게 판단하면 된다.

```markdown
문제는 아는데 방법을 모른다 → 해법 도출
```

---

### ③ Insight, 통찰 도출

**Insight**는 분석 대상은 명확하지 않지만, 분석 방법은 알고 있는 경우다.

즉, 특정 분석 기법을 적용해서  
데이터 속에서 의미 있는 패턴이나 시사점을 찾는 것이다.

예를 들어,  
고객 데이터를 군집 분석해보자는 방법은 정해져 있다.  
하지만 어떤 고객 유형이 나올지는 모른다.  
이런 경우가 Insight다.  

| 구분    | 내용                              |
| ----- | ------------------------------- |
| 분석 대상 | 모름                              |
| 분석 방법 | 알고 있음                           |
| 핵심    | 분석 기법을 통해 의미 있는 패턴 발견           |
| 예시    | 고객 구매 데이터를 군집 분석해서 새로운 고객 유형 발견 |

시험에서는 이렇게 판단하면 된다.

```markdown
방법은 아는데 무엇을 찾을지 모른다 → 통찰 도출
```

---

### ④ Discovery, 발견

**Discovery**는 분석 대상도 모르고, 분석 방법도 모르는 경우다.

즉, 아직 문제도 명확하지 않고, 어떤 분석 방법을 사용할지도 정해지지 않은 탐색 단계다.

예를 들어,  
“우리 서비스 로그 데이터를 분석해서 의미 있는 것을 찾아보자”처럼  
무엇을 분석할지도, 어떤 기법을 사용할지도 명확하지 않다면 Discovery다.

| 구분    | 내용                               |
| ----- | -------------------------------- |
| 분석 대상 | 모름                               |
| 분석 방법 | 모름                               |
| 핵심    | 새로운 문제나 기회를 탐색                   |
| 예시    | 대량의 로그 데이터를 탐색해 예상하지 못한 이상 패턴 발견 |

시험에서는 이렇게 판단하면 된다.

```markdown
문제도 모르고 방법도 모른다 → 발견
```

---

### 분석 주제 유형 암기표

| 분석 방법 How ↓ / 분석 대상 What → | Known        | Unknown   |
| -------------------------- | ------------ | --------- |
| Known                      | Optimization | Insight   |
| Unknown                    | Solution     | Discovery |

이 표는 시험 직전에 반드시 외워야 한다.

외우는 방식은 다음과 같다.

```markdown
What과 How를 둘 다 알면 Optimization
What만 알면 Solution
How만 알면 Insight
둘 다 모르면 Discovery
```

## 02. 분석 기획 방안 및 고려사항

## 1) 목표 시점별 분석 기획 방안

분석 기획은 목표 시점에 따라 크게 2가지로 나뉜다.

```markdown
단기적으로 문제를 해결할 것인가?
중장기적으로 분석 체계를 만들 것인가?
```

이에 따라 **과제 중심 접근 방식**과 **장기 마스터플랜 방식**으로 구분된다.

| 구분    | 과제 중심 접근 방식     | 장기 마스터플랜 방식        |
| ----- | --------------- | ------------------ |
| 관점    | 단기              | 중장기                |
| 목적    | 당면한 문제 해결       | 지속적인 분석 역량 확보      |
| 핵심    | 빠르게 문제 해결       | 분석 체계와 로드맵 수립      |
| 과제 유형 | Quick-Win       | 장기 전략 과제           |
| 접근 방식 | Problem Solving | Problem Definition |
| 특징    | 속도와 실행 중심       | 체계와 내재화 중심         |

---

### ① 과제 중심 접근 방식

**과제 중심 접근 방식**은 당장 해결해야 할 문제를 중심으로 분석 과제를 도출하는 방식이다.

핵심은 **빠른 문제 해결**이다.

예를 들어,  
고객 이탈률이 갑자기 증가했거나,  
매출이 특정 기간에 급격히 감소했거나,  
마케팅 캠페인 성과가 예상보다 낮게 나온 경우에는  
빠르게 원인을 분석하고 대응 방안을 찾아야 한다.  

이런 경우에는 장기적인 분석 체계를 먼저 만들기보다,  
현재 발생한 문제를 해결하는 것이 우선이다.

| 항목    | 내용                           |
| ----- | ---------------------------- |
| 목표    | 당면한 문제 해결                    |
| 기간    | 단기                           |
| 핵심    | 빠른 실행, 빠른 검증                 |
| 과제 유형 | Quick-Win                    |
| 예시    | 매출 감소 원인 분석, 고객 이탈률 증가 원인 분석 |

시험에서는 이렇게 정리하면 된다.

```markdown
과제 중심 접근 방식 = 단기 문제 해결 중심
```

---

### ② 장기 마스터플랜 방식

**장기 마스터플랜 방식**은 조직 전체의 분석 역량을 높이기 위해 중장기적인 분석 계획을 수립하는 방식이다.

핵심은 **분석 체계 구축과 분석 역량 내재화**다.

예를 들어,  
전사 데이터 분석 플랫폼을 구축하거나,  
데이터 거버넌스를 정비하거나,  
부서별 분석 과제를 로드맵으로 관리하는 경우가 여기에 해당한다.  

이 방식은 당장의 문제 하나를 해결하는 것보다  
조직이 지속적으로 데이터를 활용할 수 있는 구조를 만드는 데 초점이 있다.

| 항목    | 내용                                              |
| ----- | ----------------------------------------------- |
| 목표    | 분석 체계 구축                                        |
| 기간    | 중장기                                             |
| 핵심    | 분석 역량 내재화                                       |
| 과제 유형 | 전략적 분석 과제                                       |
| 예시    | 전사 데이터 분석 플랫폼 구축, 분석 거버넌스 수립, 데이터 기반 의사결정 체계 구축 |

시험에서는 이렇게 정리하면 된다.

```markdown
장기 마스터플랜 방식 = 중장기 분석 체계 구축
```

---

### 과제 중심 접근 방식과 장기 마스터플랜 방식 비교

둘의 차이는 **기간과 목적**이다.

과제 중심 접근은 지금 당장 발생한 문제를 해결하는 방식이고,  
장기 마스터플랜은 앞으로 계속 분석을 잘하기 위한 구조를 만드는 방식이다.

```markdown
과제 중심 = 지금 문제 해결
마스터플랜 = 앞으로의 분석 체계 구축
```

---

## 2) 분석 기획시 고려 사항

분석 기획을 할 때는 크게 3가지를 고려해야 한다.

```markdown
데이터가 있는가?
분석 결과를 쓸 수 있는가?
분석 수행에 방해되는 요소는 없는가?
```

즉, 분석 기획의 고려사항은 **가용 데이터, 활용 방안, 장애 요소**로 정리할 수 있다.

---

## ① 가용 데이터

가용 데이터란 분석에 사용할 수 있는 데이터를 의미한다.

분석을 하고 싶어도 필요한 데이터가 없거나,  
데이터 품질이 낮거나,  
데이터 접근 권한이 없다면 분석을 제대로 수행할 수 없다.  

따라서 분석 기획 단계에서는 먼저 다음을 확인해야 한다.

| 고려 항목     | 설명                         |
| --------- | -------------------------- |
| 데이터 존재 여부 | 필요한 데이터가 실제로 존재하는가?        |
| 데이터 품질    | 결측치, 오류, 중복이 많은가?          |
| 데이터 접근성   | 데이터를 가져올 수 있는 권한과 경로가 있는가? |
| 데이터 충분성   | 분석에 필요한 양과 기간이 충분한가?       |

시험에서는 이렇게 이해하면 된다.

```markdown
가용 데이터 = 분석에 필요한 데이터를 확보할 수 있는지 검토하는 것
```

데이터가 없으면 분석도 없다.
따라서 분석 기획에서 가장 먼저 확인해야 할 요소는 **데이터 확보 가능성**이다.

---

## ② 적절한 활용 방안과 유스케이스

분석 결과는 실제 업무에 활용될 수 있어야 한다.

분석 모델의 정확도가 높더라도,  
현업에서 사용할 수 없거나 의사결정에 연결되지 않으면 좋은 분석이라고 보기 어렵다.

예를 들어,  
고객 이탈 예측 모델을 만들었다면 단순히 “이 고객은 이탈 가능성이 높다”에서 끝나면 안 된다.

그 결과를 바탕으로 다음과 같은 행동이 가능해야 한다.

```markdown
이탈 가능성이 높은 고객에게 쿠폰을 제공한다.
상담 우선순위를 조정한다.
서비스 불만 요인을 개선한다.
마케팅 캠페인 대상을 재설정한다.
```

| 고려 항목    | 설명                              |
| -------- | ------------------------------- |
| 활용 가능성   | 분석 결과를 실제 업무에 적용할 수 있는가?        |
| 의사결정 연결성 | 분석 결과가 의사결정에 도움을 주는가?           |
| 업무 개선 효과 | 비용 절감, 매출 증가, 리스크 감소 등 효과가 있는가? |
| 사용자 관점   | 현업 담당자가 이해하고 사용할 수 있는가?         |

시험에서는 이렇게 이해하면 된다.

```markdown
활용 방안 = 분석 결과가 실제 의사결정과 업무 개선에 연결되는지 검토하는 것
```

분석의 최종 목적은 분석 보고서를 만드는 것이 아니라,
**비즈니스 가치를 만드는 것**이다.

---

## ③ 장애 요소

장애 요소란 분석 과제를 수행하거나 활용하는 과정에서 발생할 수 있는 방해 요인을 의미한다.

분석 기획 단계에서 장애 요소를 미리 파악하지 않으면,  
실제 분석 수행 중에 일정 지연, 비용 증가, 데이터 확보 실패, 현업 반발 등이 발생할 수 있다.

대표적인 장애 요소는 다음과 같다.

| 장애 요소      | 설명                             |
| ---------- | ------------------------------ |
| 데이터 부족     | 필요한 데이터가 없거나 양이 부족함            |
| 데이터 품질 문제  | 오류, 결측, 중복, 비정형 데이터 문제         |
| 조직 저항      | 현업 부서가 분석 결과를 신뢰하지 않거나 활용하지 않음 |
| 기술 부족      | 분석 도구, 인프라, 전문 인력이 부족함         |
| 비용과 일정     | 분석에 필요한 시간과 비용이 부족함            |
| 보안·개인정보 이슈 | 데이터 활용에 법적·보안상 제약이 있음          |

시험에서는 이렇게 이해하면 된다.

```markdown
장애 요소 = 분석 수행과 활용을 어렵게 만드는 조직·기술·비용·보안상의 제약
```

특히 ADsP에서는 **개인정보, 보안, 데이터 품질, 조직 저항** 같은 키워드가 자주 연결된다.

## 분석 주제 유형 핵심

| 유형           | What    | How     | 핵심                 |
| ------------ | ------- | ------- | ------------------ |

| Solution     | Known   | Unknown | 문제는 알지만 해법을 찾음     |
| Insight      | Unknown | Known   | 방법을 통해 통찰 발견       |
| Discovery    | Unknown | Unknown | 문제와 방법을 새롭게 발견     |

| 구분       | 핵심                      |
| -------- | ----------------------- |

| 장기 마스터플랜 | 중장기, 분석 내재화, 로드맵 수립     |

---

## 분석 기획 시 고려사항 핵심

| 고려사항   | 핵심 질문                        |

| 가용 데이터 | 분석에 필요한 데이터가 있는가?            |
| 활용 방안  | 분석 결과를 실제로 쓸 수 있는가?          |
| 장애 요소  | 데이터, 조직, 기술, 비용, 보안 문제가 없는가? |

# 시험 직전 암기 문장

```markdown
분석 기획은 분석 수행 전에 분석 과제를 정의하고,
목표 달성을 위한 데이터, 분석 방법, 관리 방안을 사전에 계획하는 작업이다.

분석 주제 유형은 분석 대상(What)과 분석 방법(How)의 명확성에 따라
Optimization, Solution, Insight, Discovery로 구분된다.

Optimization은 대상과 방법을 모두 아는 경우,
Solution은 대상은 알지만 방법을 모르는 경우,
Insight는 대상은 모르지만 방법을 아는 경우,
Discovery는 대상과 방법을 모두 모르는 경우이다.

목표 시점별 분석 기획 방안은 단기 과제 중심 접근 방식과
중장기 마스터플랜 방식으로 구분된다.

과제 중심 접근 방식은 당면한 문제를 빠르게 해결하는 방식이고,
장기 마스터플랜 방식은 조직의 분석 체계와 역량을 구축하는 방식이다.

분석 기획 시에는 가용 데이터, 분석 결과의 활용 방안,
조직·기술·비용·보안 등 장애 요소를 고려해야 한다.
```

이 정도 느낌이면 **개념 설명 → 표로 정리 → 암기 문장** 흐름이라 시험 직전 복습용으로도 꽤 좋아.
