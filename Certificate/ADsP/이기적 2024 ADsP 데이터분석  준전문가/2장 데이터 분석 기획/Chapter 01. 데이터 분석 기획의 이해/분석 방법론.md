# 분석 방법론

분석 방법론은 데이터 분석을 체계적으로 수행하기 위한 **절차와 기준**이다.

데이터 분석은 단순히 데이터를 수집하고 모델을 만드는 작업이 아니다.
분석 목적을 정하고, 데이터를 준비하고, 분석을 수행하고, 결과를 평가하고, 실제 업무에 적용하는 전체 과정이 필요하다.

즉, 분석 방법론은 다음 질문에 답하기 위한 체계다.

```markdown id="xkgx5q"
분석을 어떤 순서로 진행할 것인가?
각 단계에서 무엇을 해야 하는가?
분석 결과를 어떻게 검증하고 활용할 것인가?
```

ADsP 시험에서는 주로 다음 내용을 묻는다.

* 데이터 분석 방법론의 개념
* 폭포수 모델, 프로토타입 모델, 나선형 모델의 차이
* SEMMA, KDD, CRISP-DM의 단계 순서
* 빅데이터 분석 방법론의 5단계 흐름

---

# 01. 데이터 분석 방법론

## 1) 데이터 분석 방법론 개요

### 데이터 분석 방법론의 정의

**데이터 분석 방법론**이란 데이터 분석 과제를 체계적으로 수행하기 위해 정리된 절차, 방법, 도구, 산출물의 체계를 의미한다.

쉽게 말하면,
분석 프로젝트를 감으로 진행하지 않고 **정해진 절차에 따라 안정적으로 수행하기 위한 기준**이다.

예를 들어, 분석 프로젝트를 다음처럼 무작정 시작하면 실패하기 쉽다.

```markdown id="ygmfw7"
데이터부터 모아보자.
모델부터 만들어보자.
결과가 나오면 그때 해석하자.
```

이런 방식은 분석 목적이 불명확하고, 결과 활용도 어려워질 수 있다.

반대로 분석 방법론을 적용하면 다음 흐름으로 진행한다.

```markdown id="xo6hne"
분석 목적 정의
→ 데이터 수집 및 준비
→ 분석 수행
→ 결과 검증
→ 업무 적용
→ 평가 및 개선
```

즉, 데이터 분석 방법론은 **분석 프로젝트의 실패 가능성을 줄이고, 분석 결과의 신뢰성과 활용성을 높이기 위한 체계**다.

---

### 데이터 분석 방법론의 필요성

| 필요성        | 설명                              |
| ---------- | ------------------------------- |
| 체계적인 분석 수행 | 분석을 정해진 절차에 따라 진행할 수 있다         |
| 품질 확보      | 분석 결과의 신뢰성과 재현성을 높일 수 있다        |
| 일정 및 자원 관리 | 분석 프로젝트의 범위, 일정, 인력을 관리할 수 있다   |
| 의사소통 개선    | 분석가, 현업, IT 담당자 간 협업 기준을 제공한다   |
| 위험 감소      | 데이터 부족, 모델 오류, 활용 실패 등의 위험을 줄인다 |

데이터 분석은 여러 부서와 역할이 함께 수행하는 경우가 많다.
따라서 분석 방법론이 없으면 각자가 다른 기준으로 움직이게 된다.

시험에서는 이렇게 이해하면 된다.

```markdown id="ua4w8a"
데이터 분석 방법론 = 분석 과제를 체계적으로 수행하기 위한 절차와 기준
```

---

## 2) 분석 방법론의 적용 업무 특성에 따른 모델

분석 방법론은 업무 특성에 따라 여러 모델로 적용된다.

대표적으로 다음 3가지가 있다.

```markdown id="qmjcvh"
폭포수 모델
프로토타입 모델
나선형 모델
```

---

## ① 폭포수 모델

**폭포수 모델**은 분석 과정을 단계별로 순차적으로 진행하는 방식이다.

한 단계가 끝나야 다음 단계로 넘어가는 구조다.

```markdown id="mbmj40"
요구사항 정의 → 설계 → 구현 → 테스트 → 운영
```

물이 위에서 아래로 흐르듯이,
앞 단계에서 뒤 단계로 순차적으로 진행된다고 해서 폭포수 모델이라고 한다.

| 구분     | 내용                         |
| ------ | -------------------------- |
| 진행 방식  | 순차적 진행                     |
| 특징     | 이전 단계가 끝난 후 다음 단계 진행       |
| 장점     | 절차가 명확하고 관리가 쉽다            |
| 단점     | 중간에 요구사항 변경이 어렵다           |
| 적합한 경우 | 요구사항이 명확하고 변경 가능성이 낮은 프로젝트 |

시험에서는 이렇게 판단하면 된다.

```markdown id="tfi0qv"
폭포수 모델 = 순차적 진행, 요구사항 변경 어려움
```

---

## ② 프로토타입 모델

**프로토타입 모델**은 완성된 결과물을 바로 만드는 것이 아니라,
초기 시제품을 먼저 만들어 사용자의 요구사항을 확인하고 개선하는 방식이다.

즉, 사용자가 원하는 것을 정확히 모를 때
간단한 모델을 먼저 만들어 보여주고 피드백을 받는다.

```markdown id="b6jjaj"
초기 모델 제작 → 사용자 피드백 → 수정 및 보완 → 최종 개발
```

| 구분     | 내용                            |
| ------ | ----------------------------- |
| 진행 방식  | 시제품을 먼저 만들고 개선                |
| 특징     | 사용자 피드백을 빠르게 반영               |
| 장점     | 요구사항을 구체화하기 쉽다                |
| 단점     | 반복 과정에서 일정이 늘어날 수 있다          |
| 적합한 경우 | 요구사항이 불명확하거나 사용자 의견이 중요한 프로젝트 |

시험에서는 이렇게 판단하면 된다.

```markdown id="fmn1ak"
프로토타입 모델 = 시제품을 통해 요구사항을 구체화
```

---

## ③ 나선형 모델

**나선형 모델**은 반복적으로 개발하면서 각 단계마다 위험 요소를 분석하고 관리하는 방식이다.

폭포수 모델처럼 순차적으로만 진행하지 않고,
프로토타입 모델처럼 반복하면서 개선하되,
특히 **위험 관리**를 중요하게 본다.

```markdown id="g8ns7m"
계획 수립 → 위험 분석 → 개발 및 검증 → 고객 평가 → 반복
```

| 구분     | 내용                    |
| ------ | --------------------- |
| 진행 방식  | 반복적·점진적 진행            |
| 특징     | 반복 과정마다 위험 요소를 분석     |
| 장점     | 대규모 프로젝트의 위험을 줄일 수 있다 |
| 단점     | 관리가 복잡하고 비용이 증가할 수 있다 |
| 적합한 경우 | 규모가 크고 위험 요소가 많은 프로젝트 |

시험에서는 이렇게 판단하면 된다.

```markdown id="ay0pz6"
나선형 모델 = 반복 개발 + 위험 관리
```

---

### 적용 업무 특성에 따른 모델 비교

| 구분     | 폭포수 모델    | 프로토타입 모델      | 나선형 모델       |
| ------ | --------- | ------------- | ------------ |
| 핵심     | 순차적 진행    | 시제품 기반 개선     | 반복 개발과 위험 관리 |
| 요구사항   | 명확함       | 불명확함          | 변경 가능성 있음    |
| 장점     | 관리가 쉽다    | 사용자 요구 반영이 쉽다 | 위험 관리에 강하다   |
| 단점     | 변경이 어렵다   | 반복으로 일정 증가 가능 | 관리 복잡, 비용 증가 |
| 적합한 경우 | 정형화된 프로젝트 | 요구사항 탐색 프로젝트  | 대규모·고위험 프로젝트 |

암기 방식은 다음과 같다.

```markdown id="uw9lyo"
폭포수 = 순차
프로토타입 = 시제품
나선형 = 반복 + 위험관리
```

## 3) 분석 방법론의 종류

데이터 분석 방법론은 분석 목적과 분야에 따라 여러 종류가 있다.

ADsP에서는 특히 다음 3가지를 중요하게 본다.

| 방법론      | 핵심                          |
| -------- | --------------------------- |
| SEMMA    | SAS 중심의 데이터 마이닝 방법론         |
| KDD      | 데이터베이스에서 지식을 발견하는 과정        |
| CRISP-DM | 산업 전반에서 사용하는 표준 데이터 마이닝 방법론 |

이 3가지는 이름보다 **단계 순서**가 중요하다.

```markdown id="dqmy42"
SEMMA = Sample → Explore → Modify → Model → Assess
KDD = Selection → Preprocessing → Transformation → Data Mining → Interpretation/Evaluation
CRISP-DM = Business Understanding → Data Understanding → Data Preparation → Modeling → Evaluation → Deployment
```

# 02. 데이터 마이닝 분석 방법론

데이터 마이닝 분석 방법론은 대량의 데이터에서 의미 있는 패턴, 규칙, 지식을 발견하기 위한 분석 절차다.

대표적인 방법론은 다음 3가지다.

```markdown id="txx1jr"
SEMMA
KDD
CRISP-DM
```

---

## 1) SEMMA 분석 방법론

### SEMMA의 개념

**SEMMA**는 SAS Institute에서 제시한 데이터 마이닝 방법론이다.

데이터에서 표본을 추출하고, 탐색하고, 변환하고, 모델을 만들고, 평가하는 순서로 진행된다.

SEMMA는 다음 5단계로 구성된다.

```markdown id="hl2b7m"
Sample → Explore → Modify → Model → Assess
```

---

### SEMMA 단계

| 단계      | 의미        | 설명                         |
| ------- | --------- | -------------------------- |
| Sample  | 표본 추출     | 분석에 사용할 데이터를 추출한다          |
| Explore | 데이터 탐색    | 데이터의 특성, 분포, 이상치, 관계를 파악한다 |
| Modify  | 데이터 수정·변환 | 분석에 적합하도록 데이터를 정제하고 변환한다   |
| Model   | 모델링       | 분석 모델을 생성한다                |
| Assess  | 평가        | 모델의 성능과 분석 결과를 평가한다        |

---

### ① Sample, 표본 추출

Sample은 전체 데이터 중 분석에 사용할 데이터를 추출하는 단계다.

데이터가 너무 많으면 모든 데이터를 한 번에 분석하기 어렵기 때문에,
대표성을 가진 표본을 추출하여 분석 효율을 높인다.

```markdown id="zc6v3z"
Sample = 분석 대상 데이터 추출
```

---

### ② Explore, 데이터 탐색

Explore는 데이터의 기본 특성을 파악하는 단계다.

결측치, 이상치, 변수 간 관계, 데이터 분포 등을 확인한다.

```markdown id="agnif9"
Explore = 데이터 구조와 특징 파악
```

---

### ③ Modify, 데이터 수정 및 변환

Modify는 데이터를 분석하기 좋은 형태로 바꾸는 단계다.

결측치를 처리하거나, 이상치를 제거하거나, 변수를 변환하거나, 새로운 파생변수를 만들 수 있다.

```markdown id="le8n8m"
Modify = 분석 가능한 형태로 데이터 가공
```

---

### ④ Model, 모델링

Model은 분석 목적에 맞는 모델을 만드는 단계다.

분류, 예측, 군집화, 연관분석 등 다양한 분석 기법을 적용할 수 있다.

```markdown id="hyg7zg"
Model = 분석 모델 생성
```

---

### ⑤ Assess, 평가

Assess는 생성된 모델의 성능과 분석 결과를 평가하는 단계다.

모델이 실제 문제 해결에 적합한지, 예측력이 충분한지, 활용 가능한 결과인지 확인한다.

```markdown id="qx11gw"
Assess = 모델 성능 및 결과 평가
```

---

### SEMMA 암기

```markdown id="hjn39g"
SEMMA = Sample → Explore → Modify → Model → Assess
SEMMA = 표본추출 → 탐색 → 수정 → 모델링 → 평가
```

## 2) KDD 분석 방법론

### KDD의 개념

**KDD**는 Knowledge Discovery in Database의 약자로,
데이터베이스 안에서 의미 있는 지식을 발견하는 과정을 의미한다.

단순히 데이터 마이닝만 하는 것이 아니라,
데이터 선택부터 전처리, 변환, 마이닝, 해석과 평가까지 포함한다.

즉, KDD는 **데이터에서 지식을 발견하는 전체 과정**이다.

```markdown id="pd4bq1"
KDD = 데이터베이스에서 의미 있는 지식을 발견하는 과정
```

---

### KDD 단계

KDD는 일반적으로 다음 5단계로 정리한다.

```markdown id="as2qpz"
Selection → Preprocessing → Transformation → Data Mining → Interpretation/Evaluation
```

| 단계                        | 의미      | 설명                    |
| ------------------------- | ------- | --------------------- |
| Selection                 | 데이터 선택  | 분석 대상 데이터를 선택한다       |
| Preprocessing             | 전처리     | 결측치, 잡음, 오류 데이터를 처리한다 |
| Transformation            | 변환      | 분석에 적합한 형태로 데이터를 변환한다 |
| Data Mining               | 데이터 마이닝 | 패턴, 규칙, 관계를 발견한다      |
| Interpretation/Evaluation | 해석 및 평가 | 발견된 지식의 의미와 유용성을 평가한다 |

---

### ① Selection, 데이터 선택

Selection은 분석 목적에 맞는 데이터를 선택하는 단계다.

전체 데이터 중에서 분석에 필요한 데이터만 추출한다.

```markdown id="i47mu4"
Selection = 분석에 필요한 데이터 선택
```

---

### ② Preprocessing, 전처리

Preprocessing은 데이터의 품질을 높이는 단계다.

결측값, 이상값, 잡음, 중복 데이터 등을 처리한다.

```markdown id="rftiki"
Preprocessing = 데이터 품질 개선
```

---

### ③ Transformation, 변환

Transformation은 데이터를 분석에 적합한 형태로 바꾸는 단계다.

예를 들어, 변수를 정규화하거나, 범주형 변수를 숫자로 바꾸거나, 새로운 변수를 만들 수 있다.

```markdown id="dcp1ma"
Transformation = 분석에 적합한 형태로 변환
```

---

### ④ Data Mining, 데이터 마이닝

Data Mining은 실제로 분석 기법을 적용하여 패턴이나 규칙을 찾는 단계다.

분류, 군집, 연관분석, 예측 등이 여기에 해당한다.

```markdown id="fbjq7l"
Data Mining = 패턴과 규칙 발견
```

---

### ⑤ Interpretation/Evaluation, 해석 및 평가

Interpretation/Evaluation은 발견된 패턴이 의미 있는지 평가하는 단계다.

단순히 모델 결과가 나왔다고 끝나는 것이 아니라,
그 결과가 실제로 유용한 지식인지 판단해야 한다.

```markdown id="mwuqoy"
Interpretation/Evaluation = 발견된 지식의 의미와 유용성 평가
```

---

### KDD 암기

```markdown id="rbfuap"
KDD = Selection → Preprocessing → Transformation → Data Mining → Interpretation/Evaluation
KDD = 선택 → 전처리 → 변환 → 데이터 마이닝 → 해석/평가
```

---

## 3) CRISP-DM 분석 방법론

### CRISP-DM의 개념

**CRISP-DM**은 Cross-Industry Standard Process for Data Mining의 약자다.

이름 그대로 특정 산업이나 도구에 한정되지 않고
여러 산업에서 공통적으로 사용할 수 있는 데이터 마이닝 표준 프로세스다.

CRISP-DM은 데이터 분석을 비즈니스 문제 해결 과정으로 본다.

즉, 단순히 모델을 만드는 것이 아니라
비즈니스 이해에서 시작해 실제 업무 적용까지 이어지는 방법론이다.

```markdown id="pr1c2w"
CRISP-DM = 산업 전반에서 사용하는 표준 데이터 마이닝 프로세스
```

---

### CRISP-DM 단계

CRISP-DM은 다음 6단계로 구성된다.

```markdown id="wqvsjp"
Business Understanding
→ Data Understanding
→ Data Preparation
→ Modeling
→ Evaluation
→ Deployment
```

| 단계                     | 의미     | 설명                         |
| ---------------------- | ------ | -------------------------- |
| Business Understanding | 업무 이해  | 비즈니스 목표와 분석 목적을 이해한다       |
| Data Understanding     | 데이터 이해 | 데이터 수집 후 데이터의 특성과 품질을 파악한다 |
| Data Preparation       | 데이터 준비 | 분석에 사용할 데이터를 정제하고 변환한다     |
| Modeling               | 모델링    | 분석 모델을 생성한다                |
| Evaluation             | 평가     | 모델 결과가 비즈니스 목적에 적합한지 평가한다  |
| Deployment             | 전개     | 분석 결과를 실제 업무에 적용한다         |

---

### ① Business Understanding, 업무 이해

Business Understanding은 비즈니스 문제와 분석 목적을 이해하는 단계다.

분석을 왜 하는지, 어떤 문제를 해결하려는지, 성공 기준은 무엇인지 정한다.

```markdown id="jlaeb2"
Business Understanding = 비즈니스 문제와 분석 목적 정의
```

---

### ② Data Understanding, 데이터 이해

Data Understanding은 데이터를 수집하고 데이터의 특성을 파악하는 단계다.

데이터가 어떤 구조인지, 어떤 변수가 있는지, 품질은 어떤지 확인한다.

```markdown id="giz77l"
Data Understanding = 데이터 특성과 품질 파악
```

---

### ③ Data Preparation, 데이터 준비

Data Preparation은 분석에 사용할 데이터를 정제하고 가공하는 단계다.

결측치 처리, 이상치 처리, 변수 변환, 데이터 통합 등이 포함된다.

```markdown id="b95pch"
Data Preparation = 분석용 데이터셋 생성
```

---

### ④ Modeling, 모델링

Modeling은 분석 목적에 맞는 모델을 만들고 학습하는 단계다.

분류, 회귀, 군집, 연관분석 등 다양한 기법을 적용한다.

```markdown id="snw2qo"
Modeling = 분석 모델 생성
```

---

### ⑤ Evaluation, 평가

Evaluation은 모델의 결과가 비즈니스 목적에 적합한지 평가하는 단계다.

여기서 중요한 점은 단순히 정확도만 보는 것이 아니라,
처음 설정한 비즈니스 목표를 달성할 수 있는지 확인한다는 점이다.

```markdown id="v69668"
Evaluation = 분석 결과가 비즈니스 목표에 맞는지 검토
```

---

### ⑥ Deployment, 전개

Deployment는 분석 결과를 실제 업무에 적용하는 단계다.

보고서 작성, 시스템 반영, 의사결정 적용, 운영 프로세스 반영 등이 포함된다.

```markdown id="a7g5dd"
Deployment = 분석 결과를 실제 업무에 적용
```

---

### CRISP-DM 암기

```markdown id="dq2f63"
CRISP-DM = 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개
```

---

## SEMMA, KDD, CRISP-DM 비교

| 구분     | SEMMA             | KDD                       | CRISP-DM                   |
| ------ | ----------------- | ------------------------- | -------------------------- |
| 중심     | 데이터 마이닝 수행 절차     | 데이터베이스에서 지식 발견            | 비즈니스 문제 해결 중심              |
| 시작 단계  | Sample            | Selection                 | Business Understanding     |
| 주요 특징  | SAS 중심 방법론        | 지식 발견 과정 강조               | 산업 표준 프로세스                 |
| 마지막 단계 | Assess            | Interpretation/Evaluation | Deployment                 |
| 핵심 암기  | 표본추출→탐색→수정→모델링→평가 | 선택→전처리→변환→마이닝→해석/평가       | 업무이해→데이터이해→데이터준비→모델링→평가→전개 |

시험에서는 이렇게 구분하면 된다.

```markdown id="t1l9vb"
SEMMA = 데이터 마이닝 절차 중심
KDD = 데이터베이스 속 지식 발견 중심
CRISP-DM = 비즈니스 이해와 업무 적용 중심
```

# 03. 빅데이터 분석 방법론

빅데이터 분석 방법론은 빅데이터 분석 프로젝트를 수행하기 위한 절차다.

일반적으로 다음 5단계로 정리한다.

```markdown id="gtke7n"
분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개
```

빅데이터 분석은 데이터 규모가 크고, 데이터 종류가 다양하며, 처리 속도와 시스템 구현까지 중요하기 때문에
단순 분석보다 더 체계적인 절차가 필요하다.

---

## 빅데이터 분석 방법론 5단계

| 단계      | 영문         | 핵심               |
| ------- | ---------- | ---------------- |
| 분석 기획   | Planning   | 분석 목적, 범위, 계획 수립 |
| 데이터 준비  | Preparing  | 데이터 수집, 저장, 정제   |
| 데이터 분석  | Analyzing  | 분석 모델링 및 결과 도출   |
| 시스템 구현  | Developing | 분석 결과를 시스템으로 구현  |
| 평가 및 전개 | Deploying  | 성과 평가 및 업무 적용    |

---

## 1) 분석 기획

분석 기획은 빅데이터 분석 프로젝트의 출발점이다.

어떤 문제를 해결할 것인지,
어떤 데이터를 사용할 것인지,
분석 결과를 어디에 활용할 것인지 정한다.

분석 기획이 제대로 되지 않으면 이후 단계에서 아무리 좋은 모델을 만들어도 실제 가치로 이어지기 어렵다.

| 항목    | 내용                                   |
| ----- | ------------------------------------ |
| 주요 활동 | 비즈니스 이해, 문제 정의, 분석 목표 설정, 프로젝트 계획 수립 |
| 핵심 질문 | 무엇을 분석할 것인가? 왜 분석하는가?                |
| 산출물   | 분석 과제 정의서, 프로젝트 계획서                  |

시험에서는 이렇게 이해하면 된다.

```markdown id="z4yhwv"
분석 기획 = 분석 목적과 과제를 정의하는 단계
```

---

## 2) 데이터 준비, Preparing

데이터 준비는 분석에 필요한 데이터를 수집하고 분석 가능한 형태로 만드는 단계다.

빅데이터 환경에서는 데이터가 여러 시스템에 흩어져 있고,
정형 데이터뿐 아니라 비정형 데이터도 많기 때문에 데이터 준비가 매우 중요하다.

| 항목    | 내용                              |
| ----- | ------------------------------- |
| 주요 활동 | 데이터 수집, 데이터 저장, 데이터 정제, 데이터 통합  |
| 핵심 질문 | 분석에 필요한 데이터를 확보했는가?             |
| 산출물   | 분석용 데이터셋, 데이터 정의서, 데이터 품질 점검 결과 |

시험에서는 이렇게 이해하면 된다.

```markdown id="fkrjm9"
데이터 준비 = 분석에 필요한 데이터를 수집·정제·통합하는 단계
```

---

## 3) 데이터 분석, Analyzing

데이터 분석은 준비된 데이터를 바탕으로 분석 기법을 적용하여 결과를 도출하는 단계다.

여기에서는 통계 분석, 데이터 마이닝, 머신러닝, 시각화 등이 활용된다.

중요한 점은 단순히 모델을 만드는 것이 아니라
분석 목적에 맞는 의미 있는 결과를 도출해야 한다는 점이다.

| 항목    | 내용                            |
| ----- | ----------------------------- |
| 주요 활동 | 탐색적 데이터 분석, 모델링, 패턴 발견, 결과 해석 |
| 핵심 질문 | 데이터에서 어떤 의미 있는 결과를 얻었는가?      |
| 산출물   | 분석 모델, 분석 결과 보고서, 시각화 결과      |

시험에서는 이렇게 이해하면 된다.

```markdown id="xl0xsa"
데이터 분석 = 분석 기법을 적용해 의미 있는 결과를 도출하는 단계
```

---

## 4) 시스템 구현, Developing

시스템 구현은 분석 결과를 실제로 사용할 수 있는 시스템이나 서비스로 구현하는 단계다.

예를 들어, 고객 이탈 예측 모델을 만들었다면
그 모델을 실제 CRM 시스템에 연결하거나,
대시보드에서 확인할 수 있도록 구현해야 한다.

| 항목    | 내용                                      |
| ----- | --------------------------------------- |
| 주요 활동 | 분석 모델 시스템 적용, 대시보드 개발, 서비스 연동, 운영 환경 구축 |
| 핵심 질문 | 분석 결과를 실제 시스템에서 사용할 수 있는가?              |
| 산출물   | 분석 시스템, 대시보드, 운영 서비스                    |

시험에서는 이렇게 이해하면 된다.

```markdown id="dtocv9"
시스템 구현 = 분석 결과를 실제 활용 가능한 시스템으로 만드는 단계
```

---

## 5) 평가 및 전개, Deploying

평가 및 전개는 분석 결과와 시스템이 실제 목적을 달성했는지 평가하고,
이를 업무 현장에 적용하는 단계다.

여기서는 모델 성능뿐 아니라 비즈니스 성과도 함께 본다.

예를 들어,
이탈 예측 모델의 정확도가 높더라도
실제로 고객 이탈률이 줄지 않았다면 비즈니스 성과는 부족할 수 있다.

| 항목    | 내용                            |
| ----- | ----------------------------- |
| 주요 활동 | 성과 평가, 모델 검증, 운영 적용, 개선 방안 도출 |
| 핵심 질문 | 분석 결과가 실제 가치를 만들었는가?          |
| 산출물   | 평가 보고서, 운영 전개 계획, 개선 과제       |

시험에서는 이렇게 이해하면 된다.

```markdown id="wne99t"
평가 및 전개 = 분석 결과의 성과를 평가하고 실제 업무에 확산하는 단계
```

---

## 빅데이터 분석 방법론 단계 정리

| 단계      | 핵심 내용         | 시험 포인트           |
| ------- | ------------- | ---------------- |
| 분석 기획   | 분석 목적과 과제 정의  | 무엇을 왜 분석할지 결정    |
| 데이터 준비  | 데이터 수집·정제·통합  | 분석 가능한 데이터 확보    |
| 데이터 분석  | 분석 모델링과 결과 도출 | 의미 있는 패턴과 결과 발견  |
| 시스템 구현  | 분석 결과를 시스템화   | 실제 활용 가능한 형태로 구현 |
| 평가 및 전개 | 성과 평가와 업무 적용  | 비즈니스 가치 확인 및 확산  |

암기 방식은 다음과 같다.

```markdown id="buo03b"
기획 → 준비 → 분석 → 구현 → 전개
```

# 시험 직전 암기 문장

```markdown id="ftvlbt"
데이터 분석 방법론은 데이터 분석 과제를 체계적으로 수행하기 위한 절차와 기준이다.

분석 방법론은 업무 특성에 따라 폭포수 모델, 프로토타입 모델, 나선형 모델로 구분할 수 있다.

폭포수 모델은 단계별로 순차적으로 진행하는 방식이며,
프로토타입 모델은 시제품을 만들어 사용자 요구사항을 구체화하는 방식이고,
나선형 모델은 반복적으로 개발하면서 위험 요소를 관리하는 방식이다.

SEMMA는 Sample, Explore, Modify, Model, Assess의 순서로 진행되는 데이터 마이닝 방법론이다.

KDD는 Selection, Preprocessing, Transformation, Data Mining, Interpretation/Evaluation의 순서로 진행되며,
데이터베이스에서 의미 있는 지식을 발견하는 과정을 의미한다.

비즈니스 이해에서 시작해 분석 결과를 실제 업무에 전개하는 산업 표준 데이터 마이닝 프로세스이다.
```
