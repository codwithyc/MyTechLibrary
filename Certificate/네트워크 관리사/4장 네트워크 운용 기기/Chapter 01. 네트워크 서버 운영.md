## 네트워크 서버 운영 

### 1. NIC

#### 개요
- NIC(Network Interface Controller)의 약어로, **OSI 7계층 가장 하위 레벨인 물리 계층에 있는 하드웨어** 입니다.
- 흔히 랜카드(LAN Card) 혹은 이더넷 카드(Ethernet Card)라고 불립니다.
- 컴퓨터 메인 보드에 장착되어 컴퓨터와 랜케이블(LAN Cable(UTP)) 사이를 연결합니다.

> 랜 케이블은 차폐(특정 현상, 물체, 혹은 방사선·전자기파 등을 가려 막거나 덮어서 보호하는 것)  
> 방식에 따른 분류로 크게 UTP, FTP, STP 로 나뉩니다.
> 
> - UTP (Unshielded Twisted Pair): 차폐가 없어 유연하고 저렴, 일반 가정/사무실용.  
> - FTP (Foiled Twisted Pair): 알루미늄 포일로 선을 감싸 노이즈에 강함.
> - STP (Shielded Twisted Pair): 각 페어와 전체 케이블을 차폐하여 간섭이 심한 환경에 적합.

- OSI 7계층에서 **물리 계층과 데이터링크 사이의 통신**을 가능하게 합니다.
- NIC 카드 안에는 모든 장비의 물리적인 네트워크 주소인 MAC 주소가 할당되어 있어, 모든 장비들이 이더넷,  
불루투스, 와이파이 등 IEEE 802 표준을 따르는 대부분의 통신 시스템에서 통용될 수 있습니다.

#### NIC 카드의 종류
| 구분 | 설명 |
| --- | -------------------- |
| 이더넷(Ethernet) <br> 고속 이더넷(Fast Ethernet) <br> 기가비트 이더넷 (Gigabit Ethernet) | - IEEE 802.3 표준을 지원 <br> - 속도(이더넷 10Mbps) / 고속 이더넷 (100Mbps) / 기가비트 이더넷 (1Gbps)|
| 토큰링(Token Ring) | - 메인프레임 장비에서 통상 4 ~ 16 Mbps 속도를 지원 <br> - 다른 카드와 혼용하여 사용할 수 없으며 상대적으로 고가 | 
| ATM LAN | - 고속의 ATM 네트워크에 연결하기 위하여 사용 | 
| ArtNet | - 토큰버스형 네트워크로 조작이 간단하고 구축비용이 저렴 | 

> Mbps는 네트워크에서 초당 얼마나 많은 데이터를 전송할 수 있는지를 나타내는 단위
> Mbps에서 b는 byte가 아닌 bit

#### NIC 카드 확인 방법
- 컴퓨터 장치 관리자 ->  네트워크 어댑터 -> NIC 카드(제조사마다 제품명은 상이함)를 더블 클릭하면, PCI Slot을 통해  
컴퓨터 메인보드와 연결되어 있음을 확인할 수 있습니다.

#### NIC 카드와 컴퓨터 간의 인터페이스 방식에 따른 구분

- NIC 카드의 컴퓨터 메인보드 간의 연결 방식은 크게 ISA 방식과 PCI 방식으로 나뉩니다.
- 최근에는 대부분 PCI 방식을 사용합니다.

| 구분 | 설명 | 
| --- | ---------------------- |
| ISA 방식 | - Industry Standard Architecture Bus 방식 <br> - IBM 컴퓨터의 PC/XT(8bit)와 PC/AT(16bit)를 지원하기 위해 개발 <br> - DOS 등 구현 운영체제를 지원하며, 고속 통신을 지원하기는 어렵습니다. <br> - 개발 당시에는 ISA가 산업 표준이었으나 펜티엄 이상급의 컴퓨터에서는 찾아보기 힘들다. |
| PCI 방식 | - Peripheral Component Interconnect Bus 방식 <br> - 컴퓨터의 메인보드와 주변기기(Peripheral Components) 간의 연결 (Interconnect)을 지원 <br> - 32bit 및 64bit로 ISA 방식에 비해 고속 통신을 지원 <br> - 펜티엄급 이상 PC는 대부분 PCI 방식으로 NIC 카드와 컴퓨터를 연결 | 

> 펜티엄 컴퓨터란?   
> 펜티엄은 1993년부터 2023년까지 인텔이 생산한 x86 아키텍처 호환 마이크로프로세서 시리즈이다.  
> 오리지널 펜티엄은 인텔의 5세대 프로세서로, i486의 후속작이었다. 펜티엄은 2006년 인텔 코어 라인이 출시될 때까지  
> 10년 넘게 인텔의 플래그십 프로세서 라인이었다.

#### 정리
**NIC는 컴퓨터와 네트워크를 연결하는 하드웨어 장치로, 데이터를 네트워크 신호로 변환해 송수신하고 MAC 주소를 기반으로 프레임 통신을 수행하는 네트워크 인터페이스이다.**

### 2. VLAN
#### 개요
- **Virtual Local Area Network의 약어로, 가상 LAN이라고도 칭합니다.**
- 물리적으로는 각 컴퓨터당 하나씩만 존재하는 LAN 카드를 가상으로 분할하여 마치 여러 개의 LAN이 있는 것처럼 각기 활용하고,  
서로 다른 도메인 상에서의 보로드캐스팅을 가능하게 함으로써, **불필요한 통신으로 인한 네트워크 성능 저하를 방지하는 기술입니다.**
    - 브로드 캐스팅 : 같은 LAN 내의 모든 디바이스에 데이터를 보내는 것입니다.
    - 멀티 캐스팅 : 특정 다수에게 데이터를 보내는 것입니다.
    - 유니 캐스팅 : 단 하나의 클라이언트에게 데이터를 보내는 것입니다.
- 물리적 LAN과는 달리 네트워크 접속 포트 및 프로토콜 종류, MAC 주소를 사용해서 VLAN을 구성하며, 일반적으로 스위치나 라우터  
장비 레벨에서 가상화를 수행합니다.
- LAN의 특성과 유사하며 물리적인 장치 없이 소프트웨어를 통한 연결과 구성 컨트롤이 가능합니다.
- IEEE 802.IQ 프로토콜을 이용하여 구성하는 것이 가능 일반적입니다.

#### VLAN의 장점과 특징
| 장점 및 특징 | 설명 | 
| -------- | ------------------------ |
| 성능 향상 | 불필요한 브로드캐스트를 줄여 네트워크를 효율적으로 사용할 수 있고, 성능을 향상시킵니다. |
| 관리 용이 | 여러 개의 VLAN을 각기 다르게 설정하여 유연하면서도 단순하게 관리할 수 있습니다. | 
| 보안성 향상 | 같은 VLAN 망 안에 속한 데이터 흐름 처리 장비 (DTE : Data Terminal Equipment)를 통해서만 <br> 처리되므로, 보안성을 향상시킬 수 있습니다. | 

#### VLAN의 종류
| 종류 | 설명 | 
| --- | -------------------- | 
| 정적 (Static) VLAN | - 포트별로 VLAN을 배정하고, 포트별로 VLAN을 관리 및 모니터링 <br> - 가장 일반적인 방식 | 
| 동적 (Dynamic) VLAN | - VMPS(VLAN Membership Policy Server)를 이용하여 접속장비의 MAC 주소를 확인하여 <br> VLAN을 구성하는 방식으로, 대형 스위치에서 사용합니다. | 

> 정적과 동적 
> 정적(Static)은 고정되어 움직이지 않거나 변화가 없는 상태를 의미하며,  
> 동적(Dynamic)은 활발하게 움직이고 상황에 따라 변화하는 것을 의미합니다. 

#### VLAN의 구성

| 구성 방식 | 설명 | 
| -------- | ------------------------ | 
| Port 기반 | - 포트를 VLAN에 배정하여 같은 VLAN에서 포트에 연결된 호스트 간의 통신만 가능 <br> - 스위치 포트를 각 VLAN에 할당 <br> - 가장 일반적인 방식 |
| MAC 주소 기반 | - 같은 VLAN에 등록된 MAC 주소를 가진 호스트 간의 통신만 가능 <br> - 통신을 원하는 호스트의 MAC 주소를 모두 입력하는 것이 번거러워 자주 사용되지 않는다. | 
| 네트워크 주소 기반 | - 같은 VLAN에 등록된 같은 네트워크 주소를 가진 호스트 간의 통신만 가능 <br> - 다른 네트워크와 통신하기 위해서는 라우터를 이용 | 
| 프로토콜 기반 | - 같은 VLAN에 등록된 같은 프로토콜을 가진 호스트 간의 통신만 가능 <br> - TCP/IP, IPX/SPX, NETVIEW 등 활용 프로토콜을 통해 구분 | 

#### VLAN Trunking
- VLAN이 설정된 여러 개의 스위치가 서로 연결되어 통신하기 위해서는 각각의 VLAN을 모두 케이블로 연결해야 하는데, 매번 연결하는 것은 비효율적이다.
- 이를 효율적으로 관리하기 위해 각 VLAN에서 온 데이터 프레임들을 한 묶음으로 모아 데이터의 송/수신을 담당하고, 각 프레임이 어느 VLAN 소속인지를  
판단하여 해당하는 VLAN으로 보내주는 것이 VLAN Trunking이다.

#### 정리
**VLAN은 하나의 물리적 네트워크를 여러 개의 논리적 네트워크로 분리하여, 불필요한 브로드캐스트 트래픽을 줄이고 네트워크 성능과 보안성을 높이는 기술이다.**

### 3. RAID
#### 개요
- Redundant Array of Independent Disks(독립적인 디스크들의 중복 배열)의 약어로,  
**여러 개의 하드디스크를 중복 배열하여 하나의 디스크처럼 보이게 함**으로써 하나의 고용량, 고성능 디스크를 대체하는 기술입니다.
- 보통 하드웨어 장치를 직접 중복 배열함으로써 구현하지만, 소프트웨어적으로도 구현할 수 있으며, 모두 논리적으로는 하나의 디스크로 간주됩니다.
- 데이터를 자동으로 복제하여 중복 저장하므로 많은 용량이 필요하지만, 백업 하드디스크가 있기 때문에 디스크가 고장 나거나 데이터가 유실되더라도 즉시 복구 가능합니다.
- 스트라이핑 기술을 통해 각 드라이블를 다양한 크기로 구획하여 공간 활용을 효율적으로 할 수 있다.

#### RAID의 LEVEL 종류와 특징 
| LEVEL 구분 | 설명 | 
| ----------- | ------------------------ | 
| RAID 0 (Striping, Concatenate) | - 2개 이상의 작은 디스크들을 모아서 하나의 크 디스크로 만드는 것입니다. <br> - 데이터의 저장 및 읽는 속도가 2배 이상 빨라져 입출력 성능이 향상됩니다. <br> - 데이트를 나누어 저장하되, 중복하여 저장하지 않으므로 장애 발생시 복구할 수 없습니다.
| RAID 1 (Mirroring) | - 서로 다른 두 개의 디스크에 동일한 내용을 중복 저장하여 관리하는 기술입니다. <br> - 두 배의 데이터 용량이 필요하지만, 데이터 복구에 적합하므로 높은 신뢰도가 필요할 경우 사용됩니다. <br> - 전체 디스크 용량의 반만 사용할 수 있어 구성 비용이 비쌉니다. | 
| RAID 2 (Hamming Code ECC) | - 데이터를 포함하는 디스크와는 구분되는 별도의 디스크에 데이터 복구를 위한 <br> 디스크 오류 복구 코드(ECC : Error Correction Code) 코드 중 하나인 해밍코드를 저장해두는 것입니다. <br> - 데이터의 일부가 유실되거나 장애가 발생하는 경우 별도의 디스크에 저장된 ECC 값을 통해 유실 데이터를 다시 생성해낼 수 있습니다.|
| RAID 3 (Parity ECC) | - 데이터를 포함하는 디스크와는 구분되는 별도의 디스크에 패리티 정보를 저장해두는 것입니다. <br> - 내장된 ECC 값으로 에러를 감지하여 데이터를 복구할 수 있습니다. | 
| RAID 4 (Parity ECC + 블록 단위 입출력) | - 데이터를 포함하는 디스크와는 구분되는 별도의 디스크에 패리티 정보를 저장하되, 데이터는 블록 단위로 데이터 리스크에 분산하여 저장하는 것입니다. <br> - RAID 3과 동일하나 패리티를 블록 단위로 관리한다는 차이점이 존재한다. |
| RAID 5 (Parity ECC + Parity 분산) | - 데이터를 포함하는 디스크 내부에 패리티 정보를 저장해두는 것입니다. <br> - 패리티를 분산하여 안정성이 높고 데이터의 병렬처리가 가능해 데이터 처리 효율도 좋은 편이다. <br> 실무에서 가장 널리 이용됩니다. |
| RAID 6 (Parity ECC + Parity 분산) | - 데이터를 포함하느 디스크 내부에 패리티 정보를 다중화시켜서 저장해두는 것입니다. <br> - 패리티를 다중화시켜 분산하여 안정성이 극대화됩니다. <br> - 하나의 디스크에 대해 두 개의 패리티가 독립적으로 연산하므로 RAID 5에 비해 데이터 처리 효율은 낮지만, <br> 복잡한 장애 상황에서도 정상적으로 동작하므로 대용량 시스템에서 사용됩니다.| 
| RAID 10 | - RAID 0과 RAID 1을 혼합하여 데이터를 백업한 후 이를 나누어 저장하는 것입니다. (미러링 후 스트라이핑) <br> - 최소 4개인, 짝수 개의 디스크로 구성됩니다. | 
| RAID 1 + 0 | - RAID 0과 RAID 1을 혼합하여 먼저 데이터를 나눈 후 이를 백업하는 것입니다. (스트라이핑 이후 미러링) | 

#### RAID 계산법

RAID 계산에서 가장 많이 보는 것은 **실제 사용 가능한 용량**입니다.

기본 공식은 다음과 같습니다.

| RAID 종류 | 사용 가능 용량 계산법 | 장애 허용 |
|---|---|---|
| RAID 0 | `디스크 개수 × 디스크 용량` | 없음 |
| RAID 1 | `디스크 1개 용량` 또는 `전체 용량 ÷ 2` | 보통 1개 |
| RAID 5 | `(디스크 개수 - 1) × 디스크 용량` | 1개 |
| RAID 6 | `(디스크 개수 - 2) × 디스크 용량` | 2개 |
| RAID 10 | `(디스크 개수 × 디스크 용량) ÷ 2` | 구성에 따라 다름 |

예를 들어 **1TB 디스크 4개**를 기준으로 계산하면 다음과 같습니다.

| RAID 종류 | 계산 | 사용 가능 용량 |
|---|---|---|
| RAID 0 | `4 × 1TB` | 4TB |
| RAID 1 | `4TB ÷ 2` | 2TB |
| RAID 5 | `(4 - 1) × 1TB` | 3TB |
| RAID 6 | `(4 - 2) × 1TB` | 2TB |
| RAID 10 | `(4 × 1TB) ÷ 2` | 2TB |

핵심은 **RAID 구성에 따라 몇 개의 디스크 용량이 보호용으로 빠지는지**입니다.

- RAID 0은 보호 없이 전체 용량을 사용합니다.
- RAID 1은 데이터를 복제하기 때문에 보통 절반만 사용합니다.
- RAID 5는 디스크 1개 용량만큼 패리티에 사용합니다.
- RAID 6은 디스크 2개 용량만큼 패리티에 사용합니다.
- RAID 10은 미러링과 스트라이핑을 함께 사용하므로 전체 용량의 절반을 사용합니다.

따라서 암기할 때는 다음처럼 정리하면 쉽습니다.

```text
RAID 0  = 전체 사용
RAID 1  = 복제 → 절반 사용
RAID 5  = N - 1
RAID 6  = N - 2
RAID 10 = 절반 사용
